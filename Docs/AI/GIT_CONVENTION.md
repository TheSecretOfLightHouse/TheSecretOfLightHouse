# Git · PR 규칙

범위: 커밋 메시지 · PR 제목/본문 작성 시 따르는 규칙.

## 브랜치
- `main`: 배포용. `develop`: 통합. `feature/<이름>`: 개인 작업.
- PR은 `feature/<이름>` → **`develop`**. `main`으로 직접 보내지 않는다.

## 커밋 메시지
- 형식 자유. 무엇을 바꿨는지 알아볼 수 있게만 쓴다.

## PR 제목
`<이모지><타입>(<페이지 경로 또는 컴포넌트>): <요약>` — 범위가 없으면 `(...)` 생략.

| 제목 | 쓰는 경우 |
|---|---|
| `✨Feat(범위):` | 새로운 기능 추가 또는 기능 업데이트 |
| `🔨Fix(범위):` | 버그 또는 에러 수정 |
| `⭐️Style(범위):` | 코드 포맷팅, 코드 오타, 함수명 수정 등 스타일 수정 |
| `🧠Refactor(범위):` | 코드 리팩토링 (똑같은 기능인데 코드만 개선) |
| `📁File(범위):` | 파일 이동 또는 제거, 파일명 변경 |
| `🎨Design(범위):` | 디자인, 문장 수정 |
| `🏷Comment(범위):` | 주석 수정 및 삭제 |
| `🍎Chore:` | 빌드 수정, 패키지 추가, 환경변수 설정 |
| `📝Docs:` | 문서 수정, 블로그 포스트 추가 |
| `🔥Hotfix:` | 핫픽스 수정 |
| `🔧Patch:` | 수치 등의 변경 |
| `🚫Delete:` | 기능 제거 |

- 여러 종류가 섞이면 가장 큰 변경 기준으로 하나만 고른다.
- 예: `✨Feat(Player): 플레이어 이동 구현`, `📝Docs: 데모 가이드 · 시스템 기획 문서 추가`

## PR 본문
```
## 변경 사항
- (파일/기능 단위로 무엇을 바꿨는지)

## 확인할 것
- (리뷰어가 볼 포인트, 에디터에서 확인 필요한 부분)
```
- 변경 파일은 `git diff develop...HEAD` (갈라진 지점 기준)로 확인한다. 두 점(`..`) 비교는 develop에만 있는 변경까지 섞여 보인다.
