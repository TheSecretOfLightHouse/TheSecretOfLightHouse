# MK02 배 난파 상태 연결

작성일: 2026-10-13
갱신일: 2026-10-13
상태: 진행 중 — 내구도·난파 기본 연결 구현됨(미검증), MK02 전체 미완료
브랜치·기준 커밋: feature/myeongki / 352a1b4

## 요청과 목표
사용자가 작성한 BoatDurability를 플레이어 HFSM의 행동 불능과 연결한다.

## 진행 과정과 결정 이유
- 2026-10-13: 작업표 MK02, 이동 권위 인수인계, 실제 BoatController·PlayerController·HFSM을 대조했다. 내구도는 서버 상태지만 플레이어 행동 불능은 로컬 HFSM 상태여서 SyncVar 연결이 필요했다.
- BoatDurability의 기존 코드는 보존했다. BoatController는 서버 시작/종료에 Wrecked를 구독/해제하며, 승선 중인 주인의 SetDowned를 호출한다.
- PlayerController는 서버에서 난파 상태를 확정하고 SyncVar 훅과 최초 클라이언트 시작에서 HFSM에 적용한다. 네트워크 클라이언트의 직접 SetDowned 변경은 거절한다.
- 난파한 배의 조작·승하선 요청을 막는다. 배 복구·잔해·구조 계약을 임의로 정하지 않으며 플레이어는 배 앵커에 유지한다. 배 밖에 있는 주인을 자동으로 행동 불능으로 만들지 않는다.
- 2026-10-13: 사용자 요청에 따라 MK02 전체 진행 상황과 남은 일을 pointer·원문에 정리했다. 작업표의 MK02는 내구도·난파 외에 피해원·수리·대포·날씨/모듈/등대 보상을 포함하므로 전체 완료로 표기하지 않았다. 이번 갱신에서 게임 코드 변경이나 실행 검증은 하지 않았다.

## 변경 파일과 결과
- Assets/01.Scripts/05.Player/Boat/BoatController.cs
- Assets/01.Scripts/05.Player/Control/PlayerController.cs
- 실제 Cube 배 프리팹은 Unity PrefabUtility로 확인했으며 BoatDurability가 이미 존재해 저장하지 않았다.
- 사용자가 만든 BoatDurability.cs와 meta는 기존 미추적 파일로 유지했다.

## 검증
- Unity 6000.0.83f1 스크립트 컴파일 성공, compilationFailed=false.
- Player 씬 Play 모드에서 기존 비활성 배·플레이어를 임시 활성화하고 오프라인 승선 후 난파 처리 메서드와 동기화 훅을 직접 호출했다. boarded=true, downed=true, motion=Downed, inputLocked=true, fireBlocked=true 확인. 서버 피해 전체 경로와 네트워크 전송 시험을 대신하지 않는다.
- Play 모드 종료. 씬·프리팹 저장 없음. git diff --check 통과.
- 배 활성화 시 기존 BuoyancyBody의 WaterSamplerHost 누락 오류가 재현됨. 바다 기능은 수정하지 않음.
- 현재 씬에는 NetworkManager가 없어 호스트/원격 M2 시험, 서버 ApplyDamage→이벤트 전체 경로, 난파 이벤트 중복과 수치 동기화는 미검증.

## 남은 일과 차단 조건
- 호스트/원격에서 100→75→50→25→0 피해 시험과 난파 한 번 발생, 이동·사격·재탑승 차단을 검증한다.
- 기존 로컬의 배 참조 소실 시 SetDowned 호출은 네트워크 클라이언트에서 더 이상 상태를 확정하지 않는다. 서버에서 배 소멸로 난파시키는 경로는 별도 연결이 필요하다.
- 몬스터·암초 피해 연결이 남았다. 서버 겹침 검사·파도 보고·대포 판정은 지훈 합의 안건 7의 최명기 확인 대기 제안이며 확정 완료로 취급하지 않는다.
- 배 내구도 수리는 MK02 범위다. 비용·조건·회복량을 정하고 JH02 RepairBoat와 연결해야 한다. 난파 후 구조·배 복구 계약은 MK04와 구분한다.
- 대포는 BoatController.TryFire에서 로컬 재장전 간격 검사와 CannonFired 이벤트 발행만 있다. 본편 스크립트 검색에서 소비자는 찾지 못했다. 서버 재장전 검증·발사·명중·TW02 몬스터 체력 연결이 남았다.
- MS04 배 물리·날씨·파도 충격, 배 모듈·JH04 등대 보상의 속도/대포 피해 적용·해제 연결 및 실행 검증이 남았다. 최후 전투에서도 소환 전 보상을 유지하고 최후 수리로 신규/중복 지급하지 않아야 한다.
- MK04의 잔해 표류·화물 손실·구조·난파 후 배 복구는 이번 내구도 연결 구현 범위 밖이다. W10·W11의 자동 구조 비용/복구 경로 계약은 미정이다.

## 다음 행동
1. 개발용 서버 피해 수단과 네트워크 시험 씬을 준비한다. 시험 내구도 100/피해 25는 밸런스 확정값이 아니다.
2. 호스트·원격 배에 각각 피해를 주고 전원에게 100→75→50→25→0이 일치하는지 확인한다. 난파 한 번, 이동·사격·재탑승 차단, 다른 플레이어 정상 조작을 검증한다.
3. 배 소멸 처리 경로를 검토한 뒤 몬스터·암초 피해 → 배 수리 → 대포 → 날씨/모듈/보상 순서로 진행한다. 관련 담당과의 경계 계약을 확인하며 다른 파트 코드는 별도 허용 없이 수정하지 않는다.
4. 사용자에게 단계별 변경 코드와 이유를 먼저 설명한다. 할 일 목록을 새 구현 승인으로 취급하지 않는다.
