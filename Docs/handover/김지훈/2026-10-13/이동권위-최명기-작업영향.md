## 결정 내용

2026-10-13 김지훈이 [문제 대장 N07](../../../07-design-issue-register.md)(배 물리 권한)을 결정했다. **플레이어 캐릭터와 배 모두 소유 클라이언트 권위다.** 상세는 [네트워크 권위 §4](../../../unity/NETWORK_AUTHORITY.md#4-이동과-물리-권위)에 있다.

- 이동: 자기 PC가 움직이고 NetworkTransform(ClientToServer)으로 보고한다.
- 결과: 내구도·난파·피해·픽업은 서버가 판정한다.
- Rigidbody: 움직이는 소유 PC만 Dynamic이고 서버와 다른 PC는 Kinematic이다.

## 앞으로 작업할 때 주의할 것

| 작업 | 주의 | 이유 |
|---|---|---|
| MK02 배 피해(암초·몬스터) | 서버 판정에 `OnCollisionEnter`를 쓰지 않는다. 서버 겹침 검사 제안 | 서버에서 원격 배는 Kinematic이고 프로젝트 Contact Pairs Mode가 기본값이라 충돌 이벤트가 오지 않는다. 쓰면 호스트 배만 피해가 들어온다 |
| MK02 대포 | 발사는 요청, 탄·명중은 서버 제안 | 몬스터 체력이 서버 상태 |
| 부력 연결 | `BuoyancyBody.IsSimulating`을 배 주인 PC에서만 켠다 | 기본값이 `true`라 모든 PC에서 파도 충격 감지가 돌면 피해가 중복된다 |
| 원격 배 속도 사용 | Kinematic 배의 `linearVelocity`를 믿지 않는다 | 항적·애니메이션에 필요하면 위치 변화량으로 계산 |
| MK04 자동 구조·강제 하선 | 서버에서 `transform.position`을 바꾸지 말고 `ServerTeleport` 사용 | ClientToServer라 클라이언트 보고값이 덮어쓴다 |
| 배끼리 충돌 | 서로 밀지 않는다 | 각 PC에서 상대 배가 Kinematic. 들이받기 방해 기능은 이 방식으로 구현이 어렵다 |

피해 판정 방식은 제안이며 [합의 안건 7번](최명기-합의안건.md#7-물리피해-판정-제안-중-최명기-범위)에서 확인을 받는다.
