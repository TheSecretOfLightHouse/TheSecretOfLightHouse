# 등대 문서 읽기 안내

기획과 구현 상태를 분리해 읽는다. 기능별 코드 경계는 [담당표](CODE_OWNERSHIP.md)를 따른다. 리슨 서버 구조와 기존 게임 규칙은 유지한다.

최종 기획은 [게임 기획서 v4](design/references/game-design-v4.md)이며 게임 규칙·수치의 유일한 기준이다. 01·03~07은 2026-10-10에 v4 기준으로 갱신했다. 장·절 번호는 v4를 따른다. v4 이전 기획서(2026-10-08)는 [보존 자료](design/archive/game-design-2026-10-08.md)로 옮겼고 현행 규칙으로 쓰지 않는다. 기능 논의·구현 전에는 [설계 문제 대장](07-design-issue-register.md)의 관련 ID와 v4 13장의 결정 필요 목록을 확인한다. v4의 가안·미정은 그대로 유지한다.

## 3. 문서 간 기준

- 최신 사용자·팀 결정이 요구사항의 기준이다. 실제 구현과 다르면 양쪽을 구분하며 기획을 임의로 바꾸지 않는다.
- 게임 규칙은 최신 사용자 결정과 v4를 기준으로 하며, v4 이전 문서와의 차이(V01~V10)와 미결 계약은 문제 대장에서 추적한다. 01은 개요, 03은 기술 계약, 04는 파일 배치, 05는 구현 상태를 관리한다.
- C# 스타일은 [코딩 컨벤션](coding-convention.md), 커밋·PR 형식은 [커밋·PR 컨벤션](commit-convention.md)에서만 관리한다.
- [v4 이전 기획서](design/archive/game-design-2026-10-08.md)와 [기획 초안](design/archive/initial-game-design.md)은 과거 기록이다. 최신 기획과 충돌할 때 현재 요구사항으로 적용하지 않는다.

## 4. 상태 표기

| 상태 | 의미 |
|---|---|
| 확정 | 현재 기획의 규칙. 구현 완료와 별개 |
| 가안·미정·보류 | 현재 기획에 표시된 조정값·결정 대기·후속 검토 |
| 파일 확인 | 코드·설정·에셋 존재만 확인 |
| 구현됨·실행 미검증 | 코드가 있으나 해당 동작을 이번 작업에서 실행하지 않음 |
| 실행 검증 | 환경·명령·인원·결과 증거가 있는 범위만 인정 |
