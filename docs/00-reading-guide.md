# 등대 문서 읽기 안내

기획과 구현 상태를 분리해 읽는다. 기능별 코드 경계는 [담당표](CODE_OWNERSHIP.md)를 따른다. 리슨 서버 구조와 기존 게임 규칙은 유지한다.

최신 제공 기획은 [v4 원문](design/references/game-design-v4.md)이다. 기능 논의·구현은 [설계 문제 대장](07-design-issue-register.md)의 버전 차이와 관련 ID를 먼저 확인한다. 기존 01~06은 v4 전 내용이 섞여 있으므로 단독 기준으로 사용하지 않는다. 문서별로 v4 이전 부분은 다음과 같다.

- 01: 보이스(V01)·일수(V06)·일정(V08)·난파/구조(V04) 서술은 v4 기준으로 고쳤고 연료(V09)는 버전 충돌 확인 대기로 표시했다. 투표 횟수(V02)·심해 게이지(V03) 수치는 01에 없으므로 v4를 직접 본다.
- 02: 문서 전체가 2026-10-08 기준 v4 이전 참고 자료이며 현행 규칙의 원본으로 사용하지 않는다.
- 03·04: 기술 계약과 파일 배치를 다루며 게임 규칙·수치의 출처가 아니다. 규칙은 v4를 본다.
- 05·06: 장·절 번호는 v4 기준이다. 투표 횟수(V02)·심해 게이지(V03)·난파/구조(V04)를 다룬 결정·작업 항목(D03·D04·D07, MK04, TW03·TW04 등)은 구규칙이 남아 있을 수 있어 대장 확인 후 쓴다.

## 3. 문서 간 기준

- 최신 사용자·팀 결정이 요구사항의 기준이다. 실제 구현과 다르면 양쪽을 구분하며 기획을 임의로 바꾸지 않는다.
- 게임 규칙은 최신 사용자 결정과 제공된 v4를 기준으로 하며, 기존 02와의 차이는 문제 대장에서 추적한다. 01은 개요, 03은 기술 계약, 04는 파일 배치, 05는 구현 상태를 관리한다.
- C# 스타일은 [코딩 컨벤션](coding-convention.md), 커밋·PR 형식은 [커밋·PR 컨벤션](commit-convention.md)에서만 관리한다.
- [기획 초안 보존본](design/archive/initial-game-design.md)은 과거 제안 기록이다. 최신 기획과 충돌할 때 현재 요구사항으로 적용하지 않는다.

## 4. 상태 표기

| 상태 | 의미 |
|---|---|
| 확정 | 현재 기획의 규칙. 구현 완료와 별개 |
| 가안·미정·보류 | 현재 기획에 표시된 조정값·결정 대기·후속 검토 |
| 파일 확인 | 코드·설정·에셋 존재만 확인 |
| 구현됨·실행 미검증 | 코드가 있으나 해당 동작을 이번 작업에서 실행하지 않음 |
| 실행 검증 | 환경·명령·인원·결과 증거가 있는 범위만 인정 |
