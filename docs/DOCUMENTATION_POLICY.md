## 팀 문서가 자립하려면

- 현재 규칙과 미구현 계획을 분리하고 가안·미정·보류 표기를 보존한다.
- 기획은 게임 기획서, 코드 스타일은 코딩 컨벤션, 커밋·PR 형식은 커밋·PR 컨벤션을 단일 기준으로 삼는다.
- 문서만으로 이해할 수 있게 필요한 결론·조건·한계를 본문에 적는다. 개인 기록이나 다른 저장소를 필독으로 요구하지 않는다.
- 코드와 설정으로 확인할 수 있는 사실은 실제 파일과 대조한다. 파일 존재를 실행 통과로 표현하지 않는다.
- 과거 성공 기록은 당시 환경의 결과이며, 현재 실행 결과로 재사용하지 않는다.
- 다른 프로젝트의 이름·게임 내용·인물·절대 경로·도입 출처 문구를 운영 규칙에 남기지 않는다. 외부 라이선스와 필요한 에셋 권리 표기는 보존한다.
- 비밀값·개인 계정·PC별 설정·잔액은 공유 문서에 넣지 않는다.

## 갱신 순서

1. 사용자 요청, 관련 코드·설정, 기존 변경을 확인한다.
2. 현재 구현, 계획, 과거 기록을 구분한다.
3. 기준 문서의 본문을 고치고 중복 규칙을 만들지 않는다.
4. 파일 이동 시 들어오는 링크와 나가는 링크, [읽기 안내](00-reading-guide.md)와 [지식 맵](ai/07_PROJECT_KNOWLEDGE_MAP.md)을 함께 갱신한다.
5. 문서 링크·금지된 외부 프로젝트 잔재·실제 변경 범위를 검사하고, 실행하지 않은 항목을 보고한다.
