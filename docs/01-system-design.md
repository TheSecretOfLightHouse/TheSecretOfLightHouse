# 등대 시스템 개요

> 기획 기준: [게임 기획서 v4](design/references/game-design-v4.md)(2026-10-09). 이 문서는 개요이며 수치·세부 규칙은 v4에서 관리한다. 미결 항목은 v4 13장과 [설계 문제 대장](07-design-issue-register.md)을 본다. 원문의 가안·미정은 임의 확정하지 않는다.

## 1. 프로젝트 정의

PC 3인칭 4인 호스트-클라이언트 마피아 게임이다(Unity 3D·URP, Mirror 서버 권위). 네 명 모두 직군을 가지며 한 명이 마피아를 겸한다. 시민 셋은 메인 등대 활성화를, 마피아는 활성화 저지를 목표로 한다. 한 판 길이는 30~40분이다. 크툴루 신화 분위기의 폭풍우 치는 바다 연출이 가장 중요하다(v4 1장).

## 2. 경험의 중심

- 각자 배로 섬을 오가며 자원을 모으고, 작업대에서 모듈을 만들어 개인 배와 공유 등대에 장착한다.
- 바다 몬스터·밤·날씨(파도 충격·토네이도)가 파밍을 방해한다. 누가 언제 어디에 있었는지가 추리 단서가 된다.
- 마피아의 우선 목표는 정체를 숨기는 것이다. 괴물 소환은 끝까지 숨은 마피아의 마지막 한 수다.
- 배는 난파되지만 플레이어는 죽지 않는다. 행동 불능이 되어 잔해 위에서 표류하며 조명탄과 비밀 투표만 할 수 있다. 동료가 구조하거나, 일정 시간 뒤 가까운 섬으로 떠밀려 자력 복귀한다(v4 9.1).
- 인게임 보이스·배 무전은 없다. 밤 회의 토론 수단은 v4 13장의 결정 필요 항목이다.

## 3. 배경과 범위

중앙 등대 섬과 매 판 랜덤 배치되는 자원 섬·난파선·특수 기능 섬이 무대다. 해역은 내해 → 중간 해역(전체 일수의 1/3) → 외해(2/3) 순으로 해금되며 잠긴 구역은 폭풍벽으로 막는다(v4 8장). 메인 등대 하나만 사용하고 보조 등대는 삭제됐다. 연료는 10/8 회의에서 삭제됐으나 v4 4.4·8.3 문구에 남아 있어 재도입 여부가 미결이다([V09](07-design-issue-register.md#2-기존-문서와-달라진-규칙)). 결정 전에는 연료 기능을 추가하지 않는다.

## 4. 코어 루프

숨은 단계의 낮·밤 반복 → 파밍·제작·수리와 비밀 투표(한 판 플레이어당 2회) → 수리도 100% 후 60초 점화 의식 → 시민 승리, 기한(N일차 밤) 종료에 따른 마피아 승리, 또는 확인에 성공한 마피아의 소환 후 최후 전투.

최후 전투에서는 낮밤 구분이 사라지고 날씨가 해제되지 않는 심연으로 고정된다. 시민이 등대를 지키며 수리를 끝내고 점화하면 승리한다(투표 조건 없음). 등대 내구도 0이나 기한 종료는 마피아 승리다. 괴물의 힘은 심해 게이지 − 봉인이다.

## 5. 시스템 연결

| 시스템 | 연결되는 기능 |
|---|---|
| 플레이어·배 | 이동·승하선·파도 흔들림·내구도·난파·조명탄·구조·직군 능력 |
| 자원·제작 | 개인 인벤토리·작업대 투입/인출 기록·배/등대 모듈·모듈 부식과 표류 회수 |
| 등대 | 수리도·구간 보상·점화 의식·최후 전투 내구도 |
| 마피아·투표 | 비밀 정보·투표 2회 제한·정체 확인·숨은 방해·심해 게이지·봉인 |
| 월드 | 낮밤·일차·비율 해금·랜덤 섬·특수 기능 섬·유령선·환영 섬·몬스터 스포너 |
| 날씨·바다 | 날씨 5종(최후 전투 전용 심연 포함)·구름형 안개·폭풍벽·파도 충격·토네이도 |

## 6. 범위와 우선순위

v4 12장의 필수 기능은 유령선, 특수 기능 섬 3종, 최후 전투 전용 날씨, 부식 모듈 표류·회수다. 토네이도는 일반 우선순위, 거대 파도는 여유 우선순위이며 일정이 모자라면 가장 먼저 빠진다. 해상 인양은 v4에 없으므로 범위에 넣지 않는다. 직군 세부·모듈·레시피·구조 비용 등은 v4의 가안·미정 표기를 따른다. 일수·낮밤 길이·귀항 알림·해금 비율은 설정값 한 곳에서 바꾸며 기본값은 5일, 낮 5분·밤 2분이다. 이 문서에서 수치·직군·기능 범위를 새로 확정하지 않는다.

## 7. 팀과 통합 책임

기능별 담당자·계정·코드 경계는 [담당표](CODE_OWNERSHIP.md)를 따른다. v4 12장에 따라 네트워크 전담 역할은 없고 각 담당자가 자기 기능의 서버 동기화까지 맡는다. 김지훈이 공용 접속과 4인 테스트를 리드한다. 시스템&UI는 최명기가 맡는다. 김민성은 다른 팀에서 온 일시 AX 지원만 맡는다. 작업별 수정할 씬·파일 범위는 [작업 브리프](ai/02_TASK_BRIEF_TEMPLATE.md)에 적고 공유 씬은 동시에 저장하지 않는다.

## 8. 품질과 일정

기존 플레이어 코드와 맵 계약의 파일 상태는 [아키텍처](04-architecture.md), 작업별 검증 조건은 [구현 로드맵](05-implementation-roadmap.md)에 기록한다. 단독 플레이와 호스트·원격 클라이언트 검증을 구별한다. v4 일정은 정기 4인 테스트 10/13·10/16·10/21·10/24·10/26~27, 기능 동결 10/25, 최종 마감 11/1, 마일스톤 M01~M09다. 원본 일정이며 달성 여부는 검증된 사실이 아니다.
