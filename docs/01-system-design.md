# 등대 시스템 개요

> 버전 안내(2026-10-10): 이 문서는 v4 수령 전에 작성됐고 보이스(V01)·난파/구조(V04)·일수(V06)·일정(V08)·연료(V09) 서술은 v4 기준으로 갱신했다. 투표 횟수(V02)·심해 게이지(V03)의 수치는 이 문서에 없으므로 v4를 직접 본다. 규칙 우선순위는 최신 사용자 결정 → 제공된 v4이며 02 문서는 v4 이전 참고 자료다. 관련 작업 전 [제공된 v4](design/references/game-design-v4.md)와 [설계 문제 대장 V01~V10](07-design-issue-register.md#2-기존-문서와-달라진-규칙)을 먼저 대조한다. 원문의 미정은 임의 확정하지 않는다.

## 1. 프로젝트 정의

PC 3인칭 4인 호스트-클라이언트 마피아 게임이다. 네 명 모두 직군을 가지며 한 명이 마피아를 겸한다. 시민 셋은 메인 등대 활성화를, 마피아는 활성화 저지를 목표로 한다. 한 판 길이는 30~40분이다.

## 2. 경험의 중심

- 각자 배로 섬을 오가며 자원을 모으고, 작업대에서 모듈을 만들어 개인 배와 공유 등대에 장착한다.
- 바다 몬스터·밤·날씨가 파밍을 방해한다. 행동과 이동 경로가 추리 단서가 된다.
- 마피아의 우선 목표는 정체를 숨기는 것이다. 괴물 소환은 마지막 한 수다.
- 배는 난파되지만 플레이어는 죽지 않는다. 행동 불능이 되며 동료 구조 또는 자동 구조(가까운 섬으로 떠밀려 복귀)로 돌아온다([V04](07-design-issue-register.md#2-기존-문서와-달라진-규칙)). '수영 없음'은 02 기준이며 v4에는 명시가 없다.

## 3. 배경과 범위

중앙 등대 섬과 무작위로 배치되는 자원 섬·난파선·해역이 무대다. 일차에 따라 해역이 확장된다. 메인 등대 하나를 사용하며 보조 등대는 제외되어 있다. 연료는 구규칙(10/8)에서 제외였으나 v4 4.4·8.3에 다시 나타나므로 버전 충돌 확인이 필요하다([V09](07-design-issue-register.md#2-기존-문서와-달라진-규칙)).

## 4. 코어 루프

숨은 단계의 낮·밤 반복 → 파밍·제작·수리와 비밀 투표 → 수리도 100% 후 점화 의식 → 시민 승리, 기한 종료에 따른 마피아 승리 또는 소환 후 최후 전투.

최후 전투에서는 시민이 등대를 수리한 뒤 점화하면 승리한다. 등대 파괴나 기한 종료는 마피아 승리다. 상세 조건과 수치는 [게임 기획서](design/references/game-design-v4.md)에서 관리한다.

## 5. 시스템 연결

| 시스템 | 연결되는 기능 |
|---|---|
| 플레이어·배 | 이동·승하선·난파·구조·직군 능력 |
| 자원·제작 | 개인 인벤토리·작업대·배/등대 모듈 |
| 등대 | 수리도·보상·점화·최후 전투 내구도 |
| 마피아·투표 | 비밀 정보·정체 확인·방해·심해 게이지·봉인 |
| 월드 | 낮밤·일차·해역 확장·랜덤 섬·몬스터·날씨 |
| 보이스 | 인게임 보이스·배 무전은 v4에서 삭제됨([V01](07-design-issue-register.md#2-기존-문서와-달라진-규칙)). 밤 토론 수단은 결정 대기 |

## 6. 현재와 보류 범위

해상 인양은 02 §14 기준 플레이테스트 이후 검토할 보류 항목이며 v4에서는 확인되지 않는다(결정 필요). 직군 세부, 모듈·레시피와 구조 세부 등은 [v4](design/references/game-design-v4.md)의 가안·미정 표기를 따른다. 일수·하루 길이는 v4에서 조정 가능한 설정값(기본 5일, 낮 5분·밤 2분)이다([V06](07-design-issue-register.md#2-기존-문서와-달라진-규칙)). 이 문서에서 수치·직군·기능 범위를 새로 확정하지 않는다.

## 7. 팀과 통합 책임

기능별 담당자·계정·코드 경계는 [담당표](CODE_OWNERSHIP.md)를 따른다. 각 담당자가 자신의 서버·클라이언트를 함께 맡고 김지훈이 공용 접속과 4인 테스트를 리드한다. 김민성은 다른 팀에서 온 일시 AX 지원만 맡는다. 시스템&UI는 최명기가 기존 범위를 맡는다. 작업별 수정할 씬·파일 범위는 [작업 브리프](ai/02_TASK_BRIEF_TEMPLATE.md)에 적고 공유 씬은 동시에 저장하지 않는다.

## 8. 품질과 상태

기존 플레이어 코드와 맵 계약의 파일 상태는 [아키텍처](04-architecture.md), 작업별 검증 조건은 [구현 로드맵](05-implementation-roadmap.md)에 기록한다. 단독 플레이와 호스트·원격 클라이언트 검증을 구별한다. 일정은 v4의 기능 동결 10/25·최종 마감 11/1 등 [V08](07-design-issue-register.md#2-기존-문서와-달라진-규칙)을 따른다. 이는 원본 일정이며 달성 여부는 검증된 사실이 아니다.
