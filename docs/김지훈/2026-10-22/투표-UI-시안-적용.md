## 요청과 목표

사용자가 준 투명 PNG 시안 3장(투표창, 인게임 투표창 열기 버튼, 지목 확인창 부품)으로 실제 투표 UI를 구성한다. 규칙은 [승패·투표 결정 1절](../../design/win-vote-decisions.md)의 투표 전 확인창·마피아 동일 화면(2026-10-22)을 따른다.

## 진행 과정과 결정 이유

- 시안의 고정 문구(제목·부제·규칙 안내·"내 투표는 나에게만 보입니다"·ESC 닫기·버튼 글자)는 손글씨 느낌을 살리려고 스프라이트에 그대로 두었다. 이름·남은 횟수·내 지목·확인 질문처럼 바뀌는 값은 실시간 텍스트로 그린다.
- 인게임 버튼 시안의 "남은 지목 2/2·내 지목 없음" 글자는 패널 색으로 지우고 실시간 텍스트를 올렸다.
- 카드 틀(흰색·노란색)은 안쪽을 비워 9-slice로 썼다. 숫자 배지도 비우고 1~3 숫자를 텍스트로 넣었으며, 숫자 키 1~3으로도 카드를 고를 수 있다.
- 확인창은 시안 3의 갈색 판·지목 확인 제목·취소/지목 확정 버튼(평소·마우스 오버 두 모양을 스프라이트 교체)·고개를 내민 선원으로 조립했다.
- 열기 키는 시안에 없어서 V로 정했다. HUD 왼쪽 위에 키캡을 붙였다. 위치는 상호작용 안내와 겹치지 않게 오른쪽 아래로 두었다.
- 규칙 처리는 시험 패널(`TowerTrialPanel.DrawVotes`)과 같다. 같은 대상은 확인창 없이 안내만 하고, 남은 횟수가 0이면 "남은 지목 기회가 없습니다"만 안내한다. 확인창을 연 사이 잠기거나 서버가 거절하면 창을 닫고 사유를 알린다.
- 마피아 판별은 런타임 신호만 쓴다. 정체 확인 상태(`HasOwnIdentityState`)는 마피아에게만 오므로 이것으로 판별하고, 정체 확인이 없는 판에서는 첫 `MafiaCannotVote` 응답 뒤 가짜 상태로 전환한다. 마피아의 지목은 서버로 보내지 않는다.
- 투표 컨트롤러는 씬 네트워크 오브젝트이므로 Mirror가 생성 전까지 비활성으로 둔다. 연결이 비어 있으면 비활성 객체까지 찾도록 했다.
- 2026-10-22 후속: 사용자가 배경이 있는 투표창 시안(4번째 이미지)을 줬다. 배치·크기는 유지하라는 요청이라 레이아웃은 그대로 두었다. 4번째 이미지에서 내용을 지운 갈색 판(`vt_window_board`, 안쪽은 깨끗한 구간을 거울 반복해 채움, 9-slice로 ESC까지 덮음)을 깔았다. 같은 이미지에서 남은 투표 테두리 상자·체크 표시·노란 [현재 지목]/외곽선 [지목하기] 버튼·크림색 카드 틀·배지를 밝기 기반 투명 처리로 잘라 교체했다. 지목 중인 카드에만 체크 표시를 켠다(`VoteCandidateCard._check`).
- 담당: `07.Mafia/`는 박태욱 담당이다. 기존 투표 코드는 바꾸지 않았고 `Voting/View`·`Voting/Editor`에 새 파일만 추가했다. 2026-10-22 사용자가 박태욱과 김지훈 제작으로 협의했다고 확인했다.

## 실제 검증

- Unity 컴파일 오류 0(기존 `BoatController` 경고 1개만 있음).
- 빌더 실행으로 프리팹을 생성했다(배경 추가 후 재생성, JH04TestScene 인스턴스의 `Voting` 연결 유지 확인). 임시 씬에서 투표창·확인창·HUD를 1920×1080으로 렌더링해 육안으로 확인했다: [투표창](images/vote-ui-window.png), [확인창](images/vote-ui-confirm.png), [HUD](images/vote-ui-hud.png).
- 미검증: 플레이 동작 전부. 혼자 시험하는 판에서는 투표가 꺼지므로 M0로는 확인할 수 없다. 2인 이상 M2에서 열기·지목·확인·잠금·마피아 가짜 횟수를 확인해야 한다.
