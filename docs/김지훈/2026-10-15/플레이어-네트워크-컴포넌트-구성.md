# 플레이어 프리팹과 네트워크 컴포넌트 구성 정리

작성일: 2026-10-15
담당: 김지훈
상태: 설명 문서(코드·프리팹 수정 없음). 현재 작업 트리의 프리팹 YAML과 C# 코드를 직접 읽고 정리했다. 에디터 실행·플레이 확인은 하지 않았다

---

## 1. 결론

- **넷 오브젝트** = `NetworkIdentity`가 붙어 있고 서버가 스폰한(또는 씬에 미리 놓인) GameObject다. 미러는 이 오브젝트 단위로 "누가 주인인지", "어느 클라이언트에 보일지", "어떤 값을 동기화할지"를 관리한다. 프로젝트 문서에 따로 정의된 용어는 없고, 이 문서에서는 미러 정의를 그대로 쓴다.
- `NetworkIdentity`는 **미러 기본 컴포넌트**, `NetworkActor`는 **미러 기본이 아니라 우리 프로젝트 컴포넌트**다(`Assets/01.Scripts/01.Network/Connections/Net/NetworkActor.cs`, 김지훈 담당). 미러에는 같은 이름의 컴포넌트가 없다.
- 실제 플레이어(`tech.prefab`)의 루트에는 컴포넌트 14개가 붙어 있다(Transform 제외): 유니티 기본 4개(Rigidbody·CapsuleCollider·Animator·PlayerInput), 미러 3개(NetworkIdentity·NetworkTransformReliable·NetworkAnimator), 프로젝트 7개(NetworkActor·PlayerController·PlayerMotor·PlayerInputReader·PlayerAbilityRunner·PlayerCamera·PlayerAnimationDriver).
- 플레이어 프리팹은 지금 씬마다 다르다(§3). 상호작용 컴포넌트(`InteractionRelay`·`InteractionSelector`·`PlayerInteractionInput`)는 **아직 실제 플레이어 프리팹에 붙어 있지 않다**(최명기 부착 대기, JH02 인수인계).

## 2. 넷 오브젝트의 정의와 구성 요소

### 2.1 정의

| 조건 | 설명 |
|---|---|
| `NetworkIdentity` 1개 | 루트에 하나. 네트워크 ID(`netId`)와 주인(owner) 정보를 가진다. 없으면 미러가 그 오브젝트를 모른다 |
| 서버가 생성 | 프리팹은 `NetworkServer.Spawn` 또는 플레이어라면 `NetworkServer.AddPlayerForConnection`으로 스폰해야 클라이언트에 생긴다. 씬에 미리 놓인 것은 `sceneId`로 서버 시작 시 함께 활성화된다 |
| 등록된 프리팹 | 런타임 스폰 프리팹은 NetworkManager의 `playerPrefab` 또는 `spawnPrefabs`에 등록해야 클라이언트가 같은 프리팹을 찾아 만든다(`_assetId`로 매칭) |
| `NetworkBehaviour` 0개 이상 | 동기화 값(SyncVar)·원격 호출(Command·Rpc)을 쓰는 스크립트. 같은 오브젝트(또는 자식)의 `NetworkIdentity`에 묶인다 |

### 2.2 넷 오브젝트를 이루는 컴포넌트 역할

| 역할 | 컴포넌트 | 하는 일 |
|---|---|---|
| 신원 | `NetworkIdentity`(미러) | netId, 주인 연결(`connectionToClient`), 보임 범위(`visibility`), 서버 전용 여부(`serverOnly`) 관리 |
| 위치 동기화 | `NetworkTransformReliable` / `NetworkTransformUnreliable`(미러) | 위치·회전(·크기)을 보간해서 전달. `syncDirection`으로 누가 보낼지 정한다 |
| 애니메이션 동기화 | `NetworkAnimator`(미러) | Animator 파라미터·트리거를 전달 |
| 상태·요청 | 우리가 만든 `NetworkBehaviour` | `[SyncVar]`(서버→클라 값), `[Command]`(주인 클라→서버 요청), `[ClientRpc]`/`[TargetRpc]`(서버→클라 호출) |
| 표현·입력 | 일반 `MonoBehaviour` | 네트워크와 무관한 로컬 처리. 단, 로컬 플레이어에서만 켜지도록 `NetworkBehaviour`가 제어한다 |

### 2.3 꼭 알아야 할 미러 개념

| 개념 | 뜻 | 코드에서 보는 곳 |
|---|---|---|
| `isServer` | 이 코드가 서버(리슨 호스트 포함)에서 돌고 있음 | 판정·SyncVar 쓰기 |
| `isClient` | 클라이언트(호스트도 클라이언트이기도 함) | 표현 |
| `isLocalPlayer` | 이 PC 사람이 조종하는 **자기 플레이어** 오브젝트 | 입력·카메라 켜기 |
| `isOwned` | 이 클라이언트가 주인인 오브젝트(자기 플레이어, 자기 배) | Command 보내기 |
| 리슨 호스트 | 호스트 PC는 서버이면서 클라이언트. `isServer`와 `isLocalPlayer`가 동시에 true일 수 있다 | 4인 = 호스트 1 + 원격 3 |
| `[SyncVar]` | 서버에서 바꾸면 클라이언트로 전달. **클라이언트에서 바꾸면 전달되지 않는다** | `PlayerController._isDowned` |
| `[Command]` | 주인 클라이언트만 보낼 수 있다(미러가 강제). 서버는 보낸 연결을 안다 | `InteractionRelay`, `LobbyPlayer` |
| `syncDirection` | `ServerToClient`(0, 기본) 또는 `ClientToServer`(1) | 이동은 1(§4) |

### 2.4 스폰 콜백 순서(플레이어 기준)

`Awake` → `OnStartServer`(서버만) → `OnStartClient`(클라이언트) → `OnStartLocalPlayer`(자기 플레이어만) → `Start`. 해제는 `OnStopLocalPlayer` → `OnStopClient` → `OnStopServer`.
`PlayerController`는 이 콜백마다 `RefreshLocalControl()`을 불러 입력을 로컬 플레이어에게만 켜고, `OnStartLocalPlayer`에서 카메라를 붙인다(`PlayerController.cs:292-322`).

## 4. 실제 플레이어(`tech.prefab`) 컴포넌트

루트 오브젝트 기준. 자식은 `Armature`(mixamo 뼈대), 모델 메시(SkinnedMeshRenderer), `CameraPivot`/`Camera`(카메라 앵커)다.

### 4.1 유니티·패키지 기본

| 컴포넌트 | 목적 | 설정 메모 |
|---|---|---|
| `Rigidbody` | 물리 이동. `PlayerMotor`가 속도를 직접 넣는다 | 원격 플레이어는 `isKinematic = true`로 바뀐다(`RefreshLocalControl`) |
| `CapsuleCollider` | 몸 충돌, 접지 검사 기준 | |
| `Animator` | 캐릭터 애니메이션 | |
| `PlayerInput`(Input System) | `InputSystem_Actions`의 `PlayerActions` 맵을 읽어 `SendMessages` 방식으로 `OnMove` 등을 호출 | 로컬 플레이어만 enabled |

### 4.2 미러 기본

| 컴포넌트 | 목적 | 설정 |
|---|---|---|
| `NetworkIdentity` | 넷 오브젝트 신원 | `serverOnly: 0`, `visibility: Default`, 런타임 스폰이라 `sceneId: 0` |
| `NetworkTransformReliable` | 위치·회전 동기화 | `syncDirection: ClientToServer`, 위치·회전 O / 크기 X, `coordinateSpace: Local`. **이동 권위 = 소유 클라이언트**(N07 결정, `NETWORK_AUTHORITY.md §4`) |
| `NetworkAnimator` | 애니메이션 동기화 | `syncDirection: ClientToServer`, `clientAuthority: 1` |

배에 타면 `PlayerController`가 플레이어의 NetworkTransform을 끄고 배 위치를 따른다(`PlayerController.cs:364-368`, 내리면 복구).

### 4.3 프로젝트 컴포넌트

| 컴포넌트 | 종류 | 담당 | 목적 |
|---|---|---|---|
| `NetworkActor` | NetworkBehaviour | 김지훈 | **"이 오브젝트가 몇 번 참가자인가"** 표시. `[SyncVar] _actorId`. 서버가 스폰 전에 `AssignActorId`로 넣는다 |
| `PlayerController` | NetworkBehaviour | 최명기 | 중심 조율자. 상태기계(`PlayerHFSM`), 입력→이동·점프·능력, 배 승하선, 난파(`[SyncVar] _isDowned`), 소유 배(`[SyncVar] _ownedBoat`), 로컬 플레이어만 입력·카메라 활성화 |
| `PlayerMotor` | MonoBehaviour | 최명기 | Rigidbody 속도로 이동·회전·점프, 접지 검사 |
| `PlayerInputReader` | MonoBehaviour | 최명기 | `PlayerInput` 메시지를 받아 `MoveInput`·`LookInput`·`RunHeld` 값과 `InteractRequested` 등 이벤트로 바꿈 |
| `PlayerAbilityRunner` | MonoBehaviour | 최명기 | 직군 능력 하나를 실행·틱·취소. 실행 중 이동 보정값 제공 |
| `PlayerCamera` | MonoBehaviour | 최명기 | `Camera.main`을 플레이어 앵커에 붙이고 상하 시점 처리. 로컬 플레이어에서만 `Attach` |
| `PlayerAnimationDriver` | MonoBehaviour | 최명기 | 상태기계·능력 상태를 Animator 파라미터로 반영 |

`PlayerController`는 `[RequireComponent(PlayerInputReader, PlayerMotor, PlayerAbilityRunner)]`라서 이 셋은 빠질 수 없다.

## 6. NetworkActor 자세히

### 6.1 왜 있나

미러의 `connectionId`는 **연결** 번호라 재접속하면 바뀐다. 게임 규칙(투표, 상호작용 송신자, 승패)은 "**어떤 사람**인가"가 필요하다. 그래서 서버가 사람마다 `ActorId`(1부터, 0은 무효)를 발급해 연결과 분리했다.

| 구분 | `NetworkIdentity.netId` | `connectionId` | `NetworkActor.ActorId` |
|---|---|---|---|
| 무엇의 번호 | 넷 오브젝트 | 연결 | 참가자(사람) |
| 누가 붙임 | 미러 | 미러 | 우리 서버(`ConnectionDirectory`) |
| 바뀌는 때 | 오브젝트 재스폰 | 재접속 | 재접속 정책에서 같은 사람에게 다시 묶을 수 있도록 설계 |
| 공개 여부 | 공개 | 서버 | 공개(역할은 절대 담지 않는다) |

### 6.2 흐름

1. 접속 → 서버 `ConnectionDirectory.Register(conn)`가 ActorId 발급(`ConnectionDirectory.cs`).
2. `OnServerAddPlayer` → 프리팹 생성 → `NetworkActor.AssignActorId(actorId)` → `NetworkServer.AddPlayerForConnection`(`LighthouseNetworkManager.cs:593-599`). 스폰 전에 넣어서 첫 스폰 데이터에 ActorId가 포함된다.
3. 로비 → 게임 씬 전환 때도 같은 ActorId로 `LobbyPlayer` → 게임 플레이어가 교체된다.
4. 다른 컴포넌트는 `GetComponent<NetworkActor>().ActorId`로 읽는다(`PlayerController.ActorID`, `InteractionRelay`).

### 6.3 규칙

- 모든 플레이어 프리팹 루트에 **반드시** 붙인다(`[DisallowMultipleComponent]`, 매니저가 검사).
- 서버는 요청 메시지에 들어 있는 ActorId를 믿지 않고, Command를 보낸 연결에서 ActorId를 다시 찾는다(JH01 위조 거부, `ActorIdProbe`로 시험).
- ActorId에 시민/마피아 같은 역할을 섞지 않는다.

## 9. 코드를 읽다가 본 주의점(실행 미확인)

| 항목 | 내용 | 담당 |
|---|---|---|
| 원격 클라이언트 난파 | `PlayerController.Update`는 로컬 입력 주인에서만 돌고, 배를 잃으면 `SetDowned(true)`를 부르는데, `SetDowned`는 서버가 아니면 아무것도 안 하고 돌아간다(`PlayerController.cs:494-507`). 호스트 플레이어는 난파되지만 **원격 플레이어는 난파 상태가 적용되지 않을 수 있다**. 서버로 보내는 Command 또는 서버 판정 경로 필요 여부 확인 필요 | 최명기 |
| 직군 프리팹 미완성 | §4.4 | 최명기 |
| `SandboxPlayer`에 NetworkActor 없음 | §5. 통합 씬에서 `LighthouseNetworkManager`와 같이 쓰면 스폰 실패 | 강민서 |
| NetworkTransform 종류 혼재 | 실제 플레이어는 Reliable, 시험 플레이어는 Unreliable. 통일 결정 없음 | 김지훈·최명기 |
