# 승리로 판 종료 시 선원 대기실 복귀

- 날짜: 2026-10-29
- 요청: 시민·마피아 승리로 판이 끝나면 같은 멤버 그대로 선원 대기실로 돌아가고, 준비 상태는 각자 해제.

## 기획 대조
- 정상 종료(승패 결정) 후 흐름은 기존 문서에 없었다. 결정 §8은 이탈·단절 종료만 다루며 "첫 화면으로, 로비 복귀 없음"이다. 이탈·단절 경로는 그대로 두고, 정상 종료만 로비 복귀로 추가. [승패·투표 결정 §8](../../design/win-vote-decisions.md)에 한 줄 반영.

## 수행
- `LighthouseNetworkManager.ReturnToLobby()`(서버): `InProgress`에서만 동작. 게임 플레이어마다 `ActorLeft`를 낸 뒤 제거(로딩 때 로비 플레이어 제거와 같은 방식) → phase `Lobby`, 역할·명단·닉네임 캐시·시작 게이트 초기화 → 상태 방송 → `ServerChangeScene(onlineScene)`.
  - 연결 명단(`ConnectionDirectory`)은 유지되어 actor id 유지. 클라이언트가 씬 변경 후 다시 AddPlayer → 새 `LobbyPlayer` 생성이라 준비는 false로 시작, 닉네임은 `LobbyPlayer.LocalNickname`으로 다시 전송.
  - 클라이언트는 `Lobby` 상태를 받으면 `OwnRole`을 None으로 초기화. `SessionScreen`은 phase로 로비 화면·커서를 이미 처리.
- `TowerMatchFlow`: 판 종료(`TowerMatchNet.Ended`) 시 세션 흐름이면 `_lobbyReturnAt`(SyncVar, NetworkTime) = 지금 + `_lobbyReturnSeconds`(기본 10초). 서버 `Update`에서 시간이 되면 `ReturnToLobby()`.
- `VictoryScreen`: 결과 화면 아래 "N초 후 선원 대기실로 돌아갑니다" 카운트다운(선택 필드 `_returnText`). 확인 버튼은 화면만 닫으며 복귀 시점은 바꾸지 않는다. 프리팹 재빌드.

## 검증
- Unity 컴파일 오류 0, 프리팹 재빌드, `JH04TestScene` 연결 확인(`_returnText` 포함).
- `Builds/JH04` 재빌드 성공(`JH04Offline`→`JH07Lobby`→`JH04TestScene`), 960×540 창 4개 실행(로그 `Builds/JH04/log1~4.txt`).
- 미실행: 실제 4인 플레이로 승리 → 10초 후 로비 복귀 → 준비 해제·같은 멤버·닉네임 유지 → 두 번째 판 정상 시작 확인.

## 위험·남은 일
- 두 번째 판에서 게임 씬 기능들의 정적 상태·서비스 등록(WorldServices 등)이 첫 판 값을 남기는지 미확인. 두 번째 판 시작이 핵심 확인 항목.
- 결과 화면이 떠 있는 동안(세션은 아직 InProgress) 누가 나가면 기존 규칙대로 전원 첫 화면으로 간다. 바꾸려면 결정 필요.
- 복귀 대기 시간 10초는 임시값.

## 후속: 확인 버튼으로 즉시 복귀(2026-10-29)
- 요청: 확인을 눌러도 10초를 다 기다린 뒤에야 대기실로 가던 것 → 각자 확인하면 대기실로. 누가 먼저 나가 방이 깨지는 경우 등 예외 처리.
- 제약: Mirror는 서버 씬을 전원이 공유해 한 명만 먼저 옮길 수 없다. 그래서 **첫 확인 때 서버가 전원을 옮기고, 아직 확인 안 한 사람은 결과 화면을 씬 전환 뒤에도 대기실 위에 유지**하는 방식으로 구현.
- `LighthouseNetworkManager`(서버)
  - `FinishMatch()`: 승패가 나면 `_isMatchFinished`. 이 상태(InProgress)에서 원격 참가자가 나가거나 끊기면 그 사람만 빠지고 `EndMatch`하지 않는다(`IsMatchInPlay`로 판정 통일). 호스트 나감은 방이 닫히므로 기존대로 전원 종료 알림.
  - `ReturnToLobbyMessage`(새 파일) + `RequestReturnToLobby()`(클라) → `HandleReturnToLobbyRequest`: 등록된 actor이고 나가기 요청 중이 아니면 `ReturnToLobby()`. 끝나지 않은 판·이미 로비·종료 중이면 거절되어 중복·늦은 확인은 무시.
  - `ReturnToLobby()`는 `_isMatchFinished`일 때만. 플래그는 로비 복귀·로딩 시작·서버 초기화 때 해제.
- `TowerMatchFlow`: 10초 타이머(`_lobbyReturnSeconds`, `_lobbyReturnAt` SyncVar, `Update`) 제거, 판 종료 시 `FinishMatch()`만 호출. 씬 YAML의 옛 `_lobbyReturnSeconds` 값은 남아도 무해.
- `VictoryScreen`: 확인(버튼·Enter) = 복귀 요청 + 닫기. 세션 흐름이면 열릴 때 `DontDestroyOnLoad`(씬 루트 확인). 로비 phase가 오면 정렬 순서를 600(세션 화면 500 위)으로 올리고 Esc를 막는 오버레이로 등록. 연결 끊김·로딩 시작·로비 없이 게임 씬이 사라짐이면 스스로 제거하고 게임 커서 잠금을 복원하지 않는다. 안내 문구는 "확인을 누르면 선원 대기실로 돌아갑니다".
- `SessionScreen`: 로비에서 Esc를 누를 때 파괴된 오버레이를 정리한 뒤 남은 오버레이가 있으면 나가기 확인창을 열지 않음.
- `VictoryScreenSetup`: 기본 문구만 갱신(프리팹은 재빌드 안 함, 런타임에서 문구를 덮어씀).

### 검증
- Unity 강제 새로고침·컴파일, 콘솔 `error CS` 0. `ReturnToLobbyMessage.cs.meta` 생성 확인.
- 미실행: 2~4인 플레이. 확인할 것 — ① 한 명 확인 → 전원 대기실, 나머지는 결과 화면 유지 → 각자 확인 시 닫힘·커서 자유 ② 결과 화면 중 원격 참가자 나가기·창 닫기 → 나머지 판 종료 알림 없이 정상 복귀 ③ 결과 화면 중(게임 씬·대기실 위 모두) 호스트 나가기 → 결과 화면이 사라지고 첫 화면 종료 알림이 보임 ④ 결과 화면이 남은 사람이 있으면 준비 불가로 다음 판이 시작되지 않음 ⑤ 두 번째 판 정상 시작.


## 커밋 분리 점검 (2026-10-29)
- 로비 복귀 후속 변경만 분리. 결과 확인 순서·원격/호스트 이탈·두 번째 판 시작은 다인 검증 대기.
- 이번 실행: 현재 diff·에셋/meta 짝·포함/제외 범위 점검, Unity MCP 콘솔 오류 0건 확인. 기존 컴파일·빌드·렌더 기록과 구분하며 이번에는 빌드·다인 플레이를 실행하지 않음.
- 씬·프리팹의 공백 경고는 Unity 직렬화 출력에 한정됨. YAML 직접 수정 없이 보존.
