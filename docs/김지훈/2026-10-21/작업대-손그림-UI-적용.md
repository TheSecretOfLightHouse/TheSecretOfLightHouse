# 작업대 손그림 시안 UI 적용

작성자: 김지훈
작성일: 2026-10-21
갱신일: 2026-10-21
상태: 검증 대기(M0 통과, M2 미실행)
브랜치·기준 커밋: `feature/jihun`, `5a8a4f3`

## 요청과 목표

사용자가 Unity MCP 연결 후 첨부한 [손그림 시안](images/workbench-sketch-reference.png)을 다시 잘라 작업대 Canvas를 구성하고 기존 기능을 연결해 달라고 요청했다. CRT 시안과 다른 신규 UI 적용 작업이다.

## 진행 과정과 결정 이유

- 2026-10-21: 담당자를 김지훈으로 확인하고 pointer → 모듈 운반 구현 원문과 관련 기록을 읽었다. 시작 시 JH04TestScene·pointer 수정, `.vscode/`·CRT 문서·이미지가 이미 존재했으며 이 변경을 보존했다. 작업 중 추가된 등대 설치·목재 소품 시안 기록도 별개 작업으로 유지했다.
- `review-design-code-gaps`로 W03·W08·R22와 최신 모듈 결정을 실제 코드와 대조했다. 레시피 선택은 로컬, 투입·제작·가져가기·반환은 기존 Relay 요청, 진행·보관 수량은 공개, 인벤토리 모듈은 `OwnCarriedRecipe`만 사용한다. 미승인 재기획안·레시피 수치·서버 판정·정식 인벤토리·배 프리팹을 변경하지 않았다.
- 연결된 로컬 Unity MCP에서 프로젝트·Unity 6000.0.83f1·현재 씬·Play 상태를 확인했다. Unity API로 스프라이트 임포트·프리팹 생성·씬 연결·저장을 수행했으며 YAML을 직접 편집하지 않았다.
- 사용자 이미지에서 판·슬롯·버튼·게이지·키 틀 9개와 투명 아이콘 11개를 추출했다. 글자·배경 장면을 제거하고 9-slice 틀로 임포트했다. 기존 레시피·자원 에셋 대신 새 화면의 아이콘 매핑을 사용한다.
- 새 `WorkbenchScreen_Sketch`를 왼쪽 레시피 목록, 가운데 큰 모듈 아이콘·재료 선택·총 투입 진행도·공통 투입/제작 버튼, 오른쪽 6칸 선반·페이지·가져가기/반환, 아래 본인 모듈 슬롯·반환 바로가기로 구성했다. 원본 비율 1672×941 기준 CanvasScaler를 사용한다.
- E는 선택 재료 1개 투입 또는 선택 선반 모듈 가져가기, F는 열린 화면에서 제작, G는 반환, Esc는 닫기로 연결했다. 선반 6칸에는 페이지를 두어 등대 4종+배 4종 모두 접근할 수 있다. 부족 재료 수량은 빨간색이다.
- JH04TestScene의 기존 두 화면은 비활성화하고 새 화면에 작업대·상호작용 대상을 연결했다. `TowerTrialPanel._isRackMode`를 직렬화하고 이 씬에서만 false로 저장해 화면 모드를 기본으로 했다. 기존 다른 씬의 기본값은 true다.
- 독립 검수에서 레시피 카드의 raycast 누락을 발견해 수정했다. 빌더는 별도 임시 additive 씬에서 실행하고 원래 씬을 복원해 활성 씬에 임시 생성물·dirty 상태를 남기지 않도록 했다.
- 실제 입력 검증에서 작업대 Esc와 세션 Esc가 동시에 처리되어 판 나가기 Dialog의 Dim이 선반 클릭을 막는 것을 재현했다. 김지훈 담당 `SessionScreen`에 로컬 오버레이의 Esc 예약 API를 추가하고 작업대 Open/Close에 연결했다. 열린 동안과 닫는 프레임에는 세션 Esc를 무시하며 다음 별도 Esc의 판 나가기 동작은 유지한다.
- Canvas에 맞지 않는 기존 상태 배지는 새 프리팹에서 투명하게 하고, 재료 수량과 겹치던 작은 보유량 글자는 숨겼다. 다른 화면은 기존 표현을 유지한다.

[실제 런타임 화면](images/workbench-sketch-runtime.png). 선반 페이지 시험용 보관 상태이며 최종 캡처 직전에 OnGUI를 가진 개발/네트워크 컴포넌트를 일시 비활성화했다. 이는 검증 후 캡처용 처리이며 프리팹·씬·외부 코드에 저장하지 않았다. 캡처 후 Play를 종료해 시험 자원·보관 상태를 폐기했다.

독립 정적 검수에서 raycast 누락 수정, 기존 화면 기본값 호환, 소유 경계, 서버 계약 유지와 Esc 실행 순서 두 경우를 확인했다. 런타임 입력은 자동 주입 검증이며 사람의 실제 키보드·마우스 조작이나 M2를 대신하지 않는다.

## 시안 정렬 보정(2026-10-21)

사용자가 JH04 화면이 시안과 배치·글자 크기·아이콘·틀 위치가 다르다고 지적해 보정했다. 기능 범위·서버 계약은 바꾸지 않았다.

- 원인 확인: 프리팹을 시안 위에 겹쳐 렌더해 비교했다. 큰 틀 좌표는 시안과 거의 같았고, 차이는 레시피 목록 넘침(제목 28·카드 64로 마지막 카드 잘림), 버튼 글자 best fit 최대 26으로 틀을 꽉 채움, 시안에 없는 Esc 닫기 버튼·안내문 두 줄·"인벤토리 모듈" 캡션·"반환" 글자, CanvasScaler 0.5 혼합으로 16:10에서 비율이 커지는 점이었다.
- 빌더 `WorkbenchScreenSketchSetup` 수정 후 메뉴 함수로 프리팹 재생성·JH04TestScene 재연결·저장: 목록 제목 22·카드 61·간격 5(시안 측정값), 큰 아이콘·제목 24, 재료 수량 23, 버튼 글자 21/17(best fit은 줄이기만), 키 글자 19, 선반 제목 24, 페이지 화살표 축소, 안내문·Esc 버튼·캡션 제거, 반환 바로가기는 G 키만 있는 빈 칸, CanvasScaler Expand. 밝은 하늘에서 안 보이던 목록 제목·메시지에 어두운 외곽선.
- `WorkbenchScreen.cs`: `_progressHint`를 선택 항목으로(없으면 건너뜀), 시안 화면은 기본 안내 문구 대신 빈 메시지. 요청 결과 메시지는 그대로 표시한다. 다른 프리팹 동작은 그대로다.
- 시안과 다르게 남긴 것: 선반 페이지 화살표(6칸에 8종을 보여야 함), 시안 하단 첫 칸의 F 키(F는 제작 키라 혼동), 문구는 한국어.

## 남은 일과 차단 조건

- 원격 클라이언트에서 UI·공유 수량·본인 모듈 비공개를 M2로 확인해야 한다. 이번 작업은 M0까지다.
- 기존 `IsCapped`는 보관 수량만 보며 서버는 전체 모듈 장부를 본다. 장착/운반 등으로 서버 전체 상한에 닿은 경우 UI 투입 버튼이 가능해 보여도 기존 서버 거절 메시지를 받을 수 있다. 이번 시안 작업에서 서버/공개 계약을 확대하지 않았다.
- 배 프리팹 장착·난파 처리·정식 인벤토리 UI·등대 설치 화면은 이번 범위 밖이다.
