# 등대 설치 UI 적용

갱신일: 2026-10-21
상태: 검증 대기(M0 통과, M2·사용자 직접 조작 미실행)
브랜치·기준 커밋: `feature/jihun`, `b735247`(develop 최신화 후 커밋)

## 요청과 목표

[등대 설치 UI 시안 v3](등대-설치-UI-시안.md)대로 등대 장착 화면을 Unity Canvas로 만든다. 사용자 결정(2026-10-21):

- 작업대처럼 범위 안에서 **E로 연다**. 열린 화면에서 F는 장착, Esc는 닫기다.
- 빈손이면 들고 있는 모듈 칸을 비운다. 빈손, 배 모듈을 든 경우, 맞는 칸이 아직 잠긴 경우 모두 장착 버튼을 노란색 대신 **누를 수 없는 표시**로 바꾼다.
- 기존 8칸 시험 배치(`TowerLayout_JH04Trial`)를 쓴다. 「시험 점등」 제안은 반영하지 않는다.
- 표시 언어는 한국어다(등실·3층·2층·1층, 들고 있는 모듈, 장착, 닫기, 여기).

## 진행 과정과 결정 이유

- 기획·코드 대조: 장착 판정과 동기화는 이미 있다. 장착 여부 SyncList와 `Changed`, 아래층 우선 `IsFloorOpen`, 모든 PC에서 같은 결과를 내는 `FindOpenSlot`, 본인에게만 오는 `OwnCarriedRecipe`, 서버 `InstallModule` 처리를 확인했다. 따라서 View만 새로 만들었다. 대장 V11(층별 배치·환산 미정)은 바꾸지 않았다.
- 시안의 "here" 칸은 `FindOpenSlot(들고 있는 레시피)`의 답을 그대로 쓴다. 칸은 서버가 고르므로 화면은 예측만 표시한다.
- 장착 가능 여부는 `FindOpenSlot >= 0`을 조건으로 판단한다. 빈손(0), 배 모듈(배치에 없음), 잠긴 층의 모듈은 모두 -1이라 조건 하나로 세 경우를 처리한다.
- (후속에서 대체) 작업대(F 열기)와 등대(E 열기)의 범위가 JH04 씬에서 겹친다(작업대 (0,0.5,3) 반경 3, 등대 (4,0,3) 반경 3.5). 한 화면이 열려 있는 동안 다른 화면이 같은 키로 열리면 안 된다. 그래서 `SessionScreen.IsGameplayOverlayOpen`을 추가하고 두 화면 모두 이 값이 참이면 열기와 안내 표시를 막았다. 겹치는 곳에서는 두 안내가 위아래로 쌓이도록 등대 안내를 한 줄 위(146)에 두었다.
- 스프라이트는 작업대 스케치 세트(`WorkbenchUiSketch`)를 재사용했다. 시안에만 있는 등대 실루엣·자물쇠·여기 화살표·층 구분선 4장은 같은 톤(갈흑 `#261F17`, 미색 `#F6E9D2`, 노랑)으로 PIL에서 새로 그렸다.
- 프리팹은 작업대 스케치와 같은 방식으로 에디터 메뉴가 코드로 만든다(시안 픽셀 좌표 1672×941 기준, Expand 스케일). 칸과 층 행은 배치 에셋에서 읽어 만든다.

## 남은 일과 차단 조건

- 개발용 IMGUI 패널(판 진행·등대·작업대 시험 패널)이 화면 위에 겹친다. 기존 시험 도구이며 이번 범위에서는 손대지 않았다.
- 장착 마감(`_isInstallOpen`)은 서버에만 있어서, 마감 뒤에도 클라이언트 버튼은 노랗게 보일 수 있다. 이때 누르면 서버가 거절하고 화면에 거절 문구가 나온다.
- 실제 판에서 프레임 아이콘은 `_recipeIcons` 매핑에 따라 새장 모양이 쓰인다. 레시피 에셋 자체의 아이콘은 상자 모양이다.

## 후속: 작업대도 E로 통일, 동시 표시 금지(2026-10-21)

사용자 결정: 작업대도 등대처럼 E로 연다. 두 화면의 안내와 열림이 동시에 나오면 안 된다.

- 신규 `04.Lighthouse/Stations/View/IStationScreen.cs`·`StationScreenFocus.cs`(`Lighthouse.Stations.View`): 범위가 겹치면 가장 가까운 시설 하나만 안내를 띄우고 E를 받는다. 거리가 같으면 먼저 등록된 쪽이 받는다. 각 화면이 직접 계산하므로 Update 순서와 상관없다.
- `WorkbenchScreen`·`TowerScreen`: `IStationScreen`을 구현하고 안내·열기 조건에 `IsNearest`를 더했다. 작업대 `_openKey` 기본값은 E로 바꿨다.
- 작업대 화면 프리팹 3개(`WorkbenchScreen`·`_Sketch`·`_Wood`)의 `_openKey`를 E로 바꾸고 안내 문구의 키 글자만 E로 바꿨다(에디터 `PrefabUtility`). 재직렬화로 기존 미커밋 스크립트 필드(`_selection` 등) 줄도 함께 기록됐다. 스케치 빌더의 안내 문구도 E로 바꿨다. 등대 안내는 한 줄만 뜨므로 원래 위치(90)로 되돌렸다.
- 발견: 플레이어의 Interact(E, `PlayerInteractionInput`)가 가장 가까운 대상의 기본 행동을 함께 보내, 작업대는 Deposit, 등대는 InstallModule이 빈 인자로 거절되고 있었다. JH04TestScene의 작업대(프리팹 인스턴스 오버라이드)·등대 `InteractionTarget._defaultAction`을 None으로 바꿨다. 선택기는 기본 행동을 지원하지 않는 대상을 고르지 않으므로 이제 E는 화면만 연다. JH03TestScene 작업대는 바꾸지 않았다.

| 항목 | 방식 | 결과 | 판정 |
|---|---|---|---|
| 컴파일 | Unity 강제 새로 고침 | 오류·경고 0 | 통과 |
| 등대가 더 가까움 (2,0,2.5) | 호스트 1인, Game 뷰 포커스 후 E 이벤트 | 안내 "E 등대 열기"만 표시, E로 등대만 열림 | M0 통과 |
| 작업대가 더 가까움 (1.5,0,3) | 같은 방식 | 안내 "E 작업대 열기"만 표시, E로 작업대만 열림, 열자마자 거절 문구 없음 | M0 통과 |
| 거절 요청 제거 | 결과 수신 이벤트 탐침 | 두 번의 E 열기에서 서버 요청·결과 0건 | M0 통과 |
| 작업대 안 E(투입) | 작업대 열린 상태에서 E | "기반 프레임에 자원을 넣었습니다.", 등대 안 열림 | M0 통과 |

검증 메모: Game 뷰에 포커스가 없을 때 주입한 키는 플레이어 프레임에서 `wasPressedThisFrame`으로 잡히지 않았다. Game 뷰를 캡처해 포커스를 준 뒤 다시 실행했다. 컴파일 직후 도메인 리로드로 플레이가 한 번 저절로 종료된 적이 있으며 코드와는 관계없다.
