# 모듈 운반 구현 — 작업대 → 손 → 등대·배 장착

작성일: 2026-10-21  
담당: 김지훈  
근거: [모듈 운반과 난파·구조 결정](../../design/lighthouse-module-decisions.md#모듈-운반과-난파구조-2026-10-20-결정), [배 모듈 기획](../../design/boat-module-decisions.md) 9절, 2026-10-21 사용자 결정.

## 사용자 결정 (2026-10-21)

- 배에 장착한 모듈은 난파 시 **전부 소실**(배 모듈 기획·기존 코드 유지). 10-20 결정의 "난파해도 배에 남는다"는 폐기.
- 김지훈 범위는 서버·계약과 시험 UI. 모듈 효과, 정식 인벤토리 화면, 배 장착 입력은 최명기.
- 등대 장착 칸은 자동(열린 칸 중 가장 낮은 칸).
- 배 레시피 ID는 101~104로 김지훈이 정함(등대 1~4와 겹치지 않게).

결정 이유:

- 보유 상태를 `WorkbenchNet`에 둔 이유: 씬 YAML을 고치지 않고도 기존 UI(등대·작업대 화면)가 이미 참조하는 객체이기 때문이다. 모듈 처리기는 씬에서 참조가 없다.
- 보유자 비공개(2026-10-21 사용자 결정): 처음엔 모두에게 동기화했으나, 다른 사람이 든 모듈은 몰라야 한다는 결정으로 SyncDictionary를 지우고 본인 연결에만 TargetRpc로 보낸다. 화면에서만 숨기면 조작한 클라이언트가 볼 수 있기 때문이다.
- 배 장착 대상은 배 자체: 장착은 배 위에서 하므로 작업대 거리 검사를 쓸 수 없다. 대신 처리기가 꺼낸 작업대를 기억한다(`_carrySources`).
- 배 장착 실패 시 손 모듈 보존: 배 검사(소유·탑승·난파·종류 지원·중복)를 먼저 통과한 뒤에만 손에서 뺀다.

## 검증

- **실행함:** Unity 6000.0.83f1 배치 모드 컴파일(에디터 꺼진 상태). `Lighthouse.Runtime.dll`·`Lighthouse.Workbench.Editor.dll` 재빌드, 컴파일 오류 0, 종료 코드 0.
- **보유자 비공개 변경분은 컴파일 미확인:** 변경 시점에 사용자가 Unity 에디터를 열어 두어 배치 모드 컴파일이 거절됨. 에디터가 다시 컴파일할 때 오류 확인 필요.
- **실행 안 함:** 설정 메뉴 실행, JH04 플레이(M0 자동 시험 포함), M2, 배 장착 실제 동작. 메뉴를 돌리기 전에는 작업대가 16·17을 허용하지 않아 꺼내기가 `ActionNotSupported`로 거절되고 JH04 자동 시험도 실패한다.

## 남은 일

1. Unity에서 JH04TestScene 열기 → `Lighthouse/Modules/Set Up Module Carry In Open Scene` → 씬 저장(사용자). 배 레시피 4종이 JH04 시험 카탈로그(`ModuleRecipeCatalog_JH04Trial`)에 들어간다. JH03 씬은 다른 카탈로그라 필요하면 따로 실행.
2. JH04 M0 자동 시험·1인 직접 조작(꺼내기 → 등대 장착 → 되돌리기).
3. 최명기 합의 후 Boat.prefab `InstallModule` 허용 → 배 장착·난파 소실 확인 → M2.
4. 확인 필요: 선반형 작업대(`WorkbenchRack`)는 레시피 수만큼 칸을 가로로 늘리므로 8개가 되면 폭이 두 배가 된다. 화면 UI는 카드가 자동으로 늘어난다. 화면 UI의 제작 상한 판정은 손에 든 모듈을 세지 않아(상한 있는 등대 레시피만 해당) 버튼이 켜져도 서버가 거절할 수 있다.
5. 미구현: 미구조 시 떨어지는 모듈 줍는 물건, 구조 시 랜덤 소실 연결(최명기 재스폰 처리와 함께).

## 작업대 화면 시안 반영 (2026-10-21, 이어서)

사용자가 ChatGPT로 만든 작업대 화면 시안을 주고 제작을 요청했다. 기존 Canvas 화면(`WorkbenchScreen.prefab`)이 시안과 같은 3열 배치라 새로 만들지 않고 차이만 더했다.

| 파일 | 변경 |
|---|---|
| `Workbench/View/WorkbenchScreen.cs` | 레시피 목록을 "등대 모듈"/"배 모듈" 섹션으로 정렬(제목은 템플릿 복제), 카드 둘째 줄에 장착 위치(등대 층은 `TowerLayout`에서 계산, 배는 "배 모듈"), 진행도 제목에 "(배 모듈)", 보관함 칸마다 가져가기(`TakeModule`), "들고 있는 모듈" 줄과 되돌려놓기(`ReturnModule`), 결과 문구 |
| `Workbench/View/WorkbenchItemSlot.cs` | 선택 필드 `_name`·`_actionButton`과 `SetAction(id, 켜짐, 콜백)` |
| `Workbench/Editor/WorkbenchScreenCarryLayout.cs`(신규) | 메뉴 `Lighthouse/Workbench/Apply Carry Layout To Screen Prefab`: 창 높이 800→960·패널 576→736, 레시피 목록을 스크롤 영역으로, 섹션 제목 템플릿, 들고 있는 모듈 줄·안내 문구, 보관함 칸(78×120)에 이름·가져가기 버튼, 화면 필드 연결. 기존 제목·버튼·칸을 복제해 모양 유지 |

- 다른 선원 보유 표시는 넣지 않았다(비공개 결정).
- 배 모듈 아이콘은 아직 없어 기본 아이콘으로 보인다. 아이콘 시트를 받으면 레시피 에셋에 연결.
- 사용자가 메뉴를 실행함(Editor.log: `[WorkbenchScreenCarryLayout] ... updated.`, `ModuleCarrySetup` 배 레시피 4종 추가). 이 시점까지의 코드(보유자 비공개 포함)는 에디터 컴파일 오류 없음, 이후 플레이 로그에 예외 없음. 화면 모양은 남색 그대로라 사용자가 새 시안(나무·양피지)으로 다시 요청.

## 나무·양피지 새 버전 (2026-10-21, 이어서)

사용자 요청: 기존(남색) 화면은 두고, 두 번째 시안(나무 틀·양피지)을 잘라 새 버전을 만든다.

- 시안 잘라내기(스크래치 스크립트, 결과만 커밋 대상): `Assets/03.Images/WorkbenchUiWood/ww_*.png` 22개. 9-slice 틀(창·패널·양피지·카드 2종·칸·들고 있는 모듈 줄·메시지·버튼·진행 막대 2종·섹션 판·배지 알약·아이콘 상자), 통째 이미지(제목 판 "작업대"·닫기 X), 섹션 그림(등대·배), 배 모듈 아이콘 4종(배경 제거). 글자가 섞이지 않게 카드·줄은 왼쪽 절반을 좌우 반전해 오른쪽을 만들고 가운데는 깨끗한 영역의 중간색으로 채웠다.
- `Workbench/Editor/WorkbenchScreenWoodSetup.cs`(신규):
  - `Lighthouse/Workbench/Build Wood Screen Prefab`: 스프라이트 가져오기 설정(9-slice 경계), 배 레시피 4종 아이콘 연결, `WorkbenchScreen.prefab`을 `WorkbenchScreen_Wood.prefab`으로 한 번 복사한 뒤 복사본만 재구성(제목 판, 나무 패널, 가운데 양피지에 큰 아이콘·이름·장착 위치, 섹션 판, 상태별 색 배지, 자원 3열 이름 표시, 보관함 3열, 메시지 줄을 가운데 아래로, 아래 닫기 버튼 숨김). 다시 실행해도 같은 복사본을 고친다.
  - `Lighthouse/Workbench/Use Wood Screen In Open Scene`: 열린 씬에 새 화면을 넣고 작업대 연결을 복사, 남색 화면은 끄기만, JH04 판 진행 패널의 화면 참조를 새 화면으로. 씬 저장은 사용자.
- 코드: `WorkbenchSectionHeader`(신규, 판+아이콘 제목), `WorkbenchScreen`에 선택 필드(섹션 판, 큰 아이콘, 장착 위치 줄, 배지 색 칠하기), `WorkbenchRecipeCard.SetBadgeColor`. 남색 프리팹은 새 필드가 비어 있어 기존 동작 그대로.
- **실행됨(사용자):** 새 코드 에디터 컴파일 오류 없음, `Build Wood Screen Prefab` 실행(Editor.log `... WorkbenchScreen_Wood.prefab built.`).
- **미실행:** `Use Wood Screen In Open Scene`, 플레이 화면 확인. 좌표·글자 크기는 시안 비율로 잡은 첫 값이라 화면을 보고 조정 필요.
