**사용자 지적 반영(같은 날):** 제작 연출이 뜨기 전에 보관함에 모듈이 먼저 보였다. 이제 본인 화면에서는 제작 버튼을 누를 때의 보관 개수를 기준으로 새 모듈 1개를 빼고 보여 주고, 비행 중에는 착지할 칸을 빈 틀(`WorkbenchItemSlot.ShowAwaiting`)로 두며, 착지 순간 칸에 나타나고 그때부터 가져갈 수 있다(`ShownStoredCount`·`IsAwaitingCell`·`ReleaseReserved`). 서버에서는 처음부터 보관 상태이므로 다른 선원 화면에는 바로 +1이 보이고, 연출 중(약 1.3초) 다른 선원이 가져가는 것은 막지 않는다. 실패·화면 닫힘·결과 전 닫힘이면 즉시 정상 표시로 돌아간다. Unity 컴파일 오류 0.

**사용자 지적 반영 2(같은 날):** 가져가기·되돌려놓기도 도착지에 바로 생기면서 연출이 겹쳤다. 이제 클릭 순간부터 가져가는 모듈은 운반 줄에 안 보이고(`_isCarryHeld`, 그동안 되돌려놓기 막음), 되돌려놓는 모듈은 클릭 때 보관 개수보다 늘어난 1개를 보관함에서 뺀다(`_returnReserved*`, 비행 중 빈 틀). 착지(`FlightSeconds`) 순간 `TickCarryReveal`이 표시를 풀고 운반 줄 아이콘 튐·글자 금빛 깜빡임, 또는 보관함 칸 튐·"+1"을 낸다. 실패·화면 닫힘이면 즉시 정상 표시. 기존 `TickCarryLanding`(칸이 생길 때까지 대기)은 빈 틀 방식으로 대체해 삭제. Unity 컴파일 오류 0.

**하단 카드 정리와 자원 아이콘(사용자 지시, 같은 날):**
- 하단 'G'만 있던 빈 칸은 되돌려놓기 단축 버튼(`ReturnShortcut`)이었다. 선반의 되돌려놓기 버튼·G키와 겹쳐 삭제하고 `_returnShortcutButton` 필드도 없앴다. 들고 있는 모듈 카드는 하단 가운데(프레임 기준 x 791)로 옮겼다.
- 카드를 `Window` 밖의 프레임 크기 홀더(`CarryHolder`)로 옮겨, 화면을 닫아도 모듈을 들고 있으면 같은 자리에 남는다(`RefreshCarryCard`, 변경마다 갱신). 화면을 열면 항상 보인다.
- 왼쪽 아래에 옛 아이콘(`recipe.Icon`)으로 뜨던 D(`CarriedModuleIndicator`)는 `TowerMatchEffects` 빌더에서 빼고 스크립트·meta를 삭제했다. 매치 효과 프리팹을 다시 빌드해 컴포넌트가 없는 것을 확인했다.
- 자원: 기획의 기본 자원은 돌·나무·섬유·철·유리·수정이고 '짚'은 없다. 짚 다발 그림은 섬유 아이콘으로 썼다. 첨부 그림을 알파 기준으로 잘라 정사각 256px로 만든 `ws_icon_wood`·`ws_icon_stone`·`ws_icon_fiber`를 `WorkbenchUiSketch`에 추가하고, 빌더가 옛 `WorkbenchUi/wb_icon_*` 대신 쓰게 했다. 옛 파일은 `WorkbenchScreen_Wood` 등이 쓰므로 남겼다.
- 배치 수정(사용자 지시): 카드가 작업대·등대 열기 안내(둘 다 하단 가운데, 바닥에서 90)를 가렸다. 사용자 선택은 "안내를 카드 위로, 카드는 아주 조금만 내림". 카드를 홀더 없이 화면 하단 가운데에 고정(바닥에서 43, 이전 58)하고, 작업대·등대 열기 안내를 바닥에서 150으로 올렸다. 안내도 화면 하단 기준이라 16:10·울트라와이드에서도 간격이 유지된다. `WorkbenchScreen_Sketch`·`TowerScreen_Sketch` 재빌드. 등대 프리팹은 내부 자식 ID가 새로 생성됐지만 세 씬이 참조하는 ID 3개는 남아 있어 연결 유지.
- 등대 화면과 겹침(사용자 플레이 확인): 등대 화면 오른쪽에 자체 '들고 있는 모듈' 패널이 있어 하단 카드가 중복되고 "0/8"·진행 바를 가렸다. 카드를 더 내릴 수 없어, 작업대 화면 외의 화면(`SessionScreen.IsGameplayOverlayOpen` — 등대·투표·정체 확인)이 열려 있으면 카드를 숨긴다. 다른 화면은 작업대에 알리지 않으므로 화면이 닫힌 동안 `Update`에서 표시 상태가 어긋날 때만 갱신. 컴파일 오류 0, 플레이 미확인.
- 작업대 파티클: 사용자가 JH04TestScene에서 설정 메뉴 실행·저장(2026-10-27).
- 작업대 화면 프리팹 재빌드. JH04TestScene·MainGame·TWJH04TestScene이 덮어쓰는 프리팹 내부 fileID 3개가 재빌드 뒤에도 그대로라 씬의 작업대 연결은 유지된다(파일 대조, 씬은 열지 않음). 콘솔 오류 0.

## 결정과 이유
- **결과와 완성 신호의 순서를 가정하지 않는다.** 원격은 같은 배치에서 완성 RPC가 결과보다 먼저, 개수 동기화가 그 뒤에 온다. 호스트는 개수가 먼저 반영된다. 그래서 제작 요청한 레시피 ID를 기억하고, 결과 전에 온 같은 ID의 완성은 보류했다가 성공이면 본인 몫·실패면 다른 선원 몫으로 정한다. 결과가 먼저 오면 1.5초(`CraftWaitSeconds`) 안의 같은 ID 완성 한 번을 본인 몫으로 소비한다.
- 다른 선원 제작 펄스는 개수가 실제로 오른 뒤 재생한다(호스트는 즉시). 순서가 뒤집히면 1.5초 뒤 재생.
- 띠 C 생략은 직렬화 참조 대신 정적 속성으로 했다. 빌더 재빌드·씬 수정이 필요 없다. 에디터 도메인 리로드가 꺼져 있어(`EnterPlayModeOptions`) `RuntimeInitializeOnLoadMethod`로 초기화한다.
- 파티클은 코드로 만들어 씬에 저장하는 방식(설정 메뉴)이다. 재질은 URP 패키지의 `ParticlesUnlit.mat`을 참조해 새 에셋이 없다.
- 망치 효과음: `Assets/`와 SVN 체크아웃에 쓸 만한 클립이 없다(Mirror 예제 제외). `_hammerClip`은 비워 두었다.
