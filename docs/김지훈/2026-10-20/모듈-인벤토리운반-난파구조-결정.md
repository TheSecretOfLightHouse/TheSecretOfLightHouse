# 모듈 인벤토리 운반과 난파·구조 규칙 결정
작성자: 김지훈
작성일: 2026-10-20
갱신일: 2026-10-20
상태: 대기 (결정·문서 반영 완료, 코드 미착수)
브랜치·기준 커밋: `feature/jihun` / `1d129d7` (미커밋 JH04 선반형 시험 변경 위에서 문서만 수정)

## 요청과 목표

작업대에서 모듈을 꺼내 개인 인벤토리로 옮긴 뒤 등대(UI)·배(모듈 장착)에 넣는 흐름이 지금 가능한지 확인하고, 불가능하면 누가 무엇을 해야 하는지와 정할 규칙을 결정한다.

## 진행 과정과 결정 이유

- 2026-10-20: 코드 확인 결과 현재 흐름은 불가능.
  - `PlayerInventory.TryAdd`는 `ResourceCatalog` 자원 ID 수량만 받는다. 모듈(개별 `ModuleId`)을 담을 수 없다.
  - `TowerNet.TryInstall`(`04.Lighthouse/Tower/Net/TowerNet.cs:137`)은 작업대 `TryTakeStored`에서 바로 꺼내 장착한다. 인벤토리를 거치지 않는다.
  - `Withdraw`는 마피아 전용 자원 인출(W08)이며 모듈 꺼내기 요청은 없다.
  - `ModuleState`는 Crafting/Stored/Installed뿐이다. 배 모듈 칸·장착 코드는 `05.Player/Boat/`에 없다. `InteractionAction.Rescue` 처리기도 없다.
  - 현재 난파(`BoatController.HandleWrecked`)는 난파 순간 자원 전부를 `ResourcePickup`으로 떨어뜨리고 쓰러짐 처리한다.
- 2026-10-20: 모듈 보유 기록 위치를 정했다. `PlayerInventory` 수정 대신 `ModuleLedger`에 보유자를 기록한다. 최명기 인벤토리 코드를 바꾸지 않고, 개수 상한을 한 장부에서 계속 관리하기 위해서다.
- 2026-10-20: 최명기에게 전달받은 난파·구조 규칙을 사용자가 **최신 기획 변경**으로 확인했다. v4 9.1과 대장 V04("랜덤1개/전부손실 구현하지 않음")를 대체한다.
- 2026-10-20: 사용자 결정 내용.
  - 꺼내기는 전원 가능. 보유는 1인 1개(방해 억제 목적이라고 설명한 뒤 유지 선택). 되돌려놓기 허용, 보유자 공개.
  - 구조되면 랜덤 1개 소실이며 모듈도 포함. 잃은 모듈은 장부에서 삭제.
  - 구조를 못 받으면 재스폰 순간 자원과 모듈이 전부 떨어진다. 떨어진 것은 근처 섬 가장자리로 이동하고, 모듈도 줍는 물건으로 이동한다(안 (나)).
  - 공동 자원 소모 폐기. 배 장착 모듈은 난파해도 유지. 배 장착은 최명기 코드가 장부 함수를 호출.
  - 안 (나)는 처음에 "일이 늘어난다"고 설명했으나, 실제 추가분은 `ModulePickup`·장부 상태·줍기 경로 정도라고 정정했다. v4 7.4·9.1의 "잔해·모듈 같은 줍는 물건 통일"과도 맞는다.

- 2026-10-20: 미정 8 결정 — 구조 못 받아 떨어진 모듈에는 분해 타이머를 적용하지 않음.
- 2026-10-20: 미정 9 확인 — "인벤토리 비활성"은 v4 4.2의 마피아 소환 이후 상태다. 들고 있던 모듈이 잠기면 존재 상한 때문에 재제작이 불가해 시민이 이길 수 없게 될 수 있음(R22). 선택지 A(작업대 복귀)·B(드롭)·C(소멸) 중 사용자가 **C(소멸, 장부 삭제·재제작 가능)** 선택. 마피아의 마지막 방해 수단으로 둔다.
