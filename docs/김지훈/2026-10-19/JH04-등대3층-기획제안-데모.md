# JH04 등대 3층 기획 제안과 데모

작성일: 2026-10-19
담당: 김지훈
상태: **기획 제안(확정 아님)**. 데모 코드 작성·컴파일 확인·빌더 실행 산출물 확인. 1인 시민·마피아 스모크(M0) 통과, HUD 겹침 수정(같은 날 이어서). 4인(M2) 미확인.

## 배경과 요청
- JH04(등대·의식·최후 전투) 기획에 애매한 부분, 고려할 것, 밸런스 부담이 많다.
- 사용자 요청: 확정된 기획(최후 전투 수리도 0% 리셋 등)은 모두 무시하고, 마피아 시스템과 직관적인 재미에 맞춰 "자원을 어떻게 넣고, 어떻게 방해하고, 어떻게 이기는지"를 제안한다. 이어서 "이대로 따로 데모 진행"을 요청했다.

## 제안 요약
> 등대 3층에 불을 다 켜면 시민 승리, 불이 다 꺼지면 마피아 승리.

| 항목 | 제안 |
|---|---|
| 진행도 | 1층 기반 프레임, 2층 기어 장치, 3층 렌즈와 광원 코어(슬롯 4개). 아래층부터 장착하고, 켜진 층 수가 곧 진행도다. 장착자 이름이 명판에 남는다 |
| 자원 | 나무(가까움) → 철(중간) → 수정(먼 곳, 밤 전용). 층이 오를수록 더 위험한 곳으로 가야 한다 |
| 층 보상 | 1층: 채집이 빨라짐. 2층: 낮에도 수정 채집. 3층: 탐조등 고발 가능 |
| 마피아 방해 | 검은 녹(장착된 모듈이 밤에 보랏빛으로 깜빡이다 새벽에 떨어짐. 장착자·제작 참여자 공지), 빼돌리기(작업대 기록에 시각만 남음), 바다 부르기(데모에서는 제외) |
| 소환 | 밤마다 한 번 속삭임으로 의심받는 인원을 확인한다. 1명 이상이면 소환 가능. **촉수 수 = 일차 − 의심 수**(1~4) |
| 최후 전투 | 0% 리셋 없음. 소환 순간 장착된 모듈이 체력이다. 촉수가 슬롯을 감고 20초가 지나면 모듈을 뜯어 해안으로 던진다. 시민은 작살로 떼어내고, 떨어진 모듈을 건져 다시 장착한다. 3층이 모두 켜진 동안만 점등 게이지가 찬다. 마피아는 촉수가 노릴 슬롯을 지정한다 |
| 의식 | 비밀 투표 대신 탐조등 고발: 60초 동안 각자 빔으로 용의자를 비추고, 빔은 모두에게 보인다. 끝날 때 시민 빔 2개 이상이 마피아를 비추면 시민 승리. 빔을 받으면 마피아는 소환으로 판을 뒤집을 수 있다 |
| 기존 대비 | 수리도 %·HP 환산·최후 진행도 0% 리셋을 "켜진 층 수"로, 심해−봉인을 "일차−지목 수"로, 주기 피해를 촉수 쟁탈전으로, 비밀 투표 판정을 공개 빔으로 바꾼다 |

채택하려면 합의가 필요하다: 투표·확인·소환은 박태욱(TW03~05), 승패 확정·UI는 최명기(MK06), 촉수는 2026-10-18 촉수 결정([승패·투표 결정 5절](../../design/win-vote-decisions.md#final-battle))과 겹친다. 김지훈 범위는 등대 층·장착·최후 쟁탈(JH04)과 부식·표류(JH05)다.

## 데모
- 위치: `Assets/ThirdParty/1조 Unity Asset/_Demo/Jihun/LighthouseFloors/`. 규칙·키·구조·축약 사항은 [데모 README](../../../Assets/ThirdParty/1조%20Unity%20Asset/_Demo/Jihun/LighthouseFloors/README.md)에 있다.
- CrewMultiplayer 데모의 씬·플레이어 프리팹·접속 흐름을 재사용한다. `FloorsNetworkManager`가 `CrewNetworkManager`를 상속해 이 데모의 공유 오브젝트를 스폰한다. 포트는 7789와 47789로 분리했다.
- 비밀 상태(가방·역할·지목·쿨다운)는 `FloorsCrew`의 `SyncMode.Owner`로 본인에게만 보낸다. 녹 여부와 참여자는 서버만 안다.
- 본편 코드(`Assets/01.Scripts`)는 쓰거나 고치지 않았다.

## 결정 이유
- **별도 폴더로 분리:** 사용자가 "따로"를 요청했고, CrewMafiaRound(본편 Mafia Rules를 사용)와 규칙이 정반대라 섞으면 두 데모를 비교할 수 없기 때문이다.
- **CrewMultiplayer 씬 복사:** 맵·캐릭터·접속 코드를 다시 만들지 않으려고. 원본 씬과 프리팹은 바꾸지 않는다.
- **CrewHud.cs만 조건 추가:** 크레이트 등대가 없을 때 "짐"과 상자 조작 안내를 숨긴다. 크레이트 등대가 있는 CrewMultiplayer에서는 동작이 그대로다.
- **배·몬스터 없음:** "멀리 갈수록 위험"은 등대 섬 안의 거리(가까이 나무 → 해안 수정)로 대신했다.

### 이어서 한 작업 (2026-10-19, 다음 세션)
- **빌더 완료 여부:** 에디터가 재시작돼 이전 콘솔 로그가 없었다. 완료 로그 바로 앞 줄이 `SaveScene`이고 씬이 19:50에 저장됐으므로 끝까지 실행된 것으로 판단했다(로그 자체는 미확인).
- **앵커 위치:** `LighthouseFloorsAnchors` 아래 21개를 아래 방향 레이캐스트로 확인했다. 모두 아래에 콜라이더가 있다. 표류 지점 10개는 해안 Terrain(y≈0.6), 작업대는 등대 언덕 바위(y 13.8)다. `WoodSpot_2`(0.5, 12.9, 13.5)는 코티지 지붕 가장자리다. CrewMultiplayer 상자 지점을 그대로 물려받은 위치이며, 동쪽 2m의 바위 경사(법선 y 0.81, 약 36°)가 채집 거리(2.5m) 안에 있어 그대로 두었다.
- **1인 시민 스모크(M0, 에디터 호스트 단독):** 키 입력 대신 플레이 모드에서 서버 메서드(`ServerBeginGather`·`ServerDeposit`·`ServerBeginInstall`·`ServerStartRitual`)를 코드로 호출했다. 플레이어는 각 지점 옆으로 순간이동시켰다. 확인 결과: 나무·철 채집(서버 채널 1.5초), 낮 수정 거절과 밤 수정 채집, 기반 프레임 자동 완성·보관, 1층 장착(명판·점등 공지·채집 가속 공지), 2층·3층 장착, 3층 완성 공지, 탐조등 고발 시작이 모두 동작했다. 고발이 끝나자 **시민 승리**가 나오고 등대 램프가 켜졌으며 종료 공개(진행 기록 포함)도 표시됐다. 축약: 나무·철·수정은 1개씩만 실제로 채집하고 나머지는 `ServerAdd`로 넣었다. 고발 60초는 `_ritualEndsAt`를 리플렉션으로 당겼다.
- **1인 마피아 스모크(M0):**
  - 빼돌리기(Z): 작업대 재료 2개가 마피아 가방으로 옮겨지고, 작업대 기록에는 "사라졌다"만 남는다.
  - 검은 녹(G): 진행 중 재료에 묻은 녹이 완성 모듈로 이어진다. 녹 모듈을 장착하면 밤에 1층 고리가 보라색으로 깜빡인다(`_flicker[0]=true`, 발광색 보라).
  - 새벽 낙하: 모듈이 해안 `DebrisPoint_5`에 표류하고 장착자·제작 참여자가 공지된다. 이어서 건지기 → 작업대 수리(4초) → 보관 → 재장착까지 동작했다.
  - 소환과 승패: 2일 밤 속삭임에서 혼자 시험 예외로 소환 창(15초)이 열렸다. 소환하자 촉수 2개(2일차 − 의심 0명)가 나왔고, 촉수가 1층을 뜯어 모듈이 0개가 되자 **마피아 승리**로 끝났다. 종료 공개의 "마피아가 몰래 한 일"에 녹·빼돌리기·속삭임이 모두 남았다.
  - 축약: 시계(`_startedAt`)와 촉수 잡기 종료 시각을 당겼다.
- **발견하고 고친 것(`FloorsHud.cs`):**
  - 결과 창이 화면 가운데에 그려져 왼쪽 CrewHud 패널과 겹쳤다. 결과 창을 왼쪽 패널 오른쪽으로 옮겼고, 수정 뒤 화면으로 확인했다.
  - 상단 배너와 하단 안내 문구를 두 패널 사이의 가운데 열에 그리도록 바꿨다. 가운데 열이 360px보다 좁으면 원래처럼 전체 폭을 쓴다. 1920px에서의 배치는 계산으로만 확인했다.
  - 고발 중에는 등대 근처 안내를 끄고, 소환된 마피아에게는 "[1~4] 촉수가 노릴 슬롯"을 보여 준다. 이전에는 이때도 "[E 길게] 모듈 장착"이 남아 있었다.
  - 수정 후 컴파일 오류·경고 0을 확인했다.
- **기록만 한 것:**
  - 밤에는 태양 세기만 2.0에서 0.5로 낮추고 Trilight 환경광과 절차 하늘은 그대로 두기 때문에 화면이 거의 어두워지지 않는다. 녹 깜빡임은 고리 발광으로 보이므로 진행에는 지장이 없다.
  - 수정 지점은 모두 6개이고 렌즈와 코어에 5개가 필요하다. 지점이 비면 30초 뒤 다시 차므로(`_respawnDelay`), 빼돌리기 때문에 판이 막히지는 않는다.
- **2인 테스트 준비(사용자 요청):**
  - 데모 씬만 담은 빌드를 `Builds/LighthouseFloors/`(git 제외)에 만들었다. 공용 Build Settings는 바꾸지 않았다.
  - 에디터가 방장(포트 7789), 빌드 창 1개가 원격 접속하는 구성이다.
  - 사용자 요청 "자원 모으기가 너무 까다롭다 → 치트 모드, 등대에 넣는 곳은 임시로 캠프파이어로(탑에 오르기 힘듦)"에 따라 두 가지를 추가했다.
    - 치트 모드: `FloorsRound._isCheat`(대기실 토글, 기본 켬)와 `ServerCheatResources`로, [F1]을 누르면 레시피 비용 한 벌을 받는다.
    - 장착 지점: `FloorsLighthouse`에 동기화되는 장착 지점과 반경(`_interactPoint`·`_interactRange`)을 두었다. 장착·고발·작살 판정과 장착 채널 기준점이 이 지점을 쓴다. `FloorsNetworkManager._lighthouseInteractAnchor`를 `NightGatherPoint`(-6, 4, -12)로 지정하고 반경은 5m로 했다. 씬 지정은 에디터 API로 하고 저장했다. 빌더도 같은 지정을 하도록 고쳤다.
  - 검증: 컴파일 오류·경고 0. 에디터 1인으로 확인한 결과, 치트로 자원 6·5·5를 받고 모듈 4개를 완성·보관했다. 캠프파이어 옆 장착 성공, 탑 위치는 범위 밖 판정, 지점 표시·F1 안내 표시를 확인했다. 재빌드(20:29) 후 2인 세션을 다시 열었다.
- **2인 테스트 중 사용자 보고:** "작업대에서 1을 눌러도 나무 0/4 그대로, 만드는 법을 모르겠다."
  - 원인: 두 플레이어가 캠프파이어 옆에 있었고 작업대는 언덕 위(32~36m 거리)에 있었다. 숫자 키는 레시피 선택만 했고, 투입은 작업대 3.5m 안에서 E를 눌러야 했다(작업대 기록 0건).
  - 조치 ① 작업대를 캠프파이어 동쪽 9m 평지(3, 4, -12)로 옮겼다. 씬의 `WorkbenchAnchor`를 에디터 API로 옮기고 저장했고, 빌더도 같은 위치를 쓰도록 고쳤다.
  - 조치 ② 작업대 앞에서 1~4를 누르면 그 레시피를 고르면서 바로 투입한다(`FloorsCrew.ReadNumbers`). 마피아도 숫자 키를 누르면 투입된다.
  - 조치 ③ "[작업대]" 머리 위 표시를 추가하고, 안내 문구를 바꿨다.
  - 검증: 에디터에서 가상 키 "1"을 입력해 나무 4개가 투입되고 기반 프레임이 완성·보관됐다. 재빌드(20:37) 후 2인 세션을 다시 열었다.
- **미확인:** 사람이 직접 키로 조작하는 흐름(E 길게·1~4·V·R·Q 입력 경로), 작살과 점등 게이지로 얻는 시민 승리, 4인 M2(원격 Owner 동기화, 빔·촉수·명판이 모든 PC에서 같게 보이는지).
