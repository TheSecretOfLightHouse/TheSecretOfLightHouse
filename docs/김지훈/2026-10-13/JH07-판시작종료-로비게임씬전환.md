## 요청과 목표

JH07과 JH02 중 무엇을 먼저 할지 정하고, 박태욱의 투표·마피아 보완 결정과 대조한 뒤 JH07부터 진행한다. 목표는 4명이 로비에 모여 전원 준비하면 자동으로 판이 시작되고, 판 진행 중 누가 나가면 전원에게 종료 사유를 보낸 뒤 판이 끝나는 틀이다. 모든 기능이 이 판 틀에 붙는다.

## 진행 과정과 결정 이유

- 2026-10-13: [승패·투표 결정](../../design/win-vote-decisions.md)·[작업표](../../06-owner-work-plan.md)·[지훈 설계](../../design/jihun-system-design.md)와 `07.Mafia` 코드를 대조했다. 투표는 자체 Command와 `Connections` 계약을 쓰므로 JH02와 충돌이 없다. 다만 실제 판에서 `InitializeVoting`을 부르는 곳이 시험 패널뿐이라는 점, 판 시작 신호가 없다는 점을 확인했다.
- JH07을 먼저 하기로 했다. 이유: 결정이 모두 닫혀 있다. 투표 초기화·시계 시작 등 전원의 통합이 판 시작 신호를 기다린다. JH02의 MatchId도 판 개념에 의존한다. JH02는 강민서·최명기 확인이 남아 있다.
- 로비 구조는 사용자가 로비 씬·게임 씬 전환 방식을 결정했다. 로비 씬에 로비 전용 플레이어를 만들고 씬을 이동한다. 객체 없는 로비보다 반나절~1일 더 든다는 비교를 듣고 정했다.
- 판 종료 후 화면은 사용자가 "연결 끊고 첫 화면"으로 결정했다. 로비 복귀는 각 기능에 판 단위 초기화가 필요해 범위가 커지기 때문이다.
- 팀원 합의 항목은 사용자가 권장안으로 결정했다. ActorJoined 의미 변경은 재공지한다. MatchStarted 신호는 만들고, 합의 전에는 99.Dev 시험 코드가 투표를 초기화한다. 강민서 코드는 수정하지 않고 전달만 한다.
- Mirror 96.0.1 동작 확인:
  - 씬이 바뀌면 `SetAllClientsNotReady`가 호출된다.
  - 클라이언트는 `localPlayer == null`이면 씬 로딩 후 AddPlayer를 다시 보낸다(`NetworkManager.OnClientSceneChanged`).
  - 로비 플레이어는 씬 전환 전에 `RemovePlayerForConnection(Destroy)`로 명시적으로 제거해, Unity 파괴 판정에 기대지 않게 했다.
  - 게임 씬에서 AddPlayer가 도착하는 것을 그 클라이언트의 로딩 완료로 쓴다.
- 기존 시험 씬 보호: 로비 프리팹이나 게임 씬이 비어 있으면 기존 단일 씬 방식(접속 즉시 게임 플레이어·ActorJoined, 이탈 시 판 종료 없음)으로 동작한다.
- 2026-10-13(Unity MCP 세션) 에디터 구성과 M2를 진행하면서 결함 3개를 찾아 고쳤다.
  1. 첫 화면에서 종료 사유가 항상 비어 있었다. 원인: Mirror 96은 offline scene으로 가기 전에 매니저를 DontDestroyOnLoad 밖으로 옮긴다(`NetworkManager.StopServer`·`StopClient`). 그래서 첫 화면 씬의 새 매니저가 자리를 대신하고, 인스턴스 필드의 `LastSessionEnd`가 사라진다. 조치: 종료 기록을 static으로 옮기고 `SubsystemRegistration`에서 초기화한다.
  2. 판 시작 후 접속 거절 사유가 항상 사라졌다. 원인: `OnServerConnect`에서 보낸 직후 `Disconnect`해 배치 전송 전에 연결이 지워졌다(`[KCP] RawSend invalid connectionId` 반복). 끊기만 미루는 방법은 쓰지 않았다. Mirror가 `OnServerConnect` 전에 SceneMessage를 보내 거절된 클라이언트가 게임 씬 로딩을 시작하는데, 로딩 중 끊기면 첫 화면으로 돌아가지 못한다(`NetworkManager.cs` 1289행 `loadingSceneAsync == null` 조건). 사용자 결정으로 `SessionJoinAuthenticator`(인증 단계 거절)를 추가했다. 이 방식은 SceneMessage 전에 사유를 보내고, 0.5초 + 2프레임 뒤 끊는다. 인증기가 없는 씬은 즉시 끊는 대체 경로를 쓴다.
  3. 호스트가 나갈 때 원격 클라이언트에는 "호스트 연결 끊김"이, 호스트에는 사유 없음이 표시됐다. 원인: 0.5초보다 긴 프레임이 하나 생기면 `Update`의 StopHost가 `LateUpdate` 전송 flush보다 먼저 실행된다. 시험에서는 MCP 코드 실행이 메인 스레드를 막아 2프레임 만에 꺼졌다. 조치: 종료·거절 지연에 최소 2프레임 조건(`NoticeFlushFrames`)을 더했다.
  4. 로딩 중 끊기면 클라이언트가 빈 게임 씬에 갇혔다(사용자 지적으로 남은 위험에서 수정 대상으로 바꿈). 원인: 로딩 중 연결이 끊기면 Mirror가 매니저를 현재(로비) 씬으로 옮기고 offline scene 이동은 건너뛴다(`loadingSceneAsync != null`). 로딩이 끝나 로비 씬이 언로드되면 매니저도 파괴돼 아무도 첫 화면으로 보내지 않는다. 재현: `SceneLoadHoldProbe`로 원격 클라이언트의 게임 씬 활성화를 8초 막고 호스트 시간 초과를 3초로 줄였다. 수정 전 빌드에서 클라이언트가 패널 없는 빈 화면에 남는 것을 확인했다. 조치: `OnClientDisconnect`에서 로딩 중이면 offline scene 경로를 static에 저장하고, static `sceneLoaded` 콜백이 로딩 완료 직후 offline scene을 로드한다. Mirror가 로딩 중 메시지 처리를 멈추므로(`NetworkClient.isLoadingScene`) 서버가 보낸 `LoadTimeout`은 클라이언트에 도달하지 않는다. 사용자 결정에 따라 통지 없는 끊김은 중립 사유로 표시한다. `SessionEndReason.HostLost`를 `ConnectionLost`로 바꿨고, 시험 패널 문구는 "연결이 끊겨 판이 종료되었습니다"다. 실제 UI(MK06)도 같은 기준을 따르도록 [팀원 공지](../../handover/김지훈/2026-10-13/판시작종료-로비게임씬전환-팀원공지.md)에 추가했다.

  - 요청 대조: 강민서 안은 매니저가 `WorldServices`에서 `IWorldReadyGate`(`Lighthouse.World.MapGeneration.Rules`)를 조회하는 방식이었다. 검증해 보니 `01.Network`는 다른 도메인을 하나도 참조하지 않고, World(`MapStateNet`·`WorldStateNet`)는 이미 `Lighthouse.Network.Session.Net`을 참조한다. 매니저가 World 계약을 참조하면 World ↔ Network 순환이 생긴다. 단일 asmdef라 컴파일은 되지만 [아키텍처 §3](../../04-architecture.md)은 의존 방향을 담당자 합의 대상으로 둔다. 사용자에게 보고했고, 사용자가 A안(게이트 계약을 Network에 두고 World가 등록)을 선택했다.
  - A안 이유: Network가 기능 코드에 의존하지 않는 바닥 계층으로 남는다. 등대·마피아 등 다른 기능의 시작 전 준비가 생겨도 매니저 코드를 바꾸지 않고 게이트만 추가한다. `IWorldReadyGate` 모양(`Changed` + `AreAllReady(roster)`)이 이미 기능 중립적이라 옮기기 쉽다.
  - 등록 방식: 매니저가 조회하지 않고 기능이 `RegisterStartGate`로 넣는다. 게이트는 게임 씬 `OnStartServer`에서 생기므로 로딩 시작 시 조회하면 놓칠 수 있다는 강민서 지적을 등록 방식으로 해결했다. 등록 시와 `Changed` 때마다 `TryStartMatch`를 다시 부르고, 기존 Loading·전원 로딩 검사가 앞에 있어 중복·조기 시작을 막는다.
  - 누락 정책: 강민서 제안(필수 설정 bool, 기본 false)을 받아들여 `_requireStartGate`로 이름 붙였다. 등록된 게이트는 설정과 관계없이 항상 기다린다. 설정은 "게이트가 하나도 없을 때 바로 시작할지"만 정한다. true인데 게이트가 없으면 Loading을 유지하고 기존 시간 초과(60초)로 끝난다.
  - 정리: `ResetServerSession`(서버 시작·종료)에서 구독을 모두 해제한다. 한 판이 한 서버 실행이라 판 종료 시 별도 해제는 넣지 않았다. 게이트 쪽은 자신의 `OnStopServer`에서 `UnregisterStartGate`를 부르며, 매니저가 먼저 비웠으면 false만 반환한다.
  - 강민서 쪽 필요 변경은 [회신](../../handover/김지훈/2026-10-16/N3-판시작게이트-강민서-회신.md)으로 정리했다. 월드 코드는 수정하지 않았다.

## 남은 일과 차단 조건

1. (결정됨) JH07 씬 시작 인원은 2로 유지한다. 통합 씬을 만들 때 4로 둔다.
2. 미검증 항목: M3(다른 PC). 로딩 n/4와 정원 초과는 2026-10-13에 확인했다. 예전 방식 회귀는 다른 담당 씬 2개(M0)로 확인했으며, JH01 원격 확인은 필요하지 않다(JH01은 김지훈 전용 시험 씬).
3. (결정·확인됨) 통지 없는 끊김은 중립 문구로 표시한다. 최명기의 MK06 반영 확인을 기다린다.
4. (결정·확인됨) 로비 단계 끊김은 `LobbyConnectionLost`로 표시한다. 접속 자체가 실패한 경우는 여전히 문구가 없다(의도된 동작).
5. 이탈 원인 구분 남은 위험: 창 닫기 통지는 비신뢰성 사본에 기대므로 실제 네트워크에서 손실되면 "연결이 끊겼습니다"로 보일 수 있다(사용자가 수용한 범위). 작업 관리자 종료처럼 프로세스가 바로 죽는 경우는 정의대로 연결 끊김이다.
6. 팀원 확인 대기: [팀원 공지](../../handover/김지훈/2026-10-13/판시작종료-로비게임씬전환-팀원공지.md)의 박태욱·최명기·강민서 확인란. 인증기 추가는 팀원 계약에 영향이 없다.
7. (2026-10-16 매니저 측 구현) 판 시작 게이트 `IMatchStartGate`·`RegisterStartGate`를 추가했다. 남은 것: 강민서가 `WorldReadyTracker`를 이 계약으로 등록하고 자기 Offline 매니저의 `_requireStartGate`를 켠 뒤 통합 검증(강민서 담당). 김지훈은 기존 씬 회귀를 확인한다. 이전 기록: 강민서 월드 생성 완료 신호가 생기면 시작 조건에 추가한다(코드 TODO). 함께 `develop`의 `WorldStateNet.BeginMatch()` 호출 시점을 `OnStartServer`가 아니라 `MatchStarted`로 맞추도록 강민서와 합의한다(위 원격 확인). 요청 문서: [강민서 연결 요청](../../handover/김지훈/2026-10-13/판시작-월드시계-강민서-연결요청.md)
8. `Assets/00_Scenes.meta` 삭제 처리: 최명기와 확인한다(위 진행 과정).
9. 알려진 한계:
   - 정원 초과(5번째) 접속자에게는 사유 문구가 없다. Mirror가 인증 단계보다 먼저 전송 계층에서 끊기 때문이다. 문구가 필요하면 Mirror 정원을 5로 두고 `SessionJoinAuthenticator`에서 "방이 가득 찼습니다"를 보낸 뒤 끊는 방식으로 바꿀 수 있다(미결정).
   - 로비 이탈 직후에는 시작 조건을 다시 평가하지 않는다. 시작은 준비 변경 때만 판정한다. 시작 인원 4에서는 영향이 없다.
   - `MatchId`는 매니저 인스턴스 필드라 호스트를 다시 열면 1부터 다시 센다. 첫 화면 복귀 때 매니저가 교체되기 때문이다. JH02 MatchId 설계 때 고려한다.
