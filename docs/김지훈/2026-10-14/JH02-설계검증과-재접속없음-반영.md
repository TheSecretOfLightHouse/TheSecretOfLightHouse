# JH02 A단계 착수 전 설계 검증과 재접속 없음 반영

작성일: 2026-10-14
담당: 김지훈
상태: 설계 갱신 완료, A단계 구현 미착수

> 처음 읽는다면 먼저 [JH02 상호작용 시스템 한 번에 이해하기](../2026-10-15/JH02-상호작용-전체-이해하기.md)(2026-10-15)를 본다. 용어(ActorId·netId·Arg0/Arg1·요청 번호·세션), 실제 동작 흐름, 스크립트 목록, 컴포넌트 부착 위치를 한곳에 정리했다. 이 문서는 당시 작업 일지다.

## 요청

JH02 A단계 진행 전에 구현 코드와 확정 문서를 대조해 설계 문제가 없는지 검증한다. 재접속 없음·4인 중 한 명 이탈 시 판 종료(JH07)를 설계에 반영한다.

## 수행 과정과 결정

- 2026-10-14: 네트워크 매니저·연결 명단·`NetworkActor`·로비·인증기·판 단계, `InteractionRequest`/`InteractionAction`, `PlayerController`·`BoatController`, 채집 지점 계약, 프리팹 구성, JH01·JH07 씬 설정, Mirror 소스를 문서와 대조했다. 진행을 막는 결함은 없었다.
- 발견: (1) §5 요청 번호 설계가 재접속을 전제로 작성됨(연결 세대·만료·처리 중 상태). (2) 판 단계를 보는 코드가 세션 밖에 없어 `Loading`·`Ended` 중 요청을 막는 곳이 없음. (3) JH07 씬의 시험용 플레이어(`NetworkTestPlayer`)에 `PlayerController`가 없음. (4) 네트워크 객체는 netId로도 대상 식별 가능(Mirror netId는 서버 종료 때만 초기화. Steam 전송으로 바꿔도 동일, 호스트 이전만 예외).
- 사용자 결정(2026-10-14): 기존 단일 씬 시험 씬은 모두 폐기하고 팀원 씬은 로비 방식으로 옮긴다(팀원 요청 완료). 설계를 재접속 없음·한 명 이탈 시 판 종료 전제로 갱신한다.
- 반영: 요청에서 ActorId·MatchId·연결 세대를 빼고 `(ActorId, 요청 번호)` 키, 한 번에 하나, 처리 중 상태 없음, 번호 계약 5행으로 축소. 판 `InProgress`일 때만 접수, 단일 씬 방식 미지원. 입력 원천과 Interaction 분리(시험용 입력 어댑터). 4번(netId)은 기존 결정(장부 일원화)을 유지하고 사용자 선택으로 남김.
- 사용자 결정(2026-10-14, 2차): 네트워크 객체 대상은 Mirror netId로 식별한다. 서버 대상 장부(TargetId·Generation 발급·등록·SyncVar)를 없애고, 비네트워크 대상 변환기(TargetResolver)와 등록 없는 표식 컴포넌트(InteractionTarget)만 둔다. 근거: netId는 서버 종료 때만 초기화되고 판 하나가 서버 실행 한 번이라 판 안에서 재사용되지 않는다(Mirror `NetworkIdentity.GetNextNetworkId`·`ResetServerStatics` 확인). Steam 전송·재접속에서도 성립, 호스트 이전만 예외(지원 범위 밖). ActorId는 요청에 넣지 않을 뿐 서버의 사람 식별(원장 키·인벤토리 주인·투표·배 주인)로 계속 쓴다.
- 확인 정정: 채집 지점이 네트워크 객체인지는 정해지지 않았다(강민서 확인 ① 대기, `origin/develop`·`origin/feature/minseo` 2026-10-14에도 생성 코드 없음). 두 갈래를 모두 받게 만든다.
- 구현 순서 결정: JH02의 막히지 않은 범위를 A-1 요청 경로(DTO·Relay·접수 검사·원장·Router·대상 확인·거리 검사·표식·탐지·입력 어댑터) → 검증 → A-2 지속 세션 → 검증으로 진행한다. 채집 연결·실제 기능 처리기·메뉴 UI·본편 검증은 다른 담당 선행 필요로 제외. 구현은 사용자 최종 승인 후 시작.
- `NetworkActor.cs`: 대화 시작 시 git 상태에 없던 변경(첫 줄 BOM+공백 4칸, 수정 시각 2026-10-14 14:32)이 이 세션 중 생겼다. 직접 수정하지 않았으나 Unity MCP 스크립트 생성·재컴파일 중 부수 효과일 가능성이 있고 원인은 미확정. 사용자 승인으로 `git checkout`해 커밋 상태로 되돌렸다.
- Mirror 직렬화 확인: `99.Dev/Network/TempSerializationProbe.cs`(기존 `InteractionRequest`를 Command 인자로 둠)를 임시로 만들어 Unity 6000.0.83f1에서 컴파일했다. Weaver가 `_Write_/_Read_…InteractionRequest`를 생성했고, 생성 함수로 에디터 왕복 직렬화 6필드 일치(16바이트). 에디트 모드라 `Writer<T>` 등록은 비어 있어 생성 함수를 직접 호출했다. 임시 스크립트는 삭제했다. 실제 네트워크 전송은 미실행.
