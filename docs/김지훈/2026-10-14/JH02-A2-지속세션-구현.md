## 수행 과정과 결정

- 계약은 [지훈 시스템 설계 §6](../../design/jihun-system-design.md#6-작업대모듈부식)의 2026-10-14 A-2 표로 정리했다. 기능은 `IInteractionSessionHandler`(독점 여부, `Begin`→소요 시간, `CanContinue`, `Complete`, `Cancel`)를 등록하고, Interaction은 시작·진행 확인·완료·취소·정리를 맡는다.
- 진행 확인 위치: 별도 구동 오브젝트 없이 그 사람의 `InteractionRelay`가 서버 `Update`에서 자기 세션을 확인한다. 한 사람당 세션 하나이고 Relay는 판마다 새로 생기므로 수명이 맞는다.
- 취소 요청은 번호 없는 Command다. 자기 세션만, 세션 번호가 맞을 때만 끝낸다. 자원을 바꾸지 않아 반복해도 결과가 같다.
- 알림: 시작·종료를 본인에게만 각 한 번 보낸다. 시작 알림과 종료 알림을 따로 추적한다. 처음 구현에서는 시작 직후 같은 프레임에 끝난 세션의 종료 알림이 빠지는 경로가 있어 작성 중에 고쳤다.
- 완료 처리 전에 활성 목록에서 먼저 빼서, 처리기가 대상을 지우는 등 다시 들어와도 같은 세션이 두 번 끝나지 않게 했다.
- 결과 코드 `Busy = 11`, 종료 사유 `InteractionSessionEndReason`을 추가했다(값은 뒤에만 추가).
- 시험 처리기 `DevSessionHandler`는 기존 `Harvest`에 개발 씬에서만 등록했다. Arg0은 시험 전용으로 소요 시간(ms)이다. `Vanish…` 대상은 세션 시작 0.5초 뒤 서버에서 삭제한다.
- 확인된 입력 사항(최명기 범위, 결정 아님): `InputSystem_Actions`의 Player/Interact에 `Hold` 인터랙션이 있어 0.4초 이상 눌러야 `performed`가 발생한다. 단발 동작도 0.4초 눌러야 한다. 본편 `PlayerController.InteractionRequested`에는 키 뗌 이벤트가 없어, 본편 플레이어는 지금 세션을 키 뗌으로 취소할 수 없다(범위 이탈 등 서버 조건으로만 끝남).
