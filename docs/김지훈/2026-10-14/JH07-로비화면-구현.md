# JH07 실제 화면 — 첫 화면·로비·로딩·종료 사유

작성일: 2026-10-14 · 담당: 김지훈 · 상태: 코드·아틀라스 작성, C# 오프라인 컴파일과 배치 미리보기만 확인(Unity 실행 미확인)

## 요청과 범위
- 사용자 요청: 로비 씬 UI를 제대로 구성. 사용자가 준 참고 이미지(나무 액자·양피지·밧줄·등대·갈매기·랜턴, 파랑/노랑 판자 버튼)의 느낌을 유지하고, 이미지에서 쓸 부분은 가공해 사용.
- 담당 근거: 2026-10-13 결정으로 첫 화면·로비 화면·준비/취소·로딩 표시·종료 사유 화면은 김지훈(JH07). 게임 안 HUD는 MK06(최명기).

## 결정과 이유
- **화면을 코드로 생성**: 씬·프리팹 YAML 직접 편집 금지이고 이번 세션에 에디터 조작 도구가 없어서, `SessionScreen`이 `RuntimeInitializeOnLoadMethod`로 스스로 생성된다. 매니저가 세션 흐름(로비 프리팹+게임 씬 지정)일 때만 만들어지므로 단일 씬 시험 씬에는 나타나지 않는다. Mirror가 첫 화면 복귀 때 매니저를 교체하므로 화면은 DontDestroyOnLoad로 유지하고 매 프레임 `LighthouseNetworkManager.Instance`를 다시 읽는다.
- **아틀라스 한 장 + Resources**: 텍스처 임포트 설정(.meta)을 손대지 않으려고 조각을 2048×1024 PNG 한 장에 모으고 런타임에 `Sprite.Create`로 자른다. 기본 임포트(Default)여도 POT라 크기 변형이 없다. AssetPostprocessor는 프로젝트 전체 텍스처 재임포트를 유발할 수 있어 쓰지 않았다.
- **참고 이미지 가공**: 체크무늬 배경 제거(가장자리 flood fill), 메인 패널·목록 패널·대화창 내부의 예시 내용 제거(Coons patch 보간), 판자 버튼의 가운데 아이콘 제거, 아바타·상태 점 원형 마스크, 초록 바를 붉게 바꾼 `준비 취소` 버튼, 밤바다·등대 배경 생성. 가공 스크립트는 저장소 밖(세션 scratchpad)에서 실행했다.
- **글꼴**: TMP 한글 폰트 에셋이 없어 레거시 `Text` + OS 폰트(맑은 고딕)를 쓴다. Windows 외 환경은 대체 이름 목록으로 찾는다.
- **문구**: 종료 사유는 승패·투표 결정 §8 문구(나감/연결 끊김 구분, 통지 없는 끊김은 중립)를 따른다. 본인이 나간 경우(`SelfLeft`, 또는 `ParticipantLeft`의 ActorId가 본인)는 팝업을 띄우지 않는다. 이름이 없어 `플레이어 {ActorId}`로 표시한다.
- **기존 시험 패널**: `SessionTestPanel`은 실제 화면이 떠 있으면 그리지 않는다.

## 화면 구성
| 상태(판정) | 화면 |
|---|---|
| 오프라인·연결 중 | 메인 패널: 제목·닻 엠블럼, 호스트 주소 입력(마지막 주소 PlayerPrefs 저장), 안내, [참가하기]/[호스트 열기]. 연결 중엔 [연결 취소]. 우상단 종료 버튼(확인 후 `Application.Quit`). 종료 사유·참가 실패 대화창 |
| `MatchPhase.Lobby` | `선원 대기실`: 4칸 목록(ActorId 순, 나 강조, 준비 완료/대기 중 점), `준비 r / 접속 c`, 안내 문구, 준비하기/준비 취소, 나가기(호스트는 확인 후 방 닫기). 호스트에게 LAN 주소 리본(게이트웨이 있는 IPv4) |
| `Loading` | 키 회전 + `선원 도착 n / m` |
| `InProgress` | 우상단 작은 나가기 버튼 + Esc → 확인 대화창 후 `LeaveSession`. 대화창 동안 커서 잠금을 풀고 닫으면 되돌림 |
| `Ended` | `판 종료 중` 표시 후 첫 화면 |

참가 실패: 클라이언트가 로비 상태를 한 번도 받지 못하고 끊기면 매니저 종료 기록이 없으므로 화면이 직접 판단한다. 연결 자체 실패는 "호스트에 연결하지 못했습니다", 연결 후 끊김(정원 초과 등)은 "호스트가 참가를 받지 않았습니다. 방이 가득 찼을 수 있습니다"(임시 문구, 결정 필요).

## 2026-10-15 갱신: Canvas 프리팹 방식으로 전환
- 사용자 확인: 코드 생성 시안은 에디터 플레이에서 동작(로그에 호스트 방 닫기 확인). 되돌릴 수 있게 임시 커밋으로 보존했으나, 같은 모습이 시안 프리팹으로 남아 아래 정리 때 하나의 커밋으로 합쳤다.
- 사용자 요청: 인스펙터에서 다듬을 수 있는 Canvas 프리팹으로 다시 구성. 이미지 들어간 시안은 따로 보존하고, 같은 구성에서 이미지를 뺀 **틀**을 따로 만든다(나중에 사용자가 가공한 이미지만 넣음).
- 결정:
  - 한 레이아웃 코드로 두 프리팹을 만든다. 틀 `Assets/02.Prefabs/UI/Session/SessionScreen.prefab`(스프라이트 없음, 자리 색만), 시안 `SessionScreen_Draft.prefab`(현재 아트). 계층·이름·위치가 같아 틀의 Image에 스프라이트만 넣으면 된다.
  - 씬: `JH07Offline`에는 틀, 복사본 `JH07OfflineDraft`(빌드 설정에 추가, 매니저 offlineScene을 자기 자신으로)에는 시안. 로비·게임 씬은 공용이고 화면은 첫 화면 씬에서 DontDestroyOnLoad로 따라간다.
  - 런타임: 화면별 MonoBehaviour(`SessionTitleView`·`SessionLobbyView`·`SessionLobbySlot`·`SessionLoadingView`·`SessionDialogView`)가 직렬화 참조를 쓴다. 스프라이트가 비어 있으면 준비 버튼·상태 점은 색으로 바뀐다. 첫 화면 복귀 때 씬에 딸려 온 중복 인스턴스는 스스로 비활성화 후 제거한다. 텍스트는 기본 폰트로 저장하고 `_useOsFont`가 켜져 있으면 시작 시 맑은 고딕으로 바꾼다.
  - 아트는 Resources 아틀라스 대신 `Assets/03.Images/SessionUi/Draft/*.png` 개별 스프라이트(Sprite·밉맵 없음·무압축 임포트). 코드 생성용 `SessionUiBuilder`·`SessionUiArt`·`SessionUiSprite`는 삭제.
  - Unity MCP가 이 세션에 연결되지 않아(도구 없음) 에디터 메뉴 빌더 `TheLightHouse/Session UI/Build Screens (Frame + Draft)`로 작성했다. 새 Editor asmdef `Lighthouse.Session.Editor`(`01.Network/Session/Editor/`).
- 검증: Runtime·Editor 어셈블리 Roslyn 오프라인 컴파일 오류·경고 0. 사용자가 빌더 메뉴를 실행했고(로그 `[SessionScreenBuilder] Built ...`), 두 버전 화면이 정상 표시되는 것을 확인. 씬 변경은 프리팹 인스턴스 추가뿐, 빌드 설정은 `JH07OfflineDraft` 추가뿐임을 diff로 확인. 2인 흐름(M2)은 미실행.
- 정리(사용자 결정): 디자인을 C#으로 배치한 에디터 빌더(`SessionScreenBuilder`·`SessionUiFactory`·`Lighthouse.Session.Editor` asmdef, 677줄)는 YAML 편집 금지와 MCP 미연결로 생긴 우회 구현이라 프리팹 생성 후 삭제했다. 재실행 시 다듬은 프리팹을 덮어쓰는 위험도 없앤다. 이후 화면 수정은 에디터에서 프리팹을 직접 고친다. 런타임 코드(`Session/View/`, 약 1,035줄)는 동작만 맡고 디자인 값은 프리팹에 있다. 푸시 전이라 코드 생성 시안 커밋과 프리팹 전환 커밋을 하나로 합쳐, 쓰지 않는 아틀라스(1.9MB)와 생성 코드를 이력에서 뺐다.

## 2026-10-15 갱신: 2인 시험 통과와 결정 정리
- 검증(사용자 보고): 2인 흐름(M2, 같은 PC) 시험 통과. 세부 단계별 관찰 기록은 받지 않았다. 다른 PC(M3)·4인 로딩 n/4는 미검증.
- 결정(사용자):
  - 표시 이름: 이름 기능 전까지 임시로 `플레이어 {ActorId}`를 쓴다.
  - 판 중 나가기 버튼 위치(MK06 HUD·Esc와 겹침): 지금은 다루지 않는다. 현재 우상단 버튼 + Esc 확인창을 그대로 둔다.
  - 최종 이미지: 틀 프리팹에 나중에 넣는다(사용자).
- 정원 초과 문구: 임시 문구 유지로 결정(사용자, 2026-10-15). 4인 게임에서 5번째 참가는 시험 외에 드물고, 판 진행 중 참가는 이미 정확한 문구가 나온다. 원인 확인 결과:
  - 판 진행 중 참가는 `SessionJoinAuthenticator`가 거절하고 `JoinRejected`("진행 중인 판에는 참가할 수 없습니다.")를 보낸다. 로그 `Join rejected`가 이 경우다.
  - 로비 5번째 참가는 Mirror `maxConnections = 4`에 걸려 인증 전에 사유 없이 끊긴다. 화면은 "방이 가득 찼을 수 있습니다"로 추정 표시한다.
  - 나중에 정확한 문구가 필요하면 별도 작업으로 로비 정원 초과 사유(예: `LobbyFull`)를 추가하고, `maxConnections`를 늘려 인증기가 직접 거절하게 바꿔야 한다(코드 수정, 미착수).
