# 범선·유령선 반투명 유령 재질과 JH04 빌드 흐름

- 작성일: 2026-10-31
- 담당: 김지훈
- 상태: 미커밋. 에디터 안에서 실행하고 스크린샷 확인함. 플레이 모드는 확인하지 않음

## 요청

`sailing ship 3d model`과 현재 유령선 모델 두 가지 모두에 유령선처럼 살짝 투명한 느낌을 넣는다. Build Settings를 JH04Offline → JH04TestScene 흐름으로 맞추고, 작업한 모델을 JH04TestScene에 띄운다.

## 판단

- 투명도는 Unity 재질이 정한다. FBX에 넣은 Blender 재질의 알파는 URP 임포트에서 제대로 넘어오지 않는다. 그래서 모델은 바꾸지 않고 Unity 셰이더와 재질만 만들었다. Blender MCP는 Blender는 켜져 있었지만 애드온 서버에 연결되지 않아("Not connected to Blender") 쓰지 않았다.
- 보통의 투명 재질은 돛대·안쪽 면이 선체 너머로 겹쳐 보여 지저분하다. 그래서 깊이만 먼저 쓰는 패스를 두어, 가장 앞쪽 면만 반투명으로 섞이게 했다.
- `GhostShip.prefab`은 강민서 폴더(`02.Prefabs/World/GhostShip/`)에 있어 바꾸지 않았다. 그 대신 프리팹의 `Visual` 자식을 복사해 네트워크·스크립트 없이 JH04TestScene에 미리보기로 놓았다.
- JH04Offline의 NetworkManager는 `onlineScene`가 JH07Lobby이고 `_gameScene`이 JH04TestScene이다. 그래서 빌드 목록을 JH04Offline(0) → JH07Lobby(1) → JH04TestScene(2)으로 켰다. 나머지 씬은 목록에 남기고 끔(Main 3개 포함).

## 수행

1. 새 셰이더 `Lighthouse/GhostTranslucent`를 만듦. 1패스에서 깊이만 쓰고, 2패스에서 반투명으로 그림. 텍스처 채도를 낮춘 청록 톤, 하프 램버트 조명, 가장자리(프레넬) 청록 발광, 위로 흐르는 느린 깜빡임을 넣음. 양면을 그리고 그림자는 끔.
2. 처음에는 Unity 배치 모드로 실행하려 했으나 사용자가 에디터를 열어 실패함("another Unity instance"). 그다음에는 에디터 안에서 한 번만 도는 임시 에디터 스크립트로 실행함. Unity MCP는 세션 시작 때 연결에 실패해서, 다시 떠 있던 MCP 서버(127.0.0.1:8080)를 HTTP로 직접 불러 새로고침·컴파일을 요청함.
3. 스크립트가 한 일:
   - 원본 재질마다 고스트 재질을 만들고 원본 텍스처를 연결함(유리 재질은 초록 발광을 살리려고 그대로 둠).
   - Build Settings를 바꿈.
   - JH04TestScene을 추가 로드(additive)로 열어 기존 `SailingShip_StreetLantern`의 렌더러 재질을 바꿈(씬 오버라이드, FBX는 그대로). `GhostShip_TranslucentPreview`를 범선 기준 (-22, 0, +6), Y 60° 자리에 놓음. 저장한 뒤 닫음. 열려 있던 JH04Offline과 그 미저장 변경은 건드리지 않음.
4. 임시 스크립트는 지움. 재질 이름은 에디터 `RenameAsset`으로 바꿈(GUID 유지).

- 실제 유령선(`GhostShip.prefab`)에 적용하려면 강민서 합의가 필요함. `Visual` 아래 렌더러 재질을 `M_Ghost_PiratesWarship`로 바꾸면 됨.

## 후속: 원래 모습 ↔ 은은한 유령 모습 왕복 (2026-10-31)

### 요청
배 전체가 투명하고 초록인 느낌은 원하지 않는다. 단순하게, 원래 모델과 유령 재질 사이를 오가는 느낌으로 한다. 가장 유령다운 순간에도 원래 색을 유지하고, 윤곽만 초록으로 빛나게 한다.

### 수행
1. 같은 셰이더에 유령 정도 값을 넣고, 셰이더 시간(`_Time`)으로 왕복시킴. 스크립트는 없고 재질만 바꾸면 됨.
   - 0: 원래 텍스처, 불투명, 테두리 빛 없음.
   - 1: 원래 색에 채도 20%만 낮춤, 알파 0.75, 윤곽만 청록으로 빛남.
   - 사이: smoothstep을 거친 sin으로 왕복해 양 끝에서 잠시 머묾. `_PulseSpeed` 0.8이면 한 번 왕복에 약 7.9초.
   - 조절 값: `_GhostMin`·`_GhostMax`(왕복 범위), `_PulseSpeed`, `_Alpha`, `_RimColor`, `_RimPower`. 위로 흐르던 깜빡임은 뺌.
2. 재질 3개의 값을 위 기본값으로 다시 맞춤(Unity MCP `execute_code`).
3. 확인 캡처: 유령 정도를 0과 1로 각각 고정해 찍고 원래대로(0~1) 되돌림. MCP 스크린샷 기능이 `Assets/Screenshots/`에 만든 PNG는 scratchpad로 옮기고 프로젝트에서는 지움.

### 검증
- 실행함: 셰이더 다시 import. 0과 1 상태 카메라 캡처. 0은 원래 모델과 같은 색이고, 1은 원래 색에 살짝 비치며 윤곽이 청록으로 빛남.
- 실행 안 함: 플레이·씬 뷰에서 왕복 애니메이션을 직접 보지 않음. 왕복 속도는 확인하지 않음.

### 주의
- 캡처 정리 중 에디터에 추가로 열려 있던 `JH04TestScene`을 저장하지 않고 닫음(`CloseScene`). 캡처 전에 사용자가 그 씬을 열어 둔 상태였음. 그 씬에 저장 안 된 편집이 있었다면 사라졌음. 디스크의 씬 파일(이전 배치 결과 포함)은 그대로임. 이후로는 원래 열려 있던 씬은 닫지 않도록 할 것.
- 얇은 돛은 면이 비스듬히 보여 1 상태에서 테두리 빛이 강하게 보임. 너무 밝으면 `_RimPower`를 올리거나 `_RimColor`를 낮출 것.

## 후속 5: 안개 확인과 렌더 순서 보정 (2026-10-31)

- 확인: `GhostShipView._fog`는 파티클 2개(FogWisps·FogLow)를 그대로 참조함. 재질 교체는 선체 MeshRenderer만 건드렸고, 파티클 렌더러와 `M_GhostShipFog`는 바꾸지 않음.
- 문제: 선체가 투명 큐 3000이 되어 안개(3000)와 순서가 겹쳤음. 그래서 배 앞의 안개가 배에 덮일 수 있었고, 바다(`ClearOcean`, Transparent-10)보다도 늦게 그려졌음.
- 수정: 셰이더 Queue를 `Transparent-20`(2980)으로 내림. 그리는 순서가 선체 → 바다(2990) → 안개(3000)가 되어, 불투명 선체였을 때와 같아짐. 재질 3개 모두 2980인 것을 확인함.
- 참고: 프리팹 diff에는 `ShipLanterns` 등 이 작업이 아닌 다른 변경도 미커밋으로 섞여 있음.
- 실행 안 함: 플레이에서 안개 재생과 겹쳐 보이는 모습 확인. 다시 빌드하지 않음.

## 후속 6: 초록 제거·살짝 투명, 안개를 배 전체로 (2026-10-31)

- 사용자 결정: 초록 윤곽·색 보정을 빼고 살짝만 투명하게 함. 안개가 잘 안 보이니 배 전체에 퍼지게 함.
- 셰이더: `_BaseMap`와 `_Alpha`만 남김. 원래 텍스처에 기본 조명을 쓰고 알파는 0.85. 깊이 먼저 쓰는 패스와 Queue `Transparent-20`은 유지함. 재질 3개의 `_Alpha`를 0.85로 맞춤.
- 프리팹 안개(`GhostShip/Fog`, 강민서 담당, 사용자 지시로 수정):

  - FogWisps: 박스 38×2.5×62 @y4를 12×14×30 @(0, 8, 2.3)으로 바꿔 갑판에서 돛대까지 세로로 퍼지게 함. 크기 16~24를 6~10으로, 알파 0.07을 0.2로, 생성률 9~11을 16~18로, 최대 개수 180을 300으로 바꿈.
  - 배 크기 기준: `Visual` bounds 중심 (0, 8, 2.3), 크기 10.2×22×27.8.
- 검증: 저장하지 않는 임시 씬에 프리팹을 놓고 파티클을 15초 진행시켜 캡처함. 안개가 선체와 돛대를 감싸는 것을 확인함. 콘솔 error 0. 임시 씬은 저장하지 않고 닫음.
- 실행 안 함: 플레이(`GhostShipView`의 안개 재생·사라짐), 바다 위·밤 조명에서의 모습, 다시 빌드.

## 후속 7: 떠오름·가라앉음 속도와 경로, 회전 속도 (2026-10-31)

- 요청: 사라짐·생김을 조금 더 천천히 함. 사라질 때도 생길 때처럼 대각선으로 쭉 사라지게 함. 회전 속도는 0.7배로 줄임.
- 원인(코드 확인, `GhostShipNet.StepSinking`): 가라앉기는 8초에 35m를 내려가는데 앞으로는 4m/s로 감. 그래서 경사가 약 47°로 떠오르기(5초 12m, 약 31°)보다 훨씬 가팔랐음. `GhostShipView._hideDepth` 10m에서 배가 숨겨져 보이는 시간은 약 2.3초뿐이었음. 앞머리 숙임(t=0.5까지 18°)이 다 되기 전에 숨겨져 "아래로 내려갔다가 기울며 사라지는" 모양이었음.
- 수정(코드 변경 없음, 설정 값만 에디터 SerializedObject로 바꿈). `GhostShipConfig.asset`(메인, 강민서 담당, 사용자 지시)과 `GhostShipConfig_JH04.asset`:
  - 떠오름 5초를 7초로 늘림.
  - 가라앉음 8초·35m·18°를 7초·12m·18°로 바꿔 떠오름의 정반대로 맞춤. 둘 다 약 23° 대각선이고, 보이는 시간은 각각 약 5.8초.
  - 회전 `_turnSpeed` 18을 12.6°/s로 줄임.
- 영향: 숨은 동안 대기하는 깊이(`Park`, `SinkDepth` 사용)가 35m에서 12m로 얕아짐. 숨김 깊이 10m보다 깊고, 숨은 단계에서는 `GhostShipView`가 배를 끔. JH04 에셋에는 기본값과 같은 `_isLastNightGuaranteed`·`_risePitch`가 새로 직렬화됨(동작 변화 없음).
- 실행 안 함: 플레이에서 떠오름·가라앉음·회전 모습 확인, 다시 빌드.
