# 보상 해금 알림에 능력 이름 표시, 장착·제작 알림은 본인만

작성일: 2026-10-31

## 요청 (사용자, 2026-10-31)
- 등대 수리도 보상 알림에 어떤 능력이 해금됐는지 보여 주고, 글자가 알림 판 밖으로 나가지 않게 한다.
- 모듈 제작 완료·등대 부품 장착 알림이 한 명이 하면 모두에게 뜬다. 누가 했는지가 드러나므로 한 본인에게만 띄운다.

## 원인
- `WorkbenchNet.RpcRecipeCompleted`(ClientRpc)와 `TowerNet.SlotInstalled`(SyncList 변경, 모든 기기)를 `TowerMatchEffects`가 받아 모두의 화면에 `ScreenNotice`를 띄웠다.
- 보상 알림은 층이 완성될 때만 "{층} 수리 완료 — 보상 해금"으로 나왔다. 보상 %(25·50·75)가 층 경계와 맞지 않으면 보상 알림이 빠질 수 있었다.

## 수행
- `TowerNet`: 장착 성공 시 장착한 플레이어 연결에만 `TargetOwnInstalled(slot, 장착 수)` → `OwnInstalled` 이벤트. 장착 수를 함께 보내는 이유는 RPC가 동기화 칸 목록보다 먼저 도착할 수 있어서다.
- `WorkbenchNet`: 제작 완료 시 누른 플레이어에게만 `TargetOwnRecipeCompleted` → `OwnRecipeCompleted`. 기존 `RecipeCompleted`(모두)는 작업대 불꽃 효과(근처 사람만)·작업대 화면 재고 갱신용으로 그대로 둔다.
- `TowerMatchEffects`
  - "등대 부품 장착 (n/m)"+게이지+장착 소리 → `OwnInstalled`에서만.
  - "{모듈} 완성" → `OwnRecipeCompleted`에서만.
  - 탑 공용 소식(층 완성, 보상 해금, 마지막 부품, 전체 수리)은 누가 했는지 없이 모두에게 유지.
  - 보상 해금: 보상 단계가 오를 때마다 "수리 25% 보상 해금 — 배 이동 속도 상승"(금색, **게이지 없음**). 게이지 없는 줄은 판 전체 글자 영역을 쓰고 줄바꿈·글자 축소(best fit)로 판 안에 맞춘다. 최후 전투 중에는 보상이 고정되므로 띄우지 않는다. 같은 장착에서 보상이 나오면 층 완성 줄은 생략한다.
- `TowerLayout`: `_rewardNames`·`GetRewardName(tier)` 추가(v4 6.1 문구). `RepairRewardScreen`의 이름 목록을 지우고 이것을 쓴다. 기존 `TowerLayout_JH04Trial` 에셋은 필드가 없어 기본값을 쓴다(에셋 YAML 수정 없음).

## 검증
- Unity 컴파일 error 0.
- `ScreenNotice.prefab` 오프스크린 렌더: "수리 75% 보상 해금 — 배 대포 피해 상승"이 글자 크기 26, 1줄, 글자 영역 520×76 안에 들어감 확인.
- **플레이·원격 확인 안 함**: 다른 사람이 장착·제작할 때 내 화면에 알림이 없는지, 본인에게는 뜨는지(호스트·원격 각각), 보상 해금 줄이 모두에게 뜨는지.

## 남은 일
- 4인 시험으로 위 항목 확인.
- 층 완성·마지막 부품·전체 수리 공용 알림도 장착 시점을 알려 주기는 한다(HUD 수리도도 공개라 같은 정보). 이것까지 감출지는 사용자 결정.

## 후속 (2026-10-31): 보상 해금·층 완성·마지막 부품 알림도 장착한 본인만

- 사용자 보고: 등대 수리도 보상 알림과 장착 관련 알림이 아직 모두에게 뜬다. 개인에게만 보이게 한다.
- 원인: 위 작업에서 "등대 부품 장착 (n/m)"만 본인 전용(`OwnInstalled`)으로 옮겼고, 보상 해금·층 완성·마지막 부품 줄은 `SlotInstalled`(동기화 목록 변경, 모든 기기)에 남아 있었다.
- `TowerMatchEffects.cs`
  - `HandleOwnInstalled` 끝에서 `ShowInstallNews(layout, slot, count)`로 보상 해금·층 완성·마지막 부품 줄을 띄운다. 장착 수는 TargetRpc로 함께 받은 값을 쓴다.
  - 층 완성 판정은 `IsFloorFilled`로 바꿨다. 동기화 목록이 TargetRpc보다 늦게 올 수 있어 방금 장착한 칸은 채워진 것으로 본다.
  - `HandleSlotInstalled`(모두)에는 전체 수리 완료 판정(`_isReadyPending`, 화면 중앙 제목)만 남겼다.
- 수리도 HUD 막대와 보상 창 수치는 그대로 모두에게 공개된다. 이 알림 변경과는 별개다.
- 검증: 컴파일 error 0. Main 흐름 빌드와 창 4개 실행은 아래 참고. 다른 사람이 장착할 때 내 화면에 알림이 없는지는 플레이로 확인해야 한다.
- 빌드: Main 흐름 `Builds/MainHudFix` 재빌드 성공(18:16, `Lighthouse.Runtime.dll` 갱신 확인), 창 4개(960x540, `Builds/MainHudFix/logs/client0~3.log`) 실행. 시작 15초 로그에 Exception·Error 없음. 플레이 확인은 사용자가 한다.

## 후속 2 (2026-10-31): 장착·수리도 보상 알림을 다시 4명 모두에게

- 사용자 결정: 모듈 장착 알림과 등대 수리도 보상 알림을 본인에게만 띄우던 결정을 취소하고, 4명 모두에게 띄운다. 모듈 제작 완료 알림은 이번 요청에 없어 본인 전용(`OwnRecipeCompleted`)을 유지한다.
- `TowerNet.cs`: 장착자에게만 보내던 `OwnInstalled` 이벤트, `NotifyInstalled`, `TargetOwnInstalled`(TargetRpc)를 지웠다. 이 때문에만 쓰던 `Lighthouse.Network.Session.Net` using도 지웠다.
- `TowerMatchEffects.cs`: `HandleOwnInstalled`를 없애고 `HandleSlotInstalled`(동기화 목록 변경, 모든 기기)에서 처리한다. 띄우는 것은 "등대 부품 장착 (n/m)"·게이지·장착 소리와 `ShowInstallNews`(보상 해금·층 완성·마지막 부품)다. 장착 수는 그 시점의 `InstalledCount`를 쓴다. 층 완성 판정은 목록이 이미 반영된 뒤라 `IsFloorFilled` 대신 `TowerNet.IsFloorComplete`를 쓴다. 전체 수리 판정(`_isReadyPending`)은 그대로다.
- 늦게 들어온 클라이언트는 첫 상태에서 `SlotInstalled`가 나지 않아 지난 장착 알림을 다시 보지 않는다(기존과 같음).
- 검증: Unity 컴파일 error 0(`Lighthouse.Runtime.dll` 19:04 갱신, `TargetOwnInstalled` 없음 확인).
- 실행 안 함: 4인 플레이에서 다른 사람이 장착할 때 내 화면에 장착·보상 알림이 뜨는지. 다시 빌드도 하지 않음.
