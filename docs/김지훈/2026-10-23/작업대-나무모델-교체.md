# JH04 작업대를 나무 작업대 모델로 교체

작성일: 2026-10-23
브랜치: feature/jihun
담당 파트: Lighthouse(작업대) — 김지훈
이전 세션: [세션 인수인계](../../handover/김지훈/2026-10-23/작업대-나무모델-교체-세션인수인계.md)

## 요청
- 사용자가 JH04TestScene에 배치한 `wooden_workbench_3d_model_low`를 작업대 본체로 쓰고 콜라이더를 붙인다.
- 추가 요청: `wooden_market_stall_3d_model`에도 콜라이더를 붙인다.

## 수행
1. Unity MCP 연결 확인. 활성 씬이 `JH04Offline`(미저장 변경 있음)이라, 그 씬은 저장·교체하지 않고 `JH04TestScene`을 additive로 열어 작업했다.
2. 메뉴 `Lighthouse/Workbench/Use Wooden Model In Open Scene` 실행. 로그: 모델 절반 길이 0.61m, 작업대 InteractionTarget 범위 3.0m(인수인계의 3.5m는 실제 값과 다름). 범위 조정은 필요 없다고 판단했다.
3. `wooden_market_stall_3d_model`(씬 루트, 단일 메시 34,689 정점)에 MeshCollider(non-convex, 같은 메시)를 에디터 API로 추가했다. 위치·회전·스케일은 그대로이며 작업대 자식으로 옮기지 않았다.
4. `JH04TestScene`만 저장하고 닫았다. `JH04Offline`의 미저장 변경은 건드리지 않았다.

## 결과(에디터에서 확인)
- `Workbench` 루트: (2.40, 0.61, 1.12). BoxCollider 제거, MeshRenderer는 비활성 그대로.
- 자식: `WorkbenchRack` (2.40, 0.11, 1.12), `wooden_workbench_3d_model_low` (2.40, 0.11, 1.12, Y 179°, 스케일 1.2, MeshCollider). `WorkbenchBox` 제거.
- `TowerTrialPanel._screenBox` = 모델, `_isRackMode` = false.
- 판매대 바운드 중심 (1.84, 1.18, 0.75), 반경 (1.92, 1.19, 1.27) — 작업대가 판매대 안에 들어간다.
- 상호작용 선택은 거리 판정만 쓴다(`Assets/01.Scripts`에 상호작용용 Raycast 없음). 판매대 콜라이더가 상호작용을 가리지는 않는다.

## 변경 파일
- `Assets/00.Scenes/Jihun/JH04TestScene.unity` (메뉴 실행·판매대 콜라이더, 에디터 저장. 사용자가 이전에 배치한 모델 두 개의 미커밋 변경도 이 파일에 함께 있다)

## 검증
- L1: 메뉴 실행 로그 정상, 오류 없음(read_console).
- L2: 에디터에서 계층·컴포넌트·참조 확인(위 결과).
- 미실행: 플레이(M0) — 모델 가까이에서 작업대 화면이 열리는지, 판매대 기둥·카운터 메시에 막혀 작업대에 3.0m 안으로 접근하지 못하는 경우가 있는지.
