# JH04 플레이어 이동 불가 수정 — JH04 전용 플레이어 변형

작성일: 2026-10-28
브랜치: `feature/jihun`
이어받은 기록: [인수인계](../../handover/김지훈/2026-10-28/JH04-플레이어이동불가-세션인수인계.md)

## 결론
- `JH04Offline` NetworkManager `playerPrefab`을 새 Prefab Variant `Assets/00.Scenes/Jihun/JH04Player.prefab`(GUID `9396f17f3460631439cea5740ad7f38a`)으로 바꿨다.
- 변형은 `Tech 1.prefab`을 바탕으로 `PlayerController._requireLocalWorldReady`만 `false`로 덮어쓴다. 원본 `Tech 1.prefab`·`PlayerController.cs`(최명기)는 바꾸지 않았다.
- 상태 조건은 풀렸다. 실제 키 입력으로 걷기·달리기·점프·배 탑승은 아직 확인하지 못했다.

## 수행 과정
1. UnityMCP 연결 확인 → 연결됨. `EditorUtility.scriptCompilationFailed=False`, 콘솔 오류 0(머지 `5839ee2` 뒤 첫 확인).
2. 수정 전 재현(플레이 모드, 코드로 `StartHost` → `JH07Lobby`에서 `LobbyPlayer.RequestSetReady(true)` → `JH04TestScene`).
   - `phase=InProgress`, `_requireLocalWorldReady=True`, `CanRunLocalWorld()=False`, Rigidbody `isKinematic=True`, `PlayerInputReader enabled=False`.
   - 세션 단계 조건은 통과하므로 남은 실패 조건은 `MapStateNet` 준비뿐이다. 인수인계의 원인 추정과 일치.
3. 에디터 API(`PrefabUtility.InstantiatePrefab` → `SerializedObject`로 값 변경 → `SaveAsPrefabAsset`)로 변형을 만들었다. 덮어쓰기 목록: `_requireLocalWorldReady=0`, 변형 기본 루트 Transform(원본과 같은 0·단위 회전), `m_Name`.
4. `JH04Offline` NetworkManager `playerPrefab`을 변형으로 바꾸고 저장. git diff는 `playerPrefab` 한 줄뿐.
5. 수정 뒤 같은 경로로 재확인: 플레이어 `JH04Player [actor=1 connId=0]`, `CanRunLocalWorld()=True`, `isKinematic=False`, `PlayerInputReader enabled=True`. 플레이 종료 뒤 콘솔 오류 0.
6. `InputSystem.QueueStateEvent`로 W 키를 넣어 봤으나 Game 뷰 포커스가 없어 키가 곧 리셋됐다(`backgroundBehavior=ResetAndDisableNonBackgroundDevices`). 위치가 약 0.2 움직인 한 번이 있었지만 걷기 확인으로 보지 않는다.

## 결정 이유
- 인수인계 2절의 선택안을 따랐다. Player 코드 완화는 최명기 영역이고 실제 게임에서 맵 준비 전 이동을 허용할 위험이 있다. JH04에 맵 구성을 넣는 안은 World 의존이 크다.
- 변형 위치는 Jihun 소유 경로인 `Assets/00.Scenes/Jihun/`로 했다(`02.Prefabs/Player/`는 최명기 영역).
