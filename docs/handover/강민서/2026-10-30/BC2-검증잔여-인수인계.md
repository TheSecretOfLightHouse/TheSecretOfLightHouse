# 인수인계 — BC2 통합 검증 잔여
경로: docs/handover/강민서/2026-10-30/BC2-검증잔여-인수인계.md
작성일: 2026-10-30
브랜치: feature/minseo
담당 파트: World 강민서 / Monsters 변경은 이번 사용자 합의 범위

## 1. 목표
몬스터7종의 공통 부력·잠수·표류 연결을 다인·실제 전투까지 검증한다. [작업 원문](../../../강민서/2026-10-30/BC2-몬스터-부력-연결.md)의 재개 결과부터 읽는다.
## 2. 완료한 것
코드·7종 프리팹 연결, Unity 컴파일, 전용 실제 Mirror호스트 기본/큰파도 전환, 슬롯경계·사망회수, MainGame 시연과 상어 실제 이동/물살 관측. 세부 근거는 원문 표를 따른다. 상태는 호스트 로컬 조건부 통과다.
## 3. 완료하지 못한 것
M2/4인·별도PC, 실제 대상선택/BT/피해 종단, 표본/지형 실패시간초과, 배·Player 회귀, 최대동시수·장시간·성능/GC. 테스트의 보스 단계 주입을 전체 전투 성공으로 바꾸지 않는다.
## 4. 현재 저장소 상태
사용자 요청으로 BC2 구현·연결·시험·문서만 한 커밋에 포함한다. 커밋 해시는 git log에서 해당 feat 제목으로 확인한다. 다른 변경(Clock·F3·Player·지도·MainOffline·Mirror·개인 기록)은 제외·보존한다. 새 씬은 Minseo/BC2/MonsterBuoyancyChecks.unity 하나이며 본편씬 저장 없음, 새 SO 없음.
## 5. 검증 현황
L1: 컴파일 오류0 및 diff --check. L2: 호스트 로컬·7종 부력·두 보스 상태 전환·큰 파도1183관측·MainGame 이동/물살. L3/M2 이상: 미실행. 별도 원격·4인은 미검증이다.
## 6. 차단 조건
새 소유권 승인 대기 없음. 사용자 합의는 Monsters 변경·종별 가안 위임·MosaWhale 포함을 포괄한다. 원격/4인 실행 환경을 마련하고 검증해야 한다. 현재 값은 가안이다.
## 7. 다음 세션의 첫 행동
1. git 상태와 이 원문을 대조하고 에디터 Play/활성 씬·미저장을 확인한다.
2. 전용 BC2 씬 Play에서 StartBC2Checks.cs → RunBC2Scenario.cs로 기본 회귀를 실행한다(자세한 사용법 원문).
3. 실제 메인 접속 경로로 M2 이상을 구성해 서버만 물리 계산·원격 Kinematic/표본미점유·동기화 위치를 검증한다.
4. 실제 배 탐지와 전투·취소·사망·표본실패/지형걸림을 검사한다. 배·Player 회귀와 최대수/GC를 측정한 후 상태를 갱신한다.
## 8. 주의
MosaWhale 도약3단계는 기존 궤적을 보존하기 위한 부력·중력·표류 중단 예외다. Spinocroc는 부력을 유지한다. 프리팹/YAML 직접 편집 금지. 시연 카메라·추적중심 변경은 런타임 전용이다. MainOffline startPlayerCount4→1과 다른 병행 변경은 BC2 변경으로 취급하거나 되돌리지 않는다. 전체 인수 기준이 충족되기 전 BC2 전체 완료로 올리지 않는다.
