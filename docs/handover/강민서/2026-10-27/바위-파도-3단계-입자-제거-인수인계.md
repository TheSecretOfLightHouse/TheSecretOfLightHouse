## 1. 목표
- 새 파도 렌더(`BreakerWave`, 해안 `SurfCrest` 교체)가 끝났으므로, 사용자가 부정한 **기존 입자 방식(탄산 점·분무 안개·시트)**을 제거한다.
- 완료 기준: ① 바위·해안 파도 모양이 이번 세션의 캡처와 같거나 더 낫다 ② 입자 때문에 생기던 흰 막대·안개 덩어리가 사라진다 ③ 컴파일·셰이더 오류 0 ④ `BreakerEventChecks.RunAll()` 통과.
- 근거: [설계](../../../강민서/2026-10-27/물보라-부서지는-파도-리서치와-설계.md) 8절 3·4번, [작업 결과와 캡처](../../../강민서/2026-10-27/바위-부서지는-파도-모양-확인-결과.md).

## 4. 3단계가 건드릴 파일과 주의
기존 입자 코드는 이전 세션(`물보라-분무-파티클-재제작`)이 만든 미커밋 변경이며 현재 내용을 반드시 먼저 읽는다. 아래 설명은 문서·이전 읽기 기준이고 줄 단위로 재확인하지 않았다.
- `Assets/01.Scripts/02.World/Ocean/View/WaterSprayRenderer.cs`: 입자 버퍼(`Capacity` 8192)와 컴퓨트 커널(`SprayUpdate`·`ShoreSpray`·`ContactSpray`) 디스패치, 입자 그리기. **같은 클래스가 `SurfCrest`(해안 파도)도 그린다(`_crest`, `96*20*6` 정점). 이 부분은 지우면 안 된다.** 이름이 입자 전용이라 정리 시 해안 그리기를 `BreakerWaveRenderer` 쪽으로 옮기는 안이 깔끔하나 별도 결정이다.
- `Assets/07.Materials/World/Shaders/WaterSpray.shader`, `Include/WaterSprayShapes.hlsl`: 물방울·안개·벽 시트 3종.
- `Assets/07.Materials/World/Shaders/SurfaceInteraction.compute`: `ContactSpray`의 플룸 발생, `SprayUpdate`.
- `Assets/01.Scripts/02.World/Ocean/View/SurfaceInteractionGrid.cs`(`SprayIntensity`), `WaterContactEffectsView.cs`(`_sprayShader`, `_sprayIntensity`, `_crestShader`).
- `SurfaceInteractionGrid`·컴퓨트의 **정지 접촉 거품(`_StaticContactFoam`)과 수면 교란은 입자가 아니므로 유지**한다(`섬-물느낌-3단계-정지물거품-결과.md`).

## 5. 사용자 결정이 필요한 것 (구현 전 확인)
- **물방울을 남길지**: 설계 문서는 "가장자리 물방울만 유지"이고 사용자는 점 방식을 부정했다. 전부 제거할지 물방울만 남길지 첫 질문으로 정한다.
- **정리 범위**: 입자 코드를 완전히 삭제할지, 인스펙터 값(`_sprayIntensity`)으로 끄고 보존할지. 삭제하면 씬의 직렬화 필드(`_sprayShader`, `_sprayIntensity`)가 사라져 `WorldSessionGame.unity`를 다시 저장해야 한다.

## 7. 검증 현황과 절차
- L1 컴파일·셰이더 오류 0, `BreakerEventChecks` 7종 통과(마지막 실행).
- L2 정지 캡처뿐. 움직임·폭풍·4인·GPU 미검증.
- **3단계 전/후 비교:** 같은 바위·같은 사건 시점으로 찍어 파도 모양이 변하지 않음을 확인한다. 아래 재현 절차를 쓴다.

## 8. 첫 행동과 재현 절차
1. [결과 문서](../../../강민서/2026-10-27/바위-부서지는-파도-모양-확인-결과.md)와 위 4절 파일을 읽고 `git status`로 소유를 확인한다. 사용자에게 5절 결정을 묻는다. `CLAUDE.local.md` 3장 절차(계획 제시, 단계는 컴파일 단위)를 따르고, AI 직접 작성 허용 여부를 다시 확인한다(이전 세션 허용은 이어지지 않는다).
2. 구현 후 `recompile` → 컴파일 오류 0 확인 → `Breaker/Run All Tests`(또는 eval `BreakerEventChecks.RunAll()`).
3. 캡처 재현(에디터 MCP, 1인 Play): 쿼터스타트 `WorldSessionGame`.
   - 세션 로딩 후 `EditorApplication.isPaused=false`. 시계는 `GameClock.Resync(NetworkTime.time-4.0)` 다음 호출에서 `Stop()`.
   - 바위 사건 고정: `WaterContactEffectsView._clock`을 리플렉션으로 `ManualClock`으로 바꾸고, `_breaker._collector`의 `_sources[0]`에 대상을 넣고 `_nextScan=float.MaxValue`, `<Count>k__BackingField=1`로 단일 소스로 만든다. 사건 시작 시각은 `BreakerEventSchedule.Collect`로 나이 0 근처를 찾는다.
   - 임시 카메라(`depth=50`)로 `capture_game_view`. 시점: 접근 0.4s, 꺾임 1.05s, 충돌 1.35~1.6s, 흘러내림 1.85~2.0s.
4. 결과를 `docs/강민서/2026-10-27/`에 저장하고 pointer를 갱신한다.

## 9. 주의 (도구·함정)
- **포커스(플레이어)를 땅 없는 곳으로 텔레포트하면 추락해 y가 -8만이 되고, 그리기 경계 상자(`Bounds(focus,…)`)가 따라가 모든 파도가 컬링된다.** 바위 옆 육지 위(`Physics.Raycast`로 지면 확인)로 옮긴다.
- `Material.SetVector` 등 비선언 프로퍼티는 셰이더 재임포트 때 사라진다. 파도 값은 전역 셰이더 값(`Shader.SetGlobal*`)을 쓴다. 입자 쪽 머티리얼이 같은 문제를 겪는지는 확인하지 않았다.
- 잘못된 매개변수의 MCP 호출이 콘솔 오류를 내면 Error Pause가 걸려 Play 로딩이 멈춘다. `EditorApplication.isPaused=false`로 푼다.
- 컴파일·Play 진입 직후에는 MCP 연결이 한두 번 끊긴다. 재시도한다.
- `Assets/Mirror/`·`ThirdParty/`·`.unity`·`.prefab`·`.asset`은 YAML을 직접 편집하지 않는다. 씬 필드는 에디터(MCP `SerializedObject`)로만 바꾸고, 저장 전후 diff를 비교한다.
