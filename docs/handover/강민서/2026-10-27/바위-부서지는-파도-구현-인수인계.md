## 1. 목표
- 최종 상태: 섬 바위에 파도가 **철썩 밀려오며 부서지는** 연출. 입자 점·폭발이 아니라 파도 자체가 급해지고(접근) 앞으로 꺾이고(꺾임) 바위에 부딪혀 하얀 난류 시트가 퍼지며 물막이 바위 면을 타고 오르고(충돌) 줄무늬로 흘러내리며 거품이 되돌아 나가는(흘러내림) 약 2.4초짜리 사건. 바위마다 3~6초 간격으로 엇갈려 일어나고 세기는 날씨 에너지에 비례.
- 근거 문서: [레퍼런스 분석·리서치·설계](../../../강민서/2026-10-27/물보라-부서지는-파도-리서치와-설계.md)(구현의 기준). 레퍼런스 이미지는 `docs/강민서/2026-10-27/물보라/레퍼런스/` 3장. 사용자 지적은 "탄산 톡톡도, 폭발 퐁퐁도 아니고, 이미 만든 하얀 거품 띠 파도(`SurfCrest`)가 밀려오며 부서지는 모양"이다.

## 5. 검증 현황
- L1: 컴파일·셰이더·컴퓨트 오류 0(마지막 컴파일 시점). Unity 테스트는 실행하지 않았다.
- L2: 퀵스타트 1인 Play에서 같은 시점 캡처·입자 수 측정(M0). 움직임의 자연스러움은 정지 캡처 한계로 판정하지 못했다.
- L3 / 멀티플레이: 4인·`MainGame`·개발 빌드 모두 미실행.
- 미검증: 폭풍 날씨, 정박한 배, GPU 비용, 클라이언트 간 모양 차이(입자·거품은 로컬 시뮬).

2. 현재 코드를 확인한다: `SurfaceInteractionGrid.Rasterize`(콜라이더 수집), `SurfCrest.shader`(거품 띠 파도의 단면·위상), `WaterSprayRenderer`·`SurfaceInteraction.compute`(제거 대상인 입자 발생). `git status`로 위 변경 목록과 대조한다.
3. 구현 순서(설계 8절 기준): ① `BreakerWaveRenderer`(CPU, 바위별 사건 스케줄, 너울 방향은 `WaterSamplerHost.Inputs.Waves`) → ② `BreakerWave.shader` + `Include/BreakerWaveProfile.hlsl`(접근·꺾임 립 리본·충돌 시트·흘러내림) → ③ `WaterSpray`에서 안개·시트 제거(물방울만 유지) → ④ 컴퓨트 `ContactSpray`의 플룸 발생 제거.
4. 검증: 같은 바위를 4단계 시점별 연속 프레임으로 캡처하고, 사용자가 눈으로 판정하도록 이미지를 `docs/강민서/2026-10-27/`에 저장한다.

## 8. 주의
- 되돌리면 안 되는 변경: `IslandTerrainV8.shader`의 GUID(`230e3c6b…`)는 원본 쪽에 있다. 복제·이름 변경은 에디터 안(`rename_asset`)에서만 한다. V12 섬 시각 파생물은 공개 git에 올리지 않는다.
- 도구 함정(실행 검증 시간을 크게 줄인다):
  - 컴퓨트·셰이더를 고친 뒤 첫 Play는 컴파일 지연으로 세션 로딩이 `LoadTimeout`으로 끝난다. Play를 껐다 켠다.
  - Play 진입 직후 `eval` 첫 호출이 5초 시간 초과로 실패하며 에러 일시정지를 건다. `editor_pause`로 해제한다(이미 재생 중일 때 호출하면 오히려 일시정지된다. `editor_status`의 `playMode`로 확인).
  - 시계는 `GameClock.Resync(Mirror.NetworkTime.time - 4.0)` 후 **다음 호출에서** `Stop()`(같은 호출에서 정지하면 하늘이 갱신되지 않는다).
  - 입자·거품 확인은 포커스(메인 카메라)를 바위 해안으로 옮겨야 한다. 격자는 포커스 주변 32m만 시뮬한다.
  - 퀵스타트 토글(`Tools/World/Quick Start From WorldSessionGame`)은 기본 켜짐이다. 누르면 꺼진다(`SessionState`로 확인).
  - 수면 재질의 런타임 인스턴스를 `.material`로 건드리지 않는다(에셋 오염). `sharedMaterial` 런타임 인스턴스 값 변경은 Play 종료로 사라진다.
- 다른 사람이 병행 작업 중인 파일: `ClearOcean.shader`·`OceanOpticsProfile`은 팔레트·라군 비례 세션도 수정한다. 수정 전 `git diff`로 상태를 확인한다. 다른 영역 파일(`03.Interaction/`, `05.Player/`)은 수정하지 않는다.
