## 현재 확정 계약
- 별도 연출 씬 로드 없이 **실제 메인 씬의 등대섬·촉수**로12초 Timeline을 재생한다. 기존 플레이어 카메라는 이동시키지 않고 연출 카메라로 화면만 전환한다.
- 소환 승인 → Preparing → Playing → Returning → Combat. 각 클라이언트의 준비/복귀 보고와 서버 공통 시각을 사용한다.
- 메인 월드 시간·파도·배 물리는 계속 진행한다. 입력/UI 클릭과 새 서버 행동 요청만 잠그고, 이미 서버가 승인한 작업은 계속한다. UI 상태는 보존하고 연출 중 가린 뒤 복구한다.
- 플레이어·배 피해 보호, 난파/구조 복구 대기 타이머 보존은 유지한다. 개인 연출 준비 실패자는 연출만 생략하고 공통 전투 시작까지 보호·잠금을 유지한다.
- 연출 종료 시 같은 촉수 객체가 최종 감기/등장 자세로 남는다. 등대 공격은 **등대 HP 감소**이며 수리 진행도 감소가 아니다.
- 등대 촉수의 공격은 조이기만 사용한다. 주변 촉수는 동일 모델/애니메이션을 공유하며 배 공격은 후속 연결이다.
- 테스트 씬 삭제는 아직 하지 않았다. 본편 통합 확인 후 삭제 가능하다는 사용자와의 대화만 있으며 삭제 요청은 없었다.

## 다른 컴퓨터로 옮길 때
- **현재 PC의 미커밋·미추적 파일은 다른 PC에서 pull만 해서는 받을 수 없다.** 아래 파일을 `.meta`와 함께 커밋/푸시하거나 동일 상태로 전달해야 한다. 이번 요청으로 커밋·푸시는 수행하지 않았다.
- Unity 버전은 `ProjectSettings/ProjectVersion.txt` 기준 **6000.0.83f1**. `Assets`, `Packages`, `ProjectSettings` 및 문서를 공유하고 `Library`, `Temp`, `Logs`, `UserSettings`는 복사 대상에서 제외한다.
- Git 본편뿐 아니라 `Assets/ThirdParty/1조 Unity Asset/` SVN 체크아웃/업데이트도 필요하다. 섬 모델·재질이 이 구매 에셋에 의존한다. 폴더명/원본 `.meta`를 유지한다. [파일 관리 규칙](../../../unity/LARGE_FILES.md)을 따른다.
- 기존 LFS 파일이 포인터 상태로 남지 않았는지 확인한다. 새 LFS 규칙을 추가하지 않는다. 새 PC는 저장소의 Git 설정 안내에 따라 설정한다.
- 데스크톱의 Blender 원본 경로나 임시 실행 스크립트는 Unity 런타임 의존성이 아니다. 추가 모델링이 필요하면 `.blend`/원본 모델은 별도로 확보한다. 이번 인수인계는 Unity 작업 상태에 대한 것이다.
- Unity MCP 연결은 새 PC에서 다시 확인한다. 기존 세션 연결·임시 host fixture·캡처는 재개 조건이 아니다.

## 코드에서 이어 볼 지점
- `MainIslandFacilitiesBuilder`가 생성한 실제 섬에 `SummonCinematicView.BindIsland`를 호출한다. 미리 배치된 rig가 있으면 재사용하고 없으면 Settings의 프리팹을 생성한다. 본편 씬에 수동으로 또 추가해서 중복시키지 않는다.
- `MainSceneSummonPresentation.Awake`가 촉수를 숨긴다. `Synchronize`는 서버 elapsed에 맞춰 처음 seek 후 연속 재생하며0.1초 초과 오차만 보정한다. `Finish(true)`가12초 최종 자세를 유지한다.
- `CinematicLoadDeadline`/load timeout 이름은 남아 있지만 이제 **섬/프리팹 연결 준비 제한시간**이다. 씬을 로드한다는 뜻이 아니다.
- `SummonCinematicPreview`는 네트워크 비활성·단일 씬의 독립 미리보기다. 실제 rig 프리팹에는 없으며 테스트 씬 Director에만 있다. 본편 동작 검증을 미리보기 성공으로 대체하지 않는다.
- World 연결은 강민서 영역, Tower는 김지훈 영역, Player/UI 보호/입력은 최명기 영역이다. 기존 사용자 승인 범위의 연결을 보존하고 후속 범위 확대는 저장소 담당 경계 지침을 따른다.

## 새 PC에서 확인 순서
1. `git status --short`, 브랜치/최신 변경과 `.meta`, SVN 섬 원본을 확인한다. Unity 임포트·컴파일이 완료될 때까지 기다린다. Missing Script/Material/Prefab부터 해결한다.
2. `TentacleIslandTest.unity`만 단독으로 열고 Play. 네트워크 없이12초 연출이 반복되는지 확인한다. 실제 섬 하위 MainSceneSummonRig와 비활성 보존된 옛 테스트 촉수는 중복 활성화하지 않는다.
3. 설정 에셋의 SummonPresentationPrefab이 MainSceneSummonRig이고 길이가12초인지 확인한다. Timeline Director의 촉수6개·카메라·Audio/물보라 참조가 유지되는지 확인한다.
4. 본편의 기존 네트워크 시작/소환 승인 경로로 테스트한다. 승인 임계나 수리 상태를 임의로 바꾸지 말고 해당 기능의 테스트 절차를 따른다. 서버승인 → 실제 섬에 rig1개 →12초 연출 → 카메라/UI/입력 복구 → Combat 순서를 점검한다.
5. 연출 동안 씬 추가 없음, 월드/배 이동 지속, 피해 보호, 이미 승인된 작업 진행, 난파 잔여시간 보존을 확인한다.
6. 호스트+별도 원격 클라이언트에서 공통 시작/종료, 지연 준비·연출 준비 실패, 늦은 접속과 최종 촉수 표시, 취소·접속 종료의 복구를 검사한다. 실패자 때문에 전원 보호가 먼저 끝나면 안 된다.
7. 본편에서 실제 조명·날씨·바다·카메라 culling/후처리와 컷 구도가 맞는지 확인한 뒤 연출을 조정한다. 테스트 씬 삭제는 그 뒤 결정한다.

## 검증 증거와 한계
- 단독 Play: 씬1개, Timeline 연속 재생. 종료 후12초 Paused, 연출 카메라 꺼짐, 촉수 SkinnedMeshRenderer6개 활성 유지.
- 임시 KCP 로컬 호스트+ready 플레이어+Tower fixture: Preparing→Playing→Combat 및 두 번째 시퀀스 확인. Playing 입력 잠금/연출 카메라 ON·기존 카메라 OFF, Combat 반대로 복구. 전 과정 씬1개. 검사 직후 콘솔 오류/경고0개.
- 임시 fixture는 Play 종료로 제거했다. 영구 테스트 버튼/자동화 테스트로 저장한 것이 아니다.
- 이전 도메인 리로드에서는 ShaderGraph의 domain-backup 직렬화 오류를 관찰했다. 실행 오류와 분리해 기록했고 패키지는 수정하지 않았다.
- **실제 본편 전체 소환 경로·별도 원격 M2·개인 준비 실패·재접속의 새 방식은 아직 미검증**이다. 상세 증거는5단계 작업 원문에 있다.
