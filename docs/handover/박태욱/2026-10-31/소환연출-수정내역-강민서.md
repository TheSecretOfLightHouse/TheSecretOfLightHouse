## 1. 목표
- 소환 연출 구현 중 World 코드에 추가한 연결을 설명하고, 섬 생성 코드를 수정할 때 유지할 계약을 전달한다.
- 기준: [담당 경계](../../../CODE_OWNERSHIP.md), [최종 연출 결정](../../../design/final-battle-summon-cinematic-decisions.md).
- 현재 방식은 **실제 메인 씬의 등대섬에서 12초 Timeline을 재생**하는 것이다. 별도 섬·바다·조명을 복제하거나 Additive 연출 씬을 로드하는 이전 방식은 대체됐다.

## 2. 완료한 것

### 직접 수정한 코드 — 1개

| 파일 | 수정한 위치·내용 | 이유·영향 |
|---|---|---|
| [MainIslandFacilitiesBuilder.cs](../../../../Assets/01.Scripts/02.World/Islands/Net/MainIslandFacilitiesBuilder.cs) | `Step()`의 `tower.BindWorkbench(workbench)` 다음에 `SummonCinematicView`를 얻고, 존재하면 `BindIsland(_presentation.transform)` 호출 | 호스트와 각 클라이언트가 만든 실제 로컬 등대섬에 촉수·카메라·효과 Rig를 연결한다. 별도 표시 섬을 만들지 않고 실제 환경에서 연출한다. |

- 변경 근거: `3fe79744`의 해당 파일 diff. 추가한 것은 위 null 확인·바인딩 호출 5줄이다.
- `BindIsland`는 같은 섬/Rig가 이미 연결돼 있으면 재생성하지 않는다. 기존 Rig가 있으면 재사용하고 없으면 등대 설정의 `SummonPresentationPrefab`을 실제 섬 하위에 생성한다.
- 서버 HP/공격 상태는 네트워크 등대 프리팹이 담당하고, 섬 하위 Rig는 로컬 표현이다. 주변 촉수의 서버 박스 판정은 호스트의 같은 배치 Transform을 사용한다.
- 섬 생성 알고리즘·맵 배치 수치·날씨·월드 시간·파도/부력 계산을 이 연출 작업에서 변경한 것으로 보지 않는다. 같은 파일의 다른 후속 수정은 별도 작업이다.

### 연결 에셋과 다른 담당 계약
- 본편 등대 프리팹 `Assets/02.Prefabs/World/MainIsland/MainIslandLighthouse.prefab`의 등대/네트워크 연결은 김지훈 문서에서 설명한다. World 폴더에 있다는 이유로 몬스터 서버 로직을 World 담당으로 넘기지 않는다.
- Rig·Timeline·촉수 공격·먼지/파편은 박태욱 구현이다. 입력/피해 보호는 최명기·김지훈 인수인계를 함께 참고한다.
- 외부 버블 원본은 `Assets/ThirdParty/1조 Unity Asset/ThirdParty/NamuFX/`에 있고 SVN 공유 대상이다. Git만 받아서는 이 원본이 전달되지 않는다.

## 4. 현재 저장소 상태
- 직접 코드 변경은 `3fe79744`에 커밋돼 있고 현재 HEAD에서도 바인딩이 남아 있음을 확인했다.
- 조사 시작 시 작업 트리는 깨끗했다. 이번 작업은 인수인계 문서 작성만 수행한다.
- 강민서 개발 씬이나 통합 씬을 이 연출 연결 목적으로 저장하지 않았다. 테스트 씬 변경은 박태욱 영역이다.
- 최근 develop 병합으로 들어온 다른 World 작업을 이번 수정 내역에 포함하지 않았다.

## 5. 검증 현황
- L1: 해당 커밋 diff와 현재 코드의 호출을 대조했다.
- L2: [5단계 기록](../../../박태욱/2026-10-30/소환연출-5단계-Timeline.md)에 단독 재생·임시 호스트에서 씬1개 유지, 실제 섬 하위 Rig, 카메라 복귀·최종 자세 유지 확인이 있다.
- 사용자 확인: 본편 촉수 크기/배치 만족, 등대 HP 감소·타격 타이밍 일치 보고.
- L3/M2: 이번 실제 메인 씬 연출 경로의 별도 원격 통합은 미검증이다. 이번 문서 작성에서 Unity 실행을 새로 하지 않았다.

## 6. 차단 조건
- 담당자에게 추가 게임 규칙 결정을 요청하는 항목은 없다.
- 별도 원격 환경에서 실제 월드 생성·바인딩·연출 준비/복귀를 확인해야 통합 완료로 볼 수 있다.
- 새 섬 구조에서 `_presentation.transform`이나 시설 수명 계약이 달라지면 김지훈·박태욱과 연결 대상을 맞춰야 한다.

## 7. 다음 세션의 첫 행동
1. 현재 `MainIslandFacilitiesBuilder.Step()`에서 실제 섬을 `BindIsland`에 전달하는 호출이 유지되는지 확인한다.
2. 본편에서 호스트와 원격 각각 Rig가 실제 섬 하위에 한 개만 생성되는지 확인한다.
3. 월드 생성 지연·섬 교체/정리·소환 중단 시 오래된 Rig가 남거나 카메라를 빼앗지 않는지 확인한다.

## 8. 주의
- World 생성 완료 신호나 배 물리를 연출 때문에 멈추지 않는다. 이미 승인된 작업은 기존 조건으로 계속하고 새 행동만 막는 계약이다.
- `CinematicLoadDeadline`은 현재 씬 로드 시간이 아니라 **섬/Rig 연결 준비 기한**이다.
- 월드 코드의 다른 변경을 일괄 되돌려 이 5줄만 복구하는 식으로 처리하지 않는다.
