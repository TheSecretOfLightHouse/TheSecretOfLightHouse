## 1. 목표
- 소환 연출을 위해 Player 코드에 넣은 피해 보호·입력·새 행동 차단·난파 복구 시계 변경을 전달한다.
- 기준: [담당 경계](../../../CODE_OWNERSHIP.md), [최종 연출 결정](../../../design/final-battle-summon-cinematic-decisions.md).
- 확정 정책은 월드/배 물리를 계속 진행하면서 입력과 새 서버 행동을 막고, 플레이어·배 피해 및 난파/구조 복구 타이머를 보호하는 것이다. 이미 서버에서 승인된 일반 작업은 기존 조건으로 계속한다.

### 공용 계약
- `ServerCinematicProtection.IsActive`: 서버 보호 여부. 연출 Preparing/Playing/Returning 전체와 공통 Combat 직전 여유 동안 유지되며, 서버가 Combat으로 넘길 때 해제한다.
- `ServerCinematicProtection.RecoveryTime`: **난파 복구용** 시계. 연출 구간의 시간을 제외한 값이다. 기한과 현재 시각을 서로 다른 시계로 비교하면 안 된다.
- `CinematicPresentationLock.IsLocked`: 해당 클라이언트 입력 표시 잠금. 월드 시간·네트워크 시계·배 부력/관성 정지 기능이 아니다.
- 이 공통 타입의 소유·연출 서버 상태는 [김지훈 인수인계](소환연출-수정내역-김지훈.md)를 참고한다.
- 상호작용 Relay도 연출 중 새 전송/취소를 막는다. 기기 비활성화가 승인된 작업을 키 해제 취소로 바꾸지 않도록 함께 적용된 변경이다.

## 4. 현재 저장소 상태
- 위 변경은 커밋돼 현재 HEAD에 포함돼 있다. 작업 트리는 조사 시작 시 깨끗했다.
- 이번 인수인계 작성 중 Player 코드·프리팹·최명기 개발 씬·InputAction 에셋을 수정하지 않는다.
- 현재 파일에는 이후 다른 작업도 병합돼 있다. 이 문서는 위 두 커밋에서 추가한 연출 가드와 시계 변경을 설명하며 파일 전체를 박태욱 수정으로 분류하지 않는다.

## 5. 검증 현황
- L1: 두 커밋의 실제 diff와 현재 보호/입력 호출을 대조했다. 이번 문서 작업에서 새 실행 검증은 하지 않았다.
- [1~3단계 원문](../../../박태욱/2026-10-30/소환연출-서버보호와-난파타이머.md): 실제 임시 KCP 서버에서 모든 BoatDamageType의 큰 피해에도 내구도·방어막 유지, 보호 해제 후 정상 피해·방어막 소모, 새 downed 차단 확인.
- 같은 시험에서 RecoveryTime 정지·잔여30초 보존과 해제 후 시계 재개, 다중 보호 owner의 개별 해제를 확인했다. 서버 상태를 주입한 격리 검사이며 실제 난파 전체 시나리오가 아니다.
- [4단계 원문](../../../박태욱/2026-10-30/소환연출-4단계-Additive-전환.md): 당시 방식의 입력기기/카메라/UI 복구·실패 중 보호 유지·물리 시간 진행 확인. 현재 메인 씬으로 바뀐 뒤의 원격 통과로 확대하지 않는다.
- [7단계 원문](../../../박태욱/2026-10-31/소환연출-7단계-주변촉수-배공격.md): 실제 배 피해 API로 탑승 배 다중피해·빈배/난파/범위밖 제외·준비 중 하선 제외·동시 난파 확인. 탑승 플래그는 fixture 주입이므로 실제 승선 입력 시험은 아니다.
- L3/M2: 별도 원격에서 이번 연출 통합은 미검증이다.

## 6. 차단 조건
- 실제 플레이어·배·구조 상호작용과 원격 환경을 연결해 전체 복구/아이템 정산을 확인해야 한다.
- 독립 플레이어 HP 시스템이나 새 피해/복구 진입점을 추가하면 이 공통 보호를 함께 소비해야 한다. 현재 확인한 경로만으로 미래 피해 경로까지 보호된다고 볼 수 없다.
- 현재 주변 촉수는 사용자 결정에 따라 안전지대를 무시한다. 배 자체의 빈배/난파/방어막/피해 보호 검사는 유지한다.

## 7. 다음 세션의 첫 행동
1. 현재 능력·대포·대쉬·승하선의 보호 가드가 남아 있는지 확인한다.
2. 실제 난파 상태에서 연출을 시작하고 잔여 대기 시간이 보존되는지, 구조/복구 완료와 정산이 연출 뒤 한 번만 진행되는지 확인한다.
3. 배를 움직인 채 연출을 시작해 관성/부력과 복귀 후 입력 초기화를 호스트·원격에서 비교한다.
4. 연출 직전 승인된 작업과 연출 중 새 요청의 응답을 구분해 검사한다.

## 8. 주의
- RecoveryTime과 NetworkTime을 섞어 기한을 계산하거나, 전체 timeScale을0으로 바꿔 대체하지 않는다.
- 보호 중 기존 downed 상태를 자동 해제하거나 배를 정지·순간이동시키는 정책은 추가하지 않는다.
- 입력기기 비활성화와 서버 가드는 함께 필요하다. 한쪽만 제거하지 않는다.
