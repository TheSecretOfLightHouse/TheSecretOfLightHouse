## 2. 인계 회신

| 인계 항목 | 회신 |
|---|---|
| Selector 레이어 마스크·NetId 0 제외·`Supports(DefaultAction)` 필터·요청 직전 갱신 | 수용, 코드 그대로 유지(기본값 0 포함). 이 필드가 생기기 전에 저장된 김지훈 시험 프리팹 `NetworkTestPlayer.prefab`은 마스크 0이 되어 JH07Game 시험 대상(Default 레이어)을 못 고르므로, 에디터 저장으로 그 프리팹에 마스크 Everything(`m_Bits: 4294967295`)이 저장됐다(2026-10-17). `tech.prefab`과 본편 기본값에는 영향 없음 |
| 같은 이름 어댑터 2개 | Interaction 쪽 `03.Interaction/Relay/View/PlayerInteractionInput.cs`(+`.meta`)를 삭제했다. 프리팹·씬 GUID 참조 없음 확인. 이제 E키 어댑터는 Player 쪽 `05.Player/Control/PlayerInteractionInput` 하나다 |
| "TryStartMatch는 씬 로딩만 검사하는 TODO" | 낡은 설명이다. 판 시작 게이트(`IMatchStartGate`·`RegisterStartGate`)는 PR #48로 develop에 있다. 남은 것은 강민서의 World 쪽 등록이다 |
| `HarvestSpot` 변환기 중복 등록 | 현재는 서로 다른 씬이라 충돌 없음(본편 연결 시 주의). `TargetResolver.RegisterAdapter`는 종류당 하나만 받으므로 시험 `HarvestInteractionHandler`와 World `HarvestHost`를 함께 켜면 늦은 쪽이 `false`. 본편은 World 변환기를 쓰고 처리기는 `IHarvestSpotRegistry.TryConsume`으로 잔량을 차감하는 구성을 제안한다(강민서에게도 같은 내용 전달). 결정은 세 사람이 한다 |
| 좌클릭 SpotId 경로 | 김지훈 요청 경로(`TrySendToNonNetworkTarget`)는 그대로 쓰고 있다. 다만 SpotId를 World `HarvestSpot`이 아니라 `LocalHarvestTestSpot`에서 읽고(`PlayerHarvestProbe.cs:124`), 서버에서 강민서 `HarvestTargetAdapter`·`TryConsume`을 쓰지 않아 클릭마다 드롭 1개가 생긴다. 인계 §3의 미연결 내용과 같으며 본편 연결 때 바꾸면 된다 |
| 2인 회귀 시험 | 이번에는 하지 않았다(사용자 결정으로 제외). 일정 잡아 함께 진행 |

## 3. 작업대(JH03)와 인벤토리 차감

- 현재 `PlayerInventory`·`InventoryData`에는 `TryAdd`·`GetCount`만 있다. 작업대 투입·인출에는 차감이 필요하다.
- 2026-10-17 사용자 전달: 최명기가 인벤토리 차감을 바로 진행한다. API 형태는 최명기가 정한다. 김지훈은 차감 API가 develop에 들어올 때까지 JH03 투입 구현을 대기한다.

## 4. 현재 저장소 상태

- `InteractionSelector.cs`: 최명기 버전 그대로(한때 기본값을 `~0`으로 바꿨다가 되돌림). `NetworkTestPlayer.prefab`에는 마스크 Everything이 저장됨(Mirror `_assetId` 자동 기록 포함)
- 삭제: `Assets/01.Scripts/03.Interaction/Relay/View/PlayerInteractionInput.cs`, `.cs.meta`
- 공유 문서 갱신: 로드맵·담당자 작업표·지훈 시스템 설계의 E키 어댑터 설명. 커밋·푸시 없음.

- Play·M2·M3 미실행.
