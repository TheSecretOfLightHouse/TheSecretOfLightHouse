## 1. 상호작용 대상 탐지·선택 담당

**결정:** B. 플레이어 프리팹에 붙는 Interaction(김지훈) 컴포넌트가 `PlayerController.InteractionRequested`를 구독하고 근처 대상을 골라 요청을 만든다. Player는 키 입력만 알린다.

| 세부 | 결정 |
|---|---|
| Action 결정 | 키 입력은 Interaction이 대상의 기본 Action을 정한다. 메뉴에서 동작을 고르는 경우(작업대 등)에는 UI가 대상·Action·인자를 Relay에 직접 넘긴다 |
| 홀드·점유 수명 | 세션 시작·취소·완료와 이탈·대상 소멸 시 해제는 Interaction이 맡는다. 소요 시간과 취소 조건은 각 기능(MK03 채집, MK04 구조)이 정한다 |
| 대상 식별 | 서버 대상 장부(TargetRegistry)가 TargetId + Generation을 발급한다. 네트워크 객체 대상은 대상 컴포넌트가 TargetId를 SyncVar로 클라이언트에 노출한다. 채집 지점은 클라이언트가 (종류, SpotId)를 보내 서버가 변환한다 |
| 화면 표시 | 누를 수 있는 대상을 강조해야 하면 Interaction이 "현재 선택 대상" 이벤트를 내고 UI(최명기)가 구독한다 |

어떤 요청이 JH02를 거치는지는 [네트워크 권위 §2.2](../../../unity/NETWORK_AUTHORITY.md#22-jh02-상호작용-요청-경로)에 있다.

## 2. 네트워크 매니저의 직군별 프리팹 코드

**현재 상태:** `ce48fae`에서 [LighthouseNetworkManager.cs](../../../../Assets/01.Scripts/01.Network/Session/Net/LighthouseNetworkManager.cs)에 직군 프리팹 4종 무작위 배정 코드가 주석으로 들어왔다. 실행 코드는 바뀌지 않았고 지금은 `playerPrefab` 하나로 4명이 생성된다.

**결정:** A. 매니저는 "이 참가자를 어떤 프리팹으로 만들지"를 묻는 선택 훅(actorId → 프리팹)만 제공하고, 직군 선택 로직은 최명기 코드에 둔다. 훅에 답이 없으면 기존 `playerPrefab`을 쓴다.

- **직군 배정 시점:** 미정. MK06·D06 결정에 따른다. 게임 시작 시 배정으로 정하면 이 훅 대신 공용 프리팹 생성 후 외형·능력 교체 방식이 될 수 있다.
- **주석 코드 정리:** 김지훈이 훅을 추가할 때 주석 코드를 지운다. 참고용으로 남겨야 하면 최명기가 알려 준다.

## 3. 접속이 끊긴 플레이어

**결정:** 판 진행 중 참가자가 한 명이라도 끊기면(호스트 포함) 판을 종료한다. [승패·투표 결정 §8](../../../design/win-vote-decisions.md#disconnection)을 2026-10-13 이렇게 바꿨다.

- 김지훈(JH07)이 이탈을 감지해 전원에게 종료 사유를 보내고 판을 끝낸다.
- 최명기(MK06)는 판 진행 여부를 김지훈에게 제공하고, 판 중단 상태와 종료 사유 UI를 맡는다. 게임 단계가 생기기 전까지 김지훈은 임시 플래그를 쓴다.
- 로비에서 나가면 자리만 비운다. 판 시작 후 새 접속은 거절한다.
- 그래서 끊긴 배·캐릭터를 남기거나 정지시키는 처리는 필요 없다. 기존 검토 항목(배 정지, 승선 중 단절, 난파 중 단절)은 모두 대상에서 빠진다.
- 재접속은 10/25 이후 선택 범위다.

## 4. `ActorJoined`·`ActorLeft` 공용 계약

**결정:** 현재 동작을 계약으로 고정하고, 바꿀 때 사전 공지한다. 투표 코드도 이 계약을 쓰므로 박태욱에게도 [별도로 알렸다](접속이벤트계약-박태욱-작업영향.md).

| 이벤트 | 시점 | 인자 |
|---|---|---|
| `ActorJoined(uint actorId, NetworkConnectionToClient conn)` | 서버 전용. `AddPlayerForConnection` 성공 직후, `conn.identity`가 플레이어 | ActorId는 1부터, 0은 무효 |
| `ActorLeft(uint actorId, NetworkConnectionToClient conn)` | 서버 전용. 플레이어 객체 정리 전 | 판 진행 중이면 이어서 판 종료가 일어난다 |

## 5. 승하선의 요청 경로

**결정:** JH02에서 제외하고 `BoatController`의 `CmdRequestBoard`·`CmdRequestDisembark`를 유지한다. 승하선은 상호작용 키가 아니라 접촉으로 자동 처리되므로([BoatContactBoarding.cs](../../../../Assets/01.Scripts/05.Player/Boat/BoatContactBoarding.cs)) JH02 입력과 겹치지 않는다.

## 6. 배를 상호작용 대상으로 등록하는 방식

**결정:**

- 배 프리팹에 김지훈의 대상 컴포넌트를 붙인다. 이 컴포넌트가 배의 `OnStartServer`에서 대상 장부에 등록하고 `OnStopServer`에서 해제한다. 그래서 스포너가 등록 API를 부를 필요가 없고, 배가 어떤 경로로 사라져도 해제된다.
- 발급된 TargetId·Generation은 대상 컴포넌트가 SyncVar로 클라이언트에 노출한다. TargetId는 netId가 아니라 장부가 발급한다.
- 주인 확인은 `boat.Owner`의 `NetworkActor.ActorId`로 한다.
- 배가 대상인 행동은 v4 4장·9장 기준으로 `InstallModule`(모듈 장착), `RepairBoat`(배 내구도 수리), `Rescue`(난파 동료 구조)다. `RepairBoat = 10`, `Rescue = 11`을 [InteractionAction.cs](../../../../Assets/01.Scripts/03.Interaction/Requests/Net/InteractionAction.cs)에 추가했다.
- 모듈 수리(`RepairModule`)는 작업대 대상이다. 난파 화물은 강민서의 표류 잔해 객체가 대상이다.

## 7. 물리·피해 판정 제안 중 최명기 범위

[네트워크 권위 §4.2](../../../unity/NETWORK_AUTHORITY.md#42-합의-대기-제안)의 제안을 김지훈 쪽에서 제안대로 진행하기로 했다. 최명기가 확인하면 §4.2에서 §4.1로 옮긴다.

| 항목 | 제안 | 최명기 확인 |
|---|---|---|
| 암초 충돌 피해 | 서버 겹침 검사. 서버에서 원격 배는 Kinematic이라 `OnCollisionEnter`가 오지 않음 | ☐ |
| 대포 | 발사는 요청, 탄과 명중은 서버(박태욱과 함께) | ☐ |
| 파도 충격 | 배 주인 PC가 감지해 보고, 서버가 날씨·쿨다운·상한 검증(강민서와 함께) | ☐ |
| 부력 실행 위치 | 배 주인 PC에서만 `IsSimulating = true`. 권위 전환에서 켜고 끔(강민서와 함께) | ☐ |
| 배끼리 충돌 | 피해 없음, 서로 밀지 않음(R24 기획 결정 전) | ☐ |
| 서버 강제 이동 | 자동 구조·하선 위치 강제는 `ServerTeleport` 사용 | ☐ |

## 8. 로비에서 판 시작 (추가 결정)

**결정(2026-10-13):**

- 접속과 로딩이 끝나면 로비에 들어간다. 각자 [준비 완료]를 누르고, 4명이 모두 준비하면 자동으로 게임을 시작한다.
- 준비는 다시 눌러 취소할 수 있다. 로비에서 나가면 그 사람의 준비도 사라진다.
- 게임 씬은 4명 모두 씬 로딩과 월드 생성을 마친 뒤 시계·입력을 연다. 설정 시간(시험값 60초) 안에 모두 마치지 못하면 판을 종료한다.
- 시작 인원은 설정값(기본 4)이다. 4 미만은 개발 시험용이다.
- 준비 집계·시작 판정·로딩 확인은 김지훈, 로비 화면·버튼·로딩 표시와 게임 단계 전환은 최명기, 월드 생성 완료 신호는 강민서가 맡는다.
