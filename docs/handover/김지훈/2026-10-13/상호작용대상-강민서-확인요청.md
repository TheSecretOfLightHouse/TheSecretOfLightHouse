# 상호작용 대상 식별 — 강민서 확인 요청

작성자: 김지훈
수신자: 강민서(ri-ver-1)
작성일: 2026-10-13
기준: 브랜치 `feature/jihun`, 커밋 `ac2bd12`

## 결정 내용

2026-10-13 김지훈이 JH02(상호작용 요청)의 대상 탐지·식별 방식을 정했다. 상세는 [네트워크 권위 §2.2](../../../unity/NETWORK_AUTHORITY.md#22-jh02-상호작용-요청-경로)와 [지훈 시스템 설계 §5.1](../../../design/jihun-system-design.md#51-식별과-전송)에 있다.

- 플레이어가 상호작용 키를 누르면 **각 플레이어 PC**의 Interaction 컴포넌트(김지훈)가 근처 대상을 고른다.
- 대상 번호(TargetId + Generation)는 **서버 대상 장부**가 발급한다.
- 대상이 네트워크 객체이면, 대상 컴포넌트가 자기 `OnStartServer`에서 등록하고 `OnStopServer`에서 해제한다. 번호는 SyncVar로 각 PC에 전달된다.
- 대상이 네트워크 객체가 아니면(채집 지점 등), 플레이어 PC가 **(대상 종류, 기존 ID)**를 보내고 서버가 장부에서 번호로 바꾼다. 강민서의 `SpotInfo`·`IslandHandle` 타입은 바꾸지 않고 김지훈이 adapter를 만든다.

## 자원 ID와 SpotId 구분 (2026-10-14 보충)

"자원 ID만 알면 되지 않나"라는 질문에 대한 답이다.

| 작업 | 필요한 것 | SpotId 생성 방식(`HarvestSpotIds.Compose`) |
|---|---|---|
| JH03 작업대·레시피·투입 | `ResourceId`와 수량만 | 몰라도 됨 |
| JH02 채집 요청 | **어느 지점인지 가리키는 SpotId** | 몰라도 됨 |

- 채집은 지점 단위로 처리된다. 강민서 계약 `IHarvestSpotRegistry.TryConsume(spotId, …)`가 지점별 잔량을 줄이고, `TryGetSpot(spotId, …)`의 위치로 거리를 검증한다. 같은 자원의 지점이 여러 개면 `ResourceId`만으로는 구별할 수 없다.
- 김지훈에게 필요한 것은 생성 로직이 아니라 아래 두 가지다. 확인 항목 2·3과 같다.
  1. 플레이어 PC가 근처 지점의 SpotId를 읽을 방법. 제안: 채집 지점 오브젝트에 SpotId를 담은 컴포넌트와 콜라이더를 붙이면 Interaction 컴포넌트가 이를 탐지해 읽는다. 이 경우 위치로 찾는 조회 인터페이스는 필요 없다.
  2. 같은 판의 4개 PC에서 같은 지점이 같은 SpotId를 갖는 것(MS01 완료 기준과 같음).

## 강민서 범위에서 확인할 것

| # | 확인할 것 | 이유 |
|---|---|---|
| 1 | 채집 지점은 네트워크 객체(서버 Spawn)인가, 같은 시드로 각 PC에서 생성하는 일반 오브젝트인가 | 일반 오브젝트이면 위의 (종류, SpotId) 방식을 쓴다. 네트워크 객체이면 대상 컴포넌트 방식을 쓴다 |
| 2 | 플레이어 PC에서 "근처 채집 지점의 위치와 SpotId"를 얻을 방법 | 탐지는 플레이어 PC에서 한다. 지금 `IHarvestSpotQuery`는 `SpotId`로 한 지점을 조회하는 기능만 있고, 위치로 근처 지점을 찾는 기능은 없다 |
| 3 | 같은 판의 4개 PC에서 같은 지점이 같은 `SpotId`를 갖는지 | 1이 일반 오브젝트이면 필수다. MS01 완료 기준(같은 판의 위치·ID가 4인 동일)과 같은 조건이다 |
| 4 | 특수 섬(`IslandHandle`), 유령선(MS06), 표류 잔해(MS02)가 각각 네트워크 객체인지 | 대상마다 위의 두 방식 중 어느 쪽을 쓸지 정한다 |

## 강민서가 할 일 (확인 후)

- 2의 조회 방법을 제공한다. 형태(인터페이스·컴포넌트)는 강민서가 정하고 김지훈에게 알려 준다.
- 네트워크 객체 대상(유령선·표류 잔해 등)의 프리팹에는 김지훈의 대상 컴포넌트를 붙인다. 컴포넌트는 JH02에서 김지훈이 만든다.
- 게임 씬에서 각 PC의 월드 생성이 끝났다는 신호를 제공한다. 김지훈이 4명 모두의 완료를 확인한 뒤 판을 시작한다(2026-10-13 로비 시작 결정, [승패·투표 결정 §8](../../../design/win-vote-decisions.md#disconnection)).
- 채집 판정(잔량 차감·지급)은 지금처럼 강민서·최명기 기능이 맡는다. 김지훈 Validator는 경제·횟수 규칙을 대신 판정하지 않는다.
