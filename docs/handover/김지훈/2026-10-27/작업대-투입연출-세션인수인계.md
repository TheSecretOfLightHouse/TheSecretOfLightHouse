경로: `Assets/01.Scripts/04.Lighthouse/Workbench/View/`(작업대 화면), 빌더 `Assets/01.Scripts/04.Lighthouse/Workbench/Editor/`

담당 파트: Lighthouse(작업대·모듈·등대). 작업대·모듈·등대 UI는 전부 김지훈 담당(2026-10-27 사용자 확인)

## 1. 목표
- 최종 상태: 작업대 **화면 방식**(`WorkbenchScreen`)에 아래 4가지 연출이 들어가 있다. 선반 방식(`WorkbenchRack`)은 2026-10-27 사용자 결정으로 폐기했으므로 대상이 아니다.
  1. **넣기 성공(본인)**: 넣기를 누르면 내 자원 칸(`_resourceSlots`)에서 해당 재료 줄(`WorkbenchIngredientRow`)로 자원 아이콘이 날아간다. 내 자원 칸 숫자는 줄어들면서 살짝 튄다.
  2. **"제작 가능" 맥박**: 레시피 재료가 다 차면(`WorkbenchNet.IsReadyToCraft`) 제작 버튼이 빛나고 레시피 카드 배지가 튄다.
  3. **다른 선원의 투입**: 같은 레시피를 보고 있을 때 본인 요청이 대기 중이 아닌데 투입량이 늘면, 그 재료 줄 위에 "+N"이 뜨고 막대가 차오른다. 이름은 표시하지 않는다(기여자는 서버 전용, [모듈 결정 36행](../../../design/lighthouse-module-decisions.md) 보유자 비공개 취지).
  4. **실패**: 넣기가 거절되면 넣기 버튼이 흔들리고 문구가 빨갛게 깜빡인다. 막힌 재료 줄도 한 번 깜빡인다.
- 근거 문서: [UI연출-기획.md 끝 절 "투입·제작·장착 연출 제안"](../../../김지훈/2026-10-26/UI연출-기획.md). 사용자는 그중 "1. 자원 넣기"의 위 4항목만 진행을 승인했다. 같은 절의 "줄 숫자 올림·체크 도장·전체 바 차오름"은 3번(다른 선원 투입)을 만들면서 공용으로 써도 되지만, 별도 항목으로 확대하지 않는다.

### 구현 메모(코드 확인 결과, 2026-10-27 기준 줄 번호)
- 요청 흐름: `HandleDepositClicked`([WorkbenchScreen.cs:955](../../../../Assets/01.Scripts/04.Lighthouse/Workbench/View/WorkbenchScreen.cs#L955)) → `Send`(880, `_pendingAction` 기록) → `HandleResultReceived`(997)에서 성공·거절 문구를 정한다. 거절 문구는 `DescribeRejection`(1013)이 정한다. 1번과 4번 연출은 여기에서 시작한다. **성공 결과를 받은 뒤** 재생한다(요청 시점이 아님).
- `_pendingResourceId`·`_pendingRecipeName`은 투입할 때만 채운다. 날아가는 시작점(내 자원 칸)은 `RefreshStock`(728)·`RefreshSketchStock`(776)이 어느 `_resourceSlots[i]`에 어떤 자원을 넣었는지로 찾는다. 스케치 레이아웃은 페이지가 있어 해당 자원 칸이 화면에 없을 수 있다. 그때는 넣기 버튼(`_depositButton`)에서 출발하게 한다.
- 화면 갱신은 `WorkbenchNet.Changed`·`ResourceCountChanged` → `Refresh()`(574) 한 경로뿐이다. 3번(다른 선원 투입)은 `RefreshProgress`(610)에서 재료 줄별 이전 투입량을 기억해 두고 비교해 만든다. 레시피를 바꾸면 기억한 값을 다시 잡아 바꾼 순간에 연출이 나오지 않게 한다. 본인 요청이 대기 중이면(`_relay`가 대기 중) 늘어난 양은 본인 것으로 보고 3번을 건너뛴다. 대기 상태를 어떻게 읽는지는 `InteractionRelay` API에서 확인해야 한다(미확인).
- 줄어든 경우(제작으로 비워짐 또는 마피아 인출)는 이번 범위가 아니다. 아무 연출도 넣지 않는다. 인출 표시는 결정 대기(E·R19)다.
- 2번 판정은 이미 `RefreshCards`(586, 603의 `SetBadgeColor`)와 `RefreshProgress`(614의 `isReady`)에 있다. 거짓에서 참으로 바뀌는 순간에 한 번 튀게 하고, 참인 동안 버튼 빛이 반복되게 한다.
- 화면 구성 요소: `WorkbenchIngredientRow`(`SetProgress`, `SetSelected`), `WorkbenchItemSlot`(`Show`, `SetSelected`), `WorkbenchRecipeCard`(`SetBadgeColor`). 버튼 눌림 피드백 선례는 `00.Common/UI/UiButtonFeedback`, 알림 띠는 `00.Common/UI/ScreenNotice`다.
- 프리팹: `WorkbenchScreen.prefab`·`WorkbenchScreen_Wood.prefab`·`WorkbenchScreen_Sketch.prefab` 셋 다 JH04·`MainGame`·`TWJH04TestScene`에서 GUID가 참조된다. 실제로 켜져 쓰이는 것은 씬에서 확인해야 한다(`_isSketchLayout`이 켜진 것이 손그림판). 새 직렬화 필드를 추가하면 빌더(`WorkbenchScreenSketchSetup`·`WorkbenchScreenWoodSetup`)에서 연결하고 메뉴로 다시 빌드한다. 프리팹 YAML은 직접 편집하지 않는다.
- 연출은 화면이 열려 있을 때(`_isOpen`)만 재생하고, 닫으면 진행 중인 트윈을 정리한다. 매 프레임 할당은 0으로 한다(코루틴 대신 `Update` 진행값이나 재사용 오브젝트).
