## 한 줄 요약

작업대에서 완성된 모듈은 **플레이어 인벤토리로 가져온 뒤** 등대나 자기 배에 장착합니다. 김지훈 쪽 서버 처리는 끝났고, 배에 실제로 장착하려면 **Boat.prefab에서 장착 요청을 받도록 허용**해야 합니다. 이 허용을 포함한 아래 요청 5개를 부탁드립니다.

## 게임에서 보이는 흐름

1. 작업대에서 모듈을 제작하면 작업대 보관함에 들어갑니다.
2. 작업대 화면의 보관함 칸에서 **가져가기**를 누르면 그 모듈이 내 인벤토리로 들어옵니다.
3. 등대 섬에서 등대에 장착하거나, 자기 배에 탄 채 배에 장착합니다.
4. 마음이 바뀌면 작업대 화면에서 **되돌려놓기**를 눌러 작업대 보관함으로 돌려놓을 수 있습니다.

규칙:

| 규칙 | 내용 |
|---|---|
| 개수 | 인벤토리에는 모듈을 **1개만** 가질 수 있습니다. 등대 모듈과 배 모듈을 합친 개수입니다 |
| 가져갈 수 있는 사람 | 시민·마피아 모두 |
| 비공개 | 내 인벤토리의 모듈은 **나만** 압니다. 다른 PC에는 정보 자체를 보내지 않습니다. 작업대 보관 개수는 모두에게 보이므로 "누군가 하나 가져갔다"는 것은 알 수 있습니다 |
| 배 난파 | 배에 장착한 모듈은 난파하면 모두 사라집니다. 같은 레시피는 다시 만들 수 있습니다 |
| 마피아 소환 | 소환 순간 마피아 인벤토리에 있던 모듈은 사라집니다 |

## 코드에서 알아야 할 것

모듈은 `PlayerInventory`의 자원 수량에 **넣지 않습니다**. 서버는 `WorkbenchNet`에 플레이어별로 "이 사람이 가진 모듈"을 따로 기록하고, 본인 PC에만 레시피 ID를 보냅니다. 인벤토리 화면은 이 값을 읽어 모듈 칸을 그리면 됩니다.

> 코드 이름에는 `Carry`·`Carried`가 들어갑니다. 모두 "인벤토리에 가진 모듈"이라는 뜻입니다.

| 쓰는 것 | 설명 |
|---|---|
| `WorkbenchNet.OwnCarriedRecipe` | 내 인벤토리에 있는 모듈의 레시피 ID. 없으면 0. 본인 PC에서만 값이 있습니다 |
| `WorkbenchNet.Changed` | 위 값이 바뀌면 발생합니다 |
| `InteractionAction.TakeModule` (16) | 가져가기. 대상은 작업대, `Arg0` = 레시피 ID |
| `InteractionAction.ReturnModule` (17) | 되돌려놓기. 대상은 작업대 |
| `InteractionAction.InstallModule` (5) | 장착. 대상은 등대 또는 **자기 배**(`BoatController`의 netId), `Arg0` = 레시피 ID |
| `ModuleRecipe.IsBoatModule` / `BoatModuleType` | 배 모듈인지와 그 종류 |
| `ModuleInteractionHandler.DiscardCarried(actorId)` | 서버 전용. 그 플레이어 인벤토리의 모듈을 없앱니다(장부에서도 지워 다시 제작 가능) |

배 장착이 서버에서 처리되는 순서:

1. 요청한 플레이어가 그 모듈을 인벤토리에 가지고 있는지 확인합니다. `Arg0`이 가진 모듈과 다르면 거절합니다.
2. 기존 `BoatModuleEquipment.TryInstall(player, type)`을 부릅니다. 소유·탑승·난파·지원 종류·중복은 이 함수가 검사합니다. **`BoatModuleEquipment` 코드는 고치지 않았습니다.**
3. 장착에 성공했을 때만 인벤토리에서 모듈을 뺍니다. 실패하면 모듈은 인벤토리에 그대로 남습니다.
4. 배가 난파하면(`BoatDurability.Wrecked`) 그 배에 장착됐던 모듈을 장부에서 지웁니다. 배 쪽 장착 목록 초기화는 기존 `HandleWrecked`가 그대로 합니다.

배 모듈 레시피 (재료는 기획 9절 시험값, 제작 상한 없음):

| ID | 모듈 | `BoatModuleType` | 현재 상태 |
|---|---|---|---|
| 101 | 탐조등 | `Searchlight` | 장착 가능(효과도 기존에 있음) |
| 102 | 대쉬 | 없음 | **장착 거절됨**. 종류 값이 아직 없음 |
| 103 | 장애물 경보 | `DepthAlarm` | 장착 가능, 효과 없음 |
| 104 | 선체 안정기 | `Stabilizer` | 장착 가능, 효과 없음 |

## 요청 (최명기)

| # | 할 일 | 왜 필요한가 |
|---|---|---|
| 1 | **Boat.prefab의 `InteractionTarget`에 `InstallModule`(5) 허용 추가** | 지금은 `RepairBoat`(10)만 허용돼 있어 배 장착 요청이 `ActionNotSupported`로 거절됩니다. 직접 넣어도 되고, 동의해 주시면 김지훈이 메뉴 `Lighthouse/Modules/Allow Module Install On Boat Prefab`로 넣습니다 |
| 2 | `BoatModuleType`에 대쉬 값 추가, `IsSupported`에 포함 | 값이 생기면 레시피 102 에셋의 종류만 김지훈이 바꿉니다 |
| 3 | 대쉬·장애물 경보·선체 안정기 효과 | 김지훈 쪽은 종류만 넘깁니다 |
| 4 | 정식 인벤토리 화면에 모듈 칸 표시, 배 장착 입력 | 화면은 `OwnCarriedRecipe`를 읽어 그리고, 입력은 위 `InstallModule` 요청을 보내면 됩니다. 지금은 가져가기·되돌려놓기만 작업대 화면에 있고, 배 장착은 JH04 시험 패널(`TowerTestPanel`) 버튼으로만 할 수 있습니다 |
| 5 | 재스폰 때 인벤토리 손실 처리(기존 결정) | 구조되면 인벤토리의 자원·모듈을 종류(칸)별로 놓고 무작위 1칸을 **통째로** 잃습니다(예: 나무 10개가 뽑히면 10개 모두, 2026-10-21 결정). 구조받지 못하고 재스폰하면 전부 떨어뜨립니다. 모듈을 없애는 것은 `DiscardCarried(actorId)`를 쓰면 됩니다. 바다에 떨어뜨려 나중에 줍게 하는 함수는 아직 없으니 호출 시점과 형식을 같이 정해야 합니다 |

## 검증 상태

- 확인함: 에디터 컴파일 오류 0. 사용자가 JH04TestScene에서 `Set Up Module Carry In Open Scene` 메뉴를 실행해 배 레시피 4종을 작업대에 추가했습니다. 이후 플레이 로그에 예외가 없었습니다.
- 아직 안 함: 가져가기 → 등대 장착 → 되돌려놓기 플레이 확인, 배 장착 실제 동작(1번 요청 전이라 불가), 원격 클라이언트 확인(M2).
