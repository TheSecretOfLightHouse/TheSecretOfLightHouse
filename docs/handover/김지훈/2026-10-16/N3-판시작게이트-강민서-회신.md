## 1. 목표

- 최종 상태: 게임 씬 전원 로딩과 전원 맵 준비가 모두 끝난 뒤에만 `MatchStarted`가 1회 발생한다.
- 근거: 강민서 요청 "N3′ 월드 준비 게이트의 매니저 연결 요청"(`docs/handover/강민서/2026-10-16/N3-월드준비-매니저연결-요청.md`, 2026-10-16), [JH07 원문](../../../김지훈/2026-10-13/JH07-판시작종료-로비게임씬전환.md) 진행 과정 2026-10-16.

## 2. 회신

| 요청 항목 | 회신 |
|---|---|
| 구현 담당 | 상호작용·공용 접속 담당(김지훈)이 매니저를 구현했다 |
| 누락 정책 | 필수 설정 방식에 동의한다. 이름은 `_requireStartGate`(기본 false). 강민서 Offline 매니저에서 켠다 |
| 연결 방식 | **요청안과 다르게 바꿨다.** 매니저가 `WorldServices`에서 `IWorldReadyGate`를 조회하지 않고, World가 Network 쪽 계약으로 매니저에 등록한다(아래 3) |
| 통합 검증 | 강민서가 등록 변경 후 진행한다(사용자 결정 2026-10-16) |

### 연결 방식을 바꾼 이유

- `01.Network`는 현재 다른 도메인을 참조하지 않는다. World(`MapStateNet`·`WorldStateNet`)는 이미 `Lighthouse.Network.Session.Net`을 참조한다.
- 매니저가 `Lighthouse.World.*`를 참조하면 World ↔ Network 순환이 생긴다. 단일 asmdef라 컴파일은 되지만 [아키텍처 §3](../../../04-architecture.md)은 의존 방향을 합의 대상으로 둔다.
- 계약을 Network에 두면 의존은 World → Network 한 방향으로 유지되고, 등대·마피아 등 다른 기능의 시작 전 준비가 생겨도 매니저를 바꾸지 않는다.
- 등록 방식이라 "게이트가 게임 씬 `OnStartServer`에서 늦게 생겨 조회를 놓칠 수 있다"는 요청 문서의 우려도 사라진다. 매니저는 등록 시와 `Changed`마다 시작을 다시 검사한다.

### 요청 문서 검토 결과 (2026-10-16, `feature/jihun` `2b8e9d8` 코드 기준)

| 요청 문서 주장 | 확인 결과 |
|---|---|
| `TryStartMatch`는 로딩만 검사하고 월드 대기는 TODO | 요청 작성 시점(`a76f3d0`) 기준 사실. 이번 구현으로 해소됨 |
| `MapStateNet`이 맵 생성보다 먼저 게이트를 만들고, 생성 실패·설정 누락 시 준비 불인정 | 코드상 맞음. `_config`가 없거나 `TryBuild` 실패 시 `_map`이 비어 `HandleWorldReady`가 무시함. 새 방식에서도 등록은 `return`보다 앞에 둬야 함(아래 3-2) |
| 중복 정상 제출은 `Changed`를 다시 올리지 않음 | 맞음(`WorldReadyTracker.Submit`의 `HashSet.Add`) |
| 서버는 연결에서 ActorId를 조회 | 맞음. 단 조회 실패 시 `(uint)conn.connectionId`로 대체한다. ActorId도 1부터 세므로 매니저에 없는 연결의 제출이 다른 참가자의 준비로 잡힐 수 있다(추론, 정상 흐름에서는 거절 연결이 게임 씬 전에 끊겨 발생 가능성 낮음). 조회 실패 시 무시하는 쪽이 안전하다 |
| `WorldStateNet`은 `MatchStarted`에서 `BeginMatch(startTime)` | 맞음. 다만 코드 기본값 `_isBeginOnStartServer = true`라 씬에서 끄지 않으면 판 시작 전에 시계가 돈다. WorldSessionGame에서 false로 했다는 설정은 씬이 미추적이라 이쪽에서 확인 못 함. 기본값을 false로 바꿀지 검토 권장 |
| 해시 불일치 → Loading 유지 후 시간 초과 / 로딩 중 이탈 → 판 종료 / 새 판에 이전 상태 미사용 | 매니저 코드 흐름상 맞음. 실제 World 게이트로는 미검증 |
| WorldSession 씬 3개·Build Settings 변경 미추적 | 이쪽 저장소에는 없음(확인 불가). **Build Settings는 0번이 `JH07Offline`인 팀 공용 설정이다.** 개인 씬을 추가할 때 기존 순서를 바꾸지 않도록 커밋 전에 diff를 확인해 달라 |
| 근거 링크 | `win-vote-decisions.md#disconnection`, 대장 N13, 김지훈 2026-10-13 요청은 존재. 강민서 작업 원문(`docs/강민서/2026-10-16/…`)과 이 요청 문서는 아직 저장소에 없음 |

## 3. World 쪽에 요청하는 변경 (강민서 담당, 김지훈은 수정하지 않음)

제공된 계약(`Assets/01.Scripts/01.Network/Session/Rules/IMatchStartGate.cs`):

```csharp
namespace Lighthouse.Network.Session.Rules
{
    public interface IMatchStartGate
    {
        event Action Changed;
        bool AreAllReady(IReadOnlyList<uint> roster);
    }
}
```

매니저 API(`LighthouseNetworkManager`, 서버 전용): `bool RegisterStartGate(IMatchStartGate gate)`, `bool UnregisterStartGate(IMatchStartGate gate)`.

필요한 변경 예시(최종 형태는 강민서가 정한다):

1. `IWorldReadyGate`가 `IMatchStartGate`를 상속하거나(`public interface IWorldReadyGate : IMatchStartGate { }`), `WorldReadyTracker`가 `IMatchStartGate`를 직접 구현한다. 시그니처가 같아 본문 변경은 없다.
2. `MapStateNet.OnStartServer`에서 `_tracker` 생성 직후 등록한다. 맵 생성 실패로 `return`하는 경로보다 앞에 두어야 실패 시에도 게이트가 남아 시작을 막는다.
   ```csharp
   LighthouseNetworkManager manager = LighthouseNetworkManager.Instance;
   if (manager != null)
   {
       manager.RegisterStartGate(_tracker);
   }
   ```
3. `MapStateNet.OnStopServer`에서 `_tracker`를 비우기 전에 `UnregisterStartGate(_tracker)`를 부른다. 매니저가 서버 종료 때 먼저 비웠으면 false만 반환하므로 순서는 상관없다.
4. 개인 `WorldSessionOffline` 씬의 `LighthouseNetworkManager`에서 `Require Start Gate`를 켠다(에디터에서).
5. `WorldServices`의 `IWorldReadyGate` 등록을 유지할지는 World 내부 사용처에 맞춰 강민서가 정한다. 매니저는 더 이상 조회하지 않는다.

### 매니저 동작 정리

| 상황 | 결과 |
|---|---|
| 게이트 0개, 설정 false (기존 시험 씬·JH07) | 기존처럼 전원 로딩 시 시작 |
| 게이트 0개, 설정 true | Loading 유지 → 60초 시간 초과 종료 |
| 게이트 1개 이상 (설정 무관) | 전원 로딩 + 모든 게이트 `AreAllReady(roster)` 참일 때 시작 |
| 마지막 준비가 로딩보다 늦음 | 그 `Changed`에서 시작 |
| `Changed` 반복·중복 | Loading 단계 검사로 1회만 시작 |
| 서버 시작·종료 | 매니저가 구독을 모두 해제하고 목록을 비움 |
