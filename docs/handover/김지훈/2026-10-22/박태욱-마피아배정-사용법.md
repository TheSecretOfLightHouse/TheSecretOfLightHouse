# [인수인계] 마피아 배정 사용법 — 박태욱(투표·확인·바다 소환)

작성: 김지훈 · 2026-10-22 · 대상: 박태욱 · 브랜치 `feature/jihun`(PR로 develop에 올림)

## 요약

판이 시작될 때 서버가 마피아 1명을 정해 둔다. 이제 시험용 무작위나 `TrialSeaSummonAuthority`처럼 마피아를 직접 고를 필요 없이 아래 API를 읽으면 된다. 배정 방식·합의 요청 배경은 [합의 요청](최명기-박태욱-마피아배정-합의요청.md)에 있다.

## 쓸 수 있는 것

모두 `Lighthouse.Network.Session.*` 네임스페이스. 매니저는 `LighthouseNetworkManager.Instance`.

| 위치 | 이름 | 내용 |
|---|---|---|
| 서버 | `manager.Roles.IsMafia(uint actorId)` | 마피아면 true. 배정 전·단일 씬 모드에서는 항상 false |
| 서버 | `manager.Roles.MafiaActorId` | 마피아의 ActorId. 배정 전에는 `ConnectionDirectory.InvalidActorId` |
| 서버 | `manager.Roles.GetRole(uint actorId)` | `MatchRole.Mafia`·`Citizen`, 참가자가 아니거나 배정 전이면 `None` |
| 서버 | `manager.Roles.IsAssigned` | 배정이 끝났는지 |
| 서버 | `manager.Connections.TryGetActorId(sender, out uint actorId)` | Command 보낸 연결 → ActorId (기존 API) |
| 클라이언트 | `manager.OwnRole` | 내 역할만(`MatchRole`). 판 시작 전 `None` |
| 클라이언트 | `manager.OwnRoleReceived` (`Action<MatchRole>`) | 내 역할을 받은 순간 한 번 |

- 배정 시점: `TryStartMatch`에서 `MatchStarted` **직전**. 그래서 `MatchStarted` 처리기 안에서 `Roles`를 바로 읽어도 된다.
- 재배정 없음(서버 실행 한 번 = 판 하나). 다른 사람의 역할은 클라이언트로 보내지 않는다. 시민도 `OwnRoleMessage`를 받는다.
- 마피아 ID는 일부러 로그에 남기지 않는다. 디버그 로그에 찍을 때도 주의.

## 연결 방법 (제안 — 결정은 박태욱)

### 1. 투표 초기화 (`VotingNetworkController.InitializeVoting`)

지금은 시험 코드 `99.Dev/Network/MatchStartVotingProbe`가 대신 부른다. 본편에서는 투표 컨트롤러가 직접 받는 형태를 제안한다.

```csharp
// VotingNetworkController (서버)
public override void OnStartServer()
{
    _manager.MatchStarted += HandleMatchStarted;
}

public override void OnStopServer()
{
    _manager.MatchStarted -= HandleMatchStarted;
}

private void HandleMatchStarted(uint matchId, double startTime, IReadOnlyList<uint> roster)
{
    InitializeVoting(roster, _manager.Roles.MafiaActorId);
}
```

본편에서 직접 부르게 되면 같은 씬의 `MatchStartVotingProbe`를 빼야 한다(두 번 부르면 `InitializeVoting`이 예외를 던짐). 알려 주면 프로브는 김지훈이 정리한다.

### 2. 바다 소환 권한 (`ISeaSummonAuthority`)

지금 `CanSummon(uint playerNetId)`는 플레이어 객체 netId 기준이다. 플레이어 객체는 로비→게임 씬에서 새로 만들어져 netId가 바뀌므로, 사람 구분은 ActorId로 바꾸는 걸 제안한다.

```csharp
// 예: 본편 권한 구현
public sealed class SessionSeaSummonAuthority : ISeaSummonAuthority
{
    public bool CanSummon(uint actorId)
    {
        LighthouseNetworkManager manager = LighthouseNetworkManager.Instance;
        return manager && manager.Roles.IsMafia(actorId);
    }
}

// 컨트롤러에서 sender.identity.netId 대신
if (!_manager.Connections.TryGetActorId(sender, out uint actorId)) { return false; }
```

- 바꿀 곳: `SeaSummonPermissionController`(권한·`_topViewFrames` 키), `SeaSummonPointController`(`selection.PlayerId`), `SeaSummonSpawnController`(`_usedCounts`·`_summoned` 키). 배(`boat.netId`)·몬스터 netId는 객체를 가리키므로 그대로 둬도 된다.
- 시험 매니저(`SeaSummonTestNetworkManager`)는 `LighthouseNetworkManager`가 아니라서 `Roles`가 없다. 시험용 `TrialSeaSummonAuthority`는 남겨 두고 본편 경로에서만 위 구현을 쓰면 된다.

### 3. 정체 확인 등 마피아 판정이 필요한 다른 곳

서버에서 `Roles.IsMafia(actorId)`만 쓰면 된다. 마피아 여부를 따로 저장하지 않으면 투표·모듈 회수·소환이 항상 같은 사람을 본다. 참고로 모듈 기본 자원 회수(`ModuleInteractionHandler.Withdraw`)는 이미 이 배정을 쓴다.

## 검증 상태

- 실행함: dotnet 빌드 오류 0, Unity 재컴파일·Mirror Weaver 오류 0.
- 실행 안 함: 플레이 시험(M0·M2). 판 시작 때 마피아 1명·각자 자기 역할만 수신·투표 초기화와 `Withdraw`가 같은 마피아를 보는지는 아직 확인 못 했다. 시험용으로 실행 인자 `-roleOverlay`를 주면 화면 위에 내 역할이 뜬다(`99.Dev/Network/OwnRoleOverlay`).

## 답이 필요한 것

1. 바다 소환을 ActorId 기준으로 바꿔 줄 수 있는지, 언제쯤인지.
2. 본편 `InitializeVoting` 호출을 위 1안(컨트롤러가 `MatchStarted` 직접 구독)으로 할지. 다른 위치면 알려 주면 맞춘다.
