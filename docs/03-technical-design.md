# 등대 기술설계서

> 기획 기준: [승패·투표 결정](design/win-vote-decisions.md)이 충돌하는 [게임 기획서 v4](design/references/game-design-v4.md) 규칙보다 우선한다. 이 문서는 기술 계약을 다루며 게임 규칙·수치의 출처가 아니다. 미결 계약은 [설계 문제 대장](07-design-issue-register.md)에서 추적하고 원문의 미정은 임의 확정하지 않는다.

기준일: 2026-10-11(승패·투표 결정 반영). 기존 기획·설정·코드의 기술 경계를 정리한다. 네트워크 기능 전체의 구현 완료를 뜻하지 않는다.

## 1. 목적과 적용 범위

[제공된 v4](design/references/game-design-v4.md)의 4인 호스트-클라이언트 구조와 비밀 정보 보호를 유지한다. v4 4.8은 직군·마피아, 소환 여부, 부식 여부, 미래 날씨, 환영 섬 대상을 당사자에게만 보내는 비밀 정보로 정한다. 투표·봉인·심해·확인 결과의 구체적인 수신 범위는 [새 결정 §7](design/win-vote-decisions.md#7-정보-공개-범위--n04r16)을 따른다. 백엔드·전용 서버·영구 저장 체계는 현재 확인된 기획 범위에 없다. 도입이 필요하면 요구사항과 기술 방향을 별도로 결정한다.

## 2. 실제 기반

| 항목 | 확인한 값 | 파일 |
|---|---|---|
| Unity | 6000.0.83f1 | `ProjectSettings/ProjectVersion.txt` |
| URP | 17.0.4 | `Packages/manifest.json` |
| 입력 | Input System 1.19.0 | `Packages/manifest.json` |
| 네트워크 | Mirror 96.0.1 | `Assets/Mirror/version.txt` |
| 테스트 패키지 | Unity Test Framework 1.6.0 | `Packages/manifest.json` |

패키지 설치는 프로젝트 테스트 통과를 뜻하지 않는다. 버전 변경 시 실제 파일과 이 표를 함께 갱신한다.

## 3. 실행 구성

리슨 호스트 한 명과 원격 클라이언트 세 명이 한 판을 구성한다. 각 담당자는 자기 기능의 서버 판정·동기화·클라이언트 표현을 함께 구현하며 [담당 경계](CODE_OWNERSHIP.md)를 따른다. 공용 접속 기반과 4인 안정화 테스트는 김지훈이 담당한다. 게임 규칙 판정은 호스트의 서버 측에서, 입력과 표현은 각 클라이언트에서 처리하는 방향이다. 플레이어 제어 코드는 현재 `MonoBehaviour` 기반이며 네트워크 권한 처리가 완료된 것으로 보지 않는다.

## 4. 권위와 통신

| 구분 | 책임 |
|---|---|
| 호스트 서버 | 게임 진행·승패·몬스터 AI·비밀 투표 등 공유 규칙 판정 |
| 클라이언트 | 입력·카메라·UI·연출, 허용된 요청 전달 |
| 네트워크 계약 | 요청과 동기화 데이터. 클라이언트의 결과 주장 자체를 신뢰하지 않음 |

Command 인자의 권한·범위·쿨타임은 서버에서 검증한다. 비밀 투표 결과는 본인과 시스템만 알며 역할 등 비밀 정보는 전체 SyncVar/ClientRpc로 보내지 않는다. 필요한 정보만 해당 대상에게 전달한다. 몬스터의 소환/자연 스폰 여부는 클라이언트에 보내지 않는다. 상세 운영 규칙은 [네트워크 권위](unity/NETWORK_AUTHORITY.md)를 따른다.

호스트 자신은 서버 상태를 가진다. 원격 클라이언트 정보 제한이 호스트 운영자의 메모리 접근까지 막는다는 보장을 뜻하지 않는다.

## 5. 현재 요청·데이터 계약

- `Assets/01.Scripts/03.Interaction/Requests/Net/InteractionRequest.cs`: ActorId, TargetId, Action, Arg0, Arg1, ServerTime을 가진 읽기 전용 구조체다.
- `Assets/01.Scripts/03.Interaction/Requests/Net/InteractionAction.cs`: 상호작용 종류를 정의한다.
- `Assets/01.Scripts/02.World/Harvest/Rules/ResourceDefinition.cs`: 자원 ID·표시명·아이콘·희귀도·픽업 프리팹의 ScriptableObject 정의다.

이 타입의 존재는 요청 전송·검증·실제 데이터 연결의 완료를 의미하지 않는다. 아직 구체적인 전송·실패 응답 계약은 이 문서에서 새로 확정하지 않는다.

송신자와 ActorId의 관계는 JH01에서 다음과 같이 구현했다. 상세 설계는 [지훈 시스템 설계 §5.1·§8](design/jihun-system-design.md)을 따른다.

- ActorId는 서버가 플레이어 생성(`OnServerAddPlayer`) 때 1부터 발급한다. 0은 무효다. 연결 번호(connectionId)·객체 번호(netId)와 분리된 주체 번호다.
- 서버 코드는 Command 인자나 `InteractionRequest.ActorId`처럼 클라이언트가 보낸 ActorId를 신뢰하지 않는다. `LighthouseNetworkManager.Instance.Connections.TryGetActorId(connectionToClient, out actorId)`로 송신자를 조회하거나 `IsSender`로 대조한다.
- 플레이어 객체의 `NetworkActor.ActorId`는 모든 클라이언트에 공개된다. 역할 등 비밀 정보와 연결되지 않는다.
- 타임스탬프(`ServerTime`) 검증과 요청 번호·연결 세대는 JH02에서 정한다. JH01의 현재 `OnServerDisconnect`는 `ActorLeft` 알림 후 연결 명단에서 제거하고 Mirror 기본 해제를 실행한다. 캐릭터·참가자 상태 보존과 재접속 재결합은 구현 완료 상태가 아니다. 새 결정의 우선 범위인 단절 캐릭터·ActorId 기반 상태 보존은 JH07에서 반영하고, 재접속은 후순위로 검토한다.

## 6. 상태와 실행값

게임 단계, 투표, 점화, 소환과 승패 조건은 [새 결정](design/win-vote-decisions.md)을 우선하며 바꾸지 않은 규칙은 v4를 따른다. 아래 표는 기획에서 요구하는 의미 계약이며, 실제 API 이름·구현·팀 합의 완료를 뜻하지 않는다.

| 서버 상태·전이 | 요구되는 계약 | 담당 연결 |
|---|---|---|
| 투표·확인 | 시민만 투표 가능, 자기 지목·철회 금지, 2회 소비·같은 대상 재클릭 무차감. 확인 요청 처리 순간의 현재 표로 판정. 성공한 10초 소환 권리는 이후 표 변경·마지막 확인권 소진과 분리해 유지하며 난파 중 확인·소환 금지 | 박태욱 판정 → 최명기 시스템·UI, 최명기 Player 난파 상태 제공 |
| 의식 시작 | 수리도 100% 후 누구나 등대 상호작용으로 60초 의식 시작. 투표 변경 잠금·게임 기한 정지·모듈 낙하 억제를 같은 단계 전이에 연결 | 김지훈 등대 → 최명기 단계 관리 → 박태욱 투표·김지훈 모듈 |
| 의식 종료 | 소환 없이 완료한 의식은 종료 순간의 표를 판정해 시민 2명 이상 정답이면 시민 승리, 아니면 즉시 마피아 승리. 실패 게이지 증가·잠금 해제 후 재시도 없음 | 김지훈 의식 완료·박태욱 투표 상태 → 최명기 최종 승패 |
| 최후 전투 전환 | 소환 시 기존 의식 타이머·게임 기한 제거. 소환 전 수리도와 별개인 새 수리 진행도 0%. 고정 최대 HP와 환산 현재 HP로 시작 | 박태욱 소환 → 최명기 단계 관리·김지훈 등대 |
| 최후 전투 수리·보상 | 자원 투입은 새 수리 진행도만 올림. 현재 HP 회복·최대 HP 증가 없음. 기존 수리 보상 유지·전투 진행도로 새 보상 또는 중복 보상 지급 없음 | 김지훈 등대 → 최명기 Player 보상 적용·시스템·UI |
| 최후 전투 종료 | 새 수리 진행도 100% 또는 HP 0에 먼저 도달하면 시민 또는 마피아 승리를 한 번만 확정. 별도 점화·기한 패배·괴물 처치 승리 없음 | 김지훈 등대 상태 → 최명기 최종 승패, 박태욱 몬스터 종료 소비 |
| 공격력 정산 | 시민별 유지 시간 기록, 아침 기본 충전·봉인/오투표 합산. 난파·단절·확인 성공 후에도 누적. 소환 시 미정산분과 완료된 하루의 기본 충전만 반영, 최소 공격력 보장·소환 이후 고정 | 강민서 아침/시간 제공 → 박태욱 정산·몬스터 공격력, 최명기 Player 상태 연결 |

등대는 숨은 단계 수리도, 최후 전투용 수리 진행도, 현재 HP, 최대 HP와 이미 획득한 보상을 구분한다. 소환 시 현재 HP는 `기본 HP + (최대 HP − 기본 HP) × 소환 전 수리도 비율`이며 비율 범위는 0~1이다. 전환 전 값을 읽어 환산한 결과와 새 진행도 0%를 구분해 소비한다. 최명기 시스템이 최종 승패를 한 번만 확정하며 각 기능은 필요한 조건과 상태를 제공한다. 동일 판정 시점의 의식 완료/소환 또는 수리 100%/HP 0 우선순위는 아직 정하지 않았다.

게임 기한과 월드의 일차·아침 이벤트·일일 효과는 별개 계약이다. 의식 시작은 게임 기한만 정지하며 월드 시간까지 멈춘다는 결정을 뜻하지 않는다. 최후 전투의 기한 제거가 모든 일일 효과의 제거를 뜻하지 않는다. 의식 중 월드 시간 진행, 최후 전투 일일 효과 및 의식 중 억제한 낙하의 후속 처리도 [설계 문제 대장](07-design-issue-register.md)의 남은 결정을 확인한다.

기획과 현재 코드를 구분한다. `07.Mafia/Voting/Rules/VoteService.cs`는 참가자·횟수·같은 대상 재클릭을 처리하지만 마피아/자기 투표 제한과 의식 잠금은 아직 검사하지 않는다. 위 단계 전이·승패·HP·보상·공격력·정보 전달의 통합 구현이나 4인 실행 검증이 완료된 것으로 보지 않는다.

현재 `NetworkActor.ActorId`는 `uint`이고 `VoteService`의 참가자 ID는 `int`다. 실제 호출자 연결 전에 ID 타입·허용 범위와 매핑 여부를 김지훈·박태욱·최명기가 합의해야 한다. 문서 갱신으로 코드 타입을 바꾸거나 두 값이 이미 연결됐다고 표시하지 않는다.

판 길이 값(숨은 단계 기한 기본 5일, 낮 5분·밤 2분, 귀항 알림, 해금 비율 1/3·2/3)은 기준 문서대로 설정값 한 곳에서 바꿀 수 있게 둔다. 확인 횟수·성공 기준, 최소 공격력·기본 심해 충전량·유지 시간당 증가량은 설정값이며 최종 수치는 플레이테스트 후 조절한다. 직군 세부·레시피·회복량 등 남은 미정 항목은 작업 브리프에 입력 대기로 적는다.

## 7. 장애·접속과 남은 결정

[새 결정 §8](design/win-vote-decisions.md#8-접속-단절과-재접속--n11n12)에 따라 일반 참가자의 연결이 끊겨도 캐릭터를 남기고, 기존 행위 상태와 참가자 ID 기반 상태를 보존한다. 입력과 연결 소유권은 정리하되 투표·누적 시간 등을 연결 목록 삭제와 함께 폐기하지 않는다. 김지훈은 공용 연결/객체 수명을, 각 기능 담당자는 자신의 참가자 상태와 시간 기록을 함께 확인한다. 이 계약은 현재 JH01 코드에 추가 반영해야 하는 기획 요구다.

재접속 기능은 우선 범위에서 제외하며 시간 여유가 있으면 검토한다. 호스트 이탈·이전, 중도 참가, 저장·복구의 실제 통합 방식은 여전히 확정하지 않는다(대장 N11~N13). 일반 참가자 단절 결정은 서버가 사라지는 호스트 이탈 정책을 대신하지 않는다. 배 물리 권한(배 주인 클라이언트/서버)도 v4 13장의 결정 필요 항목이다(N07). 해당 기능 착수 전에 요구사항과 실패 경로를 결정해야 한다.

## 8. 검증과 통합

[검증 플레이북](ai/03_VERIFICATION_PLAYBOOK.md)과 [멀티플레이 테스트](ai/04_MULTIPLAYER_TEST_PROTOCOL.md)를 따른다. 입력·승하선·난파의 로컬 동작, 호스트 판정, 원격 관찰, 비밀 정보 전달 범위를 각각 확인한다. 지정 버전 Unity 6000.0.83f1의 컴파일·Play Mode·다인 접속은 확인 전까지 실행 완료로 표시하지 않는다.
