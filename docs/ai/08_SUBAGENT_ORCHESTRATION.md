# 병렬 작업 분업

> 여러 작업을 동시에 진행할 때 충돌을 막고, 독립 검수를 붙인다.

실제 모델과 작성자 역할은 현재 세션에서 사용자가 지정한 분업 지침과 아래 팀 공용 에이전트 정의를 따른다. 지정이 없으면 이 문서의 역할·쓰기 범위 규칙만 적용한다. 개인의 모델 선호를 팀 공통 기본값으로 확대하지 않는다.

팀 공용 에이전트 정의는 `.claude/agents/`에 있다([도구 설정 안내](TOOL_SETUP.md)). 예를 들어 `perf-code-implementer`는 자주 실행되는 서버 판정·Update 계열 C# 구현용이며 부모(작업을 나누고 통합하는 쪽, [역할](#2-역할))가 정한 쓰기 범위 안에서만 수정한다.

---

## 1. 언제 나누나

| 나눌 만함 | 나누지 말 것 |
|---|---|
| 서로 다른 파트의 독립 시스템 | 같은 씬을 건드리는 작업 |
| 여러 관점의 읽기 전용 조사 | 인터페이스가 아직 확정 안 된 작업 |
| 문서 여러 개를 각각 작성 | 서로의 출력을 입력으로 쓰는 순차 작업 |
| 대안 비교 (격리된 공간에서) | 공유 ScriptableObject를 함께 수정 |

**병렬화하면 안 되는 대표 사례**: 두 작업이 모두 같은 공유 통합 씬을 건드리는 경우.
씬은 머지가 안 되므로 반드시 순차로 한다.

나누는 데에도 비용이 든다. 작업자마다 맥락을 다시 읽고 부모가 통합 · 검수해야 하므로, 한 맥락에서 끝낼 수 있는 일반 코딩 작업을 여러 작업자나 여러 검수자로 쪼개지 않는다. 병렬화와 역할 분리는 아래 실패를 막을 때 값을 한다.

| 한 맥락에서 오래 일할 때 생기는 실패 | 나눠서 막는 방법 |
|---|---|
| 일부만 처리하고 끝났다고 판단한다 (50개 중 35개) | 독립 항목을 적절한 묶음으로 배정하고 부모가 전체 개수와 누락을 대조한다 |
| 자기 결과를 후하게 평가한다 | 작업자와 분리된 새 맥락의 검수자가 판정한다 |
| 긴 작업과 요약을 거치며 원래 목표 · 금지 조건이 흐려진다 | 작업자마다 규칙 원문과 좁은 목표를 직접 준다 |

## 1.5 사람 단위 분업

팀 작업은 기능·담당자 단위로 나눈다. 단일 기준은 [코드 소유권](../CODE_OWNERSHIP.md)이다. 각 담당자는 자기 기능의 Rules·Net·Server·View 전체를 책임지므로 서버·클라이언트 코드라는 이유만으로 다른 담당에게 넘기지 않는다.

- 브랜치는 [커밋·PR 컨벤션](../commit-convention.md)과 현재 팀 합의를 확인하고, 자기 기능 범위 밖 파일 수정은 [AGENTS.md](../../AGENTS.md)의 담당 경계 확인을 따른다
- 담당 개발 씬(`Assets/00.Scenes/<담당>/<씬>.unity`, 실제 경로 확인)은 담당자만 저장한다. 공유 통합 씬은 실제 지정된 통합 담당자가 관리한다. 미지정 상태에서 소유자를 추측하지 않는다
- AI 작업자를 여러 개 돌릴 때도 쓰기 범위는 자기 파트 안에서만 배정한다
- `08.Systems`·`09.UI`는 최명기(cmg6991)가 담당한다. `99.Dev`는 관련 기능 담당자들이 공유하며 작업별 쓰기 범위를 배타적으로 나눈다. AX·문서·자동화 담당을 게임 코드 담당으로 배정하지 않는다.

## 2. 역할

이 문서에서 부모는 작업을 나누고 통합·최종 검증하는 쪽, 작업자는 배정받은 범위만 조사하거나 수정하는 쪽, 검수자는 작업자와 분리된 새 맥락에서 읽기 전용으로 판정하는 쪽을 가리킨다.

### 부모

- 작업 브리프와 분할 기준을 확정한다
- 작업자별 읽기 · 쓰기 범위를 **배타적으로** 배정한다
- 공유 상태, 통합, 최종 검증을 전담한다
- 충돌과 중복 결과를 해소한다
- 작업자 보고에서 근거(파일 · 줄 · 명령 출력)와 미검증 범위를 확인한다. 통합 계약과 변경 결과를 검증하되 신뢰할 수 있는 동일 조사를 통째로 반복하지 않는다

### 작업자

- 배정받은 범위만 조사하거나 수정한다
- 다른 작업자의 파일과 공유 상태를 건드리지 않는다
- 막히면 우회해 범위를 넓히지 말고 차단 조건을 보고한다

### 검수자

- 작업자와 분리된 새 맥락에서 판정한다
- 읽기 전용으로 동작한다
- [검증 플레이북](03_VERIFICATION_PLAYBOOK.md)의 판정과 JSON 스키마를 쓴다

## 3. 쓰기 충돌 방지

1. 하나의 파일은 한 작업자에게만 배정한다
2. **씬 파일은 절대 병렬 배정하지 않는다**
3. 공유 ScriptableObject와 전역 설정은 부모가 전담한다
4. 이동 · 이름 변경 중인 항목은 병렬 쓰기에서 제외한다
5. 사용자가 수정 중인 항목은 쓰기 범위에서 제외한다
6. 작업자 완료 후 부모가 한 번만 통합하고 정적 검사를 실행한다

읽기 전용 조사는 같은 파일을 여러 관점에서 볼 수 있다.

---

## 4. 작업 계약

각 작업자에게 아래를 전달한다.

```text
목표:
읽기 범위:
쓰기 범위:
금지 범위:
수정할 씬: (없음 / {{Assets/00.Scenes/<담당>/ 아래 실제 씬 경로}})
네트워크 영향: (없음 / 서버 권위)
산출물:
완료 기준:
검증 방법:
차단 시 보고할 내용:
```

부모의 요약만 전달해 중요한 제약을 잃지 않는다. 작업자에게 규칙 원문을 직접 준다.

---

## 5. 표준 파이프라인

```
[부모] 작업 브리프 확정
  → [부모] 배타적 범위와 공유 상태 지정
  → [작업자] 독립 실행
  → [부모] 결과 통합과 정적 검사
  → [검수자] 읽기 전용 독립 판정
  → [부모] 보완 또는 최종 보고
```

---

## 6. 종료 전 점검

- 쓰기 대상이 겹치지 않았는가?
- 씬 파일을 병렬로 수정하지 않았는가?
- 공유 상태를 부모만 변경했는가?
- 모든 작업자가 같은 완료 기준을 썼는가?
- 검수자가 작업자의 자기평가에 의존하지 않았는가?
- 최종 검증이 통합된 전체 결과를 대상으로 했는가?
