# 작업 기록과 세션 재개

작업 과정과 결과를 저장소에 남기고 pointer로 찾아 읽는다. 새 대화에 인수인계 본문을 복사하지 않아도 현재 작업과 남은 일을 확인할 수 있게 한다.

## 저장 구조

| 경로 | 내용 |
|---|---|
| `docs/WORK_POINTER.md` | 담당자별 pointer 진입점 |
| `docs/{이름}/POINTER.md` | 날짜별 작업 링크, 진행 상태, 남은 일·차단 조건, 다음 행동 |
| `docs/{이름}/{날짜}/{내용}.md` | 수행 과정·결정 이유·변경 파일·검증·남은 일의 원문 |
| `docs/handover/{이름}/{날짜}/{내용}.md` | 다른 담당자나 세션에 전달할 인수인계. 기존 작업 원문을 링크 |

- `{이름}`은 사용자가 확인한 작성 담당자 이름이다. AI 모델명이나 PC 로그인으로 추측하지 않는다. 기존 담당자 폴더 이름을 재사용한다. 수신자는 인수인계 본문에 따로 적는다.
- `{날짜}`는 처음 작성한 날 `YYYY-MM-DD`다. 같은 작업을 이어가면 원본의 갱신일과 날짜별 진행 이력을 추가하고 파일을 날짜별로 복제하지 않는다. 별개 작업은 새 파일로 만든다.
- `{내용}`은 작업을 구분하는 짧은 제목이다. 개인 폴더의 고정 진입점은 `POINTER.md`다.
- 기록과 pointer는 Git 관리 대상이다. 저장과 커밋·푸시는 구별하며 후자는 요청 범위에서만 수행한다. 다른 PC는 공유된 최신 변경을 받아야 읽을 수 있다.
- 비밀번호·키·토큰·개인 PC 설정·불필요한 원시 로그를 공유 기록에 넣지 않는다. 기존 `.claude/docs/`·`.claude/handover/`는 비공개 보존 영역으로 남긴다. 이어 쓸 기록은 공유 가능한 내용을 확인해 새 위치에 정리하고 상대 링크를 다시 계산한다. 일괄 공개·삭제하지 않는다.

## 세션 시작

1. `AGENTS.md` 다음에 [전체 pointer](../WORK_POINTER.md)를 읽는다. Claude도 `CLAUDE.md`가 가져오는 같은 지침을 따른다.
2. 현재 대화에서 확인된 담당자의 pointer를 읽는다. 이름이 없으면 담당자를 질문한다. 아직 답이 없어도 현재 요청의 담당자와 무관한 확인은 진행할 수 있다.
3. 현재 요청과 일치하는 작업의 원문·연결된 인수인계를 지정된 순서로 읽는다. 여러 작업이 모호하면 선택을 확인하고, 날짜가 최신이라는 이유로 다른 작업을 재개하지 않는다. 전체 이력을 매번 전부 읽지 않는다.
4. 원문의 브랜치·변경 파일·검증 상태를 현재 `git status`, 관련 문서·코드와 대조한다. 기록의 완료는 당시 상태이며 현재 실행 검증을 대신하지 않는다.
5. 첫 작업 응답에 담당자, 진행 중 작업, 남은 일·차단 조건, 다음 행동을 간결하게 알린다. 기록이 없거나 링크가 깨졌거나 현재 체크아웃에 없으면 미확인으로 밝힌다. 내용이나 완료 상태를 추측하지 않는다.

예: “김지훈님의 A 작업은 구현됨(미검증)으로 기록돼 있습니다. 원격 접속 확인이 남았고, 현재 브랜치와 변경을 대조한 뒤 테스트 환경부터 확인하겠습니다.”

pointer는 읽을 맥락을 선택한다. 과거의 다음 행동이 새 실행 승인이나 게임 규칙이 되지는 않는다. 최신 사용자 요청과 담당 경계를 우선한다. 저장소에 접근할 수 없는 환경에서는 자동 읽기가 불가능함을 알린다.

## 작업 후 갱신

의미 있는 구현·조사·설계·문서 작업을 마치거나 중단할 때 원문과 pointer를 같은 작업에서 갱신한다. 단순 인사·상태 확인은 새 기록을 만들지 않는다. 읽기 전용·기록 금지 요청은 우선하며 파일을 쓰지 않는다.

1. 기존 관련 원문을 찾아 갱신한다. 무엇을 어떤 순서로 했는지, 확인한 근거와 판단 이유를 적는다. 다른 사람의 기존 변경을 자신의 성과로 적지 않는다.
2. 담당자 pointer의 해당 행만 갱신한다. 완료된 작업도 날짜별 이력으로 남기고 진행 중 목록과 구분한다. 다른 작업의 행을 덮어쓰지 않는다.
3. 처음 만든 담당자 pointer를 전체 pointer에 연결한다. 전체 pointer에는 진행 내용을 중복 저장하지 않는다.
4. 인수인계가 필요하면 [세션 인수인계](05_SESSION_HANDOFF.md) 양식으로 작성하고 해당 작업 행의 읽을 순서에 연결한다. 작업 원문 본문을 복제하지 않는다.
5. 상대 링크, Git 제외 여부, 상태와 원문 일치를 확인한다. 기록 경로와 실제 실행한 검증을 보고한다.

확정된 팀 규칙은 해당 기준 문서에도 반영한다. 작업 기록은 규칙의 단일 기준을 대체하지 않는다.

## 작업 원문 양식

```markdown
# 작업명
작성자: 이름
작성일: YYYY-MM-DD
갱신일: YYYY-MM-DD
상태: 진행 중 / 대기 / 구현됨(미검증) / 완료(검증됨)
브랜치·기준 커밋: 실제 확인한 값

## 요청과 목표
## 진행 과정과 결정 이유
- YYYY-MM-DD: 수행 내용, 근거, 결정과 이유
## 변경 파일과 결과
## 검증
- 실행한 확인과 결과:
- 실행하지 못한 확인과 이유:
## 남은 일과 차단 조건
## 다음 행동
## 관련 원문·인수인계
```

## 담당자 pointer 양식

```markdown
# 이름 작업 pointer
갱신일: YYYY-MM-DD

## 진행 중·대기
| 작성일 / 갱신일 | 작업 | 상태 | 남은 일·차단 조건 | 다음 행동 | 읽을 순서 |
|---|---|---|---|---|---|

## 완료 이력
| 작성일 / 완료일 | 작업과 결과 | 원문 |
|---|---|---|
```

표에는 짧은 상태와 실제 상대 링크만 둔다. 예를 들어 담당자 폴더에서는 `2026-10-12/작업명.md`, 인수인계는 `../handover/이름/2026-10-12/전달명.md`로 연결한다. 아직 없는 문서를 실제 링크처럼 등록하지 않는다.
