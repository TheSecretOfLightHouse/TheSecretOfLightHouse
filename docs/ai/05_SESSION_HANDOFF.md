# 세션 인수인계

> 중단된 작업을 다음 세션이 추측 없이 재개하도록 현재 상태, 근거, 제약, 다음 행동을 한곳에 기록한다.

---

## 저장 위치와 독자

개인 세션 기록과 담당자 전달 문서의 경로와 날짜 규칙은 [AGENTS.md](../../AGENTS.md)를 따른다. 두 경로 모두 Git에서 제외되며 커밋하지 않는다. 현재 작업 색인(작업별 개인 기록의 위치와 상태를 모아 둔 목록. 정해진 경우에만 쓰며 없다고 새로 만들지 않는다)을 사용한다면 그 위치를 개인 기록에 남긴다. 팀 공유 계약은 [문서 분류 기준](../DOCUMENTATION_POLICY.md)에 따라 `docs/`에 작성한다.

- 개인 기록: 실행 환경·명령 결과·시행착오·재개할 작업을 기록한다. 기존 작업이면 원본을 갱신하고 날짜를 바꾸지 않는다.
- 팀 공유 문서: 현재 동작·API·데이터·검증 방법을 본문만으로 이해할 수 있게 작성한다. 개인 기록의 파일이나 링크를 참조하지 않는다.
- 담당자 전달: 수신자, 요청 이유, 증상 또는 현재 계약, 관련 코드와 확인 방법, 필요한 결정, 다음 행동을 명시한다.
- 현재 작업 색인은 개인 기록의 위치와 상태만 관리한다. 공유 문서에 복제하지 않는다.
- 파일 이동 후 링크는 파일의 실제 위치에서 계산한다. 이전 경로의 접두사를 무조건 복사하지 않는다.

---

## 작성 시점

아래 중 하나라도 해당하면 작성하거나 갱신한다.

- 작업이 끝나기 전에 세션을 종료한다
- **다인 접속 테스트를 기다린다** (이 프로젝트에서 가장 흔한 중단 사유)
- 다른 파트의 인터페이스 확정을 기다린다
- 여러 단계 중 일부만 완료했다
- 커밋하지 않은 작업물이 남아 있다

---

## 작성 원칙

- 관찰한 사실과 추정을 분리한다.
- 완료 주장은 실제 증거와 함께 기록한다.
- 동적인 값은 기억에 의존하지 말고 재확인 방법을 적는다.
- 다음 세션이 읽을 순서와 첫 행동을 명령형으로 적는다.
- 검증 상태는 [검증 플레이북](03_VERIFICATION_PLAYBOOK.md)의 어휘를 쓴다.

## 이 프로젝트에서 특히 기록할 것

| 항목 | 왜 |
|---|---|
| 수정한 씬 이름 | 다음 세션이 다른 씬을 열면 작업이 안 보인다 |
| 신규 ScriptableObject 경로 | 인스펙터에서 값을 넣어야 동작하는 경우가 많다 |
| 멀티플레이 검증 등급 | M0까지만 했는지 M2까지 했는지가 신뢰도를 결정한다 |
| 다른 파트에 요청한 인터페이스 | 답을 못 받으면 계속 막힌다 |
