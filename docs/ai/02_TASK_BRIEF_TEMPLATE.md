# 작업 브리프 템플릿

> 작업의 이유와 실행 계약을 함께 제공해 범위 이탈, 과잉 구현, 근거 없는 완료 주장을 줄인다.

---

## 사용 규칙

- 결과와 제약을 적고 세부 구현 순서는 실행자에게 맡긴다.
- 간단한 조회나 오타 수정에는 필요한 필드만 쓴다.
- 불명확한 값은 추측하지 말고 `{{미정}}`으로 표시한다.
- 분석만 요청할 때는 수정 금지를 명시한다.
- 검증 수준은 [검증 플레이북](03_VERIFICATION_PLAYBOOK.md)에 맞춰 정한다.

---

## 등대 프로젝트 예시

아래는 향후 구현 요청을 작성하는 예시이며 기존 구현 완료를 뜻하지 않는다. 파일 경로는 조사 후 실제 대상에 맞춰 기입한다.

```markdown
# 등대 수리 자원 동시 투입 검증

## 배경
- 4명이 같은 등대에 자원을 투입해도 자원과 수리도가 중복 반영되지 않아야 한다
- 근거 문서: docs/design/references/game-design-v4.md의 등대·모듈과 크래프팅 절

## 산출물
- 최종 형태: 현재 투입 경로 조사와 중복 요청 처리 보완
- 이번에 포함: 소유 자원 확인, 호스트 판정, 수리도 동기화
- 후속으로 미룸: 새 자원 종류·레시피·연출

## 영향 범위
- 담당 기능·담당자: {{실제 담당자 확인}}
- 다른 담당자와 합의: {{대상 파일·수정 이유·영향·합의 범위}}
- 수정할 씬: {{실제 검증 씬}}
- 네트워크 영향: 호스트 권위, 공유 수리도
- 밸런스 데이터 영향: 기존 수치 유지
- 다른 파트와 충돌 가능성: 인벤토리와 등대 상태 계약

## 범위
- 읽기: Assets/01.Scripts/ 및 관련 씬·데이터
- 수정 가능: {{조사 후 확인한 파일 목록}}
- 제외: 외부 코드, 구매 에셋, 다른 담당자의 미승인 파일

## 제약
- 호스트에서 소유권·수량·현재 상태를 검증한다
- 기존 어셈블리 참조와 게임 규칙을 유지한다
- 사전 범위 확인: 승인된 Lighthouse.Runtime 구조 밖 어셈블리 변경 또는 다른 담당·공용 계약 수정

## 완료 기준
- [ ] 동시에 요청해도 자원이 중복 소비되지 않는다
- [ ] 수리도가 호스트와 원격 클라이언트에서 일치한다
- [ ] 부족한 자원의 요청은 거부된다
- [ ] 검증 결과와 미검증 항목을 구분한다

## 검증
- 위험도: 높음 (공유 상태·네트워크)
- 최소 수준: L1 + L2 + L3
- 멀티플레이 등급: M2, 정원 관련 조건은 호스트 1 + 원격 클라이언트 3
- 성공 신호: 각 요청 결과·자원 잔량·수리도가 일치
- 중단 조건: 중복 차감 또는 수리도 불일치
```

## 분석 전용 변형

분석만 필요하면 아래 제약을 추가한다.

```text
읽기 전용으로 조사하라. 어떤 파일도 수정하지 마라.
원인, 선택지, 영향, 근거를 보고한 뒤 중지하라.
수정은 별도 승인된 작업으로 분리하라.
```

## 작성 전 점검

- 목적이 구현 절차가 아니라 관찰 가능한 결과로 적혔는가?
- 수정 가능 범위와 제외 범위가 겹치지 않는가?
- 완료 기준마다 확인 방법이 있는가?
- 네트워크 영향과 씬 소유권을 검토했는가?
- 이번 작업 제외 범위를 건드리지 않는가?
