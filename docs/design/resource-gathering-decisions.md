# 자원 채집 확정 기획

결정일: 2026-10-16
갱신일: 2026-10-17
기준: 사용자가 확정한 자원 범위와 현재 채집·획득 흐름.
상태: 기획 확정 범위와 미정 사항을 구분한 규칙 문서.

## 1. 적용 범위와 우선순위

### 2026-10-17 추가 사용자 결정

- 자원 원본과 채집 잔량은 개인별이다. 다른 플레이어의 채집은 내 원본과 잔량에 영향을 주지 않는다. 로컬 원본 생성만으로 개인 잔량 관리가 구현된 것은 아니다.
- 돌은 내구도와 잔량을 같은 값으로 취급한다. 플레이어별 원본 하나에 초기값 3, 승인된 매 타격마다 1 감소 및 돌 1개 드롭, 0이면 해당 플레이어 화면의 원본만 비활성화한다.
- 결과 드롭은 공유 네트워크 객체이며 다른 플레이어도 획득할 수 있다. 개인 보유 수량은 기존대로 소유자에게만 표시한다.
- 다른 자원은 대상별 초기 잔량을 설정할 수 있도록 준비한다. 다른 자원의 수치는 미정이다. 재생 시점·개인 잔량 복원·드롭 생성 실패 복구는 후속 계약이다.
- 이 결정은 아래 §3.2·§5의 돌 파괴 조건 및 개인/공유 범위 미정 설명보다 우선한다. World의 지점별 공유 잔량 API를 개인 잔량으로 그대로 사용하지 않는다. 코드 통합·다인 검증 완료를 뜻하지 않는다.

이 문서는 플레이어가 월드 자원에서 드롭을 만들고 개인 인벤토리에 획득하는 흐름을 정한다. 코드 구조·구현 상태·시험값은 기획 규칙으로 정의하지 않는다.

최신 사용자 결정으로서 이 문서의 확정 범위는 기존 작업 기록과 [게임 기획 v4](references/game-design-v4.md)의 같은 범위보다 우선한다. 변경하지 않은 시간대·해역·자원 분포·부분 재생 등의 규칙은 v4를 유지한다. [승패·투표 결정](win-vote-decisions.md)은 변경하지 않는다.

## 2. 확정된 자원 범위

**강민서의 월드 스폰 자원은 플레이어가 좌클릭 등의 채집 행동으로 부숴서 드롭을 만들 수 있는 오브젝트만 해당한다. 상호작용키로 바로 줍는 자원 아이템은 월드에 배치하지 않는다.**

| 구분 | 의미 | 플레이어 행동 |
|---|---|---|
| 자원 원본 | 섬 등에 배치되는 파괴 가능한 채집 대상 | 좌클릭 등의 채집 행동으로 부순다 |
| 자원 드롭 | 원본을 부순 결과로 생성되는 획득물 | 가까이 다가가 E키로 줍는다 |
| 인벤토리 자원 | 드롭 획득에 성공해 플레이어가 보유한 수량 | 이후 제작·수리 등 기존 소비 규칙에서 사용한다 |

자원 원본과 자원 드롭은 역할이 다르다. 월드에 처음부터 놓이는 것은 파괴형 원본이고, E키로 줍는 것은 채집 결과로 생성된 드롭이다. **직접 줍는 배치 아이템을 두지 않는 결정은 파괴 후 드롭의 E키 획득을 없애는 결정이 아니다.**

난파 화물·표류 모듈 회수·유령선 조사 등 별도 기능의 규칙은 이번 자원 스폰 범위 결정으로 바꾸지 않는다.

## 3. 채집부터 획득까지의 플레이 흐름

### 3.1 자원 발견과 접근

- 플레이어는 섬 등의 월드 자원 원본을 발견하고 채집 가능한 거리로 접근한다.
- 원본을 가까이서 발견했거나 E키를 눌렀다는 이유만으로 자원을 받지 않는다.
- 월드에 배치할 자원 종류·위치·생산량은 기존 월드 기획을 따르며, 이 문서에서 새 자원이나 수치를 추가하지 않는다.

### 3.2 원본 채집과 파괴

- 현재 채집 조작은 커서로 대상을 가리키고 좌클릭하는 흐름을 기준으로 한다. 원본을 E키로 채집하지 않는다.
- 채집 행동으로 원본을 부수고 그 결과로 드롭을 만든다.
- 원본 파괴에 필요한 타격 횟수·시간·도구 조건은 아직 정하지 않았다. 한 번 클릭할 때마다 반드시 원본 하나가 파괴된다고 확정하지 않는다.
- 채집 단계에서는 자원이 인벤토리에 직접 들어가지 않는다. 원본 채집과 결과 드롭 획득은 별도 행동이다.

### 3.3 드롭 생성과 획득

- 유효한 채집 결과로 월드에 드롭이 생성된다.
- 플레이어는 생성된 드롭 근처에서 E키로 획득한다.
- E키 획득 대상은 자원 드롭이다. 원본이 가까이 있다는 이유로 E키가 원본 채집이나 추가 드롭 생성을 실행하지 않는다.
- 드롭 획득에 성공하면 획득한 플레이어의 개인 인벤토리 수량이 증가하고 드롭이 사라진다.
- 지급에 실패하면 드롭을 남긴다. 지급되지 않은 드롭을 성공한 것처럼 제거하지 않는다.

**전체 흐름: 월드 원본 배치 → 좌클릭 등으로 파괴형 채집 → 드롭 생성 → 접근 후 E키 획득 → 개인 수량 증가·드롭 제거.**

## 4. 획득과 정보 표시의 기준

- 자원 지급과 드롭 제거는 서버가 판정한다. 클라이언트의 요청만으로 보유 수량을 확정하지 않는다.
- 드롭 하나를 여러 플레이어가 중복 지급받지 않도록 처리한다. 동시 요청의 구체적인 우선권·지연 보정 방식은 미정이다.
- E키로 드롭을 고르는 현재 흐름은 범위 안의 가까운 자원을 선택하는 방식이다. 원본 채집의 커서 조준과 드롭 획득을 구분한다.
- 개인 보유 수량은 소유 플레이어에게 전달·표시한다. 타인의 인벤토리를 공개하는 기능을 이번에 추가하지 않는다.
- 본편 HUD의 모양·선택 대상 강조·실패 메시지·획득 연출은 미정이다. 현재 시험 화면의 크기·위치를 기획으로 고정하지 않는다.
- 작업대 등 다른 E키 행동과 통합하더라도 원본 채집과 드롭 획득의 구분을 유지한다. 대상 우선순위와 표시 정책은 별도 결정한다.

## 5. 아직 확정하지 않은 사항

| 항목 | 남은 결정 |
|---|---|
| 파괴 조건 | 자원별 내구도·타격 횟수·채집 시간·도구 필요 여부 |
| 원본 변화 | 타격 반응·파괴 연출·파괴 후 사라지는 시점 |
| 드롭 결과 | 자원별 종류·수량·확률, 직군 능력에 따른 변화 |
| 자원량·재생 | 구체적인 매장량·회복량·시점, 파괴된 원본이 다시 나타나는 방식. v4의 일부 회복 방향은 유지 |
| 드롭 유지 | 소멸 시간·표류·물리 이동·회수 가능 영역 |
| 인벤토리 제한 | 용량·보유 상한, 가득 찼을 때 안내와 처리 |
| 동시 채집·실패 | 같은 원본을 함께 부술 때 결과, 생성 실패 시 원본·잔량 복구와 보상 처리 |
| 선택·안내 | 여러 드롭과 작업대가 가까울 때 우선순위, 선택 표시·거절 안내 |
| 행동 제한 | 채집 거리·속도, 도중 취소·탑승·난파와 다른 행동이 겹칠 때 세부 규칙 |

시험용 수치나 현재 코드 동작만으로 위 항목이 확정된 것으로 해석하지 않는다. [설계 문제 대장](../07-design-issue-register.md)의 W05·N09·N10은 관련 경제·자원 보존·상호작용 계약이 남아 있다.

## 6. 담당 경계

담당자의 단일 기준은 [코드 소유권](../CODE_OWNERSHIP.md)이다.

| 담당 | 맡는 범위 |
|---|---|
| 강민서 | 월드 자원 원본의 배치·자원 정의·지점·매장량·재생. 스폰 대상은 §2의 파괴형 원본으로 한정 |
| 최명기 | 플레이어 채집 행동, 결과 드롭 생성·획득, 개인 인벤토리와 표시 |
| 김지훈 | 공용 상호작용 검증·전달, 다른 E키 행동과의 통합 및 네트워크 공용 기반 조율 |

원본 파괴 결과와 월드 잔량·드롭 생성의 경계는 세 담당자가 함께 맞춘다. 이 기획 확정만으로 세부 연동 방식까지 합의되거나 구현 완료된 것은 아니다.

## 7. 기획 적용 시 확인할 결과

- 월드 스폰 자원은 부숴서 드롭을 만드는 원본이며, 처음부터 E키로 줍는 배치 자원은 없다.
- 원본 앞에서 E키를 눌러도 바로 지급되거나 원본 채집이 실행되지 않는다.
- 원본을 유효하게 채집하면 드롭이 생기고 인벤토리 수량은 아직 증가하지 않는다.
- 드롭을 E키로 획득하는 데 성공하면 본인 수량이 증가하고 해당 드롭이 사라진다.
- 지급 실패·동시 획득·반복 요청으로 자원이 복제되거나 보상 없이 사라지지 않아야 한다. 원본 파괴·실패 복구의 구체 조건은 §5 결정 후 확정한다.

위 내용은 기획상 기대 결과이며 실제 시험 통과 기록이 아니다. 구현 과정과 코드·설정·현재 미연결 상태는 [구현 참고](../최명기/2026-10-16/자원채집-구현참고.md)에서 별도로 관리한다.
