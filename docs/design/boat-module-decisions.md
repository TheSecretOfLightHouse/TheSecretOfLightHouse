# 배 모듈 상세 기획

작성일·갱신일: 2026-10-20  
결정자·배 장착 담당: 최명기  
상태: 4종 구성과 기존 공통 규칙 확정. 아래 상세 동작·시험 수치는 채택 전 설계안이며 구현·실행 검증 완료를 뜻하지 않는다.

## 1. 목적과 기준

개인 배에 장비를 제작·장착해 관찰, 순간 기동, 충돌 위험 인지, 파도 속 조작을 보완한다. 모듈이 없어도 기본 항해와 임무 수행이 가능해야 하며, 제작 자원을 등대 진행에 투자할지 개인 배에 투자할지 판단하게 한다.

최신 사용자 결정 → 이 문서의 확정 규칙 → [승패·투표 결정](win-vote-decisions.md) → 미변경 범위의 [게임 기획 v4](references/game-design-v4.md)를 따른다. 등대는 [등대·작업대 모듈 결정](lighthouse-module-decisions.md), 수리는 [배 수리 결정](boat-repair-decisions.md)을 따른다. 이 문서의 상세 제안은 다른 시스템의 확정 규칙을 변경하지 않는다.

## 2. 사용자 확정 규칙

| 항목 | 규칙 |
|---|---|
| 종류 | 탐조등, 대쉬, 장애물 경보, 선체 안정기 4종 |
| 기존 목록 변경 | 수심 경보기 대신 장애물 경보를 채택하고 대쉬 추가. 장애물의 정확한 감지 범위는 아래 제안 |
| 제작 | 자원을 모아 작업대에서 제작하는 개인 배 업그레이드 |
| 장착 조건 | 자기 배에 탑승 중 장착. 하선 중 장착 불가 |
| 장착 개수 | 종류별 전용 슬롯 1개, 서로 다른 종류 동시 장착 가능. 현재 최대 4종 |
| 중복 | 같은 종류 중복 장착 불가 |
| 탐조등 공개 | 빛은 다른 플레이어에게도 보임 |
| 난파 | 장착 모듈 전부 소실. 복구 시 자동 복원·반환·추가 드롭 없음 |
| 확장 | 종류를 추가할 수 있는 공통 장착 구조 유지 |
| 효과 방향 | 탐조등은 관찰 보조, 안정기는 파도로 인한 기울기·흔들림 완화. 직군·등대 보상 중복 최소화 |

이하 3~8절과 10절의 새 효과 동작·수치·입력은 **권장 상세안**이다. 9절 제작 레시피는 사용자 위임에 따른 초기 시험값이다. 완성품 보관 위치는 2026-10-20 김지훈 결정(작업대 보관 → 플레이어 인벤토리로 가져가기 → 장착)으로 정해졌다(9절). 권장 효과 상세안은 사용자 채택 전 구현의 확정 요구사항으로 쓰지 않는다. 대쉬는 순간이동인지 가속인지 사용자 지정이 없으므로 이 기획에서는 짧은 가속 방식으로 제안한다.

## 3. 네 모듈의 역할과 사용 흐름 — 제안

| 종류 | 방식 | 플레이어가 하는 판단 | 제공하지 않는 능력 |
|---|---|---|---|
| 탐조등 | 장착 후 자동 점등 | 빛으로 주변을 직접 관찰 | 환영 섬 진위 판별·안개 관통·자동 탐지·공격 |
| 대쉬 | 재사용 대기시간이 있는 수동 사용 | 탈출·돌파·접근 시점 선택 | 순간이동·무적·충돌 무시·추가 충돌 피해 |
| 장애물 경보 | 탑승 중 자동 감지 | 경고 방향을 보고 감속·선회 | 자동 회피·몬스터 탐지·자원 탐지·지도 정답 제공 |
| 선체 안정기 | 탑승 조종 중 자동 적용 | 거친 바다에서도 관찰·조종 유지 | 직접 피해 감소·보호막·자동 수리·속도 증가 |

기본 흐름: 자원 수집 → 작업대 제작 → 완성품 보유 → 자기 배 탑승 → 종류별 장착 → 효과 사용 → 난파 시 소실. 모듈 간 택일이 아니라 제작 순서와 자원 배분이 선택이다.

## 4. 탐조등 — 상세 제안

### 사용과 효과
- 배 앞부분에서 배의 수평 진행 방향을 따라 넓은 전방을 비춘다. 별도 조준 입력은 첫 버전에 추가하지 않는다.
- 장착 후 자동 점등하고 하선 중에도 유지한다. 난파·모듈 제거·판 종료 시 모듈 조명과 빛줄기를 함께 끈다.
- 기본 배 조명은 유지한다. 연료·전력 소비와 별도 토글은 첫 버전에서 도입하지 않는다.
- 빛과 장착 외형은 다른 플레이어에게도 보인다. 위치 노출은 자연스러운 결과지만 몬스터가 빛에 반응하는 규칙은 추가하지 않는다.
- 지형·장애물 차폐와 안개 영향을 받으며 환영 섬도 일반 조명과 같은 방식으로 보인다. 진위 정보를 제공하지 않는다.

### 표현과 체감
- 전방 Spot Light와 얇은 빛줄기 표현을 사용한다. 빛줄기 자체가 실제 안개 산란을 보장하지는 않는다.
- 장착 전후 같은 야간 위치에서 장애물 윤곽이 더 잘 보여야 한다. 과도한 노출·수면 반사로 시야가 오히려 나빠지면 밝기를 낮춘다.
- HUD에는 장착·점등 상태만 표시하고 자원·몬스터 윤곽 강조는 넣지 않는다.

## 5. 대쉬 — 상세 제안

### 발동 조건과 입력
- 대쉬 입력 액션을 한 번 누르면 발동한다. 실제 키는 기존 입력 충돌 확인 후 지정하고 재설정 가능하게 한다.
- 자기 배 소유·탑승·정상 조종 가능·모듈 장착·재사용 가능 상태에서만 발동한다.
- 난파·다운·하선·입력 잠금·판 종료·UI가 조작을 차단하는 상태에서는 요청을 거절한다. 거절 시 쿨다운을 소비하지 않는다.
- 정지 상태에서도 사용 가능하되 후진 입력 중에는 거절한다. 첫 버전은 충전 횟수 1회, 연료 소비 없음으로 제안한다.

### 이동과 종료
- 발동 시 배의 전방을 수면의 수평면에 투영한 방향으로 가속한다. 파도에 들린 선수 방향으로 위쪽 발사되지 않는다.
- 발동 방향은 지속 시간 동안 고정하고 선회는 막는다. 짧은 직선 돌파 능력으로 구분한다.
- 수직 부력과 충돌 판정을 유지한다. 통과할 수 없는 장애물을 뚫거나 폭풍벽 밖으로 넘어갈 수 없다.
- 지속 시간 만료, 전진 취소/후진 입력, 하선, 다운, 입력 잠금, 난파, 판 종료 시 가속을 종료한다. 고체 장애물 충돌도 종료 조건으로 두며 접촉 종류 기준은 구현 전 확인한다.
- 종료 후 즉시 속도를 0으로 만들지 않고 기본 이동의 감속·가속 규칙으로 복귀한다. 조작 잠금·난파 시에는 해당 시스템의 정지 규칙을 우선한다.
- 성공한 발동 시점부터 쿨다운을 계산한다. 중도 취소·재탑승·UI 개폐로 초기화하지 않는다. 종료와 동시에 다시 발동하지 못하도록 서버 시각으로 관리한다.

### 중첩·표현
- 항해사나 확정된 공동 보상이 적용된 평상시 전진 최고속도를 기준으로 대쉬 속도를 계산하고, 별도의 대쉬 최고속도 상한을 둔다. 정확한 중첩식·상한은 플레이테스트 후 확정한다.
- 기본 가속 처리에서 대쉬 속도를 다음 프레임에 덮어쓰지 않도록 이동 처리에 단일 최종 목표속도를 제공해야 한다.
- 추진 물보라·발동음은 주변 플레이어도 볼 수 있다. HUD는 준비/사용 중/남은 쿨다운을 표시한다.
- 대쉬 충돌의 추가 공격 보너스는 없다. 기존 속도 기반 충돌·파도 피해가 있다면 해당 규칙의 영향을 별도로 시험한다.

- 컴파일·격리 검사와 실제 플레이/M2 검증을 구분한다. [작업 기록](../최명기/2026-10-26/장애물-경보-모듈.md).

### 감지 대상과 범위
- 전방 암초, 섬 해안·절벽, 고정 구조물 등 배의 실제 이동을 막는 고체 지형을 경고한다.
- 자기 배·탑승자·물 표면·트리거·아이템·수중 장식·몬스터·다른 배는 첫 버전의 감지 대상에서 제외한다. 다른 배까지 경고하면 협업 중 경보 과잉과 위치 탐지로 확대될 수 있다.
- 단순한 중심선 Ray 대신 배 폭과 앞부분을 고려한 충돌 예상 영역을 사용한다. 최종 물리 조회 방식과 레이어는 실제 월드 지형 확인 후 결정한다.
- 전진 시 실제 수평 이동 방향을 기준으로 감지하고, 저속·정지 시 선수 방향을 사용한다. 후진 경보는 첫 버전에서 제공하지 않는다.
- 수면 아래 깊이만 낮다는 이유로 경고하지 않는다. 기존 수심 경보기의 연속 수심 측정은 이번 제안에 포함하지 않는다.
- 환영 섬 전용 정보나 진위 판별 값을 읽지 않는다. 감지 가능 여부만으로 진짜 섬을 구별할 수 있다면 월드 담당자와 표현·충돌 계약을 먼저 맞춘다.

### 경고 단계와 공개 범위
- 가장 가까운 충돌 위험 하나를 좌/중앙/우 방향 표시로 전달한다. 멀리 있는 장애물의 정확한 위치·전체 지도를 공개하지 않는다.
- 주의 단계는 노란 아이콘, 위험 단계는 붉은 아이콘과 짧은 반복음으로 표시한다. 색상 외 형태·텍스트를 함께 사용하고 소리는 끌 수 있게 한다.
- 경고는 소유 탑승자에게만 표시·재생한다. 하선·난파·모듈 제거 즉시 끈다.
- 주의·위험 전환에 거리 여유와 해제 지연을 두어 파도·경계 거리에서 깜빡이거나 소리가 중첩되지 않게 한다.
- 대쉬 중에는 현재 속도와 남은 가속을 고려해 감지 거리를 늘린다. 최대 감지 거리가 필요한 회피 시간을 확보하지 못하면 속도·거리 설정을 함께 조정한다.

## 7. 선체 안정기 — 상세 제안

### 효과와 경계
- 자기 배에 탑승해 조종할 때 자동 적용하고 하선 시 기본 물리 설정으로 복귀한다. 모듈 자체는 장착 상태를 유지한다.
- 파도 때문에 좌우로 기우는 롤과 앞뒤로 기우는 피치를 완화한다. 좌우 선회인 요 회전과 기본 선회 속도는 변경하지 않는다.
- 수면 높이를 따라 뜨는 움직임·큰 파도 연출·바람·해류·토네이도 이동은 유지한다. 배를 수평으로 고정하거나 환경 위협을 무효화하지 않는다.
- 강한 파도에서는 흔들림이 남아야 한다. 장착 전후 비교에서 관찰·조종이 안정되면서 바다 위협은 유지되는 것을 목표로 한다.
- 장착·해제·재탑승 시 계수를 반복 곱하지 않고 원본 설정과 현재 장착 상태에서 계산한다. 다른 배의 안정성 설정을 바꾸지 않는다.
- World에 이미 존재하는 `ShipStabilizer`는 기본 부력 안정화 구성이다. 모듈 구현 완료로 세지 않으며 공용 값을 직접 바꾸지 않는다.
- 직접 피해 감소는 주지 않지만 물리 반응 변화가 파도 충격 피해를 간접적으로 줄일 수 있다. 이 효과까지 방어 능력으로 굳어지지 않는지 비교 검증한다.

### 표현
- HUD에 적용 상태를 표시한다. 효과가 켜질 때 작은 장착음만 사용하고 지속 진동·화면 효과는 추가하지 않는다.
- 카메라만 덜 흔들리게 하는 처리를 선체 안정화 완료로 보지 않는다. 실제 배의 롤·피치를 비교하고 카메라 결과도 함께 확인한다.

## 8. 초기 시험 수치 — 전부 가안

Unity 월드 단위를 기준으로 한 시작값이다. 월드 크기·배 치수·기본 속도와 실제 야간 화면을 확인한 뒤 조정한다. 광도·레시피 재료 종류는 현 설정 확인 전 숫자를 정하지 않는다.

| 모듈 | 초기 시험값 | 조정 기준 |
|---|---|---|
| 탐조등 | 조사 거리 35, 전체 조사각 80도 | 기본 시야와 비교해 전방 관찰 향상, 안개·수면 눈부심 억제 |
| 대쉬 | 지속 0.8초, 평상시 전진 최고속도의 1.8배, 쿨다운 12초 | 반복 이동의 필수 버튼이 되지 않으며 회피 체감 확보. 최고속도 상한 별도 결정 |
| 장애물 경보 | 주기 0.1초, 기본 감지 15, 최대 40, 주의 도달시간 2초 이하·위험 1초 이하 | 배 앞부분부터 장애물까지 거리/속도로 도달시간 추정. 정지·극저속은 거리 6/3으로 주의/위험 판단 |

경보 감지 거리는 최소 기본 거리와 속도×주의시간+여유거리 중 큰 값을 사용하되 최대 거리로 제한하는 방향을 제안한다. 대쉬 가속·배 크기·조회 주기를 여유거리에 반영하고, 제한 때문에 2초 여유가 안 나오면 경보 문구만으로 안전을 보장하지 않는다.

## 9. 제작·장착·수명 상세안

### 제작과 이전 — 2026-10-20 사용자 위임에 따른 정리

사용자가 등대 모듈과 같은 방식으로 정리하도록 위임했다. 아래는 배 모듈의 제작·보관·장착 기준이다. 타 담당의 API 구현·협의 완료를 뜻하지 않는다.

| 배 모듈 | 1개 제작 재료 | 선택 이유 | 값의 상태 |
|---|---|---|---|
| 탐조등 | 유리 3 + 철 2 | 기존 자원 기획의 탐조등 조합 유지, 렌즈와 지지대 | 초기 시험값 |
| 대쉬 | 철 3 + 섬유 3 | 등대 기어 장치와 같은 비용, 추진 장치·연결 부품 이미지 | 초기 시험값 |
| 장애물 경보 | 철 2 + 유리 1 + 수정 1 | 감지 장비와 표시부, 수정 사용으로 제작 시점 차별화 | 초기 시험값 |
| 선체 안정기 | 나무 4 + 철 3 + 섬유 2 | 선체 장착 프레임과 고정부 이미지 | 초기 시험값 |

재료는 기존 돌·나무·섬유·철·유리·수정 체계 안에서 선택한다. 새 자원·중간 제작품은 추가하지 않는다. 재료 수량은 확정 밸런스가 아니며 등대 진행 지연과 4인 자원 수급을 보고 조정한다. 수정이 필요한 경보는 외해 진출 이후 제작될 수 있는 의도적인 시험안이다.

- **제작 장소·진행:** 등대와 같은 공유 작업대. 각 레시피에 여러 플레이어가 부분 투입하고 레시피별 진행도를 따로 유지한다. 재료를 모두 넣고 제작 버튼을 누르면 1개 즉시 완성한다. 별도 제작 시간·장착 시간·추가 장착 재료 없음으로 정리한다.
- **보관·권한 — 결정(2026-10-20 김지훈, [모듈 운반 결정](lighthouse-module-decisions.md#모듈-운반과-난파구조-2026-10-20-결정)):** 완성품은 작업대에 보관하고, 누구나(시민·마피아) 자기 플레이어 인벤토리로 가져간 뒤 자기 배에 탄 채 장착한다. 인벤토리의 모듈은 1인 1개(등대·배 모듈 합산), 작업대로 되돌려놓기 가능, 가진 사람은 본인만 앎(2026-10-21 비공개로 변경). 모듈은 `PlayerInventory` 자원 수량에 넣지 않고 서버 `WorkbenchNet`이 플레이어별로 기록하며 본인 PC에만 `OwnCarriedRecipe`로 알린다. 2026-10-21 코드 반영: 가져가기 `TakeModule`=16, 되돌려놓기 `ReturnModule`=17, 배 장착은 자기 배를 대상으로 `InstallModule`(Arg0=레시피 ID)을 보내면 모듈 처리기가 `BoatModuleEquipment.TryInstall`을 부른다. 배 레시피 ID 101 탐조등·102 대쉬·103 장애물 경보(`DepthAlarm`)·104 선체 안정기. 대쉬는 `BoatModuleType`에 종류가 생길 때까지 장착 거절.
- **제작 상한:** 배 레시피의 전체 존재 상한은 우선 제한 없음(`MaxExisting = 0`, 초기 시험값). 등대 레시피의 각 1개 설정은 유지한다. 배마다 종류별 장착 1개 제한과 전체 제작 상한은 별개다. 미장착 완성품은 작업대 보관 또는 플레이어 인벤토리(1개)에 있다.
- **장착 흐름:** 재료 투입·제작 → 작업대 보관 → 플레이어 인벤토리로 가져가기 → 자기 배 탑승 → 장착 요청 → 성공 시 인벤토리에서 모듈을 빼고 배 장착을 함께 확정한다. 작업대 재고에서 바로 장착하는 경로는 없다.
- **거리·접근:** 인벤토리에 모듈이 있으면 작업대 거리와 관계없이 자기 배에서 장착한다. 이전 작업대 거리 10 시험안은 쓰지 않는다.
- **입력 경계:** 기존 작업대 재료 투입·제작의 하선 조건은 유지한다. 배 모듈 장착은 자기 배 탑승 조건을 유지한다. 가져가기·되돌려놓기는 작업대 화면(김지훈), 인벤토리 모듈 칸 표시와 배 장착 입력은 최명기가 맡는다. 기존 Deposit/Craft의 탑승 거절을 통째로 풀지 않는다.
- **서버 검사:** 요청자·자기 배 소유·탑승·정상 상태·난파 여부·유효한 배 레시피·사용 권한이 있는 완성품·동일 종류 미장착을 확인한다. 판 종료·입력 잠금·다운 상태에서는 거절한다. 요청한 레시피가 요청자 인벤토리의 모듈과 같은지 확인한다(2026-10-21 구현).
- **단일 처리:** 실제 보관 위치에서 완성품 1개 제거·모듈 기록 상태 전이·배 장착은 함께 성공하거나 함께 실패해야 한다. 거절·중복·동시 요청 시 소비/장착이 중복되지 않아야 한다. 시험용 무료 장착 경로를 일반 UI에 연결하지 않는다.
- **장착 후 수명:** 장착 개체는 원래 보관 위치에서 제거하고 난파 시 소실 기록까지 반영한다. 기존 등대 표류·부식 처리를 배 모듈에 재사용하지 않는다.
- **ID:** 등대 레시피 ID 1~4와 기존 자원 ID는 유지한다. 새 배 레시피 ID와 배 종류의 대응은 김지훈·최명기가 구현 시 확인한다. 이미 사용 중인 ID를 임의 점유하지 않는다.

김지훈에게 공유할 종류·효과·재료·장착 규칙과 보관 위치 미정 사항은 [배 모듈 기획 전달](../handover/최명기/2026-10-20/김지훈-배모듈-기획전달.md)에 정리한다.
### 수명·예외
| 상황 | 상세 제안 또는 현재 확정 규칙 |
|---|---|
| 빈 종류 슬롯 | 다른 모듈과 함께 장착 가능 — 확정 |
| 같은 종류 재장착 | 거절, 완성품 보존 — 중복 금지는 확정, 반환 처리 상세는 제안 |
| 탈착·교체 | 첫 버전 수동 탈착·반환·분해 없음 제안 |
| 하선 | 모듈 보존. 대쉬 종료, 경보·안정화 중지, 탐조등 유지 제안 |
| 난파 | 전부 소실 — 확정. 효과·HUD·진행 중 대쉬 즉시 정리 |
| 난파 후 복구 | 이전 모듈 자동 복원 없음 — 확정 |
| 미장착 완성품과 난파 | 난파 순간에는 인벤토리 모듈을 잃지 않는다. 구조되면 인벤토리 자원·모듈 중 무작위 1칸 통째 소실(2026-10-21), 구조받지 못하고 재스폰하면 모두 떨어뜨림(2026-10-20 [모듈 결정](lighthouse-module-decisions.md#모듈-운반과-난파구조-2026-10-20-결정)) — 확정, 재스폰 처리는 미구현 |
| 판 종료·새 판 | 효과 제거·쿨다운/장착 상태 새 판 초기화 제안 |
| 마피아 공개·소환 | 배 사용 가능 여부와 연결된 미정. 직군 비활성화 규칙을 장비까지 임의 확대하지 않음 |

v4의 부식은 등대 모듈 대상이다. 배 모듈 부식·낙하 타이머는 이번 기획에 추가하지 않는다.

## 10. 네트워크·담당 계약 — 구현 제안

[네트워크 권위](../unity/NETWORK_AUTHORITY.md)와 [담당 경계](../CODE_OWNERSHIP.md)를 따른다. 배 이동은 기존 소유 클라이언트의 ClientToServer 동기화를 유지한다.

| 내용 | 책임·전달 범위 |
|---|---|
| 제작품 차감·장착·난파 소실 | 서버 확정, 관찰 대상에게 필요한 장착 상태 동기화 |
| 대쉬 발동·종료 시각·쿨다운 | 서버가 요청자·상태·장착·중복·쿨다운 검사 후 확정. 소유 클라이언트가 승인된 상태로 물리 적용 |
| 이동 결과 | 기존 배 이동 동기화 사용. 호스트에서 물리 효과를 서버/클라이언트 양쪽에 중복 적용하지 않음 |
| 조명·대쉬 연출 | 관찰 클라이언트에서 표현. 늦게 관찰하는 경우 현재 점등·대쉬 상태 복원 |
| 장애물 경보 | 소유 탑승 클라이언트의 물리 조회·개인 UI. 피해·획득·몬스터 판정에 사용하지 않음 |
| 안정화 | 현재 배 물리를 계산하는 소유 클라이언트에만 적용. 원격 관찰자는 동기화된 배 움직임 표시 |

대쉬 요청 연타·지연 응답·거절 시 연출 취소·난파와 발동 동시 발생·소유권 변경 정리가 필요하다. 서버 승인 도착 시 남은 지속 시간이 없다면 새 0.8초를 시작하지 않는다. 첫 버전은 승인 후 발동으로 제안하며 입력 지연이 크면 예측·보정을 별도 설계한다.

최명기: 배 장착·효과·관련 입력/HUD. 김지훈: 완성품 보관 위치 결정 및 제작품 소비와 배 장착의 원자적 이전 계약 연결 협의. 강민서: 지형 충돌 레이어·부력/파도 적용 계약 협의. 실제 타 담당 코드 수정은 별도 범위 확인 후 수행하며, 이 문서는 합의 완료를 뜻하지 않는다.

| 공통 장착 | `BoatModuleEquipment`에 종류별 중복 검사·자기 배 탑승 검사·서버 목록·난파 제거가 존재 |
| 탐조등 | `SearchlightModule`에 Light·빛줄기 켜기/끄기 존재. 기존 기록상 프리팹 연결, 실제 야간/다인 체감 미검증 |
| 종류 목록 | `BoatModuleType`은 Searchlight/DepthAlarm/Stabilizer. 4종 기획과 불일치하며 대쉬 추가·DepthAlarm 변경 호환성 검토 필요. 기존 ID 무단 재배열 금지 |
| 대쉬 | Player/Boat 검색에서 전용 효과 미발견. `BoatController.Move`는 매 물리 프레임 목표속도를 계산하므로 단발 힘 추가만으로 유지된다고 가정할 수 없음 |
| 장애물 경보·안정기 | Player/Boat 검색에서 전용 효과 미발견. World의 기본 `ShipStabilizer`와 모듈은 별개 |
| 효과 기반 클래스 | `BoatModule`은 현재 클라이언트 효과 적용 중심. 서버 쿨다운·발동 판정을 여기에 넣기만 해서는 서버 계약이 성립하지 않음 |
| 제작 연결 | `TryInstall` 자체는 완성품 소비를 검사하지 않음. 2026-10-21 김지훈 `ModuleInteractionHandler`가 플레이어 인벤토리의 배 모듈을 검사한 뒤 `TryInstall`을 부르고 성공 시에만 인벤토리에서 빼 장부에 기록(난파 시 장부 삭제). Boat.prefab `InteractionTarget`에 `InstallModule` 허용이 필요(최명기 합의 대기). 컴파일만 확인, 배 장착 플레이 미검증(PR #64) |

[문제 대장 W03](../07-design-issue-register.md)의 모듈 효과·수명 계약은 부분 결정 상태다. 4종·종류별 장착·난파 소실은 결정됐지만 9절에 레시피·장착 소비 원칙을 정리했고 완성품 보관 위치는 2026-10-20 결정됐다(작업대 보관 → 플레이어 인벤토리). 효과 상세안 채택·구현·실행 검증은 남아 있다. W05·W07 등 제작/부식 관련 기존 미정은 이번 종류 선정만으로 닫지 않는다.

## 12. 구현 순서와 검증 계획

권장 순서: 상세 동작·입력/수치 채택 → 4종 ID 계약 → 기존 탐조등 회귀 → 대쉬 이동/서버 판정 → 경보 지형 연결 → 안정기 부력 연결 → 제작품 이전/HUD 통합 → M2·4인 시험.

| 시험 | 기대 결과 |
|---|---|
| 네 종류 장착·같은 종류 중복 | 4종 공존, 같은 종류 거절, 거절 시 완성품 보존 |
| 타인 배·하선·난파·다운 장착 | 서버 거절, 재고·장착 불변 |
| 탐조등 야간·안개·차폐·원격 관찰 | 관찰 향상, 벽 너머/환영 진위 정보 없음, 타인에게 빛 공개 |
| 대쉬 정지·전진·후진·연타 | 제안 조건대로 발동/거절, 쿨다운 1회, 수평 가속 |
| 대쉬+파도·충돌·폭풍벽 | 위로 발사·관통·무적·추가 공격 보너스 없음, 기존 피해 회귀 |
| 대쉬 취소·하선·난파·입력 잠금 | 효과 즉시 종료, 취소로 쿨다운 초기화 없음 |
| 경보 암초·해안·자기 배·아이템 | 대상만 경고, 좌/중앙/우 일치, 다중 알림 과잉 없음 |
| 경보+대쉬·후진·거리 경계·환영 섬 | 제안 감지 거리/후진 제한 준수, 깜빡임 억제, 진위 판별 수단이 되지 않음 |
| 안정기 동일 파도 장착 전후 | 롤/피치 완화, 요·기본 속도·수면 추종 유지, 피해 간접 변화 측정 |
| 해제·재탑승·난파·새 판 | 효과 중첩/잔존 없음, 다른 배 설정 불변 |
| 원격 소유 배·지연·동시 요청 | 서버 승인/쿨다운 일치, 호스트 이중 적용 없음,지연 승인으로 추가 지속 없음 |
| 완성품 동시 장착·재요청 | 단일 소비·단일 장착, 실패 시 보존 |

위 표는 미실행 계획이다. 동작은 담당 씬과 M2, 지연 관련 항목은 다른 PC·지연 주입, 최종 부하는 4인 환경에서 확인한다. 문서 검토는 실행 검증을 대신하지 않는다.

## 13. 채택 전에 남은 결정

1. 대쉬 가속 방식·방향 고정·취소 조건·입력 키와 시험 수치, 속도 중첩 상한.
2. 탐조등 자동 점등·하선 유지·소비 없음 방식.
3. 장애물 경보의 고정 지형 한정·개인 경고·후진 제외·환영 섬과의 정보 경계.
4. 안정기의 탑승 중 적용·약 30% 완화 목표와 실제 부력 연결 방식.
5. 완성품 보관 위치는 결정됨(작업대 보관 → 플레이어 인벤토리로 가져가기 → 장착, 9절). 남은 것: 정식 인벤토리 화면 표시·배 장착 입력(최명기), 미장착품의 구조/미구조 재스폰 처리. 레시피 시험값 밸런스·탈착·마피아 공개 후 장비 사용 범위도 후속이다.

선정한 네 종류와 기존 공통 규칙은 확정이다. 위 질문은 상세안을 검토할 항목이며 문서 작성 자체를 막는 차단 조건은 아니다.
