## 1. 기획 의도와 문서 범위

일찍 정체가 드러난 마피아는 불리하고, 늦게 드러난 마피아는 누적 심해 게이지로 시민의 복구 부담을 늘리는 방향이다. 시민에게 조기 추리·투표의 이유를 주면서, 틀린 지목을 다음 투표에서 고치는 행동에는 별도 벌점을 주지 않는다.

이번 대화에서 정리된 방향을 문서 전체에 반영했다. 아래 본문의 규칙은 이 검토안 안에서의 진행 방향이며 공식 기획 채택·구현 착수 승인을 뜻하지 않는다. 미정 수치와 남은 선택은 9절에 모았다.

[기존 승패·투표 결정](win-vote-decisions.md), [기존 모듈 결정](lighthouse-module-decisions.md), v4와의 차이는 비교 대상으로 남긴다. 별도 제안인 [점화 방어안](lighthouse-ignition-defense-proposal.md)이나 [점화의 밤](../김지훈/2026-10-20/JH04-재기획-점화의밤-제안.md)의 3인 동의·완성 후 60초 방어·대포 촉수 약화 등을 이 안에 자동으로 포함하지 않는다.

## 2. 전체 게임 흐름

1. 시민은 파밍·제작·모듈 운반으로 등대를 수리한다. 마피아는 정체를 숨기며 수리와 파밍을 방해한다.
2. 심해 게이지는 봉인 전까지 시간이 흐를수록 증가한다.
3. 투표는 2일차부터 한 판 총 N번, 정해진 시각에 진행하고 집계한다. 매일 1회로 정한 것이 아니며 N과 시각은 미정이다.
4. 집계에서 시민 2명 이상이 마피아를 지목하면 게이지의 추가 증가를 봉인하고 마피아에게 소환권을 준다.
5. 강제 소환하지 않는다. 마피아가 즉시 소환하거나 기다릴 수 있지만, 봉인 후 기다리는 동안 이미 쌓인 게이지가 서서히 감소한다.
6. 소환 시 그 순간 남은 게이지에 따라 수리도를 한 번 깎고 최후 전투로 넘어간다.
7. 시민은 같은 수리도를 복구하고 마피아는 공개적으로 파밍·운반·복구를 방해한다. 수리 완성·붕괴·전체 마감으로 승패를 판정한다.

## 3. 수리도와 승패

등대는 별도 HP·내구도 없이 수리도 하나로 건설·피해·복구를 표현한다. 배 내구도는 이 변경 대상이 아니다.

| 조건 | 이 안의 결과 |
|---|---|
| 소환 여부와 관계없이 수리도 100% 달성 | 즉시 시민 승리. 자원을 보유하기만 한 상태는 완성으로 보지 않는다. |
| 전체 마감까지 미완성 | 마피아 승리. 소환 대기나 최후 전투로 마감을 연장·제거하지 않는다. |
| 최후 전투에서 현재 수리도가 고정 붕괴선 미만으로 하락 | 마피아 승리. 붕괴선과 같은 값은 이 조건만으로 패배하지 않는다. |

조기 발견 시 3일차 전후 완성, 늦은 발견 시 추가 파밍 때문에 5일차 전후까지 진행하는 것이 밸런스 목표다. 3일차는 강제 종료일이 아니다. 전체 기한은 5일차를 기준으로 잡고, 정확한 밤 마감 시점은 후속 결정으로 남긴다.

수리100% 후 별도 60초 점화 의식이나 정답 투표 판정을 요구하지 않는 방향을 유지한다. 끝까지 소환하지 않아도 시민이 수리100%를 달성하면 시민 승리다. 등대 괴물 처치는 승리 조건으로 두지 않으며, 게이지 임계치만으로 전투 없이 마피아 승리를 주는 특수 종료도 넣지 않는다.

## 4. 심해 게이지·봉인·오투표

| 상태 | 처리 |
|---|---|
| 봉인 전 | 시간이 흐를수록 기본 심해 게이지 증가 |
| 집계에서 정답 2표 이상 | 추가 증가 봉인·소환권 부여 |
| 봉인 후 소환 대기 | 누적 게이지가 서서히 감소 |
| 실제 소환 | 남은 게이지로 수리도 차감량을 계산하고 적용 |
| 오투표 유지 | 별도 벌점 없이, 봉인을 늦춰 기본 증가가 계속되는 시간 손해 |
| 다음 투표에서 대상 변경 | 변경 자체에 별도 벌점 없음 |

**오투표를 한 시간에 비례한 추가 증가, 오답 표마다 추가 증가, 잘못된 다수 지목 벌점은 적용하지 않는다.** 봉인이 늦어진 시간 자체가 비용이다.

정답 1표만으로 성장 속도를 낮추는 이전 초안 문구는 이번 정리에서 사용하지 않는다. 정답 2표라는 봉인 조건으로 설명을 통일한다.

봉인 후 감소는 기존 게이지를 즉시 지우는 방식이 아니다. 마피아에게 지금 소환할지, 소환 효과가 약해지는 비용을 감수하고 더 숨을지 선택을 준다. 감소가 너무 느리면 시민의 복구 시간이 적은 마지막 소환이 계속 유리할 수 있으므로 실제 수급·복구 시간과 함께 검증해야 한다.

후속 집계에서 정답이 2표 미만으로 바뀌었을 때 봉인·감소·이미 얻은 소환권을 유지할지는 미정이다. 이 문서에서 영구 유지나 즉시 취소를 임의로 정하지 않는다.

## 5. 투표 방식과 정보 공개

투표는 2일차부터 한 판 총 N번의 정해진 기회에 진행한다. 정해진 집계 시점의 유효한 표로 판단하며, 자유 지목 변경 때마다 소환 반응으로 정답을 검사하는 방식은 아니다. 다음 기회에 다른 대상을 고칠 수 있다. 시민만 투표하고 자기 지목은 금지하는 기존 제한은 유지하는 방향이다.

총 N회와 시각, 투표창 길이·창 안에서의 수정·미제출·이전 표 유지 여부는 아직 미정이다. 앞서 예시로 제안한 2·3·4일차 총 3회는 채택된 일정으로 기록하지 않는다.

| 정보 | 시민 | 마피아 |
|---|---|---|
| 본인의 지목 | 본인만 확인 | 투표자별 내역은 비공개 |
| 집계의 정답·오답 표 수 | 비공개 | 확인 |
| 봉인 여부 | 비공개 | 확인 |
| 현재 게이지·현재 소환 차감량 | 비공개 | 확인 |
| 다른 시민이 누구를 찍었는지 | 비공개 | 비공개 |

**시민은 자신이 틀렸는지 모르고, 마피아는 집계 결과와 자신에게 유리해진 정도를 아는 구조다.** 마피아에게 보여주는 것은 정답·오답 합계이며 다른 대상별 득표 내역이나 투표자 신원까지 주지 않는다. 집계 이후 게이지 변화는 마피아가 확인할 수 있도록 한다. 실제 표시 형식은 후속 설계다.

마피아가 소환하지 않아도 시민은 틀렸다고 단정할 수 없다. 소환권을 얻었지만 기다리는 경우가 있기 때문이다. 실제 소환은 정체 공개 단계로 이어지며 세부 공개 시점은 미정이다.

기존 정체 확인 횟수·실패 시 무고 공개·성공 후 10초 소환권은 이 안에서는 정시 집계와 자유 소환권으로 바꾸는 방향이다.

## 6. 소환 손실과 고정 붕괴선

```text
S = 소환 직전 수리도 − 소환 순간 남은 게이지에 따른 차감량
붕괴선 = S − k%p
현재 수리도 = 직전 수리도 + 시민 복구량 − 전투 피해량
```

- S는 게이지 손실을 반영한 소환 직후 수리도다.
- 붕괴선은 소환 순간 한 번 계산하고 고정한다. 이후 시민이 복구해도 선을 올리거나 다시 계산하지 않는다.
- k는 비율 곱셈이 아니라 %p 차감이다. 예를 들어 S=70%, k=20%p면 붕괴선은 50%다. 숫자는 설명용이다.
- 소환 순간 남은 게이지가 클수록 일회성 차감량을 크게 한다. 게이지 효과는 이 손실에 집중한다.
- 이후 촉수 공격은 게이지와 독립된 일정한 세기로 수리도를 깎는 방향이다. 피해량·주기는 미정이다.
- 시민은 같은 수리도를 복구하며 별도 최후 수리도0%나 심연 결정 재점화 목표는 두지 않는다.
- 소환 전 획득한 수리 보상은 유지하고 재수리로 중복 지급하지 않는 방향이다.

**붕괴선이 0 이하일 때와 S=0으로 시작할 때의 처리는 미정이다.** 수리도 최저값이 0이면 음수 붕괴선에 도달할 수 없는 문제가 있다. 0% 도달 패배·최소 시작 수리도·보호 시간 등은 후보일 뿐 아직 선택하지 않았다. 기존 초안의 최초 n% 도달 전 보호도 현행 방향으로 자동 유지하지 않는다.

## 7. 모듈 복구와 파밍 연결

기본 자원 → 작업대 제작 → 개인 운반 → 등대 모듈 장착 흐름을 바탕으로 검토한다. 등대에 기본 자원을 직접 넣는 것으로 바꾸지는 않았다.

깎인 수리도를 장착 모듈의 손상·파괴 중 무엇으로 표현할지, 어떤 모듈·재료를 넣어 복구할지는 미정이다. 장착 슬롯이 찼거나 제작 존재 상한 때문에 복구품을 만들 수 없으면 최후 전투의 복구 경로가 막힌다.

3일차 완성과 5일차 재파밍 목표를 만족하려면 자원 공급·재공급·외해 해금·레시피·제작 상한도 함께 확인해야 한다. 필수 모듈 독점이나 자원 고갈로 복구가 영구 봉쇄되지 않는지 검증한다.

## 8. 기존 기획·코드와의 차이

아래는 채택 시 변경할 범위를 찾는 비교표다. 기존 기준의 효력을 이 문서가 대체했다는 의미가 아니다.

| 관련 ID | 뜻 | 이 검토안의 방향 |
|---|---|---|
| R09 | 기한·승패·동시 종료 | 전체 5일차 마감 유지, 수리100%/붕괴/기한으로 종료. 동시 판정 순서는 미정 |
| R10 | 수리도와 내구도의 관계 | HP 분리 대신 단일 수리도, 소환 손실 후 S−k%p로 붕괴선 고정 |
| R12 | 게이지와 봉인의 실제 효과 | 정답2표로 성장 봉인, 대기 중 감소, 남은 게이지로 소환 손실 계산 |
| R13 | 적립·봉인·소환 정산 시점 | 정해진 집계에서 봉인, 이후 감소, 소환 순간 손실 확정. 정산 간격 미정 |
| R01·R02·R16 | 정체 확인·소환권 | 확인 횟수·10초 권리 대신 정시 집계와 자유 소환권 |
| R03~R07 | 투표 기회·의식 | 2일차부터 총 N회 투표, 수리100% 후 별도 의식 없음 |
| R14·R15 | 기다림·무작위 투표의 유불리 | 반복 탐색 제한과 기다림 비용을 검토. 전략 우세·승률은 미검증 |
| N04 | 비밀 정보 수신 범위 | 시민에게 정오·게이지 비공개, 마피아에게 집계 합계·게이지 공개 |
| W01·W03·W08 | 모듈·복구·회수 | 모듈 손상·복구·제작 상한 연결은 추가 설계 필요 |

정적 확인한 코드에는 기존 경로가 있다. `Assets/01.Scripts/04.Lighthouse/Tower/Net/TowerMatchNet.cs`는 의식·별도 HP·심연 결정 재점화·특수 종료를, `Assets/01.Scripts/07.Mafia/AbyssGauge/Rules/AbyssGaugeService.cs`는 아침 기본 증가와 봉인/오투표 누적을, `Assets/01.Scripts/07.Mafia/IdentityCheck/Rules/IdentityCheckService.cs`는 확인 횟수와 10초 소환권을 사용한다. 이 검토안이 구현된 상태로 보지 않는다.

기존 소유권에 따른 채택 후 연결 범위는 김지훈(수리도·모듈·복구), 박태욱(투표·게이지·소환·몬스터), 최명기(단계·최종 승패·UI·Player), 강민서(시간·자원 공급)다. 신규 API·담당 간 합의 완료를 뜻하지 않는다.

## 9. 남은 결정과 검증 계획

| 항목 | 남은 내용 |
|---|---|
| 투표 | 총 N회·시각·투표창·내부 수정·미제출·이전 표 승계 |
| 후속 집계 | 정답2표 미만으로 바뀔 때 봉인·감소·소환권 유지 여부 |
| 수치 | 기본 증가·감소 속도와 하한, 게이지별 차감 함수, k%p, 촉수 피해·주기 |
| 붕괴 경계 | 붕괴선0 이하·S=0·수리도 하한·소환 손실 상한 |
| 복구 | 모듈 손상·교체·복구 레시피·제작 상한·부식/회수 연결 |
| 단계·공개 | 난파 중 소환, 정체 공개와 능력/인벤토리 전환 시점 |
| 마감·경합 | 5일차 밤의 정확한 마감, 집계·소환·완성·붕괴·마감이 겹칠 때 순서 |

플레이 검증은 아직 실행하지 않았다. 조기/늦은 정답, 즉시/지연/미소환, 무작위/추리 투표를 같은 수급 조건으로 비교해야 한다. 완성 일차·재파밍량·소환 시 게이지·붕괴 여유·승패를 기록하고 마지막 소환이 여전히 일방적으로 유리한지 확인한다. 다인 시험에서는 시민·마피아의 정보 수신 범위와 최종 결과 일치를 확인한다. 기준은 [검증 플레이북](../ai/03_VERIFICATION_PLAYBOOK.md)이다.

## 10. 이번 문서 작업 기록
