# 등대·작업대 모듈 결정

결정일: 2026-10-17
근거: 사용자(김지훈) 결정. 담당: 김지훈(작업대·모듈·등대).
상태: 아래 "확정 규칙"은 결정 완료. JH03 작업대는 구현·M0·M2 통과(2026-10-17, 제작 버튼 반영 후 재검증). 2026-10-18 레시피별 동시 진행으로 바꾼 뒤 M0 통과, M2 재검증 전. JH04·JH05는 미구현. "시험값"은 플레이 테스트로 조정한다.

## 확정 규칙

| 항목 | 결정 |
|---|---|
| 등대 구조 | 등대는 1·2·3층으로 나뉘고, **층마다 다른 모듈**을 장착한다 |
| 등대 투입 | 등대에는 **모듈만** 넣는다. 기본 자원(돌·나무·섬유·철·유리·수정)을 등대에 직접 넣을 수 없다 |
| 자원 사용처 | 기본 자원은 **작업대에서만** 쓴다(자원 → 모듈) |
| 작업대 | 등대 섬의 공유 작업대 1개. **레시피마다 진행도를 따로** 두어 여러 레시피를 동시에 채울 수 있다(2026-10-18 변경, 이전: 한 번에 1개). 이번 범위는 등대(공유) 모듈 레시피만이며 배(개인) 레시피는 배 장착 계약 뒤에 추가한다 |
| 레시피 선택 | 어떤 레시피를 볼지는 **각자 화면에서만** 고르며 다른 선원에게 공유되지 않는다. 진행도(투입량)와 보관 개수는 모두에게 동기화된다. 투입·제작 요청은 레시피 ID를 함께 보낸다(2026-10-18 변경. 이전의 "첫 투입 후 변경 불가"와 첫 투입 확인창은 폐지) |
| 제작 완료 | 재료가 모두 차도 자동으로 완성되지 않는다. 누구나 **제작**(`InteractionAction.Craft`)을 눌러야 서버가 완성해 보관한다. 동시에 눌러도 한 번만 성공한다(2026-10-17 추가) |
| 부분 투입 | 가진 만큼만 넣고 부족분은 나중에 넣는다. 서버가 요청량을 남은 필요량 이하로 제한하고 실제로 빠진 수량만 누적한다([인벤토리 API](../unity/PLAYER_INVENTORY_API.md)) |
| 완성 모듈 보관 | 장착 전까지 작업대에 종류별 개수로 보관한다. 보관 중에도 다음 레시피를 시작할 수 있다 |
| 투입 가능 시점 | 판 진행 중이면 낮·밤 모두. 쓰러짐·배 탑승 중에는 거절한다. 의식·최후 전투 중 제한은 JH04에서 정한다 |
| 제작 상한 | 레시피별 "현재 존재 개수" 상한(데이터 값, 0 = 제한 없음). 상한에 닿으면 그 레시피를 고를 수 없다 |
| 존재 기준 | 서버의 모듈 기록이 분해 전이면 존재한다. 제작 중·작업대 보관·장착·표류·건져서 든 상태를 모두 센다. 부식 여부와 무관하다. **분해될 때만** 개수가 줄고 다시 만들 수 있다 |

## 가안·시험값

| 항목 | 값 | 상태 |
|---|---|---|
| 등대 모듈 레시피 | 기반 프레임 = 돌 5 + 나무 5 + 철 2 · 기어 장치 = 철 3 + 섬유 3 · 렌즈 모듈 = 유리 3 + 철 2 + 수정 2 · 광원 코어 = 수정 3 + 유리 2 | 시험값. 재료 조합은 [자원·섬·맵 생성 결정](world-resource-island-decisions.md) 4장 후보 |
| 레시피별 존재 상한 | 각 1 | 시험값. 층 배치 확정 후 조정 |
| 분해 기준 | 표류 시작 시 서버 타이머 시작, 120초(데이터 값). 건지면 종료, 다시 표류하면 재시작. 잠긴 구역·폭풍벽 밖으로 밀리면 경계 안쪽으로 되돌린다 | 가안(JH05). v4 7.4 "일정 시간 안에 회수 못 하면 분해"의 구체값 |

## 기존 문서와 달라진 점

새 결정이 아래 문장을 대체한다. 원문은 보존하고 이 문서를 우선한다.

| 문서 | 기존 문장 | 바뀐 점 |
|---|---|---|
| [v4 6장](references/game-design-v4.md) | "수리 자원을 투입해 수리도를 올린다" | 등대에는 모듈만 넣는다. 수리도는 층별 모듈 장착으로 오른다(환산은 미정) |
| [승패·투표 결정 5절](win-vote-decisions.md#final-battle) | "최후 전투에서 자원 투입은 새로운 수리 진행도만 올린다" | 최후 전투에서도 등대에 넣는 것은 모듈이다. 진행도 계산은 미정 |
| [공용 인벤토리 결정](shared-inventory-decisions.md) | "등대 수리에 이미 반영된 자원도 마피아가 회수" | 등대에는 자원이 없으므로 등대 쪽 회수 대상은 모듈이 된다. 모듈 탈착 권한·진행도 되돌림은 미정. 작업대 투입 자원의 마피아 인출 결정은 그대로 |

## 미정 (JH04·JH05 전에 결정)

| # | 정할 것 | 영향 |
|---|---|---|
| 1 | 층별 모듈 배치: 후보 4종(기반 프레임·기어 장치·렌즈 모듈·광원 코어) 중 어떤 모듈이 몇 층에 들어가는가, 층 하나에 모듈이 여러 개인가 | 레시피 상한, 등대 슬롯 구조 |
| 2 | 장착 순서: 1층부터 차례대로만 장착할 수 있는가 | 등대 장착 검증 |
| 3 | 수리도 환산: 층 단위(예: 33·67·100%)인가, 모듈 단위인가. v4 6.1 구간 보상 재정의 | 등대 상태·보상 |
| 4 | 최후 전투 진행도(0%부터): 이미 장착된 모듈은 어떻게 되고, 무엇을 넣어 100%로 올리는가 | 최후 전투 승리 경로(R08·R10) |
| 5 | 마피아의 등대 회수: 장착된 모듈을 떼어 갈 수 있는가, 떼면 진행도를 얼마나 되돌리는가 | 공용 인벤토리 결정과의 정합(W08) |
| 6 | 건진 표류 모듈을 어디에 두는가(개인 인벤토리는 자원 수량만 다룸) | 최명기 인벤토리·JH05 |
| 7 | 분해 결과: 일부 자원 드롭 / 완전 소멸 | JH05 |
