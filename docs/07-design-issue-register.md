# 설계 누락과 검토 항목 대장

기준일: 2026-10-11. 사용자 제공 [게임 기획 v4 원문](design/references/game-design-v4.md)·[설계 결함·누락 검토 원문](design/references/v4-design-review.md)과 [승패·투표 결정](design/win-vote-decisions.md)을 대조한 작업용 색인이다. **71개 검토 항목이며 확인된 구현 버그 71개가 아니다.** 원본 DOCX의 본문·표를 Markdown으로 보존했고 v4의 일정 그림도 확인했다.

## 1. 기준과 현재 상태

- 최신 사용자 결정 → 승패·투표 결정 → 미변경 범위의 v4 → 이를 반영한 기술·작업 문서 순으로 대조한다. 검토 보고서의 권고·상태 머신·처리 순서·통과 기준은 승인된 규칙이 아니다.
- v4(10/9)의 승패·투표·정보 공개·단절 범위는 2026-10-11 공유 기준으로 반영한 새 결정이 보완·대체한다. 10/8 기준 이전 기획서는 2026-10-10 [보존 자료](design/archive/game-design-2026-10-08.md)로 옮겼고, 같은 날 01·03·05·06의 구규칙을 v4 기준으로 고쳤다. 보존 자료·개인 기록·과거 이슈의 구규칙으로 새 코드를 구현하지 않는다.
- 원문의 P0/P1/P2는 **보고서의 설계 검토 우선도**다. 현재 버그 심각도나 전 항목 착수 승인을 뜻하지 않는다. 각 지적은 구현 전 필요한 계약과 검증 범위에 따라 적용한다.
- 현재 구현은 [로드맵](05-implementation-roadmap.md)과 [담당 작업 기록](06-owner-work-plan.md#6-처음-함께-맞출-일과-작업-기록)을 따른다. 최근 JH01 연결·ActorId와 투표 Rules가 추가됐으나 새 기획 전체가 구현됐다는 뜻은 아니다. 코드 존재를 각 지적의 재현 증거로 쓰지 않으며 실제 동작·누출·성능·승률은 코드와 실행 근거로 다시 확인한다.
- 담당은 [실명 담당표](CODE_OWNERSHIP.md)를 따른다. 시스템은 최명기, UI는 김지훈(인벤토리 화면·배 모듈 장착 UI는 최명기, 2026-10-30 사용자 결정), AX 김민성은 다른 팀의 일시 지원이며 게임 코드 담당이 아니다. v4의 시스템&UI 미정 표기를 다시 적용하지 않는다.

## 3. 관련 작업이나 대화에서 사용하는 방법

1. 구현·수정·할 일·남은 일뿐 아니라 관련 기능의 규칙·동작·대안·버그를 논의할 때 아래 기능 색인에서 해당 ID를 찾는다. 전체 71개를 매번 읽거나 되풀이하지 않는다.
2. 관련 V 차이와 원본의 해당 절, 항목의 원문 문제·제안·시험을 읽고 최신 코드/결정을 비교한다. 제목만으로 현재 버그라고 단정하지 않는다.
3. `관련 ID와 상태 → 근거 → 결정하지 않으면 생길 영향 → 지금 가능한 일/필요한 결정/검증` 순으로 짧게 설명한다. 제안은 선택지로 제시한다. 관계없는 항목은 끼워 넣지 않는다.
4. 필수 규칙이 없으면 그 결정에 의존하는 구현만 대기하고 독립 작업은 계속한다. 질문·설명 요청만으로 코드·기획·GitHub를 수정하지 않는다. 같은 결정과 안내는 새 정보가 없으면 반복하지 않는다.
5. 최신 근거로 해결된 항목은 해결 내용을 인정한다. `결정 완료`와 `구현·검증 완료`를 별도로 기록하며 미해결로 되돌려 말하지 않는다.

보고 예: “R08·R10은 최후 전투의 새 수리 진행도 0%, HP 환산과 보상 유지가 결정됐고 구현·검증은 남았습니다. R09의 동일 판정 시점 경합과 W01의 추가 모듈 조건은 여전히 확인이 필요합니다. 확정된 상태 전환과 데이터 준비는 진행할 수 있고, 경합·모듈 조건은 임의로 정하지 않습니다.” 이 예시는 미정의 해결안을 승인하지 않는다.

## 5. 71개 항목별 현행 검토 상태

`계약 확인 필요`는 보고서와 v4에 제기된 질문을 필요한 결정을 담당자나 사용자에게 확인하고 해당 작업에서 검증해야 한다는 뜻이다. `가설 검증 필요`는 관측 결함이 아니다. 각 원문 링크에는 문제/예상 상황, **미승인 결정 제안**, 통과 기준이 모두 있다. 근거 절 번호는 원본 v4 기준이다.

## 6. 시험과 해결 기록

검토 원문 8장의 T01~T16은 교차 시나리오 제안이다. 관련 항목만 선택해 승인된 규칙을 기대값으로 채운다. 원문 7장의 상태 머신·A/B/C 점화안·동일 틱 순서는 미승인 선택지다. 9장의 명세 산출물과 10장의 원문 미정14개도 참고하되 새 기능·전용 서버·계정·매칭을 자동 필수로 추가하지 않는다. 인게임 보이스 삭제를 되돌리는 시험도 만들지 않는다.

|---|---|
| 결정 대기 | 항목 ID·해당 질문·현재 규칙/원문 절·협의 담당 |
