# 설계 누락과 검토 항목 대장

기준일: 2026-10-10. 사용자 제공 [게임 기획 v4 원문](design/references/game-design-v4.md)과 [설계 결함·누락 검토 원문](design/references/v4-design-review.md)을 대조한 작업용 색인이다. **71개 검토 항목이며 확인된 구현 버그 71개가 아니다.** 원본 DOCX의 본문·표를 Markdown으로 보존했고 v4의 일정 그림도 확인했다.

## 1. 기준과 현재 상태

- 최신 사용자 결정 → 제공된 v4의 명시 규칙 → 아직 v4를 반영하지 않은 기존 문서 순으로 대조한다. 검토 보고서의 권고·상태 머신·처리 순서·통과 기준은 승인된 규칙이 아니다.
- 기존 `02-game-design.md`는 10/8 기준이다. v4는 10/9 문서이며 이 대장의 원문 링크로 확인한다. 기존 01·03·05·06의 관련 내용도 아래 V 항목과 비교해야 한다. 이전 문서의 구규칙으로 새 코드를 구현하지 않는다.
- 원문의 P0/P1/P2는 **보고서의 설계 검토 우선도**다. 현재 버그 심각도나 전 항목 착수 승인을 뜻하지 않는다. 각 지적은 구현 전 필요한 계약과 검증 범위에 따라 적용한다.
- 현재 본편 34개 C#은 로컬 플레이어 기반과 월드/상호작용 계약 중심이다. 이 사실을 각 지적의 재현 증거로 쓰지 않는다. 실제 구현·누출·성능·승률은 관련 작업 때 코드와 실행 근거로 다시 확인한다.
- 담당은 [실명 담당표](CODE_OWNERSHIP.md)를 따른다. 시스템&UI는 최명기, AX 김민성은 다른 팀의 일시 지원이며 게임 코드 담당이 아니다. v4의 시스템&UI 미정 표기를 다시 적용하지 않는다.

## 3. 관련 작업이나 대화에서 사용하는 방법

1. 구현·수정·할 일·남은 일뿐 아니라 관련 기능의 규칙·동작·대안·버그를 논의할 때 아래 기능 색인에서 해당 ID를 찾는다. 전체 71개를 매번 읽거나 되풀이하지 않는다.
2. 관련 V 차이와 원본의 해당 절, 항목의 원문 문제·제안·시험을 읽고 최신 코드/결정을 비교한다. 제목만으로 현재 버그라고 단정하지 않는다.
3. `관련 ID와 상태 → 근거 → 결정하지 않으면 생길 영향 → 지금 가능한 일/필요한 결정/검증` 순으로 짧게 설명한다. 제안은 선택지로 제시한다. 관계없는 항목은 끼워 넣지 않는다.
4. 필수 규칙이 없으면 그 결정에 의존하는 구현만 대기하고 독립 작업은 계속한다. 질문·설명 요청만으로 코드·기획·GitHub를 수정하지 않는다. 같은 결정과 안내는 새 정보가 없으면 반복하지 않는다.
5. 최신 근거로 해결된 항목은 해결 내용을 인정한다. `결정 완료`와 `구현·검증 완료`를 별도로 기록하며 미해결로 되돌려 말하지 않는다.

보고 예: “R08·W01은 의식 중 소환 시 수리도/모듈/타이머 승계가 결정 대기입니다. v4 2.3과 6장은 최후 전투의 조건식을 완전히 닫지 않습니다. 이대로 구현하면 즉시 승리 또는 타이머 재시작 중 서로 다른 결과가 생길 수 있습니다. 지금은 상태/요청 틀을 만들 수 있고, 전환 시 승계 규칙은 먼저 정해야 합니다.” 이 예시는 특정 해결안을 승인하지 않는다.

## 5. 71개 항목별 현행 검토 상태

`계약 확인 필요`는 보고서와 v4에 제기된 질문을 필요한 결정을 담당자나 사용자에게 확인하고 해당 작업에서 검증해야 한다는 뜻이다. `가설 검증 필요`는 관측 결함이 아니다. 각 원문 링크에는 문제/예상 상황, **미승인 결정 제안**, 통과 기준이 모두 있다. 근거 절 번호는 원본 v4 기준이다.

## 6. 시험과 해결 기록

검토 원문 8장의 T01~T16은 교차 시나리오 제안이다. 관련 항목만 선택해 승인된 규칙을 기대값으로 채운다. 원문 7장의 상태 머신·A/B/C 점화안·동일 틱 순서는 미승인 선택지다. 9장의 명세 산출물과 10장의 원문 미정14개도 참고하되 새 기능·전용 서버·계정·매칭을 자동 필수로 추가하지 않는다. 인게임 보이스 삭제를 되돌리는 시험도 만들지 않는다.

| 단계 | 기록할 증거 |
|---|---|
| 결정 대기 | 항목 ID·해당 질문·현재 규칙/원문 절·협의 담당 |
| 결정 완료 | 실제 사용자/팀 결정·날짜·갱신한 규칙 문서·남은 구현 |
| 구현 완료·미검증 | 변경 파일·연결 경로·미실행 사유 |
| 검증 완료 | 승인된 기대값·실제 결과·환경/인원·재현 절차/로그 |
| 적용 제외 | 명시적인 범위 결정과 이유. 원문 지적은 삭제하지 않고 이력 보존 |

현재 해결 이력: S01의 담당 배정, S02의 실명/작업 분해, N01의 호스트 신뢰 한계 설명, S06의 검증 절차는 기존 문서·사용자 결정에 근거한 부분 보완이다. 관련 게임 기능 통과를 주장하지 않는다. 새 결정은 이곳의 해당 항목 상태와 기준 문서를 함께 갱신하고 양쪽 스킬의 절차는 동일하게 유지한다.
