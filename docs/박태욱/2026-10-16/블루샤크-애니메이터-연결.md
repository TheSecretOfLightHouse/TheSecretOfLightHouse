# 블루샤크 애니메이터 연결
작성자: 박태욱
작성일: 2026-10-16
갱신일: 2026-10-16
상태: 구현됨(호스트 재생 확인, 실제 AI 흐름·다인 접속 미검증)

## 요청과 목표
- 사용자 확정: 순찰은 idle, 추적 돌진은 dash-attack, 공격 후 이탈은 dash.
- 입은 idle/dash에서 닫고, dash-attack 시작에 벌린 뒤 유지한다.

## 진행 과정과 결정 이유
- 기존 모델과 애니메이션 FBX는 사용자 작업/앞선 Blender 작업 산출물이다. 이번 작업 시작 당시 BlueShark 애니메이션 폴더는 이미 미추적 상태였고 FBX 세 개가 있었다. 원본 FBX 바이트는 수정하지 않았다.
- 기존 프리팹에는 Animator가 없었다. 뼈 경로가 모두 일치함을 확인해 SeaCreature_Rig에 Animator를 추가했다. Generic/NoAvatar로 직접 Transform 경로를 사용하며 원본 모델 임포트 설정은 변경하지 않았다.
- Unity 임포터에서 idle 1–73프레임(2.4초), dash 13–37(0.8초 반복), dash-attack-start 1–13(0.4초), dash-attack-loop 13–37(0.8초 반복)로 나눴다. 30fps. 돌진이 길어져도 입 벌리기를 반복하지 않는다.
- AnimatorController는 Idle, DashAttackStart, DashAttackLoop, Dash 네 상태와 AnimationState 정수(0/1/2)를 사용한다. 기본 상태는 Idle, 공격 시작 완료 후 반복 상태로 전환한다. 행동 변경 전환은 Exit Time 없이 0.1초다.
- BlueSharkAnimation이 서버의 표현 상태와 시작 시각을 Mirror SyncVar로 전달한다. 늦은 접속 시 이미 끝난 입 벌리기 구간을 건너뛴다. 사망 시 현재 자세에서 정지한다. Root Motion은 사용하지 않는다.
- TrackingChargeAction과 RetreatFromBoatAction이 시작/종료 시 해당 표현 상태를 요청한다. 일반 순찰 복귀와 공격 후 이탈은 둘 다 MonsterState.Return이므로 Return만으로 dash를 선택하지 않는다. 이동·피해 판정 로직은 유지했다.
- 프리팹 저장 중 Mirror가 초기화한 assetId를 Unity SerializedObject/PrefabUtility로 기존 3799906804 값에 복원했다. GUID를 직접 변경하지 않았다. 씬/프리팹 YAML 직접 편집 없음.

## 검증
- 신규 파일 임포트 전 일시적인 타입 미발견 컴파일 오류는 전체 Refresh 후 해소했다. 최종 콘솔 컴파일 오류 0건.
- 격리 PreviewScene의 프리팹 복제본에서 Animator.Update로 Idle → DashAttackStart/Loop → Dash → Idle 전환 확인. 모든 애니메이션 곡선의 뼈 경로 존재 확인.
- idle/dash의 턱 회전 차이 0도, 공격 반복은 닫힌 자세 대비 43도 차이. 각 상태 3초 진행 후에도 유지.
- idle 반복 양 끝 차이 0, 공격 반복/dash는 최대 약 2.98e-8. 반복 구간이 이어짐을 수치 확인.
- 실제 표현 적용 메서드로 상태 전환, 사망 정지, 경과 2초의 늦은 접속 재생 시 공격 반복 선택 확인. 실제 원격 접속 검증은 아니다.
- MonsterCollisionTestScene에서 Play → 로컬 StartHost 실행. BlueShark isServer/isClient=true, 순찰 Idle normalizedTime 약 3.52 확인. 서버 표현 상태를 직접 요청해 DashAttackLoop와 열린 턱(52.49도), Dash와 닫힌 턱(9.49도) 확인. 이후 Idle 복구 및 Play 종료.
- 호스트 실행 중 배 생성 경로의 BuoyancyBody.OnEnable(56행)에서 WaterSamplerHost 미설정/샘플 슬롯 부족 Error 로그 1건이 발생했다. 컴파일 오류가 아니며 이번 애니메이션 변경에서는 수정하지 않았다.
- 프리팹 연결이 씬 인스턴스에 반영됨, assetId 보존, 작업 전후 씬 dirty=false 확인. 씬을 저장하지 않았다.
- git diff --check는 Unity가 프리팹에 생성한 빈 직렬화 문자열 세 줄의 trailing whitespace를 보고한다. YAML 직접 편집 금지에 따라 그대로 유지. C# 범위는 별도 확인.
- 실제 배 감지 → 추적 돌진 → 피해 → 이탈 → 재공격 전체 행동, M2 원격 동기화, 시각적 폴리싱은 미검증이다. PreviewRenderUtility 캡처 시도는 신뢰할 수 있는 시각 검증으로 세지 않았다.

## 2026-10-29 배 명중 물기 애니메이션 연결
- 새 BlueShark_LungeBite 클립을 Animator의 Bite 상태에 연결했다. 배 접촉으로 서버 피해가 실제 적용된 직후 ClientRpc로 명중 시각을 전달하고, 각 클라이언트가 클립 0.53초 지점(입이 열린 직후)부터 재생한다. 서버 물리·피해·이탈 판정은 변경하지 않는다.
- 이탈 상태 동기화가 물기를 즉시 끊지 않도록 클립의 남은 구간을 재생한 뒤 최신 상태로 복귀한다. 늦게 도착해 클립이 이미 끝난 이벤트와 사망 중 이벤트는 재생하지 않는다. 사망은 재생을 중단한다.
- 검증: Unity 컴파일과 콘솔 오류 0건. 프리팹 복제본 Animator에서 물기 클립과 0.53초 시작 확인, 늦은 이벤트 보정·만료와 사망 무시, 이탈 파라미터 중 물기 유지와 Dash 복귀를 확인했다. 실제 배 접촉·시각적 타이밍 및 호스트/원격 M2 검증은 아직 하지 못했다.
- N07은 부분 결정 상태 유지. 배의 클라이언트 권위 이동을 서버가 판정 입력으로 쓰는 기존 계약과 피해 경계·오차 미결은 이번 시각 연결로 해결되지 않는다. 물기가 충돌 후 시작하며 이탈 이동은 즉시 시작되므로 실제 플레이에서 입과 배가 어긋나는지 확인해야 한다.

## 2026-10-29 물기 재생 속도·명중 후 정지 조정
- 사용자 요청으로 명중 후 클립 시작 지점을 0.53초에서 0.30초로 당기고 재생 속도를 0.75배로 낮췄다. 네트워크 경과 시간과 재생 완료 시점에도 속도를 반영한다.
- 서버는 배 피해를 접촉 즉시 한 번 적용하며, 물기 동작을 볼 수 있도록 성공 시 0.8초간 정지한 뒤 기존 이탈을 시작한다. 접촉 중 중복 피해를 막고 피해 콜백에서 공격 취소 또는 비활성화되면 정지를 다시 시작하지 않는다. 이는 위 기록의 즉시 이탈 설명을 대체한다.
- Unity 컴파일·콘솔 오류 0건. 프리팹 복제본에서 클립 0.30초 재생, 0.75배 속도, 0.8초 설정, 지연 수신 보정과 만료 이벤트 무시를 확인했다. 실제 충돌·중복 접촉·취소·배 위치 및 호스트/원격 플레이 검증은 남았다.

## 2026-10-29 접촉 전 거리 기반 물기 시작
- 사용자 요청으로 명중 후 재생을 없애고, 돌진 중 상어 캡슐과 유효한 배 충돌체의 최근접 거리를 확인한다. 추적 속도·가속도와 관측한 배 이동을 사용해 클립의 물기 시점(시작 후 약 0.63초)에 접촉할 것으로 예상되는 거리에서 서버가 한 번 재생을 요청한다. 시작부터 정상 속도로 재생하며 클라이언트는 수신 지연만큼 시간을 보정한다.
- 피해는 기존대로 서버 실제 접촉 시 한 번 적용한다. 접촉 후에는 재생이 이미 시작됐다면 남은 클립을 마칠 때까지 정지한 뒤 이탈한다. 공격 실패 시에도 이미 시작한 표현은 완료한 다음 현재 상태로 돌아간다. 이 항목은 위 명중 후 재생·0.75배·고정 0.8초 정지 기록을 대체한다.
- Unity 컴파일 및 콘솔 오류 0건. 실제 상어·배 프리팹의 충돌체로 먼 거리에서 시작하지 않고 가까울 때 시작하는지, 0/10/18 속도에서 예상 시작 거리가 증가하는지 확인했다. 복제 Animator에서 시작 0초·1배속·지연 보정을 확인했다. 실제 움직이는 배 충돌, 취소·목표 이탈 및 호스트/원격 실시간 플레이 검증은 미실행이다. 배가 급격히 방향이나 속도를 바꾸면 예측과 접촉이 어긋날 수 있다.
