## 요청과 목표
- 사용자 확정: 순찰 → 공격 범위 진입 → 배 위치를 실시간으로 추적하며 돌진 → 1회 공격 → 이탈 지점 도착 → 추적 범위 안이면 재공격, 밖이면 순찰.
- 이번 요청 범위는 커스텀 액션 두 개 생성이다. 그래프·프리팹 연결은 수행하지 않았다.

## 진행 과정과 결정 이유
- 기존 BlueSharkBehavior에는 순찰·감지·추적·복귀가 있고 공격·이탈 노드는 없음을 확인했다.
- 기존 SeaMonsterChargeAttack은 고정 방향 돌진, RepositionAfterChargeAction은 근거리 재배치이므로 기존 공격을 변경하지 않고 전용 액션을 추가했다.
- TrackingChargeAction: 현재 배 위치로 이동 방향을 매 갱신 재설정. 배와 몬스터의 상대 이동 구간과 합산 피격 반경으로 명중을 검사하고 기존 TryApplyDamage를 한 번 호출한다. 실패한 피해 적용은 Failure다.
- RetreatFromBoatAction: 시작 위치에서 배 반대 방향으로 Distance만큼 떨어진 목적지를 한 번 정하고 기존 부드러운 이동 API로 도착까지 이동한다. 배가 사라지거나 추적 범위를 벗어나도 이탈은 계속한다.
- 두 액션은 MonsterMotion.CanMove의 기존 서버 권위 검증을 따른다. 취소 시 부모 액션의 OnEnd에서 이동을 멈춘다. 설정 오류·타겟 무효·이동 불가·시간 초과는 Failure로 처리한다.
- Timeout은 막힌 이동이 트리를 영구 점유하는 것을 방지하는 시험용 설정이며 정상 도착을 의미하지 않는다. 그래프에서 실패를 별도로 처리해야 한다.
- 관련 N07은 부분 결정 상태다. 서버가 받은 배 위치를 사용하며 판정 허용 오차·피해 판정 팀 계약을 완료한 것으로 보지 않는다.

## 그래프 연결 안내
- 행동/등대/몬스터 → 배를 추적하며 돌진 공격: Self, TargetBoat, Speed(기본 18), HitRadius(0.65), Timeout(10초).
- 행동/등대/몬스터 → 공격 후 이탈 지점까지 이동: Self, TargetBoat, Distance(15), Speed(8), Timeout(15초).
- 수치는 시험용 초깃값이며 밸런스 확정값이 아니다. Distance는 배 중심부터의 거리가 아니라 이탈 시작 위치부터의 이동 거리다.
- 순찰 중 최초 공격 범위를 검사하고 공격→이탈 시퀀스를 실행한다. 이탈 Success 후 추적 범위를 검사해 공격 반복 또는 순찰로 분기한다. 공격 범위를 재공격 조건으로 강제하지 않는다.
- 추적 범위 조건이 이탈 노드를 중간에 중단하지 않도록 배치한다.

## 검증
- Unity 에디터 Application.dataPath가 본 프로젝트임을 확인했다. Edit 모드에서 AssetDatabase.Refresh로 임포트·컴파일했다.
- 컴파일 완료 후 두 타입이 Lighthouse.Runtime에서 로드됨을 reflection으로 확인했다.
- 두 노드의 Self 미할당 OnStart 호출이 예외 없이 Failure를 반환함을 확인했다.
- Unity 콘솔 오류 조회 결과 0건. git diff --check 통과.
- 실제 추적 돌진·단발 피해·이탈 도착·장애물·취소·다인 접속은 미검증이다. 기존 직선 돌진의 충돌 반동 처리는 새 노드에 포함하지 않았다.

## 2026-10-16 그래프 연결
- 사용자 요청으로 BlueSharkBehavior를 Unity 에디터의 GraphAsset API로 수정하고 BuildRuntimeGraph/SaveAsset로 저장했다. YAML 직접 편집은 하지 않았다.
- 사용자 편집으로 이미 배치되어 있던 TrackingChargeAction과 기존 순찰·타겟 초기화·복귀·Blackboard를 유지했다. 편집 전 그래프는 C:/Unity/TaskBackups/BlueSharkBehavior.before-graph-edit.asset에 별도 보존했다.
- 기존 Selector(돌진 실패 시 일반 추적)를 Sequence로 변경하고 일반 추적 노드를 제거했다.
- 공격 반복은 Repeat Until Failure → Sequence[Pass If(BoatTrackableCondition) → TrackingChargeAction, RetreatFromBoatAction] 구조다. Pass If의 ObserverType은 None이다. 조건은 반복 시작 시에만 평가하고 이탈 도중에는 중단하지 않는다.
- 이탈 후 다음 반복에서 추적 범위 밖이면 반복을 끝내고 TargetBoat를 비운 뒤 ReturnToPatrolAction으로 순찰 영역에 복귀한다. 비동기 공격 실패가 부모까지 Failure로 전파되는 경우에도 Start 반복이 설정 읽기·TargetBoat 초기화·순찰을 다시 실행한다.
- 최초 공격 진입 범위는 현재 AcquireBoatTargetAction이 사용하는 프로필 DetectionRadius(15)다. 재공격 범위는 MaxChaseDistance(18)다. 별도의 SeaMonsterChargeAttack.AttackRange를 사용하지 않는다. 사용자 수치 튜닝은 이 기준을 따른다.
- 이탈 기본 Distance=15, Speed=8, Timeout=15초. 돌진 Speed=18, HitRadius=0.65, Timeout=10초. Self=Monster, TargetBoat=Boat를 두 액션 모두 연결했다.
- Unity에서 에셋 재임포트 후 런타임 트리 18개 노드, 두 액션의 Self/TargetBoat 연결, Pass If의 BoatTrackableCondition 연결을 검사했다. 누락 직렬화 참조는 false. 타겟 없는 Pass If의 OnStart가 Failure를 반환함을 확인했다. 콘솔 오류 0건.
- 검증용 execute_code 첫 호출은 내부 RootGraph 직접 접근 컴파일 오류, 다음 호출은 property/field 조회 차이로 실패했다. reflection 조회를 수정한 최종 검사가 통과했다. 이는 게임 스크립트 컴파일 오류가 아니다.
- git diff --check는 Unity 직렬화가 생성한 빈 Name/Tooltip 값의 줄 끝 공백을 보고했다. 에셋 직접 수정 금지 규칙에 따라 직렬화 출력은 보존했다.
- 그래프를 Unity 에디터에서 열었다. 실제 Play·다인 접속·화면 배치 시각 검증은 아직 하지 않았다.
- 현재 남은 일: 실제 배를 움직이며 돌진 추적·단발 명중·이탈 완료·범위 안 재공격·밖 순찰 및 취소·시간 초과를 검증한다. 그래프 연결 대기는 해소했다.

## 2026-10-16 추적 돌진 가속
- 사용자 요청: 돌진을 0에서 시작해 설정 속도까지 점차 가속한다.
- TrackingChargeAction에 Acceleration(기본 9 units/s²)과 개체별 현재 속도를 추가했다. 시작 시 이전 이동을 멈추고 현재 속도를 0으로 초기화하며, OnUpdate의 deltaTime으로 MoveTowards를 적용해 Speed까지 증가시킨다. 재공격 때도 다시 0부터 시작한다.
- 시작 프레임과 deltaTime=0에서 0속도를 이동 API에 전달하지 않으므로 양수 속도 검증 때문에 실패하지 않는다. 기존 단발 피해·실시간 방향 추적·Timeout 처리는 유지한다.
- Unity 에디터 API로 기존 그래프 노드 필드를 갱신·재빌드·저장했다. Speed=18, Acceleration=9, 사용자가 조정한 HitRadius=1.5, Timeout=10을 확인했다. BlueShark.prefab의 사용자 변경은 수정하지 않았다.
- Unity 컴파일 완료·콘솔 오류 0건, Self/TargetBoat 연결 및 누락 직렬화 참조 없음을 확인했다. 실제 Play 가속 체감·물리·다인 접속은 미검증이다.
- 최고 속도 18, 가속도 9일 때 중단이나 명중이 없으면 약 2초에 최고 속도에 도달한다. 기존 Timeout에는 가속 구간도 포함하므로 시험 시 함께 조절한다.

## 2026-10-29 돌진 중 피격 이탈
- 사용자 결정으로 살아 있는 블루샤크가 추적 돌진 중 실제 피해를 받으면 서버 HealthChanged에서 체력 감소를 확인해 공격·이동을 중단한다. 별도 중단 결과를 기록하고 TrackingChargeAction은 이를 Success로 전달해 기존 그래프의 공격 후 이탈 노드로 이동한다. 명중 성공과 중단을 분리하며 이미 배에 맞은 후 물기 완료 대기 중인 상태에는 적용하지 않는다.
- 이미 시작한 물기 연출은 클라이언트 RPC로 취소한다. 사망은 기존 사망 처리가 우선하며, 체력 초기화·동일 체력·클라이언트 이벤트는 중단 조건이 아니다. 서버 접촉 피해와 N07 배 이동 권위 계약은 변경하지 않는다.
- Unity 컴파일·콘솔 오류 0건. 프리팹 복제본 격리 검사에서 동일 체력 무시, 생존 피격 시 돌진 중단·미명중 상태 유지 및 행동 노드 Success, 물기 대기 중 무시, 비서버·사망 무시, 물기 취소와 이벤트 구독/해제를 확인했다. 검사에 필요한 서버 플래그는 반사 설정으로 대체했으며 실제 대포 피격·이탈·연속 피격·호스트/원격 플레이는 미검증이다.
