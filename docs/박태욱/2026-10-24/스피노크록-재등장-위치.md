## 요청과 목표

- 사용자가 제자리 재등장은 원래 의도와 다르며 타겟 보트 기준 랜덤 위치에 재등장하는 기획이라고 정정했다.
- 최소·최대 거리는 조절하며 시험하고, 위치 선정 기준은 잠수 시작 시점으로 확정했다.
- 첨부된 과거 구현 기록의 다음 행동을 새 실행 지시로 취급하지 않았다. 이번 범위는 재등장 위치 변경이며 4단계 감속·회복 구현은 포함하지 않는다.
- 공유 기준은 [스피노크록 공격 패턴 결정](../../design/spinocroc-decisions.md)에 기록했다.

## 진행 과정과 결정 이유

- 기존 SpinocrocPreparation은 이동을 잠그고 Y만 변경했다. 타겟의 잠수 시작 위치를 별도로 보관하고, 설정 범위의 랜덤 방위·거리로 재등장 지점을 한 번 선택하도록 변경했다.
- 보트의 현재 위치를 읽는 기존 조준 데이터와 재등장 기준을 분리했다. 잠수 중 보트 이동·소멸로 저장된 목적지를 다시 계산하지 않는다.
- 최소·최대 거리 초기값은 12·20m다. 기존 속도12m/s·지속2초의 돌진 거리24m를 참고한 시험값이며 최종 밸런스가 아니다. 동일한 양수 최소·최대 값도 허용하고, 역전·0 이하·NaN·무한대는 설정 유효성 검사에서 거절한다.
- 잠수 완료 시 목적지의 잠수 깊이로 Rigidbody를 이동한 뒤 재등장을 시작한다. 같은 물리 갱신에 이전 위치의 MovePosition을 예약하지 않아 새 위치를 덮어쓰지 않도록 했다.
- 원격의 이전 위치 보간을 초기화하기 위해 기존 프리팹 NetworkTransform의 ServerTeleport를 호출한다. 이 타입은 Mirror.Components 어셈블리에 있어 공용 Lighthouse.Runtime.asmdef에 참조 한 줄을 추가했다. 담당 영역과 이유를 수정 전에 안내했다. Mirror 원본은 수정하지 않았다.
- 기존 안전구역·섬 판정을 후보 선정 및 이동 직전에 재사용한다. 후보 16개가 모두 거절되면 준비를 시작하지 않고 배회를 유지한다. 일반 고체 장애물·모델 체적 전체 검사는 추가하지 않았다.

## 검증

### 실제 수행

- 후속 사용자 확인: "랜덤 재등장 확인 했으니까 4단계 진행해". 사용자의 재등장 확인으로 기록하며, 별도 원격 클라이언트 시험을 했다는 의미로 확대하지 않는다.
- 변경 전 작업 트리 깨끗함, 기준 브랜치·커밋 확인.
- 실제 프로젝트 csproj의 C# 소스611개와 로컬 Unity/Mirror 참조를 사용해 Unity 제공 Roslyn 컴파일러로 라이브러리 컴파일 성공(오류0).
- 기준 커밋의 두 C# 원문으로 같은 컴파일을 별도 수행했다. 기준·수정본 모두 성공했고 경고472개 목록이 같았다. 이 숫자는 독립 C# 컴파일 결과이며 Unity 콘솔 경고 수가 아니다.
- git diff --check 통과, asmdef JSON 및 기존 Mirror.Components 어셈블리·프리팹 NetworkTransform 연결을 정적으로 확인.
- 컴파일 출력·기준 소스·로그는 저장소 밖 작업 공간 Artifacts/SpinocrocReappearance에 두었다. Unity의 Library·Temp 빌드 출력을 덮어쓰지 않았다.

### 미실행과 이유

- 현재 세션에 Unity 도구가 노출되지 않았다. 설정된 로컬 HTTP MCP 서버는 연결 거절, 기존 Unity relay의 tools/list는 빈 목록이었다.
- Unity 에디터 임포트·Weaver·Inspector 기본값 확인·Play/Host·실제 물리 이동·원격 표현·4인 검증은 미실행이다. 정적 컴파일을 이 항목의 통과로 세지 않는다.

## 남은 일과 다음 행동

1. 에디터 재연결 후 컴파일·Weaver 오류, SpinocrocSettings.asset의 거리12·20 기본값 및 Inspector 조절·저장을 확인한다.
2. MonsterTestScene에서 기존 매니저 Host를 시작한다. 잠수 시작 당시 보트 X/Z와 ReappearCenter, ReappearPosition을 관측하고 잠수 중 보트를 옮겨도 목적지가 유지되는지 확인한다.
3. 최소=최대인 시험과 여러 거리 범위에서 실제 재등장 위치의 수평 거리를 확인한다. 이후 준비·방향 고정·직선 돌진·피해·배회 복귀를 회귀한다.
4. 안전구역·섬 후보 거절·후보 소진·준비 취소 및 사망·비활성화 때 물리 제약 복구를 확인한다.
5. 별도 원격 클라이언트에서 수면 위 수평 보간이나 위치 되돌림 없이 재등장하는지 확인한다. 실제 World/MapStateNet 연결과 W17·N07·W18 검증은 별도로 남는다.
6. 감속·회복·반격 시간·몸통 충돌 해제/복구는 이후 4단계다.

## 후속 진행

- 사용자 확인 후 [4단계 감속·회복](스피노크록-4단계-감속과-회복.md)을 진행했다. 그 작업에서 Unity MCP 연결이 복구되어 기존 에디터·호스트로 검증했다. 위 MCP 미연결과 C# 단독 컴파일 기록은 재등장 수정 당시의 이력이다.
