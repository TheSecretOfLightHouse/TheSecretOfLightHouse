## 요청과 확정 범위
- 등대 괴물은 일반 몬스터가 아닌 독립 시스템으로 작업한다.
- 사용자 지정 Boss 폴더는 실제 기존 경로 `Assets/01.Scripts/06.Monsters/Boss/` 아래 생성했다.
- 일반 몬스터 AI·자연 스포너와 분리한다. 구체 클래스·하위 폴더는 구현 시 필요한 범위에서 정한다.

## 기획 대조와 계획안
- 기준: docs/design/win-vote-decisions.md 5·6절, docs/design/references/game-design-v4.md 5장.
- 처치 불가, 등대 우선 공격, 아침에도 유지, 소환 시 공격력 계산·고정, 호스트 판정은 기존 확정 규칙이다.
- 소환 승인과 공격력 스냅샷은 존재하지만 실제 보스·등대 피해 연결은 구현하지 않았다.
- 계획안: 진행/등대 피해 계약 → 시험용 대상에서 진행·피해 검증 → 소환 승인 연결 → 표현과 실제 등대·월드·종료 통합.
- 초기 계획 당시 출현·공격 방식은 미정이었다. 아래 2026-10-17 추가 결정을 우선한다. 공격 주기 수치·플레이어 개입 규칙은 미정이다.
- W17 안전지대 예외와 K01 동시 경합은 관련 담당과 결정·연결 필요.

## 2026-10-17 — 촉수 기획과 1단계

- 사용자 결정: 투표 UI 소환 승인 → 촉수 등대 감기 → 고정 공격력으로 주기 피해. 봉인 반영 최종 공격력이 최대 기준값에 도달하면 일반 전투 없이 특수 연출 후 마피아 승리. 기준 문서 5절과 대장 R09에 반영했다.
- 단계: 1 시험 환경 → 2 소환·분기 → 3 일반 피해 → 4 촉수 표현 → 5 특수 종료 → 6 본편 통합. 첫 피해를 감기 완료 뒤에 주는 것은 현재 제안이며 실제 타이밍은 후속 단계에서 정한다.
- 사용자 배치 모델 두 개를 확인하고 변환·메시·재질을 유지했다. FBX 두 개는 작업 시작부터 미추적 상태였으며 사용자 제공 에셋이다. 씬에 있던 미저장 배치가 씬 저장에 함께 포함됐다.
- BossSettings: 시험 HP 1000, 공격 주기 3초, 특수 기준 100. 모두 임시 테스트값이며 심해 게이지 자체 상한을 추가하거나 공격력을 클램프하지 않는다.
- BossTestEnvironment: 별도 NetworkIdentity를 가진 씬 오브젝트, 서버 시작 HP 초기화·SyncVar, 등대/촉수 참조, 우측 하단 시험 표시. 등대 담당의 본편 코드를 대체하지 않는다.
- 투표 패널: 하단 진단 여백 설정 추가(기본 0, 이 씬만 164). 기존 투표 진단과 겹치지 않게 했다. 카메라는 두 모델이 보이도록 조정했다.
- 변경: Boss/BossSettings.cs, Boss/BossTestEnvironment.cs와 meta, TaeWook/BossTestSettings.asset와 meta, VotingTestScene.unity, VotingTestPanel.cs, 관련 기준/작업 문서와 pointer.
- 검증: Unity 컴파일 오류 0, 설정/모델 참조 유효, 호스트 서버·로컬 클라이언트 연결, HP 1000/1000, netId 1, 두 모델 활성 상태 확인. 기본 포트 점유로 최초 호스트 시작 실패 후 런타임에서만 임시 17889 포트를 사용했다. 씬 포트는 변경하지 않았다.
- 첫 화면 확인에서 모델 상단이 잘려 카메라를 조정했다. 동적 폰트 명시 삭제 경고가 있어 기존 투표 패널처럼 Unity가 수명을 관리하도록 수정했다.
- 수정 후 호스트 재실행 및 최종 화면 캡처에서 두 모델 전체와 HP 표시·투표 패널을 함께 확인했고 콘솔 오류·경고 0이었다. 종료 후 편집 모드로 복귀했다. 캡처는 로컬 작업 백업으로 보관하며 Git 산출물에는 포함하지 않는다.
- 원격 다인 접속, 투표 전체 회귀, 실제 피해·애니메이션·특수 종료는 미검증/후속 범위다.

## 2026-10-17 — 2단계 소환과 분기

- 기존 `VotingNetworkController.SummonApproved`를 `BossTestEnvironment.OnStartServer`에서 구독하고 서버 종료 시 해제한다. 기존 투표 승인 규칙과 Command 코드는 변경하지 않았다.
- `BossPhase`: 소환 대기 / 일반 전투 준비 / 특수 종료 연출 준비. 단계만 SyncVar로 공개 동기화한다. 승인 스냅샷의 double 공격력은 서버에만 저장하며, 서버 전용 `TryGetAttackPower`로 후속 피해 로직이 사용할 수 있다. 심해·봉인 원본을 동기화하지 않는다.
- 소환 승인 순간 최종 공격력이 특수 기준 이상인지 한 번 판단한다. 재승인 이벤트와 재요청은 고정된 공격력·분기를 변경하지 않는다. 서버 재시작 시 초기화한다.
- 우측 하단에 승인 여부와 분기를 표시하고 호스트에만 고정 공격력을 표시한다. 씬의 투표 참조를 연결하고 기존 진단 패널의 하단 여백을 218로 조정했다.
- 변경 파일: `BossPhase.cs`와 meta, `BossTestEnvironment.cs`, `VotingTestScene.unity`, 작업 원문과 pointer.
- 검증: Unity 컴파일 오류 0. 호스트에서 승인 이벤트에 스냅샷을 주입해 공격력 99/100/101과 봉인 반영을 시험했다(기본 149/150/151, 봉인 50). 각각 일반/특수/특수, 두 번째 승인 무시, HP 1000 유지 통과. 이 경계 시험은 실제 투표 요청과 구분한다.
- 실제 요청 검증: 시험용 참가자 1~4와 시민 표는 서버에서 설정하고, UI가 사용하는 `RequestIdentityCheck`/`RequestSummon`을 통해 Command를 전송했다. 권한 없는 소환은 NoSummonRight로 거절되고 보스는 대기. 일반 승인 공격력 10 및 재시도/새 중복 요청 후 고정 유지, 특수 승인 공격력 100·SpecialEndingReady·HP1000 확인. 특수 시험의 밸런스 변경은 런타임 복제본만 사용했고 에셋은 변경하지 않았다.
- 초기 요청 검증 도중 시험 마피아의 난파 상태 제공을 누락해 StateUnavailable 거절을 확인했으며, 기존 패널과 동일하게 `SetMafiaDowned(false)`를 설정한 후 재검증했다. 제품 코드 결함이 아닌 시험 준비 누락이었다.
- 호스트 화면 캡처로 2단계 표시와 기존 투표 패널 배치를 확인했다. 로컬 임시 포트 17889 사용, 씬 포트 유지, 시험 후 편집 모드 복귀. 콘솔 오류 0, 반복 Play 전환 중 `Deleting invalid font reference.` 경고 2건 관찰(폰트 경고 원인 미확정).
- 원격 클라이언트 상태 일치·투표 전체 회귀는 미검증이다. 이번 결과는 호스트 확인이며 다인 통합 완료로 표기하지 않는다. 실제 피해·촉수 연출·승패 종료는 다음 단계 범위다.
