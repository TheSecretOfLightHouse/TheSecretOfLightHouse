## 요청과 목표
- 사용자 확정 6단계 계획 중 1단계만 진행한다. 이름·고정 ID·프리팹 목록, 드롭다운 선택, 최대 생존 수·개별 사망 후 재생성 대기 시간·수평 생성 반경을 설정한다.
- 최초 생성 요청·공용 프레임당 5회 검사·순차 기회 배분은 2단계, 수면 정착/순찰 중심은 3단계, 사망별 예약은 4단계, 판 수명/네트워크는 5단계, 월드 위치·해역·ProfileId 연결은 6단계다.
- 순찰 영역은 몬스터 기존 설정을 유지한다. 풀링은 보류한다.

## 진행 과정과 결정 이유
- 기존 MonsterProfile은 AI 능력치 정의이므로 몬스터 종류 목록 MonsterCatalog와 분리했다. 월드의 ProfileId와 catalog ID 간 계약은 아직 연결하지 않았다.
- 선택은 목록 인덱스 대신 ordinal 문자열 ID로 저장한다. 재정렬은 선택에 영향을 주지 않으며, 삭제/ID 변경 시 기존 선택을 보존하고 오류를 표시한다. 사용 중인 ID는 변경하지 않는다.
- 목록 전체가 유효해야 프리팹을 반환한다. 중복 ID, 빈 이름/ID, ID 앞뒤 공백, 누락 프리팹, 프리팹 루트 조건 및 NetworkIdentity를 검증한다. 최대 생존 수 1 이상, 대기 시간/반경은 유한한 0 이상을 허용한다.
- 서버 생성 코드가 사용할 TryGetSpawnPrefab은 검증 실패 시 false와 null 프리팹을 반환한다. 실제 Instantiate/NetworkServer.Spawn은 아직 없다.
- 에디터 전용 asmdef를 몬스터 영역 내부에 추가했다. 기존 공용 asmdef는 수정하지 않았다.
- 실제 에셋 생성 시험에서 프리팹의 NetworkBehaviour.netIdentity 캐시가 null일 수 있음을 확인해 GetComponent<NetworkIdentity> 검사로 수정했다.
- W17 안전지대 예외 계약은 여전히 확인 필요다. 자연 스포너 안전지대 제외의 구체적인 위치 검사 기준은 2단계에서 다룬다. 이번 설정 단계에서 임의 규칙을 추가하지 않았다.

## 변경 파일과 결과
- Assets/01.Scripts/06.Monsters/Spawning/Rules: MonsterCatalog, MonsterCatalogEntry
- Assets/01.Scripts/06.Monsters/Spawning/Server: NaturalMonsterSpawner
- Assets/01.Scripts/06.Monsters/Spawning/Editor: 전용 asmdef, 목록/스포너 Inspector, 기본 목록 생성 메뉴
- Assets/02.Prefabs/Monsters/Data/NaturalMonsterCatalog.asset: 블루샤크(blue-shark), 블루마린(blue-marlin), 기존 프리팹 연결. Unity AssetDatabase로 생성했다.
- 신규 코드·폴더 meta와 본 기록·담당자 pointer

## 사용 방법
1. GameObject에 Add Component → Lighthouse/Monsters/Natural Monster Spawner를 추가한다.
2. 몬스터 목록에 NaturalMonsterCatalog.asset을 지정하고 몬스터 종류를 선택한다.
3. 최대 생존 수·재생성 대기 시간(초)·생성 반경(m)을 지정한다. 선택된 객체의 Scene 뷰에서 월드 XZ 평면 반경을 표시한다. Transform 스케일에 반경을 곱하지 않는다.
4. 목록 에셋의 Entries에서 이름·ID·프리팹을 관리한다. 별도 목록은 Create → Lighthouse → Monster → Monster Catalog로 만든다.
5. Lighthouse → Monsters → Create Natural Monster Catalog는 기본 목록이 없을 때 생성하고, 이미 있으면 선택한다. 기존 내용을 덮어쓰지 않는다.

## 검증
- Unity 6000.0.83f1 MCP에서 해당 프로젝트와 새 타입 로드를 확인했다. Play 모드에는 진입하지 않았다.
- Unity 참조 DLL을 사용한 별도 Roslyn 컴파일: 오류/경고 0건(최초 구현 기준). 실제 Unity 컴파일 후 콘솔에서도 C# 컴파일 오류 없음.
- 임시 PreviewScene 및 원본 목록 복제본에서 11개 검사 통과: 정상 블루샤크 선택, 재정렬 후 ID/프리팹 보존, 중복 ID 거부, 누락 프리팹 거부, 미등록 ID 보존/거부, 최대 생존 수 0 거부, 음수 대기 시간 거부, NaN/무한 반경 거부, 0 반경/대기 시간 허용, 커스텀 Inspector 타입 등록.
- 검증 객체·복제 목록·PreviewScene을 정리했다. 시작부터 active scene dirty=true였으며 해당 씬을 저장하지 않았다. 씬/기존 프리팹 변경 없음.
- 독립 읽기 전용 코드 검수에서 기능 차단 결함 없음. 어셈블리 경계를 넘는 API의 XML 요약 보완 의견을 반영했다.
- 도메인 재로드 과정에서 MCP WebSocket not initialised 경고가 관찰됐다. 최종 주석 보완 후 Unity 재컴파일과 11개 기능 검사를 다시 실행했으며, 최종 콘솔 조회의 오류·경고는 0건이었다.
- Inspector 캡처 시도는 원하는 객체 화면을 얻지 못해 시각 검증으로 인정하지 않는다. 드롭다운 직접 조작·Undo/Redo·Scene 반경 표시의 실제 화면 확인은 미검증이다.
- git diff --check 통과. 네트워크/4인 검증은 실제 생성 구현 이후 진행한다.

## 남은 일과 다음 행동
- Unity Inspector에서 선택·재정렬·오류 표시 및 Scene 반경을 직접 확인한다.
- 2단계에서 모든 생성 요청이 검증 API를 통과하도록 연결하고, 서버 공용 위치 탐색 큐(전체 프레임당 5회, 스포너 순서 배분)를 구현한다.
- 1단계 목록 검증은 AI 그래프/능력치 유효성, Mirror spawnable prefab 등록까지 대신하지 않는다. 실제 생성 단계에서 기존 초기화와 등록 조건을 확인한다.
