## 요청과 목표
- 사용자 승인: 2단계 구현 시작. 최초 최대 생존 수만큼 요청하고, 전체 스포너 합산 프레임당 최대 5회 후보를 검사하며 대기 스포너에 순환 배분한다. 막힌 요청은 다음 프레임에도 유지한다.
- 최신 결정: 몬스터 겹침은 프리팹 CapsuleCollider 범위로 검사한다. 지형·안전지대·수면 높이는 맵 담당자 연결 시 결정한다. 시험 생성 높이는 스포너 Y 좌표다.
- 수면 정착/순찰 중심(3단계), 사망별 재생성(4단계), 월드 준비·판 종료 계약 및 4인 검증(5단계), 월드 배치 데이터 연결(6단계)은 후속 범위다.

## 진행 과정과 결정 이유
- 사용자 후속 요청으로 스포너 1·2단계의 일반 주석·XML 요약과 MonsterBase에 추가한 주석을 한글로 변경했다. 실행 코드는 변경하지 않았다. 변경 범위·주석 검색과 git diff --check로 확인했으며 주석 변경에 대한 런타임 시험은 추가하지 않았다.
- 1단계 작업 원문·현재 미커밋 변경·몬스터 초기화·Mirror 생성 및 등록 경로를 확인했다. 이전 단계 변경을 유지했다.
- NaturalMonsterSpawner는 기본 시험 옵션으로 NetworkServer.active가 된 뒤 초기 요청을 한 번 등록한다. 자동 시작을 끄면 BeginServerSpawning을 명시적으로 호출할 수 있어 이후 월드 준비 신호에 연결할 수 있다.
- MonsterSpawnScheduler 하나가 대기 스포너를 순환 처리한다. 검사 기회마다 후보 한 곳만 검사하고, 성공하면 한 마리만 생성한다. 실패 시 요청 수를 줄이지 않는다. 대기열이 비면 물리 동기화/후보 검사를 하지 않는다.
- 반경은 Random.insideUnitCircle 기반 월드 XZ 원이다. 프리팹 루트 캡슐의 center/direction/height/radius와 스케일·회전을 반영해 NonAlloc 캡슐 겹침 검사를 수행한다. IgnoreRaycast 레이어까지 포함하며, 몬스터 콜라이더만 차단한다. 버퍼가 가득 찬 경우 안전하게 실패로 처리한다.
- MonsterBase가 Awake에서 콜라이더 목록을 저장하고 활성화 시 registry에 등록한다. 파괴 시 해제한다. AI 컴포넌트만 비활성화해도 물리 콜라이더는 남으므로 OnDisable에서는 등록을 해제하지 않는다. GameObject 비활성화는 Physics 쿼리가 자동 제외한다.
- 프리팹·캡슐 참조/스케일은 시작 시 저장한다. 후보 검사 경로에서 GetComponent/GetComponentInParent와 컬렉션 생성을 제거했다. 목록 종류는 시작 시 스냅샷이며 실행 중 목록 내용을 편집한 경우 중지 후 다시 시작한다.
- MonsterSpawnPositionValidator는 월드가 후보를 거절하거나 최종 높이를 반환할 확장 지점이다. 미지정 시 스포너 Y를 그대로 사용한다. 안전지대 계약 W17은 맵 연결까지 보류 상태이며 임의 판정을 추가하지 않았다.
- MonsterSpawnFactory에 Instantiate/NetworkServer.Spawn 및 Destroy를 분리했다. 서버 초기화 실패는 위치 실패와 구별해 해당 초기 요청을 취소한다. 실패 프리팹을 무한 생성/제거하지 않는다.
- 생성 직전에 서버 상태·남은 요청·최대 생존 수를 다시 확인한다. 초기 요청이 완료된 뒤에는 자동으로 인원을 보충하지 않는다. 재생성은 4단계에서 구현한다.
- 비활성화/명시적 중지 시 대기 요청과 소속 몬스터를 정리한다. 판 단계 이벤트 연결은 아직 없으며 5단계에서 다룬다.

## 변경 파일과 결과
- Spawning/Server/NaturalMonsterSpawner.cs: 초기 요청·서버 시작/중지 API·소속 관리·수치 검사
- Spawning/Server/MonsterSpawnScheduler.cs: 공용 5회 예산·순환 처리
- Spawning/Server/MonsterSpawnPlacement.cs, MonsterSpawnCollisionRegistry.cs: 캡슐 겹침 검사와 콜라이더 소유권 캐시
- Spawning/Server/MonsterSpawnFactory.cs: 생성/회수 경로
- Spawning/Server/MonsterSpawnPositionValidator.cs: 월드 검사 확장 지점
- AI/Net/MonsterBase.cs: 콜라이더 캐싱 및 등록/파괴 시 해제만 추가. 기존 AI·체력·물리 권위 로직은 유지
- Spawning/Rules/MonsterCatalog.cs: 검증 중 HashSet 할당 제거
- Spawning/Editor/NaturalMonsterSpawnerEditor.cs: 시험 자동 시작·월드 검사 연결·생존/대기 표시
- Assets/00.Scenes/TaeWook/NaturalMonsterSpawnerTestScene.unity 및 meta: 기존 시험 씬의 저장본을 AssetDatabase로 복사한 별도 씬. 스포너 3개, 각 최대 4마리·반경 15m. MonsterTestNetworkManager와 기존 KCP Transport 사용. 두 몬스터를 spawnPrefabs에 등록
- 신규 스크립트 meta와 본 기록·pointer

## 시험 씬 사용법
1. NaturalMonsterSpawnerTestScene을 열고 Play한다.
2. NetworkManagerHUD에서 Host를 시작한다. 시험 포트는 17893이다. 기본 7777은 이번 로컬 환경에서 이미 사용 중이어서 별도 시험 포트를 사용했다.
3. Natural Spawner 1~3을 선택해 생존/대기와 반경을 확인한다. 초기 요청은 총 12마리다. 기존 씬 몬스터는 이 수에 포함하지 않는다.
4. 막힌 영역 시험은 반경을 0으로 하고 기존 몬스터 위치에 스포너를 두면 된다. 별도 인스턴스에서 Client로 같은 포트에 연결해 원격 확인할 수 있으나, 이번 작업에서는 실제 원격 검증을 수행하지 않았다.
5. 다른 씬에서 사용하려면 해당 NetworkManager의 spawnPrefabs에 목록의 몬스터 프리팹을 등록해야 한다. 이번에는 공용 NetworkManager 코드를 수정하지 않았다.

| 호스트·원격 동일 생성/제거 | L3 | 0 | 미실행 | 원격 접속 시험 없음 | 검증 대기 |

- 호스트 계측은 기존 dirty 시험 씬을 저장하지 않고 Play한 뒤, Play 중에만 시험 매니저와 검증용 스포너를 추가했다. 물리적으로 위치를 유지하는 겹침/좌표 검사를 위해 생성 몬스터의 AI를 멈추고 Rigidbody를 kinematic으로 고정했다. 정상 AI 순찰 시험을 대체하지 않는다.
- 새 전용 시험 씬은 에디터 API로 저장·로드/구성 확인했으며, 이 씬 자체의 수동 Host/원격·시각 검증은 미실행이다. 원본 MonsterCollisionTestScene의 저장되지 않은 변경은 보존했고 저장하지 않았다.
- 초기 기본 포트 Host 실패(SocketException)와 실패 상태의 공용 매니저 StopHost 예외는 별도 시험 매니저/포트로 우회했다. 공용 네트워크 코드는 변경하지 않았다.
- 스크립트 부분 Refresh 중 신규 registry 타입 미발견이 있었으나 전체 AssetDatabase Refresh 후 해소했다. 이후 실제 Unity 컴파일 오류 0건. 도메인 재로드의 MCP WebSocket 경고, MPP의 원본 미저장 씬 경고는 기능 오류와 구분한다.
- 독립 코드 검수의 반복 컴포넌트 조회 지적과 AI만 비활성화 시 콜라이더 누락 지적을 수정했고, 최종 정적 재검수 PASS. 독립 검수는 실제 원격 실행을 대신하지 않는다.
- Play 종료 후 임시 객체는 복원 과정에서 정리됐고 기존 씬·기존 프리팹을 저장/수정하지 않았다. git diff --check 통과.

- 단계2 네트워크 검증은 M1 호스트까지다. 원격에서 초기 생성·제거 일치 및 전용 시험 씬 화면을 확인해야 한다.
