## 요청과 목표
완성한 상승·한손 잡기·등대 파괴·느린 손 회수 애니메이션을 기존 최후 전투처럼 테스트 씬에서 보고 같은 프리팹으로 본편에 연결한다. 사용자 확정: 본편 등대 비율 유지, 보스·잡기 동작을 본편에 맞춤.

## 진행 과정과 결정 이유
- 사용자 레퍼런스(DREDGE 엔딩 cEFm6nFSnfo, 수면 등장 구간) 피드백으로 위쪽 피부 줄무늬 표현을 철회하고 재작업했다. 기존 `BodySurfaceRunoff` 오버레이를 공용 연출 프리팹에서 제거하고 미사용 전용 스크립트/셰이더/재질/마스크 메쉬도 Unity API로 삭제했다. 최신 구현은 `SpecialEndingWaterCurtain.cs`·`WaterCurtain.shader`·`WaterCurtain.mat`: 어깨/팔 본에 연결한16개 물막이 중력 방향으로 늘어지고, 하단의 불규칙한 투명 마스크와 최대128개 낙하 물방울로 끊어지는 표현이다. 물방울은 기존 Player 재질을 읽기 전용 참조한다. 3~7초 강해지고 13초에 숨김; 본편 수면 기준 높이 아래 물방울 제외. 초기 Director 참조 누락을 수정한 뒤 재검증했다. Play7초 최종 렌더, 2/4.5/7/9/11/13/18초 구간 검사(7초 물방울91개,13초0개), 취소 시 물막 숨김/물방울0, 카메라Y3.3 유지, 콘솔 오류0 확인. 실제 유체 시뮬레이션은 아니며 본편 전체/원격과 사용자 최종 시각 확인은 미검증. 다른 파트 코드·원본 몸/수면 에셋은 수정하지 않았다.
- 몸 표면 물 흐름 추가: 컷씬 전용 `SpecialEndingBodyRunoff.cs`·`BodySurfaceRunoff.shader`·`BodyRunoffMask.asset`·재질을 만들고 공용 연출 프리팹에 연결했다. 원본 스킨 본을 공유하는 별도 메쉬에 가슴·어깨·팔 가중치 마스크를 적용하고, 중력 방향으로 짧고 불규칙한 물 하이라이트를 흘린다. 3.8~18초에 상승 후 점차 약해지며 기존 낙하 물방울과 함께 보인다. 초기 균일 줄무늬는 폭·밀도·밝기를 줄여 수정했다. 다른 파트 코드·원본 몸 메쉬/재질·본편 수면 에셋은 수정하지 않았다. Play8.5초 렌더·본 공유/분리 메쉬·취소 후 숨김·카메라Y3.3 유지·콘솔 오류0·diff 공백 검사 통과. 실제 유체 시뮬레이션이 아닌 표면 표현이며 사용자 시각 확인·본편/원격 검증은 남아 있다.
- 2026-11-01: 기존 소환 Timeline·로컬 섬 BindIsland·서버 시각 동기화·보호/카메라 복귀 경로를 대조했다. 기존 일반 연출은 유지하고 BossTestEnvironment의 공개 특수 분기 상태로 별도 연출을 선택한다. R09·K01 결과 잠금은 미정이므로 자동 완료·승리 확정은 추가하지 않았다.
- 전달받은 FBX(1~552프레임, 24fps)를 Generic으로 가져왔다. 보스와 파괴 등대가 같은 클립 안에서 움직이며 311 렌더러·118본이다. 소스 길이 22.958334초를 23초 Timeline으로 재생한다.
- 본편 등대와 높이는 같고 폭이 달라, Stage의 X/Z를 1/0.7로 공통 보정했다. 손과 파괴 등대를 같이 보정하여 기존 접촉 관계를 보존하고 TowerBase 기준으로 배치한다. 본편 등대 원본 Transform은 바꾸지 않았다.
- SpecialEndingIslandBinding은 연출 중 본편 등대 렌더러만 숨기고 중단 시 이전 상태로 복구한다. 서버 상태와 콜라이더는 유지한다. 완료 시 파괴된 표현을 유지한다.
- 테스트 씬에 실제 섬 프리팹·간이 수면·조명·개요 카메라와 본편용 연출 프리팹을 배치했다. 섬의 게임 MonoBehaviour는 테스트 인스턴스에서만 비활성화했다. Preview 컴포넌트도 씬에만 추가했다.
- 서버는 보스 분기 결정까지 기존 준비 제한 시간 안에서 기다린 뒤 일반 12초/특수 23초를 선택한다. 클라이언트도 분기와 늦게 바인딩되는 섬을 준비 제한 시간까지 기다린다. 본편은 기존 World 빌더의 BindIsland를 그대로 사용한다.

## 변경 파일과 결과
- 물 효과1차: 상승 중 몸 주변 분출 물보라·낮은 물안개·몸에서 떨어지는 물줄기3개 파티클과, 몸 거품/확산 파문2개·촉수 거품4개를 공용 프리팹/Timeline에 추가했다. 기존 BoatCollisionSplashEffect의 물방울/거품 머티리얼을 참조하며 Player 원본 에셋은 수정하지 않았다. 분출은1.5초·물안개2.5초·몸 물줄기4초부터 시작해 상승 후 잦아든다. 물줄기는 Chest의 위치만 ParentConstraint로 따른다. 기존 Summon_WaterRise를3.2초부터3.5초간 볼륨.36으로 겹쳤다.
- 거품은 별도 WaterEmergenceFoam 셰이더/2709정점 annulus 메쉬를 사용한다. 본편 OceanGerstnerFieldLagoon 및 OceanInteraction 함수를 재사용해 각 정점이 파도·해안 보정·접촉 리플을 따른다. 반경·불투명도는 Timeline 시각의 곡선으로 평가하고 얼굴/손을 가리지 않게 수면 근처에 배치했다. 이는 시각 효과이며 실제 물리 파도/배 피해 modifier를 추가하지 않는다.
- 촉수 수면 기준점은 이제 끝점만 따르지 않고14본 체인과 수면의 교차 구간을8회 이분 탐색한다. 물에 닿지 않은 촉수 거품은 숨긴다. 몸/촉수 위치나 카메라 높이는 수정하지 않았다. 최초 물보라가 몸/섬에 가려져 몸 바깥 반경8.5m·분출속도8~13m/s·피크300개/초로 가시성을 조정했다.
- 실제 검증: Play6.5초 분출334/물안개79/물줄기69개·거품6개와 렌더 확인. 9개 시점에서 수면 조회 실패0·카메라 상하변위0, 수면 접촉 전 촉수 거품off/상승 뒤on 확인. 취소 후 보이는 물 거품/파티클0·재생 오디오0, 실제 오디오 출력 피크.17795·전체23초·콘솔 오류0·diff check 통과. 물 효과 off에서도 남는 기존 수면의 근거리 청색 띠는 신규 효과와 분리 확인했고 이번 범위에서 수정하지 않았다. 본편 전체/원격·물보라의 모든 입자-지형 충돌·GPU 수면 높이 직접 계측은 미검증이며 사용자 시각/청취 피드백 대상이다.
- 카메라 상하 흔들림 후속: 사용자 피드백으로 카메라의 매 프레임 수면 높이 추종 컴포넌트를 제거했다. 현재 테스트 씬 기준 월드Y3.3m의 일정 높이로 카메라 클립/프리팹/개요 카메라를 맞추고 시선 목표를 재조정했다. 기존 접근·후퇴와 롤은 유지한다. 몸/촉수 수면 기준점5개만 파도를 추종한다. 552프레임에서 카메라Y 최소/최대 모두3.3·상하변위0·현재 파도 위 최소여유.7314m 확인, 실제 Play17초 구도 렌더·콘솔 오류0 확인 후 재생. 이는 현재 테스트 파도/시간 구간의 여유이며 실제 본편의 다른 파도 위상은 후속 확인 대상이다. 이전 카메라 수면 자동 추종 기록보다 이 결정이 우선한다.
- 본편 수면 연결: `MainGame.unity`를 읽기 전용 PreviewScene으로 열어 실제 TestOcean의 수면 메쉬40개와 `OceanWater_Clear`/`Lighthouse/World/ClearOcean` 재질·셰이더 참조를 테스트 씬에 복제했다. 임시 PreviewSea는 비활성화해 보존했다. 원본 MainGame·World 코드·바다 에셋은 수정하지 않았다. 섬의 기존 IslandCoastWaveView만 테스트 인스턴스에서 활성화하여 같은 해안 파도 등록을 사용한다.
- 단독 테스트 전용 `SpecialEndingOceanPreview`는 Timeline을 IClock으로 등록하고, 본편 WeatherCatalog의 Maelstrom 스냅샷6파와 동일 OceanOpticsProfile_Default/MapGenerationConfig를 기존 WaterSamplerHost·OceanShaderBridge·OceanOpticsModel/Material에 연결한다. 본편 전투 후 심연 조건에 맞춰 Abyss 광학 상태를 사용한다. 테스트용 서비스는 씬에만 있으며 공용 연출 프리팹에는 포함하지 않았다. 본편의 기존 clock/query/날씨를 덮어쓰지 않는다.
- 공용 프리팹에 `SpecialEndingWaterSurfaceAnchor`를 추가했다. 본편 IWorldQuery.SampleWaterHeight를 우선 사용하고, 단독 테스트에서는 같은 WaveModel·WaveInputs·IClock·CoastWaveRegistry를 조회한다. 몸통 Body_Base와 뒤쪽 촉수4개의 수면 기준점을 만들었으며 아직 물보라를 생성하는 단계는 아니다. 보스/손의 애니메이션은 움직이지 않는다. 카메라는 기존 높이를 기준으로 수면 위 최소.65m를 확보한다. 깊이/불투명 색상 텍스처를 연출·테스트 카메라에 활성화했다.
- 수면 검증: 실제 Play에서 본편 메쉬/재질·6파·해안 파도 표시 확인, 렌더 캡처. 552프레임×6기준점(몸/촉수/카메라)을 샘플하여 CPU WaveModel 기준 높이 오차0·Shader 시간 오차0·조회 실패0·손 위치 변화0, 카메라 최소 여유.6499999m·최대Y3.2186m 확인. 몸 기준점은 최종적으로 리그 원점이 아닌 Body_Base에 정렬했다. 별도 임시 MapGeometry+실제 WorldQueryFacade를 등록한6기준점 통합 검사도 높이 오차0으로 통과하고 즉시 서비스/캐시 정리했다. 이 검사는 실제 MainGame 전체 생성/네트워크 실행을 대신하지 않으며 GPU 픽셀 높이 직접 계측도 아니다. 본편의 접촉 거품 ComputeGrid/쇄파 전체 구성과 물보라 효과는 후속이다. ## 실루엣 확대 후속과 복구
- Spine1.45배·Head추가1.3배·뒤쪽 촉수 뿌리추가1.2배의 별도 클립 `MafiaSpecialEnding_Colossal.anim`을 만들었다. Forearm 위치/배율을 보정하여 잡는 손을 유지한다. 카메라는 FOV40·거리6m 후퇴·시선 상향으로 저장했다. 원본 FBX는 보존했다.
- 최초 전체 복제 클립이 약972MB가 되어 키 정리 중 Unity가 장시간 응답하지 않았다. 초기에는 종료로 오인했으나 실제 UI는 Play 종료 대기 상태였다. 강제 재시작은 자동 승인 검토에서 거절됐으며, 이후 사용자가 위험을 확인하고 명시적으로 승인한 뒤 실행했다.
- 재시작 후 MCP를 재연결하고, 원본 곡선에서 불필요한 키를 사전에 축약하여 Unity API로 일괄 저장했다. 최종138,808키·86,831,415바이트이며 meta/GUID를 유지해 같은 경로를 복구했다. Timeline 클립 참조도 재연결했다. YAML 직접 편집은 하지 않았다.
- 최종 클립의 정수·중간 프레임을 합친1,103개 표본에서 양손 위치 최대오차 약2.10mm(임시 모델 기준), 행렬 성분 최대오차0.00527을 확인했다. 본편 Stage 수평 보정을 고려한 위치 오차 상한은 약3mm다. 완전한 메쉬 접촉·충돌 증명은 아니다.
- 실제 Play 17초 잡기·18.5초 파괴 렌더에서 확대 실루엣과 손 위치를 확인했다. IsReady=true·23초·FOV40·콘솔 오류0. 처음부터 재생 복구 완료. 레퍼런스의 폭풍 바다·역광·물보라는 아직 별도 후속이다.

## 남은 일과 차단 조건
- 최신 사용자 피드백 반영: 부분 확대 버전의 몸 비율이 맞지 않아 해당 Spine/Head/촉수 개별 확대와 Forearm 역보정을 모두 철회했다. 원본 FBX 클립에서 다시 파생하여 보스 본체·리그의 루트만 같은1.4배로 확대했다. 등대 중간 잡기 영역을 확대 기준점으로 삼았고 등대 자체 크기는 유지했다. 손도 같은1.4배로 커지므로 이전의 손 크기/위치 보존 검증은 이 최신 버전에 적용하지 않는다.
- 최신 균등 확대 검증: 7시점×118본에서 원본 포즈를1.4배 균등 변환한 기대 위치와 최대오차2.86mm(임시 모델 기준), 본별 localScale 차이 최대7.28e-7을 확인했다. 실제 Play17초 잡기 렌더 확인·콘솔 오류0. 공용 Timeline의 같은 파생 클립을 갱신하여 본편도 같은 비율을 사용한다. 최종 크기86,694,431바이트. 카메라는 FOV40 기존 구도 유지, 사용자 시각 확인 대기.
- 사용자 테스트 씬 시각 확인 후 본편 전체 흐름·원격 동기 재생 확인.
- 특수 결과 잠금·승패 최종 확정은 R09·K01의 후속 계약이 필요하다. 이번 구현은 결과를 자동 확정하지 않으며 BossPhase의 특수 연출 대기 상태를 임의 완료하지 않는다.
