# 최후 전투 촉수 연결 계획
작성자: 박태욱
작성일: 2026-10-30
상태: 조사·구현 계획 작성, 런타임 미변경

## 최신 확정 방향
- 2026-10-31 구현 후속: [7단계](../2026-10-31/소환연출-7단계-주변촉수-배공격.md) 서버 박스 판정·다섯 촉수 상태/시각 동기화 연결 및 M1 격리 검증 완료. 아래 구현 전/미정 표기는 당시 이력이며, 현재 구현·남은 범위는7단계 원문과 최신 사용자 결정을 따른다.
- 2026-10-31 사용자 후속 결정: 주변 촉수는 메쉬 크기에 맞춘 BoxCollider 범위·설정 가능한 피해량·애니메이션 타이밍에 맞춘 조절 가능한 재생 속도를 사용한다. 빈 배 제외, 안전지대 무시, 범위 내 유효 배 모두 피격. [확정 원문](../../design/final-battle-summon-cinematic-decisions.md#주변-촉수-배-공격-결정--2026-10-31). 기존 계획의 W17 미정 표기는 이 범위에서 대체한다. 실제 타격 활성 구간·본 추종 방식은 구현 전 클립 확인 대상이다.
- 코드 대조: BoatMonsterTarget.IsEligible은 탑승·비난파 조건을 이미 검사하고 안전지대는 별도 IsInSafeZone이다. 기존 TryApplyDamage API를 소비할 수 있으며 일반 몬스터 안전지대 필터를 주변 촉수에 적용하지 않는다. 이번 후속은 정책 기록·코드 조사만 수행했고 런타임 구현은 하지 않았다.
- 사용자가 [소환 연출 결정](../../design/final-battle-summon-cinematic-decisions.md)을 확정했다. 현재 씬 유지, 전체 시간 정지 없음, 월드·배 물리 진행 유지, 연출 중 플레이어/배 피해 보호, 이미 난파·구조 대기 중인 관련 타이머만 별도 정지·재개.
- 등대 감기·주변 등장은 Timeline 연출로 재생하고 카메라 복귀 후 공격을 시작한다. 아래 전체 일시정지 범위 조사는 검토 이력이며 구현 대상에서 제외한다.
- 배의 지형 걸림은 테스트에서 확인하며 자동 이동/복구는 추가하지 않는다. 이번 갱신은 결정 기록이며 런타임 구현·검증은 하지 않았다.

## 목표와 확인된 결정
- 최후 전투 시작 시 등대 감기 촉수와 주변 채찍 촉수가 등장한다.
- 등대 촉수는 기존 서버 피해 시점에 조이는 동작을 맞춘다. 사용자가 수리 진행도 감소가 아니라 기존 등대 HP 감소라고 확인했다.
- 주변 촉수는 배를 공격한다. 테스트 배치 5개는 시각 확인용이며 최종 수량·사거리·피해량·주기는 아직 확정하지 않았다.

## 현재 구현과 연결 공백
- `BossTestEnvironment.BeginBattle`: TowerMatchNet.FinalBattle 확인, 소환 공격력 서버 고정, 감기 시작 시각과 클립 지속시간 동기화.
- `DealPeriodicDamage`: 감기 완료 → 공격 간격 대기 → 공격 시작 시각/순번 동기화 → SqueezeDuration × DamageNormalizedTime 경과 → TowerMatchNet.ApplyDamage → 다음 주기.
- `TentacleAnimationView`: NetworkTime으로 Climb/Wrapped/Squeeze 상태와 normalizedTime을 직접 계산한다. Animator speed=0. 자동 Animator 전환만으로 동작하지 않으며 Animation Event에서 피해를 추가하면 중복 위험이 있다.
- `TowerTrialRound.Attack`: BeginBattle 유일한 코드 호출자(검색한 Assets/01.Scripts 범위). 보스 참조가 없으면 대체 주기 피해를 직접 준다. 새 연결과 이 대체 경로를 동시에 켜면 안 된다.
- `TowerMatchFlow`: SummonApproved → TryBeginFinalBattle. 공격력은 등대에 전달하지 않는다. FinalBattleStarted에서 기한 중지 등만 처리한다.
- `TowerMatchNet`: 현재 수리도/모듈 유지, 고정 최대 HP로 시작. 피해는 HP만 차감한다. 완성 시 시민 승리, HP0 시 마피아 승리.
- 현재 테스트 씬에서 BossTestEnvironment/TentacleAnimationView/TowerMatchNet/NetworkManager는 모두0개. 현재 프리팹은 시각/Animator 프리뷰이며 서버 전투 연결이 아니다.
- `MonsterBoatTarget.Targets`와 `BoatMonsterTarget.TryApplyDamage` 재사용 가능. 기존 IsEligible은 탑승 중이고 난파하지 않은 배만 허용한다.

## 기획·코드 대조
- R08/R09/R10 기준 문서는 소환 HP 환산·새 수리 진행도를 설명하지만, 김지훈 2026-10-22 작업 원문과 현재 TowerMatchNet은 수리도 승계·고정HP 안이다. 문서 동기화가 남아 있으며 이번 계획은 현재 HP API를 유지한다.
- BossTestEnvironment에는 고공격력 특수 종료 경로가 남아 있다. 김지훈 작업 원문은 이를 사용하지 않는 안이므로 실제 본편 설정 확인 후 기존 특수 경로를 임의 재활성화하지 않는다.
- W17 보스/소환의 안전지대 예외는 미결정이다. 주변 촉수의 탐지·피해에 일반 몬스터 필터를 무조건 복사하면 등대섬 주변 공격이 막힐 수 있다. 별도 정책 결정이 필요하다.

## 구현 순서
1. **시작과 종료를 한곳에서 연결**
   - Monsters/Boss의 서버 연결 컴포넌트에서 소환 공격력 스냅숏과 실제 FinalBattleStarted를 결합한다. 같은 이벤트 구독 순서에 의존하지 않고 둘 다 준비됐을 때 한 번만 시작한다.
   - 중복 시작 차단. TowerMatchNet.Ended·서버 종료·비활성화 시 주변 공격과 등대 피해 및 표현을 함께 중단한다.
   - TowerTrialRound의 대체 피해와 시작 경로는 테스트 어댑터 하나만 남겨 이중 실행을 방지한다.
2. **등대 프리팹 실전 연결**
   - 새 등대 모델을 기존 View에 연결하고 컨트롤러 상태를 Climb/Wrapped/Squeeze로 맞춘다. Wrapped는 최종 감기 자세를 유지한다.
   - 감기 시작/종료 및 조이기 시작/끝의 자세 연속성을 검증한다. 현재 테스트용 Emerge/Squeeze 컨트롤러를 실전 계약에 맞게 변경한다.
3. **피해와 조이는 자세 정렬**
   - 현재 설정 에셋: WrapDuration8.966666초, SqueezeDuration1.9666667초, AttackInterval3초, DamageNormalizedTime0.5.
   - 현재 서버 타격은 공격 시작 약0.9833초 후. 첫 피해는 소환 후 약12.95초(서버 프레임 지연 제외).
   - 새 클립 실측: 등장8.291667초, 조이기3.625초, 주변Idle5초, 채찍공격3.708333초.
   - 우선 기존 주기와 피해 시점을 유지한다. 가장 강하게 조이는 클립 시점을 육안·본/등대 거리로 정하고 그 지점이 서버0.9833초에 오도록 앞/뒤 재생 구간을 부드럽게 재매핑한다. 단순 전체 배속은 약1.84배이므로 시각 피드백 확인 필요.
   - 새 클립 길이 그대로 설정할 경우 AttackInterval >= SqueezeDuration 검증을 만족하도록3초 주기도 변경해야 한다. 이 대안은 사용자 결정 없이 적용하지 않는다.
   - 서버 시계로 피해를1회 적용하고 Animation Event는 이펙트/사운드 용도로만 쓴다.
4. **주변 촉수 등장과 Idle**
   - 현재 최종 반입본에는 주변Idle/Attack만 있어 주변 등장 클립이 없다. Blender의 GIF_Emerge 후보를 확인·보정해 별도 반입하거나 수면 아래에서 자연스럽게 올라오는 전용 등장 클립을 만든다.
   - 등장 전 렌더·피해 비활성 → 등장 완료 후 Idle/탐색. 공통 소환 시각에서 계산하여 늦게 수신해도 중간 시점부터 보이도록 한다.
5. **주변 촉수 서버 배 공격**
   - 제안 상태: Hidden → Emerging → Idle → Windup → Strike → Recovery → Idle, 종료 시 Stopped.
   - 고정 배치 위치 기준 사거리·방향 안의 유효 배를 서버가 선택. 준비 중 목표 방향을 정하고 타격 전 확정해 회피가 가능하도록 제안한다.
   - 공격 순번·시작 시각·확정 방향/공격 지점을 동기화. 클라이언트는 동일 클립을 시간에 맞춰 표시한다. 모든 본 Transform을 네트워크로 보내지 않는다.
   - 타격 구간의 휘두르는 경로에 맞는 서버 충돌 볼륨/구간 판정으로 현재 배 위치를 검사. 매 프레임 끝 본 위치만 검사하면 빠른 공격이 배를 지나칠 수 있으므로 이전~현재 구간 sweep 및 순번별 중복피해 방지가 필요하다.
   - 맞았을 때만 BoatMonsterTarget.TryApplyDamage. 단일 대상/범위 타격, 빈 배 허용, 타깃 고정 시점, 안전지대 정책, 수량·간격·피해·사거리·주기는 구현 전/시각 시험에서 결정한다.
6. **테스트 씬 → 본편 연결**
   - 테스트 씬에 실제 TowerMatchNet·필요한 등대 모듈/설정·Mirror 시험 호스트와 배를 연결. 작은 수동 시작 어댑터로 같은 서버 진입점을 호출한다.
   - 본편에서는 실제 소환 승인/최후 전투 이벤트로 같은 진입점을 호출한다. 테스트 전용 자동 Animator 재생/피해를 제거한다.
   - 기존 등대/배 내부 API를 바꿔야 한다면 김지훈·최명기 담당 경계 안내 후 필요한 합의 확인. 우선 기존 HP·배 피해 API를 소비하는 Monsters 영역으로 구성한다.

## 검증 계획
- 전투 전 촉수 숨김, 시작1회, 동시 등장 및 종료/비활성화 후 피해0.
- 등대 공격마다 HP 정확히1회 감소, 수리 진행도 불변. 조이기 최대 자세와 피해 로그 시각 비교.
- 감기 완료 후 대기, 반복 공격, 마지막 HP0 타격과 종료 자세, 공격 중 시민 승리 시 타격 취소.
- 주변 공격 예고→확정→타격→복귀, 빗나감/회피, 사거리 밖·난파·내림·종료 대상, 복수 콜라이더 중복 방지.
- 호스트와 원격 최소1명에서 타격 시점·방향·진행 상태 비교, 지연/뒤늦은 상태 수신, 호스트 이중피해 방지.
- 현재 조사에서는 코드를 읽고 Unity 씬 컴포넌트 수·클립 길이만 조회했다. 실전 연결/멀티플레이 시험은 수행하지 않았다.

## 후속 조사 — 소환 Timeline 동안 전체 게임플레이 정지 범위
- 사용자는 소환 승인 후 Timeline으로 등대 감기·주변 촉수 등장을 보여주고, 종료 뒤 공격/HP 감소를 시작하는 흐름을 설명했다. 아직 구현하지 않았다.
- `Time.timeAsDouble`: InteractionSessions의 시작/완료, 일부 대포 표시. scaled time을 멈추면 대기 자체는 정지하지만 Update/명령 처리까지 자동 중단되는 것은 아니다.
- `NetworkTime.time`: 월드 NetworkClock, 대포 재장전/포탄 수명, 대쉬 지속/쿨다운, GatheringFever 지속, 난파 복구 기한, 투표/확인 규칙 입력 시각, 보스/몬스터 표현 타이밍. 네트워크 시계 자체를 멈추지 않고 gameplay clock 또는 기한 보정으로 분리해야 한다.
- `WaitForSecondsRealtime`: 등대 보스 피해 루프. 단순 timeScale0에도 진행하므로 시작을 Timeline 종료 뒤로 옮기고, 진행 중 일시정지도 지원하려면 대기 방식 자체를 연동한다.
- 월드 IClock 소비는 OceanShaderBridge/WaterSamplerHost 등 해양 표시와 샘플에도 연결돼 있다. 바다 물리만 정지하고 IClock을 계속 흘리면 재개 시 파도 위상이 바뀔 수 있어 같은 시간 기준으로 정지·재개해야 한다.
- 연결 대상: 공통 서버 정지 상태/게임 시간, 플레이어·배 입력/물리/능력/대포/난파복구, 상호작용 세션과 서버 요청 검증, 몬스터 AI/투사체/피해/상태시간, 월드 낮밤/날씨/파도/유령선/스폰, 등대·보스, 관련 UI·오디오·카메라 복구.
- 새 행동은 클라이언트 입력 차단과 별도로 서버에서도 거절해야 한다. 진행 중 작업은 남은 시간을 보존하거나 명시 취소하는 정책이 필요하다. 재개 시 누적 만료·일일 이벤트·피해가 한꺼번에 실행되지 않게 한다.
- 소환 순간 심해는 FreezeForSummon 경로가 있고 의식 타이머도 최후전투 전환에서 제거된다. 이를 무조건 재개 가능한 타이머로 바꾸지 않는다. 이미 끝난 작업/소모한 권리는 그대로 유지한다.
- 계속 실행할 범위: Mirror 통신·연결 감시·종료/타임아웃, Timeline/연출카메라/연출용 촉수 Animator/연출 음향. UI unscaled 애니메이션은 모두 변환하는 대신 연출에서 보일 UI만 선별한다.
- 담당: 김지훈 공통 Network/Interaction/Lighthouse, 강민서 World, 최명기 Player/Systems/UI, 박태욱 Monsters/Mafia. 현재는 조사·범위 제안이며 타 영역 수정은 하지 않았다.
- 권장 단계: 공통 정지 계약 → 이동/피해/요청 차단 → 기한·쿨다운·월드시간 정지 연동 → 연출·복구 → 호스트/원격 경계 시험. NetworkTime 일괄 치환이나 timeScale 단독 적용으로 완료 처리하지 않는다.
