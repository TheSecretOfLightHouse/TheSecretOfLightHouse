# 소환 연출 Additive 후속 계획
작성자: 박태욱
작성일: 2026-10-30
상태: 계획, 구현 전

진행: [4단계 기반 구현](소환연출-4단계-Additive-전환.md)과 로컬 검사 완료. 아래5~8단계 실제 연출/전투/원격 통합은 남아 있다.

후속: [5단계 Timeline](소환연출-5단계-Timeline.md)12초1차 연출과 로컬 재생 확인 완료. 6~8단계 메인 전투/배 공격/원격 통합은 남아 있다.

## 기준
- 1~3단계 서버 보호·난파 복구 시계는 유지한다. 메인 월드를 계속 진행하고 별도 표시 전용 씬을 추가 로드한다.
- 기존 임시10초 자동 보호 해제로는 비동기 로드·복귀를 안전하게 보장하지 못한다. 이를 실제 연출 단계와 서버 종료 계약에 맞추는 작업을 먼저 한다.

## 4. 연출 씬 로드·복귀 기반과 입력 처리
- 제안 서버 상태: Preparing → Playing → Returning → Combat, 중단 시 Cancelled. 소환 순번과 시작 시각을 동기화하고 중복/과거 응답을 무시한다.
- Preparing부터 보호 및 복구 타이머 정지 적용. 클라이언트는 Additive 비동기 로드·연출 전용 계층/카메라 준비 상태만 응답한다. 준비 응답으로 HP/승패를 정하지 않는다.
- 서버는 현재 참가자 준비 상태와 제한시간을 바탕으로 공통 재생 시작 시각을 정한다. 로딩/클라이언트 응답을 무한 대기하지 않는다.
- 후속 사용자 확정: 연출 로딩 실패자는 개인 연출만 생략하고, 나머지 참가자는 정상 재생한다. 실패자도 서버가 정한 공통 전투 시작 시점까지 피해 보호·입력 잠금을 유지한다. 실패한 추가 씬/카메라 정리 후 메인 화면을 유지·복구하며 개인 실패 응답으로 전원 보호를 해제하지 않는다. 지연된 로드 완료가 뒤늦게 화면을 빼앗지 않도록 한다.
- 실제 연결 해제는 연출 로딩 실패와 구분하고 기존 판 종료 규칙을 따른다.
- 플레이어 새 이동·가속·조향·공격·상호작용 입력을 막고 기존 조작 입력을 초기화한다. 서버에서도 새 행동 요청을 거절한다. 관성·부력·파도·월드 물리는 유지한다.
- 후속 사용자 확정: 입력·UI 클릭을 차단하되 메뉴와 진행 중 작업을 일괄 닫기/취소하지 않는다. 서버가 연출 시작 전에 이미 승인한 작업은 기존 유효성/거리/대상 조건에 따라 계속 진행한다. 연출 시작 후 서버에 도착한 새 행동 요청은 거절한다. 난파·구조 대기 타이머/복구 완료 보류는 별도 예외로 유지한다.
- UI가 연출을 가리지 않도록 필요한 표시만 잠시 숨기고 기존 표시/카메라 상태를 복구한다. 플레이어 카메라의 Transform은 이동하지 않는다.
- 연출 씬은 메인과 분리된 공간/레이어로 구성하고 전용 카메라가 메인 객체를 찍지 않게 한다. 복제 섬 Collider/물리/AI/NetworkIdentity를 제거 또는 비활성화하며 AudioListener는 하나만 활성화한다. 조명/Volume/오디오가 메인에 영향을 주지 않도록 검증한다.
- Returning에서 메인 렌더링/입력/UI를 복구하고 비동기 unload 완료와 실패 정리를 처리한다. 서버가 복귀 정책에 따라 보호 종료·전투 개시를 한 번만 결정한다. 개인 Timeline stopped 콜백이 전체 서버 보호를 바로 해제하지 않는다.

## 5. 표시 전용 씬과 Timeline 제작
- 새 소환 연출 씬: 등대섬·등대 촉수·주변 촉수 표시 복제본, 연출 카메라, PlayableDirector, Timeline, 음향/이펙트.
- 등대 감기·주변 등장·마무리 샷을 구성한다. 주변 등장 클립은 현재 최종 반입본에 없으므로 제작/반입한다.
- 서버 시작 시각에서 경과 시간을 구해 로딩 지연에도 같은 구간을 재생한다. 늦은 진입/연출 종료 후 로드 완료 시 불필요한 처음부터 재생을 막는다.
- 연출 길이·복귀 여유를 서버 설정과 일치시키고 임시10초를 교체한다.

## 6. 메인 실제 촉수와 등대 피해 연결
- 연출 중 메인 실제 촉수는 숨기거나 공격 비활성화한다. 복귀 전에 실제 등대 촉수를 감기 완료 자세, 주변 촉수를 Idle 자세로 준비한다.
- 메인 촉수와 연출 복제본이 동시에 노출되거나 복귀 후 다시 감기 시작하지 않게 한다.
- 공통 Combat 시점 후 기존 서버 공격 주기를 시작한다. 조이기의 최대 압박 자세가 실제 HP 피해 시점과 맞도록 재매핑한다. 기존 보스의 감기 대기를 중복 적용하지 않는다.

## 7. 주변 촉수 배 공격
- 서버 표적 선택·예고·방향 확정·타격 경로 검사·순번별 중복 피해 방지·복귀. 기존 배 피해 API 재사용.
- 수량/사거리/주기/피해, 단일·범위 타격, 안전지대 정책은 별도 결정. Timeline 복제본에는 공격 로직을 넣지 않는다.

## 8. 통합 검증
- 항해·전투·채집·메뉴·난파/구조 대기에서 각각 진입/복귀. 배 위치·속도 연속성과 피해/타이머 보존 확인.
- 호스트/원격의 로딩 속도 차이·연출 진행·복귀, 중복 응답·클라이언트 이탈·연출 중 판 종료·로드 실패 검증.
- 보호/입력 잠금/오디오/카메라/추가 씬이 종료 후 남지 않고 실제 공격이 한 번만 시작되는지 확인.
- 담당: Network/Interaction/Lighthouse 김지훈, Player/Systems/UI 최명기, Monsters/Mafia 박태욱. World 물리/시계는 현재 유지하며 원본 구매 섬 수정은 하지 않는다.
