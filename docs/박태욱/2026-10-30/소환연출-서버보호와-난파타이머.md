# 소환 연출 서버 보호와 난파 타이머
작성자: 박태욱
작성일: 2026-10-30
상태: 1~3단계 코드 구현·격리 서버 검증 완료, 원격/실전 연출 통합 대기

## 요청과 구현
- 사용자 요청: 서버 연출 상태, 플레이어·배 피해 보호, 난파·구조 타이머 정지/재개부터 구현. 월드 시간·배 물리·이동 유지. Timeline·카메라·입력 연결은 후속.
- `TowerMatchNet`에 공개 SyncVar 연출 재생 여부·시작/종료 서버 시각을 추가했다. 유효한 최후전투 전환에서 HP 초기화 후 보호를 획득하고 FinalBattleStarted를 발행한다. 기존 phase가 중복 소환을 거절한다.
- `TowerBattleSettings.SummonCinematicSeconds`는 현재 임시10초다. Timeline 제작 후 실제 길이로 설정해야 하며 최종 연출 길이 결정이 아니다. 서버 Update가 종료를 결정하고, 판 종료·비활성화·서버 종료에서도 보호를 해제한다.
- 공통 `ServerCinematicProtection`: 보호 원인별 소유권을 관리해 하나의 종료가 다른 보호를 해제하지 않게 했다. 네트워크/월드 시간은 변경하지 않고 연출 시간을 제외한 RecoveryTime을 제공한다.
- `BoatDurability.ApplyDamage`가 가장 먼저 보호를 검사한다. 피해 종류 전체에서 내구도·난파·방어막 횟수가 보존된다. 힘/위치/물리 설정은 변경하지 않았다.
- 현재 플레이어 코드에는 독립 HP 피해 경로가 없고 SetDowned/배 난파가 핵심이다. 보호 중 새 SetDowned(true)와 TryBeginRecovery를 막는다. 기존 downed 상태를 회복시키거나 무효화하지 않는다.
- `PlayerWreckRecovery`의 복구 기한·완료 재시도는 RecoveryTime으로 계산한다. 보호 중 Update/구조·시간초과 완료·후속 정산 진입을 차단한다. 기한 필드는 서버 전용으로 외부 소비자가 없음을 검색 확인했다.
- `BossTestEnvironment`와 개발용 `TowerTrialRound` 대체 피해 경로는 감기 후에도 연출 재생 중이면 공격 개시를 기다린다. 등대 ApplyDamage도 연출 중 거절한다. 기존 공격 주기/타격 수치는 유지한다.

## 실제 검증
- Unity6000.0.83f1 재컴파일 후 오류 조회0, 실제 타입 로드 확인. git diff --check 통과.
- 테스트 씬 Play에서 임시 KCP 서버(자동 할당 포트)와 실제 NetworkIdentity로 Tower/Boat를 스폰해 검사. Tower의 실제 설정·레이아웃 사용, 벤치는 비스폰 참조로 구성했다.
- 실제 TryBeginFinalBattle 첫 요청true, 중복false. 서버 보호true. 모든 BoatDamageType으로10000피해를 요청했지만 배 내구도90유지·기존Shield유지. 등대 HP도 유지.
- 복구 fixture에 서버 전용 잔여30초를 설정. 보호 중 NetworkTime 약151.005초, RecoveryTime 약101.570초로 고정. 구조/시간초과 완료 거절, downed 플래그 신규 설정 차단.
- 종료 기한을 시험용으로 앞당겨 실제 Tower.Update 종료 경로 실행. 보호/재생 상태 해제, 복구 잔여30초 그대로 유지. 이후 방어막은 정상 소모, 다음 배 피해10 적용(90→80), 등대 HP10감소 확인. 뒤에 다시 조회했을 때 복구 시계가 정상적으로 계속 진행함을 확인했다.
- 판 종료 시 자신의 보호만 해제하고 다른 소유자가 있으면 유지, 마지막 소유자 해제 후 전체 보호false 확인.
- 초기 테스트 fixture를 활성 상태에서 동적으로 구성해 다단 RequireComponent의 NetworkIdentity가 누락되면서 NullReference 및 실패 결과가 발생했다. 제품 구현 통과로 세지 않았다. 비활성 GameObject에 NetworkIdentity/모든 컴포넌트를 먼저 구성한 뒤 활성화·스폰하여 재검증했다. 비활성 holder를 GameObject.Find로 찾은 시험 코드도 수정 후 다시 검사했다.
- 임시 객체 제거·NetworkServer.Shutdown·Play 종료. 서버false, 보호false 확인. 테스트 씬 파일은 저장하지 않았다.

## 미검증과 다음 단계
- 별도 원격 클라이언트와 실제 판 소환·배 항해 중 충돌·난파 상태 전체 복구/아이템 정산은 아직 검증하지 않았다. 복구 타이머 검증은 서버 전용 상태를 주입한 격리 검사이며 전체 난파 시나리오 통과가 아니다.
- Timeline·카메라 복귀·입력 잠금·보호 여유 시간은 미구현. 현재는 임시 설정시간 종료 직후 보호 해제한다. 실제 연출을 붙일 때 서버 종료 시점과 카메라 복귀 시점을 맞춰야 한다.
- 이미 진행 중인 구조 상호작용의 UI/작업 취소 처리는 4단계 연결에서 다룬다. 보호 중 실제 복구/정산은 거절한다.
- 보호 중 몬스터의 추격·투사체·월드·쿨다운은 계속 진행한다. 새 독립 플레이어 HP 시스템이 생기면 해당 피해 진입점도 같은 보호를 소비해야 한다.
- 새로운 테스트 씬에는 TowerMatchNet이 없어 보호가 자동 실행되지 않는다. 기존 실제 TowerMatchNet 경로에는 코드로 연결됐으며, 시각 테스트 씬의 네트워크 시험 구성은 후속 통합 대상이다.
