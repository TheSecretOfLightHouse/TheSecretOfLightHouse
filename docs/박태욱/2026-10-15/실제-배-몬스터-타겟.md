상태: 완료(사용자 검증 확인)

## 요청과 목표
- 실제 배의 상태·내구도에 연결하는 BoatMonsterTarget 구현. 연결 성공 후 SeaMonsterTestTarget 삭제.
- 사용자 확정 조건: 활성 상태이며 난파되지 않았고 플레이어가 탑승 중인 배. 별도 섬·안전 구역 판정은 추가하지 않는다.

## 진행 과정과 결정 이유
- 2026-10-15: 기존 센서는 Inspector 배열만 탐색하고 실제 배 연결 구현은 없음을 확인했다. ActorID는 탐지 조건이 아니다.
- 기획 v4 §5.3의 서버 AI와 NETWORK_AUTHORITY §4의 소유 클라이언트 이동을 유지한다. N07의 물리 판정 합의·원격 실행 검증과 이번 연결 구현은 구분한다.
- BoatController·BoatDurability 코드를 변경하지 않고 몬스터 영역 연결 컴포넌트에서 기존 API를 사용한다.
- MonsterBoatTarget을 NetworkBehaviour로 변경해 서버 생성 시 등록, 서버 종료·비활성화·제거 시 해제, 재활성화 시 중복 없이 재등록한다. Play 진입 시 정적 목록도 초기화한다.
- 센서의 Targets API는 유지하고 공용 목록을 반환하게 해 기존 돌진의 등록 검사·구간 명중 검사도 같은 목록을 사용한다.

- Assets/01.Scripts/06.Monsters/AI/Server/Shared/BoatMonsterTarget.cs 및 .meta: 실제 배 연결, 서버 피해 적용, 설정 가능한 HitRadius(기본 0.75).
- 같은 폴더 MonsterBoatTarget.cs: 서버 대상 수명 관리.
- 같은 폴더 SeaMonsterSensor.cs: 수동 배열을 제거하고 공용 목록 사용.
- Assets/02.Prefabs/Player/Cube.prefab: 에디터 API로 BoatMonsterTarget 추가. 기존 NetworkIdentity assetId 보존.
- Assets/00.Scenes/TaeWook/MonsterBehaviorTestScene.unity: 에디터 API로 기존 시험용 컴포넌트 두 개 제거. 남은 시험용 물체는 배 타겟으로 동작하지 않는다.
- Assets/01.Scripts/06.Monsters/AI/Server/Testing/SeaMonsterTestTarget.cs 및 .meta 삭제. Assets 코드·씬·프리팹에서 타입명과 GUID 참조 검색 결과 없음.
- 기존 사용자 변경(VotingTestPlayer, MonsterCollisionTestScene, BlueMarline 모델·프리팹 등)은 보존했다.

## 검증
- Unity 6000.0.83f1의 현재 MonsterCollisionTestScene에서 호스트 실행. ActorID 1인 tech 플레이어 소유 Cube 배가 자동 등록되고 미탑승 시 제외됨을 확인.
- 활성화 토글 시 목록 해제·중복 없는 재등록 확인.
- RequestBoard 호출은 같은 호출 내 반환값으로 완료를 판단할 수 없었다. 네트워크 처리와 이후 상태 변경을 구분하기 위해 Play를 일시정지하고 기존 서버 TryBoardCore를 reflection으로 호출해 통제된 상태를 만들었다.
- 실제 Player.CurrentBoat 연결, IsOccupied, IsEligible, 센서 TryAcquireTarget·CanTrack 성공 확인.
- 연결 컴포넌트의 TryApplyDamage(7)로 실제 내구도 90 → 83 확인. 추가 치명 피해로 난파·대상 제외·추가 피해 거부·소유 플레이어 다운 확인.
- 미탑승 상태 피해 및 NaN·음수 피해 거부 확인. 서버 StopHost 뒤 대상 수 0 확인. 에디터를 Edit 모드로 복귀.
- 이 검증은 M1의 통제된 API 검사다. 사용자 입력부터 돌진 명중까지 전체 경로, 원격 클라이언트 M2, 정상 하선·재탑승 회귀는 미검증이다.
- 기존 BuoyancyBody의 WaterSamplerHost 누락/샘플 슬롯 경고가 관찰됨. 이번 작업에서 월드/부력 코드는 변경하지 않았다.

## 남은 일과 차단 조건
- 2026-10-16 사용자 확인: 전체 공격 흐름과 클라이언트 플레이어 피격 반동을 확인했다. 이전의 전체 흐름·클라이언트 반동 검증 대기는 해소한다. 이번 세션에서 AI가 직접 재실행한 검증은 아니다. 개별 세부 항목의 별도 실행 로그는 추가로 제공되지 않았다.
- 돌진 애니메이션과 실제 돌진 지속시간의 타이밍 조정은 사용자 결정에 따라 폴리싱 단계로 이관한다. 현재 기능 완료의 차단 조건으로 두지 않는다.
- 배 크기 변경 시 HitRadius 조정. 기본값은 기존 시험용 값을 유지했으며 밸런스 확정이 아니다.
