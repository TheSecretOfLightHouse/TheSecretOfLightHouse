## 요청과 목표

## 진행 과정과 결정 이유
- 현재 코드·프리팹·미커밋 차이를 읽었다. 기존 Angler 프리팹/프로필 등 사용자 변경은 보존했다.
- Angler의 모델 루트 로컬 위치가 (0,0,-0.48)에서 (-14.03,0,-11.95), 배율이 3에서 4로 변경돼 있다. 수평 오프셋은 약18.4m다. 캡슐 중심은 (0,0.4,-0.3)이다. 루트가 회전하면 외형이 큰 원호를 그리므로 빠른 공전처럼 보일 수 있다.
- AnglerDisguiseView는 루트와 로컬 플레이어 거리10m로 공개 여부를 판정한다. 시각 모델 위치와 판정 위치가 어긋나고 경계 히스테리시스가 없다.
- MonsterWaterBody 기본 수심2m, 위장 배 루트 높이는0.48이다. 수중 잠김이 위장 배 가시성에도 영향을 줄 가능성이 있다.
- 평소 Anglerfish 재질은 Opaque, 페이드 중에는 Transparent 큐3000/ZWrite0으로 교체된다. ClearOcean은 Transparent-10(2990)/ZWrite Off이므로 페이드 중 수중 외형이 바다 위에 그려질 가능성이 있다. 실제 메인씬 렌더 재현 전까지 가설로 유지한다.
- TrackingAttack 속도7, 후퇴 속도15다. 실제 이동 속도 차이도 존재하지만 관찰된 고속 회전의 확정 원인으로 단정하지 않는다.
- review-design-code-gaps 스킬 적용. v4는 일반 몬스터의 순찰/배 공격을 정하며 아귀 위장 세부 수치는 검색한 현행 문서에서 확인되지 않았다. W17은 일반 몬스터 안전지대 제외 부분 결정/Play·M2 미검증이며 이번 외형 문제를 설명하는 항목은 아니다.

## 2026-10-31 Unity MCP 실행 중 후속 조사
- 사용자 요청으로 MCP 연결 확인 후 MainGame Play 상태를 읽었다. 연결 인스턴스는 TheSecretOfLightHouse@5879544077c33f11이며 실행 중 아귀4마리를 조회했다. 스크립트·게임 상태 수정 없이 메모리 조회와 화면 캡처만 수행했다.
- 샘플에서4마리 모두 _hasPresentation=true, _blend=0, _isRevealed=false. 위장 배의 MeshRenderer는 active/enabled=true, Opaque 큐2000, _BaseColor 알파1이었다. MaterialPropertyBlock도 없어 알파0에 의한 비가시성 근거는 없다.
- 실제 부력 MeanDepth는1.94~1.99m, 선체 bounds 최대Y는 약-0.69~-0.95였다. 위장 배까지 수중에 잠겨 있는 상태를 확인했다. 위치/높이는 실행 시점 표본이다.
- 실행 중 바다41개 Renderer의 ClearOcean 재질 큐는2990이었다. 페이드 코드는3000으로 바꾸므로 페이드 중에는 바다 뒤에 그리는 순서가 확인된다. 전환 순간 연속 캡처/비교 실험은 미실행이므로 깜빡임의 완전한 인과 검증은 남는다.
- Game 화면 캡처 성공: Captures/AnglerDiagnosis/screenshot-20261031-145219.png. 당시 플레이어 배는 이미 난파 상태였다. 사용자 플레이를 재시작하거나 이동시키지 않았다. 콘솔 error 최근 조회0건.
- 현재 모델 bounds는 루트 근처로 조회돼 이전18.4m 이격 상태가 그대로 남아 있다고 판단하지 않는다. 사용자 수정 이력과 구분하며 이번 조사에서 프리팹은 수정하지 않았다.
- 후속 권장: 수중 몸체와 수면 위장 배의 높이 표현을 분리하고 페이드의 수면 가림 처리를 일관되게 설계한 뒤, 10m 경계 접근/이탈과 원격M2를 검증한다. 게임 규칙/수심을 임의 변경하지 않았다.

## 2026-10-31 승인된 위장 배 수면 분리 수정
- 사용자 요청: 물리/수심은 루트에 유지하고 위장 배 외형만 수면을 따르게 수정.
- AnglerDisguiseView에서 Awake에 원래 위장 배 로컬 위치를 저장하고, 클라이언트 LateUpdate에서 기존 IWorldQuery.SampleWaterHeight를 사용해 위장 배의 월드Y만 수면+원래 높이 오프셋으로 배치한다. XZ/회전/배율은 기존 부모 변환을 따른다. 매 프레임 기준 위치를 다시 계산해 누적 상승을 방지한다.
- World 조회 미등록/유효하지 않은 수면 값은 위치 갱신을 건너뛴다. OnDisable 때 원래 로컬 위치를 복원한다. 새 물리체·컴포넌트나 프리팹 직렬화 변경은 없다. 기존 공개거리10m·페이드시간·몬스터수심2m·공격/충돌/네트워크 권위는 유지한다.

- 검증: Unity 컴파일 완료 및 콘솔error0. 실제 Angler 프리팹을 저장하지 않는 PreviewScene에 로드해 평면 수면 mock으로 루트깊이0/2/5m×yaw0/90/180도9조건에서 수면 위 원래 높이0.48m, 루트/물고기 위치 유지, 반복10회 누적변위0 확인. OnDisable 위치복원·World 서비스 미등록 시 위치유지 확인. 임시 인스턴스/서비스/PreviewScene은 finally에서 정리했다.

## 2026-10-31 정체 공개 시 몸체·피격체 부상
- 사용자 요청으로 공개 때 외형만이 아니라 물리 루트도 부상하도록 추가했다. AnglerDisguiseView의 서버 FixedUpdate가 준비된 연결의 플레이어 identity들을 검사하고 기존 수평 공개거리 안에 한 명이라도 있으면 BuoyancyObject 목표수심을 Revealed Depth(초기0.1m)로 바꾼다. 실제 상승은 기존 부력이 담당하고 Rigidbody/콜라이더를 옮기거나 분리하지 않는다.
- 로컬 클라이언트의 시각 상태를 공유 물리 판정에 쓰지 않는다. 호스트/원격 모두 서버가 관찰한 identity 위치를 사용하며 기존 공개 외형은 관찰자별로 유지한다. 범위에 아무도 없으면 RestoreDefaultDepth, 살아 있는 상태에서 컴포넌트 비활성 시에도 기본값 복원. 사망·미초기화·비활성 WaterBody는 서버 갱신 제외.
- 현재 사용자 프리팹의 _defaultDepth가0으로 바뀌어 있었다. 이 값을2라고 가정한 첫 격리검사는 기대값 불일치로 실패했다. 현재 설정을 확인하고 보존한 뒤 기본수심0/2 모두에 대한 검사를 수행했다. 0은 SetTargetDepth API상 목표수심제어 해제(-1), 양수는 목표수심이다. 위장 때2m 잠김을 원하면 프리팹 기본수심을2로 설정해야 한다.
- 검증: 컴파일 완료·콘솔error0, PreviewScene 실제 프리팹 기반 기본수심0/2×거리11/10/5/10.01m 8조건에서 공개 시0.1/이탈 시기본값 복귀 확인. 높이차30m에서도 기존 수평거리 판정 유지, 미준비·identity없음·접속자없음 제외, 루트 순간이동0·루트캡슐 유지 확인. 임시 연결/오브젝트/PreviewScene은 finally 정리. diff --check 통과.
- 미검증: 실제 파도에서 상승시간/안정성·대포 실탄 명중/피해·원격M2. 현재 에디터 MainOffline 편집상태에서 검증했으며 실제 부상/포격을 통과했다고 주장하지 않는다. 프리팹·World/Player 코드 수정 없음.
