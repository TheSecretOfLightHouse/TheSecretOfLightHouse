# 소환 연출 7단계 — 주변 촉수 배 공격
작성자: 박태욱
작성일·갱신일: 2026-10-31
상태: 구현됨(로컬 호스트 격리 검증, 실제 본편·원격 검증 대기)

## 요청과 목표
- [사용자 확정 규칙](../../design/final-battle-summon-cinematic-decisions.md#주변-촉수-배-공격-결정--2026-10-31): 메쉬 크기 BoxCollider, 피해량 설정, 애니메이션 속도에 맞춘 주기, 빈 배 제외, 안전지대 무시, 범위 내 유효 배 모두 피격.
- 기존 다섯 촉수의 크기·위치·방향을 유지한다. HUD 오류와 이전 에셋 정리는 보류한다.

## 구현과 판단 이유
- 실제 공격 클립3.708333초를241시점에서 BakeMesh로 샘플링해 배치 부모 좌표의 메쉬 Bounds를 에셋에 저장했다. 서버는 렌더링이나 클라이언트 애니메이션 이벤트를 피해 근거로 사용하지 않는다.
- 각 촉수의 전체 공격 Bounds에 탑승·비난파 배가 있으면 해당 촉수만 공격한다. 현재 배치 방향을 유지하는 고정 휘두르기이며 자동 조준·회전은 추가하지 않았다.
- 공격 상태(순번·서버 시작 시각·재생 속도)를 촉수별로 동기화한다. 속도와 피해량은 공격 시작 시 고정하며 속도 변경은 다음 공격부터 적용된다. 추가 쿨다운 없이 클립 종료 후 범위에 대상이 남으면 다음 공격을 시작한다.
- 타격 구간에 해당하는 시점별 BoxCollider로 Physics.ComputePenetration을 검사한다. 건너뛴 샘플도 검사하고 인접 메쉬 Bounds를 합쳐 휘두름 사이 경로를 포함한다. BoxCollider는 쿼리 동안만 켜고 finally에서 꺼 물리 스텝의 충돌/트리거 동작에 끼어들지 않는다.
- MonsterBoatTarget 등록/해제 이벤트로 실제 배 콜라이더를 즉시 캐시한다. 프레임마다 GetComponent/배열 할당을 하지 않는다. 난파·제거 중 다른 배를 건너뛰지 않도록 역순 순회한다.
- 타격 시에도 IsEligible을 재검사한다. 빈 배·난파 배 제외, 안전지대 필터 없음. HashSet으로 촉수별 한 공격에서 배당1회로 제한한다. 여러 촉수의 서로 다른 공격은 각각의 타격이다.
- 서버가 기존 BoatMonsterTarget.TryApplyDamage→BoatDurability API를 소비한다. 배 코드·방어막·연출 보호 정책은 변경하지 않는다.
- 공통 연출 복귀와 기존 등대 보스의 NormalBattleActive 이후 시작한다. 승패 확정·서버/컴포넌트 중단 시 판정 중단, 클라이언트는 종료 시각의 자세를 유지한다.

## 설정과 주요 파일
- `Assets/02.Prefabs/Monsters/Data/WhipTentacleSettings.asset`: Damage10, AttackSpeed1, HitStart0.25/HitEnd0.7. 사용자 확정 밸런스가 아닌 조절 가능한 시험값이다. 공격 길이/속도로 주기가 결정된다.
- 설정의 메쉬 Bounds 배열은 생성 데이터라 Inspector에서 숨긴다. 촉수 배치 부모의 스케일·회전은 박스에도 적용된다. 메쉬/공격 클립 자체가 바뀌면 Unity 에디터 API로 Bounds를 다시 생성해야 한다. 이번 생성은 Unity MCP execute_code로 수행했다.
- `Rules/WhipTentacleSettings.cs`, `Rules/WhipTentacleAttackState.cs`: 설정·241시점 Bounds·공개 공격 상태.
- `Net/WhipTentacleBattleNet.cs`: 서버 탐지·타격·중복 방지·시각 동기화.
- `View/WhipTentaclePresentation.cs`: 같은 촉수 객체에 서버 시각 기반 Idle/Attack 표시.
- `AI/Shared/Server/Targets/MonsterBoatTarget.cs`: 등록/해제 이벤트 추가. 기존 일반 몬스터 안전지대 규칙은 유지한다.
- `Tower/View/SummonCinematicView.cs`: 로컬 Rig와 주변 촉수 네트워크 제어 연결.
- `MainSceneSummonRig.prefab`: 표현 컴포넌트·다섯 Animator·쿼리용 BoxCollider.
- `World/MainIsland/MainIslandLighthouse.prefab`: WhipTentacleBattleNet·설정 연결.
- 프리팹·SO는 Unity API로 저장하고 새 스크립트/에셋 meta는 Unity에서 생성했다. 기존 사용자 VFX·World meta 변경은 보존했다. 씬은 저장하지 않았다.

## 실제 검증
- Unity 컴파일 오류0, 코드 diff 공백 검사 통과, 프리팹 재조회: 촉수5개·IsReady=true·등대 네트워크 컴포넌트 존재.
- 실제 KCP 로컬 호스트의 로비에 실제 등대/작업대/배/Rig 프리팹과 임시 투표 fixture를 생성했다. 투표 공격력 동결 후 실제 TryBeginFinalBattle/연출 복귀를 사용했다. 정상 로비→맵 생성→승인 전체 통합 경로는 아니다.
- 배의 탑승/난파 플래그는 fixture에서 reflection으로 설정했다. 실제 플레이어 승선 입력·보행/배 물리 시험으로 확대하지 않는다. 피해·난파는 실제 BoatMonsterTarget/BoatDurability를 사용했다.
- 안전지대 시험에는 기존 FlatWorldQuery(모든 위치 safe=true)를 사용했다.
- 피해10/속도1: 타격 전 배5개 HP모두100. 공격 후 탑승 배2개90/90, 빈 배100, 범위 밖100, 난파 배100. 배에 콜라이더를 추가한 조건에서도 중복 피해 없었다. 종료4초 후 동일 HP·순번1·stopped=true.
- 임시 설정 복제본 피해7/속도2: 공격 준비 중 하선한 배100 유지, 탑승 배93. 공격 주기1.8587초(클립/2 기대1.8542초). 다른 촉수4개 순번0. 다음 공격 준비 중 종료 후3초 추가 피해 없음.
- 최종 등록 이벤트/역순 순회 코드에서 피해100/속도2: 타격 전100/100/100/100, 타격 후 탑승2척0/0으로 모두 난파, 빈 배100·범위 밖100 유지. 추가 콜라이더는 스폰 전 부착해 캐시에 포함했다. safe=true 확인, 종료3초 후 순번1·HP불변.
- 공격 전체 BoxEnvelope의 최대 수평 반경15.12856, 배치 반경34와 테스트 섬 Ground_Visual 외곽 반경15.64233 기준 보수적 여유3.22911단위.
- 도구용 fixture 최초 구성에서는 직렬화되지 않은 SyncVar를 SerializedObject로 읽다가 구성 예외가 났고, reflection을 사용하는 fixture로 수정했다. 게임 코드를 변경해 우회하지 않았다.
- 초기 두 기능 시험 콘솔 오류/경고0. 최종 시험 중 Mirror.NetworkInformationPreview의 ObjectPreview.Finalize 정리 오류1개를 관찰했다. 앞선 리로드에서도 UnityEditor preview cleanup 오류가 있었으며 외부 패키지는 수정하지 않았다. 새 공격 코드의 런타임 예외는 관찰하지 않았다.
- Play 종료로 임시 fixture 제거, MainOffline Edit 모드 복귀. 영구 테스트 객체나 버튼은 저장하지 않았다.

## 남은 일과 다음 행동
- 실제 본편의 배 조작·파도 이동에서 휘두르는 모습과 명중 구간25~70%를 확인하고 시험값을 조정한다. 실제 육안 연속 재생의 피격 타이밍은 아직 미검증이다.
- 호스트+별도 원격 M2 이상에서 다섯 촉수 상태·속도·피해·늦은 바인딩·종료 자세를 검증한다. 이번 결과는 M1이다.
- 극단적인 재생 속도·지연/순간이동에서 이동 배의 연속 충돌은 미검증이다. 시점 사이의 Bounds 합집합은 보수적 박스 판정이며 메쉬 삼각형 단위 정밀 충돌이 아니다.
- 메쉬/클립 변경 시 Bounds 재생성 및 현재 실제 섬/부두와의 여유 재검증이 필요하다.
- HUD 수정은 보류, 이전 연출 씬/테스트 에셋 정리는 완성·테스트 이후다.
