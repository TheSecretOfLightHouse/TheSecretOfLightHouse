## 요청과 목표
상어가 배/플레이어를 실제 물리 충돌로 과하게 밀치는 반응을 끄고, 기존 공격 판정과 설정형 반동을 보존한다.

## 조사와 구현
- review-design-code-gaps 기존 세션 검토를 재사용하고 충돌 경로를 확인했다. TrackingAttack은 OnCollisionEnter/Stay에서 대상 배 피해를 판정하므로 레이어 충돌무시·트리거화는 공격을 깨뜨린다. N07은 배 소유 클라이언트 이동권위 부분결정이며 피해/물리 통합검증은 계속 남는다. 호스트만 처리하면 원격 소유배 물리에는 적용되지 않는다.
- BlueShark의 돌진18m/s, Recoil Source의 별도속도3/쿨다운0.3초 확인. 이번 변경은 별도속도/쿨다운/공격력/질량을 바꾸지 않는다.
- Monsters에 MonsterContactResponse 추가. 상어 CapsuleCollider의 hasModifiableContacts를 활성화하고 일반/CCD ContactModifyEvent에서 배·플레이어 Collider와의 접촉 SetMaxImpulse(0)만 적용한다. 접촉 자체와 Collision 이벤트는 유지하며 다른 지형/포탄과의 접촉은 필터 대상이 아니다. 물리적으로 상어와 배가 서로 막는 반응도 억제되는 것이 의도된 영향이다.
- 대상 Collider 목록은 서버에서는 NetworkServer.spawned, 클라이언트에서는 NetworkClient.spawned의 실제 BoatController/PlayerController 루트로 확인한다. Collider 목록을 캐시하고 목록 변경 시에만 immutable ID snapshot을 교체한다. 물리 워커 콜백은 Unity 오브젝트를 조회하지 않고 Volatile snapshot만 읽는다. OnDisable에서 구독해제·캐시해제·원래 hasModifiableContacts를 복원한다.
- BlueShark.prefab에만 컴포넌트를 에디터 API로 추가해 Suppress Physical Push=true 저장. 다른 몬스터/Player·Mirror 코드·플레이어/배 프리팹은 미변경이다. 사용자는 Inspector에서 토글로 원복 가능하다.

## 검증
- Unity reflection으로 ContactModifyEvent/CCD, ModifiableContactPair.SetMaxImpulse API 확인. 새 파일은 scripts refresh만으로 임포트되지 않아 전체 Assets 강제refresh 후 타입/컴파일 확인했다.
- 편집상태 LocalPhysicsMode 씬생성은 Play전용 API 오류로 실패했다. MainOffline을 Play로 시작해 격리 PhysicsScene에서 검사했다. 첫 검사 정리에서 편집용 CloseScene API를 써서 오류가 났고, 남은 테스트씬을 확인/UnloadSceneAsync로 정리한 뒤 올바른 정리 방식으로 비교검사를 재실행했다.
- 18m/s·동일질량·20×0.02초 실제 physics simulation: 기존 배속도9m/s/변위3.1000m/ContactEnter1, 억제시 배속도0/변위0/ContactEnter1. 접촉마커를 직접 지정한 격리 테스트로 물리효과/이벤트유지만 검증하며 실제 피해 적용을 대신하지 않는다. 테스트씬 해제 후 Play 종료해 MainOffline 편집상태로 복귀했다.
- 실제 Boat.prefab PreviewScene·임시 클라이언트spawned 등록 검사: Collider ID 수집, 변경없는 snapshot 재할당없음, 토글false→필터해제, OnDisable 원래 collider 설정복원 통과. 임시등록·오브젝트·이벤트·씬 정리.
- 마지막 콘솔error0, C# diff --check 통과. 프리팹추가 후 별도반동3 유지 재조회 확인.
- 미검증: 본편 상어 공격의 실제 피해/물림 애니메이션/포탄충돌·원격M2. 접촉이벤트존재만으로 피해판정/다인 통과를 주장하지 않는다.
