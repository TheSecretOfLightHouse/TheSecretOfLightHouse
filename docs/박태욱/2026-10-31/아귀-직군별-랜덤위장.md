## 요청과 목표
가짜 배를 기존4직군의 캐릭터·전용배 한 세트 중 무작위 외형으로 표시한다.

## 진행 과정과 결정 이유
- review-design-code-gaps 적용. 최신 직군 결정과 실제4개 PlayerController의 BoatPrefab 참조를 대조했다. N06은 일반 계약 확인 대기이며 이번 기능은 위장 외형 인덱스만 서버 공유로 구현한다. [결정](../../design/angler-disguise-decisions.md).
- 기존 캐릭터4종을 임시 PreviewScene에 로드해 boatidle0초 자세를 샘플링하고 SkinnedMeshRenderer.BakeMesh(useScale:false)로 고정 자세 메시를 생성했다. 원본 렌더러 회전(-90도X)·재질과 각 배의 BoardingAnchor를 반영했다. 실제 플레이어/배 프리팹은 수정하지 않았다.
- AnglerDisguiseView에 _boatVariants와 _disguiseIndex SyncVar 추가. OnStartServer에서 Random.Range로1회 선택하고 OnStartClient/SyncVar hook에서 해당 자식1개만 활성화한다. 기존 페이드는 모든 후보 렌더러를 캐시하며 비선택 후보는 비활성으로 남는다.
- 최초 기존 자식 삭제 후 교체 API 실행은 자동 승인 검토가 백업 없는 삭제로 거절했다. 실행되지 않았음을 파일/실행기록으로 확인했다. 안전한 대안으로 기존 가짜배 전체 자식을 LegacyDisguise 그룹에 보존/비활성화하고 새4세트를 추가했다. 중첩 FakeBoat 인스턴스는 에디터 API로 unpack했으며 원본 FakeBoat 프리팹과 GUID는 미변경이다. 사망 시 숨김 참조는 기존 가짜배 루트로 유지된다.
- 기존 아귀/다른 몬스터 수치·프리팹/폰트의 사용자 변경을 보존했다. 기본수심0과 물선오프셋-0.15도 저장 후 조회해 유지 확인.

## 검증
- 컴파일 완료 후 콘솔error0 확인. 실제 프리팹 PreviewScene 검사에서4개인덱스 각각 OnSerialize/OnDeserialize(initialState=true) 왕복 후 같은인덱스/선택외형1개 확인(각1바이트). 실제 소켓접속 검증을 대신하지 않는다.
- 랜덤 상태를 보관/복원하며 seed314159·400회 선택: Tech109/Captain101/Farm93/Tanker97, 유효4종 확인.
- 메시·재질 참조, 새4그룹의 Transform/MeshFilter/MeshRenderer 외 컴포넌트없음, Missing Script0, 사망숨김참조 유지, 레거시 보존/비활성 확인. 첫 성분검사는 비활성 레거시 Animator를 포함해 실패했고 검사 범위를 새4그룹으로 바로잡아 통과했다.
- 격리 렌더 첫 시도는 PreviewScene 컬링마스크 누락으로 배경만 나왔다. Camera.overrideSceneCullingMask를 설정해4세트 시각 확인했다. 두번의 렌더 정리에서 targetTexture 연결된 RT해제 콘솔오류가 발생했으나 finally의 PreviewScene 종료로 임시카메라/RT 정리됨. 런타임 로직 오류/컴파일오류와 구분한다.
- C# diff --check 통과. 전체diff --check는 Unity가 저장한prefab 빈문자열 필드의 trailing whitespace를 보고했다. YAML직접편집금지에 따라 수동 정규화하지 않았다.
- 실제 MainGame 페이드/파도/재소환 및 원격M2 미실행. 에디터 MainOffline 편집상태에서 검사했으며 다인 통과를 주장하지 않는다.
