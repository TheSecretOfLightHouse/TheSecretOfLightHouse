# 소환 연출 6단계 — 등대 조이기·HP 피해 연결
작성자: 박태욱
작성일·갱신일: 2026-10-31
상태: 구현됨(로컬 호스트 기능 확인, 본편 전체 흐름·원격·시각 검증 대기)
브랜치·기준 커밋: feature/taewook / 962b938a

## 요청과 목표
- 사용자 요청으로 6단계 시작. 확정한 크기·배치를 유지하고 연출 복귀 후 같은 등대 촉수의 조이기를 서버 HP 피해 시점에 맞춘다.
- 피해는 서버에서 한 번 적용하며 수리 진행도·공격력·공격 간격을 변경하지 않는다. 주변 촉수 배 공격과 안전지대 정책(W17)은 다음 단계다.

## 진행 과정과 결정 이유
- 기존 `BossTestEnvironment`의 서버 피해 루프를 재사용한다. 본편용 `_useSummonPresentation` 모드에서는 Timeline이 감기를 담당하므로 별도 감기 대기0초, 공통 연출 종료까지 대기 후 공격을 시작한다. 기존 독립 보스 시험 모드는 유지한다.
- `TowerMatchFlow.BindServices`가 스폰 전 투표 서비스를 전달하고, 보스가 FinalBattleStarted 이후 한 프레임 뒤 소환 공격력 스냅숏을 읽는다. 같은 소환 이벤트 처리 중 먼저/나중 구독된 핸들러의 순서 차이를 흡수한다. 중복 BeginBattle은 기존 HasSummoned로 차단하고 대기 중 외부 시작이 있어도 새 루프를 만들지 않는다.
- 본편 등대 프리팹에 서버 보스를 연결하고 특수 종료 분기는 끈다. HP·수리 규칙은 기존 TowerMatchNet을 그대로 소비한다. R08~R10의 기존 문서·구현 차이를 이번에 새 규칙으로 결정하지 않는다.
- 새 `SummonTentacleCombatView`는 서버 공격 시각·순번·조이기 길이·피해 비율을 소비해 같은 촉수를 LateUpdate에서 샘플링한다. Timeline은 종료 자세를 보존하며, 표현은 그 이후 실행한다. 애니메이션 콜백에는 피해를 넣지 않는다.
- 3.625초 조이기 클립의 수축 구간 후보1.25초를 기존 서버 타격시각(1.966667×0.5≈0.9833초)에 맞춰 앞뒤 구간을 SmoothStep으로 재매핑했다. 최종 시각적 강도/피크 선정은 사용자 확인 대기다.

## 변경 파일과 결과
- 커밋 준비 중 복구: 사용자 삭제 의심 보고 후 확인한 결과 MainIslandLighthouse.prefab과 meta는 존재하나 6단계 BossTestEnvironment 컴포넌트가 빠져 있었다. Unity Prefab API로 같은 설정·TowerMatch 참조·본편모드ON/특수종료OFF를 복원하고 재조회했다. GUID는 유지했다. 복원 후 실행 재검증은 하지 않았으며 이전 실행 검증과 구분한다.
- `Assets/01.Scripts/06.Monsters/Boss/Net/BossTestEnvironment.cs`: 본편 자동 시작·서비스 바인딩·연출 대기 모드·피해 비율 동기화.
- `Assets/01.Scripts/06.Monsters/Boss/View/SummonTentacleCombatView.cs` 및 Unity 생성 meta: 서버 시각 기반 조이기 표현.
- `Assets/01.Scripts/04.Lighthouse/Tower/Net/TowerMatchFlow.cs`: 투표 서비스 전달.
- `Assets/01.Scripts/04.Lighthouse/Tower/View/SummonCinematicView.cs`: 실제 로컬 Rig와 보스 표현 바인딩.
- `Assets/02.Prefabs/World/MainIsland/MainIslandLighthouse.prefab`: 보스 컴포넌트·기존 BossTestSettings·TowerMatch 연결, 본편 모드ON/특수 종료OFF.
- `Assets/02.Prefabs/Boss/MainSceneSummonRig.prefab`: 표현 컴포넌트·등대 Animator·Emerge/Squeeze 클립 연결.
- 프리팹은 Unity Prefab API로 저장했다. 기존 씬·VFX·World meta·카메라 작업 변경을 보존했다. MainOffline은 작업 전후 dirty 상태였으며 저장하지 않았다.

## 검증
- 후속 사용자 결정·확인: HUD 오류는 담당 영역을 고려해 보류하며 수정하지 않는다. 사용자 본편 확인에서 HP 감소 타이밍이 잘 맞는다고 보고했다.
- 종료 후속 검증(M1 실제 KCP 호스트, 임시 실제 본편 등대/작업대 프리팹·투표·Rig): HP0 시험은 Combat 후 HP10을 남기고 실제 첫 조이기 피해10으로 HP0을 만들었다. MafiaWin/LighthouseDestroyed, 보스LighthouseDestroyed, 종료 이벤트1회. 이후4초 HP0·공격순번1·공격 시작시각 불변 확인.
- 수리 완료 시험은 ModuleLedger.Create→WorkbenchNet.TryCarryExisting→TowerNet.TryInstall로 실제 장착 경로를 사용했다. 7/8 슬롯 상태에서 소환 후 첫 공격 준비0.5초 이내에 마지막 모듈을 장착했다. complete=true, CitizensWin/RepairCompleted, HP1000, 보스BattleStopped, 종료 이벤트1회. 이후4초 HP1000·공격순번1 불변으로 예정 타격 취소를 확인했다.
- 수리 종료 후 촉수 Transform83개의4초간 위치·회전·스케일 최대 변화 모두0 확인. 두 시험 중 콘솔 오류/경고0. Play 종료로 임시 fixture 제거, MainOffline Edit 모드 복귀. HUD 코드·공유 설정·씬 저장 변경 없음. 별도 원격 및 동일 프레임 경합 시험은 수행하지 않았다.
- 사용자 본편 확인: HP가 정상적으로 감소한다고 보고했다. 동시에 FinalBattleHud.LateUpdate122줄 NullReferenceException을 보고했다. 해당 줄의 `_match.isClient/isServer`는 Mirror에서 `netIdentity`를 직접 역참조하므로 `_match`만 확인하는 보호로는 부족하다. 조사 시점은 Edit 모드여서 정확한 발생 시점의 HUD/Identity 상태는 재현하지 못했다. HUD 초기 바인딩·제거 경계의 netIdentity 확인이 필요한 진단이며 이번 오류 질문에서는 코드를 수정하지 않았다.
- Unity 새 파일 전체 임포트 후 컴파일 오류0 확인. 최초 scripts-only refresh에는 새 타입 미임포트 오류가 있었으나 전체 refresh 후 해소됐다.
- 실제 KCP 로컬 호스트의 로비에 임시 투표·실제 본편 등대 프리팹·로컬 Rig fixture를 만들었다. 투표 스냅숏 공격력10을 동결하고 실제 TowerMatchNet.TryBeginFinalBattle 경로를 사용했다. 정상 로비→맵→사용자 소환 승인 전체 시험은 아니다.
- Preparing/Playing 중 HP1000 유지, 약15.33초 후 Combat 확인. 반복3타 모두 공격 순번1/2/3에 HP10씩 감소, 설치 모듈 수0 유지. 첫째/셋째 관찰은 공격 시작 후0.990/0.989초, 둘째 관찰은 에디터 도구 작업 중1.888초였다. 후자를 정밀 동기화 통과로 세지 않는다.
- 실제 실행 중 Wrap_46 scaleY0.983~1.098 변화 확인. 등장 마지막 자세와 Squeeze 시작/끝의 최대 메쉬 차이 약0.000009단위 확인.
- 공격 준비0.5초 이내에 시민 승리로 종료: HP770→4초 후770, BossPhase.BattleStopped 확인.
- fixture 콘솔: 작업대 미할당 경고1개(TowerNet), 오류0. 작업대 없는 격리 fixture 한계다. Play 종료로 임시 객체 제거, 원래 MainOffline Edit 모드 복귀.
- 코드 diff 공백 검사 통과. 프리팹은 Unity 생성 빈 m_Name/m_EditorClassIdentifier의 끝 공백4곳이 보고됐고 YAML 직접 편집 금지에 따라 그대로 둔다.

## 남은 일과 다음 행동
- 본편 실제 맵 생성→소환 승인→연출 복귀→조이기/HP 감소를 사용자 화면에서 확인한다. 실제 조명·구도에서 조이기 강도와1.25초 수축 후보가 적절한지 확인한다.
- 별도 원격 M2 이상에서 공격 시각·순번·늦은 바인딩·종료 표현·호스트 이중피해를 확인한다. 이번은 M1이며 네트워크 통합 완료가 아니다.
- HP0·실제 마지막 모듈 장착의 종료/공격 취소는 위 후속 M1에서 확인했다. 고공격력 분기, 수리100%와 피해의 동일 프레임 경합, 승인/실패/지연 전체 경로는 추가 검증 대기다.
- 주변 촉수 배 공격은 7단계이며 사거리·안전지대 정책 결정 후 진행한다. 이전 씬·테스트 정리는 전체 완성·테스트 후다.
