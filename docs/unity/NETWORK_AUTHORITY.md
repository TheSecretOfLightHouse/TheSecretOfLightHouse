# 네트워크 권위 규칙

규칙 우선순위는 최신 사용자 결정 → [승패·투표 결정](../design/win-vote-decisions.md) → [제공된 v4](../design/references/game-design-v4.md)이며, 새 결정과 충돌하는 v4 규칙은 적용하지 않는다. 문서 기준의 상세는 [AI 작업 문서](../ai/README.md)를 따른다.

기존 4인 리슨 서버(호스트 1 + 원격 클라이언트 3)와 Mirror 96.0.1을 유지한다. 게임 규칙은 위 기준 순서, 현재 구조는 [아키텍처](../04-architecture.md), 코드 작성은 [코딩 컨벤션](../coding-convention.md)을 따른다. 아래는 작업 검토 기준이며 각 기능의 구현 완료 목록이 아니다.

## 1. 판단 기준

값이 플레이어마다 다르면 게임 결과가 바뀌는지 확인한다. 결과에 영향을 주는 상태는 서버가 판정하고 클라이언트는 요청·표현을 담당한다. 호스트는 서버와 클라이언트 역할을 함께 수행하므로 로컬 실행 성공만으로 권위 경계를 검증할 수 없다.

| 구분 | 등대 프로젝트에서 검토할 대상 |
|---|---|
| 서버 판정 | 채집·획득 결과, 인벤토리 변화, 등대 수리 진행, 투표·역할·승패 등 공유 게임 규칙 |
| 서버 기준 상태 | 게임 진행·시간, 플레이어와 배의 판정에 쓰는 상태, 공유 자원·상호작용 결과 |
| 클라이언트 표현 | 입력 수집, 카메라, UI, 조명·날씨 표현, 소리·이펙트 |

서버 기준 상태에 해당한다고 기존 이동 구현의 동기화 방향을 임의 변경하지 않는다. 현재 계약과 구현을 확인하고 변경 범위 내에서 판정·동기화를 구분한다. 비밀 역할이나 개인 정보는 필요한 대상에게만 전달한다.

## 2. 요청과 동기화

| 흐름 | Mirror 수단 | 검토 |
|---|---|---|
| 클라이언트 요청 | `[Command]` | 호출자, 소유권, 거리·범위, 현재 상태, 쿨타임 검증 |
| 지속 상태 | `SyncVar`, 동기화 컬렉션 | 늦은 접속 시 현재 상태 복원 |
| 일회 표현 | `ClientRpc` | 중복 실행·호스트 이중 재생 방지 |
| 개인 응답 | `TargetRpc` | 수신 대상과 비밀 정보 노출 확인 |
| 서버 객체 수명 | `NetworkServer.Spawn/Destroy` | 프리팹 등록·생성/제거 책임 확인 |

`requiresAuthority = false`로 요청 경로를 열면 서버에서 호출자를 검증한다. UI나 클라이언트 콜백에서 권위 상태를 확정하지 않는다. 지속 상태를 일회 Rpc만으로 전달해 늦은 접속자가 놓치게 하지 않는다.

투표·확인·소환 요청은 송신자와 ActorId, 시민/마피아 역할, 요청별 허용 상태, 투표 횟수·의식 잠금 또는 10초 소환 권리를 서버에서 검증한다. 난파 중에도 시민 투표는 가능하지만 마피아의 확인·소환은 불가하다. 마지막 확인권이 소진돼도 이미 받은 유효한 소환 권리를 횟수 0이라는 이유로 거부하지 않는다. 승패 조건의 제공자와 최종 확정 책임은 [기술설계 §6](../03-technical-design.md#6-상태와-실행값)을 따른다. 확정된 게임 결과는 한 번만 종료하며 같은 판정 시점의 경합 우선순위는 [문제 대장](../07-design-issue-register.md)의 미결 사항으로 유지한다.

### 2.1 투표·확인 정보의 수신 범위

아래는 [새 결정 §7](../design/win-vote-decisions.md#7-정보-공개-범위--n04r16)의 공개 계약이다. 서버 판정에 필요한 값이라도 공개 동기화 상태에 넣는 근거가 되지 않는다.

| 정보 | 서버·클라이언트 전달 경계 |
|---|---|
| 개인 투표와 잔여 투표권 | 서버가 관리하고 해당 시민 본인에게만 필요한 상태를 전달 |
| 봉인·심해 게이지 | 서버 판정에서만 사용, 마피아를 포함한 모든 플레이어에 비공개 |
| 확인 성공과 10초 소환 권리·확인 기회 소진 | 마피아의 개인 응답/상태. 시민에게 성공·소진 사실을 알리지 않음 |
| 확인 실패 결과 | 중복되지 않는 무작위 시민의 무고함을 공개. 비밀 투표나 역할 명단 전체는 보내지 않음 |

직군·부식·환영 섬·힌트 등 다른 정보의 수신 계약은 v4와 문제 대장 N01~N06·N15를 별도로 확인한다. 이 표로 해당 미결 항목 전체가 해결됐다고 판단하지 않는다. 호스트는 서버 상태를 보유하므로 이 경계는 호스트 운영자의 메모리 접근 차단을 보장하지 않는다.

## 3. 상태와 표현 분리

서버가 확정한 시간·날씨·판정 위치를 바탕으로 클라이언트가 표현을 만든다. 렌더링 색이나 파티클을 매 프레임 공유 상태처럼 보내지 않는다. 피해·상호작용 범위에 영향을 주는 위치·시점은 표현으로 보이더라도 판정 계약을 따른다.

의식 시작의 게임 기한 정지와 최후 전투의 기한 제거를 World 시간 전체의 정지/제거로 확대하지 않는다. 숨은 단계 수리도와 전투 수리 진행도, 현재 HP와 최대 HP도 분리해 동기화·표시한다. 최후 전투 자원 투입으로 HP 회복·새 보상이 생기지 않는지 확인한다.

### 3.1 일반 참가자의 접속 단절

[새 결정 §8](../design/win-vote-decisions.md#8-접속-단절과-재접속--n11n12)에 따라 Mirror 기본 객체 삭제를 막고 캐릭터를 남기며 소유권과 입력을 정리하는 방향이다. 참가자 ID 기반 투표·행위 상태·시간 누적은 연결과 분리해 보존한다. 단절/난파 중에도 시민별 봉인·오투표 누적은 계속한다. 현재 JH01은 연결 해제 시 명단 제거와 Mirror 기본 해제를 실행하므로 새 보존 계약을 추가 구현해야 한다([기술설계 §5·§7](../03-technical-design.md#5-현재-요청데이터-계약)). 재접속은 후순위이고 호스트 이탈 정책은 미결이다.

## 4. 완료 근거

호스트와 원격 클라이언트에서 같은 결과인지, 권한 없는 요청이 상태를 바꾸지 않는지, 중복 입력과 연결 해제 시 결과가 일관되는지 확인한다. 지원 범위에 포함된 늦은 접속·재접속은 별도로 확인한다. 코드 검토와 실제 다인 실행 결과를 구분해 [검증 플레이북](../ai/03_VERIFICATION_PLAYBOOK.md)에 맞춰 기록한다.

## 5. 기능 소유와 실행 경계

기능별 담당과 공용 접속 담당의 경계는 [담당표](../CODE_OWNERSHIP.md#1-담당표)와 [기능 사이의 경계](../CODE_OWNERSHIP.md#2-기능-사이의-경계)를 따른다. `Server/`도 일반 빌드에 포함한다([아키텍처 §3](../04-architecture.md#3-어셈블리)). 호스트는 서버와 로컬 클라이언트가 동시에 활성임을 고려해 중복 판정·이중 연출을 검증한다.
