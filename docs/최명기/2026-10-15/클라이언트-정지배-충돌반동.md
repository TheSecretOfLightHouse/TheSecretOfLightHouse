## 현재 상태: Sleep 방지 최소 변경
- 2026-10-15: 원복 후 사용자가 BoatCollisionRecoil 파일에서 해결하도록 다시 요청했다.
- 기존 겹침 검사와 source 등록은 복구하지 않고, BoatCollisionRecoil.FixedUpdate에서 CanApplyRecoil 통과 시 Rigidbody.WakeUp만 호출하도록 추가했다.
- 목표는 정지한 소유 배의 Sleep이 접촉 감지 차이를 만드는 경우를 보완하는 것이다. Sleep이 실제 원인이라는 실행 증거는 없으며 해결 완료로 주장하지 않는다.
- N07의 소유 클라이언트 물리 권위, 기존 충돌 콜백·쿨다운·반동 계산은 유지했다. 몬스터 코드와 source 설정은 변경하지 않았다.
- 실제 확인: 코드 diff 및 git diff --check. Unity 컴파일/Play Mode/M2 검증은 미실행이며 이전 검증 명령 권한 거절 이후 재요청하지 않았다.
- 남은 일: 호스트와 원격 클라이언트에서 배를 정지시킨 뒤 몬스터 접근 충돌 비교. 실패하면 OnCollisionEnter 수신 여부와 CanApplyRecoil 반환 경로를 실제로 확인해야 한다. 로컬 배의 물리 Sleep 최적화를 사용하지 않으므로 물리 비용도 확인한다.

## 이전 상태: 겹침 검사 원복
- 2026-10-15: 사용자가 동작하지 않는다고 보고하고 원상 복구를 요청했다.
- 이번 변경분이 두 반동 스크립트의 전체 diff와 일치함을 확인한 뒤 두 파일을 HEAD의 기존 코드로 복구했다.
- 추가했던 FixedUpdate 겹침 검사, source 목록 등록, Collider 캐싱과 반동 처리 분리를 모두 제거했다.
- 두 코드 파일의 git diff가 비어 있음을 확인했다. 다른 작업의 변경은 보존했다.
- 아래 내용은 철회된 구현의 이력이다. 아래 검증/다음 행동은 현재 진행 계획이 아니다. 기존 클라이언트 반동 문제는 미해결이며 추가 수정은 진행하지 않는다.

## 요청과 목표
- 호스트에서는 몬스터가 정지 배에 접근하면 반동이 발생하지만 원격 클라이언트에서는 발생하지 않는다는 사용자 보고.
- 몬스터 코드 변경 없이 Player 영역에서 접촉 감지를 보완한다.

## 진행 과정과 결정 이유
- N07 및 네트워크 권위 §4의 소유 클라이언트 물리 계산을 유지했다. 호스트와 클라이언트의 구분을 제거해 모든 PC에서 힘을 주는 방식은 적용하지 않았다.
- 기존 코드는 OnCollisionEnter만으로 반동을 시작한다. 실제 몬스터 이동 코드가 현재 06.Monsters에 없어 이벤트 누락의 근본 원인은 확정하지 못했다.
- BoatCollisionRecoilSource가 활성 상태와 자신의 하위 Collider를 등록·캐싱하고, 배가 FixedUpdate에서 현재 Transform으로 ComputePenetration을 계산하도록 보완했다. 물리 콜백이나 broadphase 갱신에만 의존하지 않는다.
- 기존 충돌 콜백과 직접 겹침 검사가 같은 대상별 쿨다운을 사용한다. 계속 겹쳐 있으면 쿨다운 이후 다시 반동이 적용될 수 있다.
- Trigger, 비활성 Collider, 자기 Rigidbody, 레이어 및 Collider 쌍 충돌 제외를 존중한다. 기존 반동 속도와 쿨다운 기본값은 보존했다.

- Assets/01.Scripts/05.Player/Boat/BoatCollisionRecoilSource.cs: 활성 대상 등록과 Collider 캐싱.

- 몬스터 코드·씬·프리팹·네트워크 권위·기존 타 작업 변경은 수정하지 않았다.

## 검증
- 실행한 확인: 변경 코드 읽기, 호출 경로·소유권·쿨다운 공유·Collider 필터 정적 확인. 변경한 두 C# 파일의 git diff --check 통과.
- 전체 diff --check에서는 작업 전부터 수정돼 있던 Player.unity의 공백 문제가 확인됐으며 변경하지 않았다.
- Unity CLI 업데이트 확인은 네트워크 권한 오류 후 재시도 승인 거절로 중단했다. beta.12에서 beta.13 업데이트가 안내됐으며 설치하지 않았다.
- dotnet build Lighthouse.Runtime.csproj --no-restore --verbosity quiet는 .NET 초기 설정 경로 접근 거부로 실패했다. 권한 재시도도 거절되어 컴파일 결과를 얻지 못했다.
- Unity 컴파일·Play Mode·M2/M3 재현 및 회귀는 미실행. 컴파일/런타임 통과나 보고된 원인의 확정을 주장하지 않는다.

## 남은 일과 차단 조건
- 클라이언트에도 기존 BoatCollisionRecoilSource와 비활성/Trigger가 아닌 Collider가 있어야 한다. 이 데이터가 없는 대상까지 배 쪽에서 식별할 수는 없다.
- ComputePenetration은 쌍 중 하나가 Box/Sphere/Capsule 또는 convex MeshCollider여야 한다. 현재 Cube 배 프리팹에는 BoxCollider가 있다.
- Collider 목록은 Awake에서 캐싱하므로 이후 런타임에 Collider를 추가/재부모화하는 구성은 별도 갱신이 필요하다.
- 활성 source와 배의 Collider 쌍을 검사하므로 대상 수가 많을 때 성능 확인이 필요하다. 빠른 물체가 물리 틱 사이에 배를 완전히 통과하는 경우의 연속 충돌 감지는 이번 범위가 아니다.

## 다음 행동

2. 양쪽에서 반동 방향, 암초로 직접 접근하는 기존 반동, 쿨다운 중 중복 억제, 계속 접촉 시 반복 반동을 확인한다.
