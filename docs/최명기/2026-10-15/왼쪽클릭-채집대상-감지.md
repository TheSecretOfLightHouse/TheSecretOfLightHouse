## 요청과 목표
- 기존 HarvestTarget을 왼쪽 클릭으로 감지하고 자원 정보를 Console에 출력한다.
- 서버 채집·자원 생성·인벤토리 지급은 이번 범위에 포함하지 않는다.

## 최신 체크아웃 기준 — 2026-10-16 재대조
- 채집: 왼쪽 클릭 → PlayerHarvestProbe → LocalHarvestTestSpot.SpotId → 비네트워크 HarvestSpot 요청 → HarvestInteractionHandler(Adapter+단발 Handler) → 드롭 생성. World 본편 잔량·원본 파괴는 아직 처리하지 않는다.
- E키: Player 영역의 전역 PlayerInteractionInput → 공용 InteractionSelector → Relay/Router → 대상 DefaultAction의 Handler. stone은 PickUp → 서버 인벤토리 지급 성공 후 제거다.
- PlayerPickupInput과 meta는 삭제 상태다. tech에는 새 전역 입력 어댑터·Selector가 연결됐고 Selector는 Interaction 레이어 마스크 8, stone은 레이어3을 사용한다.
- 같은 이름의 공용 네임스페이스 PlayerInteractionInput도 별도 파일로 존재한다. 프리팹 GUID로 구분하며 중복 부착하지 않는다.
- 현재 코드·설정·남은 계약은 [구현 참고](../2026-10-16/자원채집-구현참고.md)를 기준으로 읽는다. 아래 이전 구성과 과거 컴파일/호스트 기록은 이번 실행 증거가 아니다. 이번 재대조는 문서·코드·설정 정적 확인이며 Unity 실행 미검증이다.


## 이전 진행 과정과 결정 이유 — 당시 기록
- PlayerController의 Fire 입력은 탑승 중 대포만 처리함을 확인했다.
- 기존 사용자 HarvestTarget과 씬 변경을 보존했다. 배 밖 Fire에 로컬 진단용 검사를 연결했다.
- 화면 중앙의 가장 가까운 충돌체를 검사하고 자기 콜라이더는 제외한다. 벽 뒤 대상을 선택하지 않는다.
- 카메라 검사 거리 20m, 플레이어 도달 거리 3m는 인스펙터에서 조정 가능한 시험값이며 게임 규칙 확정이 아니다.
- 본편 대상 선택은 김지훈 Interaction, 자원 지점·잔량은 강민서 World 계약과 연결해야 한다. N10 기능별 검증과 N09 자원 거래 계약은 이번 로컬 출력으로 해결되지 않는다.

## 이전 변경 이력 — 현재 입력·부착 안내로 사용하지 않음
- 2026-10-15 최신 변경: 사용자 요청으로 왼쪽 클릭을 Harvest로 분리. InputActions.inputactions에 Harvest 액션을 추가하고 기존 왼쪽 클릭 바인딩을 이동했다. Interact 액션과 기존 ID는 유지하며 E키 바인딩은 이번에 추가하지 않았다. PlayerInputReader.OnHarvest → HarvestRequested → PlayerController의 독립 요청 큐/HarvestRequested → PlayerHarvestProbe.HandleHarvestRequested로 연결했다. 구독 해제·요청 초기화·배 탑승 및 쓰러짐 상태 검사를 반영했다. 기존 공용 PlayerInteractionInput과 InteractionRequested 계약은 유지했다.
- 2026-10-15 조준 불일치 후속: 사용자는 Sphere를 커서로 클릭하는 방식이다. 화면 중앙 ViewportPointToRay를 Mouse.current.position 기반 ScreenPointToRay로 변경했다. 마우스 부재는 경고 후 종료한다. 거리·가림·자기 충돌체 제외는 유지. 앞의 화면 중앙 설명은 이전 구현 이력이다. 커서 클릭과 대상 일치 여부는 실행 재검증 필요.
- 2026-10-15 이전 Interact 복원 시도（현재는 위 Harvest 경로）: 기존 Interact 사용을 유지한다. 추가했던 Fire 액션을 제거하고 왼쪽 클릭을 Interact로 복원했다. OnAttack 전달 함수도 제거했다. PlayerController의 배 밖 대상 감지를 interactRequested 경로로 옮겼으며 기존 InteractionRequested 이벤트 호출은 유지한다. Fire는 원래의 탑승 대포 처리로 복원했다. 아래 Fire/Attack 연결 설명은 이전 시도 이력이며 최종 구현이 아니다. 입력 JSON 파싱과 바인딩 확인 및 변경 파일 공백 검사 통과, Unity 컴파일·Play 미검증.
- 클릭 미동작 후속: tech의 구 입력 에셋은 왼쪽 클릭을 Interact에 연결하고 있었다. Fire 액션 추가 및 마우스 바인딩 이관. 다른 직군의 공용 입력 에셋 Attack은 PlayerInputReader.OnAttack에서 OnFire로 전달한다. 최초 구현에서 실제 입력 이름을 확인하지 못했던 연결 누락 수정. 실행 재검증은 대기.
- Assets/01.Scripts/05.Player/Control/PlayerController.cs: 배 밖 클릭 대상 감지와 자원 정보 출력. 탑승 시 기존 대포 호출 유지.

## 과거 검증 기록 — 이번 재실행 결과가 아님
- Harvest 분리 검증: 입력 JSON 파싱·왼쪽 클릭 Harvest 바인딩·이벤트 구독/해제 및 초기화 확인. 변경 코드 diff --check 통과. Unity recompile 결과 completed, failed=false, errors=[], compilationFailed=false. 변경 후 실제 마우스 클릭·멀티플레이 동작은 미검증.
- 후속 콘솔 확인(2026-10-15 17:10 KST): 연결된 Unity 콘솔에 17:09:14~17:09:17의 `Harvest target: 돌, Id=1, Amount=1` 반복 기록과 ProcessActionRequests → ProbeHarvestTarget 호출 경로 확인. 클릭 요청에서 대상 감지 출력까지 도달한 실행 증거가 있다. 한 번 클릭당 한 번인지, 버튼을 누르지 않아도 반복되는지, 멀티플레이 동작은 미검증. 콘솔 조회 시 compilationFailed=false. 실제 생성·지급은 여전히 미구현.
- 실행: 관련 코드·호출 경로 정적 확인, 변경 파일 한정 git diff --check 통과.
- 전체 diff 검사에서는 기존 Player.unity 변경의 공백 경고를 확인했으며 씬은 수정하지 않았다.
- Unity 프로세스 존재만 확인. 에디터 컴파일·Play·호스트/원격 실행 검증은 수행하지 않았다.
