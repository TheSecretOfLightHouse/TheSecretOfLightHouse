## 이전 10/16 조사 — 당시 상태,최신 구성은 상단 참조
- 기존 E키 작업 원문·pointer 수정과 김지훈 인수인계 미추적 파일이 작업 시작부터 있었다. 이번 조사 성과로 계산하지 않고 보존했다.
- `PlayerPickupInput`은 ResourcePickup/PickUp만 선택하고, `ResourcePickup.TryCollect`는 서버 인벤토리 추가 성공 후 제거한다. `PlayerInventory`에는 Owner SyncDictionary와 변경 이벤트가 이미 있다. 아래 10/15 표 2~5의 전부 미연결·개인 동기화 없음 설명을 현재 전체 상태로 읽지 않는다. 원격·동시 획득은 여전히 미검증이다.
- `HarvestInteractionHandler`는 NetworkIdentity의 HarvestTarget으로 단발 드롭을 만든다. World HarvestSpot 잔량 차감·실패 복구 연결은 이 처리기에서 확인되지 않는다(N09·N10·W05). 잔량 제한 없이 반복 채집하면 공급량이 보존되지 않을 수 있다는 정적 추론이며 실행 재현은 하지 않았다.
- `BoatCollisionRecoil.cs`에는 현재 FixedUpdate/WakeUp이 없다. 충돌 원문의 Sleep 보완 구현 표기와 현재 파일이 다르다. 코드 복구나 원인 확정 없이 현황을 바로잡았다.
- `WorldStateNet`에는 세션 흐름 사용 시 MatchStarted → BeginMatch 연결이 추가됐다(`64fa34e`). `MapStateNet`은 해시 비교와 WorldReadyMessage, IWorldReadyGate 등록을 제공한다(`c17b875`). NetworkManager.TryStartMatch는 아직 씬 로딩 인원만 확인하며 월드 대기 TODO가 남아 있다. 준비 신호 자체가 없다는 과거 기록과, 통합 완료라는 주장을 모두 피한다. 생성이 늦거나 해시가 다른 클라이언트에서도 InProgress/시계가 먼저 열릴 수 있다는 정적 위험이다.
- `BoatMonsterTarget`과 실제 배 연결이 현재 코드에 있다. 박태욱 원문의 통제된 호스트 API 검사와 현재 4인 실제 돌진 검증을 구분한다. 몬스터 애니메이션 관련 PR #44 병합 커밋도 로컬 이력에 있지만 원격 PR의 실시간 상태는 조회하지 않았다.
- SetMafiaDowned 호출 검색은 99.Dev 시험 코드만 확인됐다. Player 난파 → 마피아 확인·소환 제한의 본편 연결은 미확인이다. 시스템·UI와 게임 단계·최종 승패는 최명기 범위이며 K01·K02 등 미결 계약을 임의 확정하지 않는다.
- 공유 문서 갱신 후보: 기술설계 §6의 VoteService int ID/역할·자기표·잠금 미검사 설명, 시스템 개요 §6의 단절 상태 보존 문구. 기존 조사 지적을 현재 문서 검색으로 재확인했다. 공유 문서 수정은 이번에 하지 않았으며 최신 결정·타입/검사 구현과 대조 후 담당 검토가 필요하다.
- 다음 행동과 담당자별 전달사항은 [통합 인수인계](../../handover/최명기/2026-10-16/현재폴더-작업현황과-전달사항.md)를 따른다. 10/16은 v4의 정기 시험 예정일이며 실제 시험 진행·완료는 미확인이다.
- 실제 검증: git status/log/branch, 관련 C# 본문·호출자·기준 문서 대조. 갱신한 원문 2개·pointer·새 인수인계의 상대 파일 링크 21개 검사에서 깨진 링크 0개, git diff --check 통과. Unity 컴파일·Play·빌드·M2/M3·원격 저장소/SVN 확인은 실행하지 않았다. 위 코드 변경은 기존 팀 작업이며 이번에는 문서만 수정했다.

## 알아둘 기준과 현재 상태
- 최명기 범위는 Player뿐 아니라 Systems·UI, 직군 배정, 게임 단계와 최종 승패 확정까지다. 각 기능의 서버 검증·동기화도 해당 기능 담당 책임이다.
- 첫 화면·로비·준비·로딩 표시·접속 종료 사유 화면은 2026-10-13 결정으로 김지훈 담당이다. 게임 HUD·인벤토리·투표·지도·정상 승패 통합은 최명기 범위다.
- 플레이어·배 이동은 소유 클라이언트, 자원·피해·난파·승패 결과는 서버 판정이다(N07). 부력·외력은 소유 PC에서만 계산한다.

- 현재 브랜치에 JH02 코드가 존재한다. 인수인계의 'develop PR 전' 문구는 작성 당시 상황이며, 이번 조사에서는 원격 develop 반영 여부를 조회하지 않았다.

## 이미 존재해 다시 만들 필요가 없는 기반
- BoatController의 소유권·승하선 Command, PlayerBoatSpawner의 ActorJoined 기반 개인 배 생성.
- BoatDurability의 서버 피해·SyncVar·난파 이벤트. RestoreDurability는 난파된 배를 복구하지 않으므로 별도 구조/복구 규칙은 여전히 필요하다.
- ReefCollisionDamage의 서버 OverlapBoxNonAlloc 접촉 검사. 원격 Kinematic 배에 OnCollision을 기대하는 방식은 이미 피하고 있다. 씬 연결·원격 피해 실행 결과는 별도 검증이다.
- Cube 프리팹의 BoatDurability와 BoatBuoyancyAuthority 참조. 부력 권위 컴포넌트는 isOwned에 따라 IsSimulating을 바꾼다.
- JH02 요청·검증·세션 기반과 VotingNetworkController의 개인 응답·확인/소환 API. 기반 존재와 본편 연결 완료는 구분한다.

- 이 작업 기록은 게임 수치·판정 규칙을 다시 정의하지 않는다. 미결 계약은 [문제 대장](../../07-design-issue-register.md)의 상태를 확인한다.

## 문서가 현재 코드보다 뒤처진 부분
- 로드맵/아키텍처/기술설계 일부의 'VoteService int ID, 역할·자기표·잠금 미구현'은 현 코드와 다르다. 현재 uint ID와 해당 검사가 있다. 같은 로직을 새로 만들지 말고 연결 API부터 확인한다.
- 아키텍처의 PlayerController MonoBehaviour 표기와 단절 상태 보존 지시는 현 코드·2026-10-13 결정과 다르다. 현 타입은 NetworkBehaviour, 판중 이탈은 판 종료다.
- 01 시스템 개요 6절의 단절 상태 보존 문구도 최신 결정과 충돌한다.
- 인수인계에 적힌 '직군 프리팹 선택 훅'은 합의 방향이며 실행 코드에서 구현을 확인하지 못했다.
- 기본 입력 에셋과 tech의 실제 연결도 달라 문서의 과거 일괄 설명만으로 판단하면 안 된다.
- 이 조사에서는 공유 기준 문서를 수정하거나 미정 계약을 결정하지 않았다.
