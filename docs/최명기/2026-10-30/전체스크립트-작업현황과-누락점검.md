## 요청과 목표
- 전체 스크립트와 작업 기록을 확인해 현재 현황과 빠뜨린 작업을 찾는다. 구현·커밋·게시 요청은 아니다.

## 진행 과정과 결정 이유
- WORK_POINTER → 최명기 POINTER → 난파 분리·지도 조사·직군 구현·MainGame 이식 원문을 읽었다. 타 담당 최신 pointer와 부력 후속 원문도 대조했다.
- 자체 코드 `Assets/01.Scripts` 806개, 약 89,565줄을 파일 열거·전체 텍스트 검색으로 조사했다. 핵심 상태 전이·요청·제공자/소비자와 관련 프리팹은 본문을 추적했다. 806개 전부를 한 줄씩 의미 검증한 전수 코드 리뷰나 실행 시험은 아니다.
- MainGame 및 정적으로 참조하는 프로젝트 프리팹 39개(씬 포함 40개)의 GUID 연결을 재귀 추적했다. 동적 Resources/Addressables 로딩과 실행 중 생성까지 보장하는 검사는 아니다.
- 처음 읽은 최명기 기록에는 부력 미구현·단일 프리팹 생성이 남아 있었으나, 현재 코드와 World 후속에서 부력 연결·4직군 배정을 확인해 미구현 판정을 철회했다. 오래된 문서만으로 누락을 판정하지 않았다.

## 우선 확인할 누락·차이

### 1. MainGame의 실제 촉수 보스 미연결
- 분류: 미연결. 관련 R08~R12·S01, 담당 박태욱·김지훈·최명기 통합.
- 근거: `MainGame.unity`의 TowerTrialRound `_tentacleBoss`는 fileID 0. 씬/참조 프리팹 추적에서도 BossTestEnvironment가 나오지 않았다. `TowerTrialRound.Attack`은 보스가 없으면 대기 후 `_match.ApplyDamage`를 반복하는 대체 루틴을 사용한다.
- 영향: 소환 후 HP 감소가 보여도 실제 촉수 감기·조이기·타격 시점 연결 완료로 볼 수 없다. 피해 자체가 없다는 뜻은 아니다.
- 다음: 실제 보스/모델/설정 연결과 대체 피해 루틴의 사용 범위를 정리하고 원격 관찰까지 확인한다.

### 2. 최후 전투의 공식 기준과 시험 구현이 다름
- 분류: 문서–코드 불일치, 기획 채택 상태 정리 필요. R08~R10·W01·K01.
- `TowerMatchNet.TryBeginFinalBattle`은 수리도·모듈을 승계하고 HP를 최대값으로 시작하며 이미 완성이면 즉시 시민 승리한다.
- `win-vote-decisions.md`는 별도 최후 수리 0%, 수리도에 따른 HP 환산, 특수 종료를 규정한다.
- `jh04-repair-carryover-fixed-hp-proposal.md`와 김지훈 기록에 사용자 시험 구현 요청 근거가 있다. 무단 구현 버그로 단정하거나 기존 방식으로 되돌리지 않는다. 이 제안은 공유 기준을 대체하지 않는다고 명시돼 있어 팀 기준 동기화가 필요하다.
- 다음: 실제 채택 규칙을 합의된 문서에 반영하고 같은 기대값으로 승패를 검증한다. K01 동일 시점 경합은 여전히 별도 계약이다.

### 3. 월드맵·미니맵·개인 환영 정보 연결
- 분류: 조사 범위에서 미구현/미연결. 최명기 지도, 강민서 World. R18·N02·N06.
- 자체 코드에서 지도 화면 구현은 미발견. NavigatorRouteView는 수면 위 구조 항로이며 지도 UI가 아니다.
- IllusionIsland에는 IIllusionService.TryCreate 선언만 발견했다. NavigatorPassive는 속도 배율을 제공하지만 지도 환영 면역 연결은 확인하지 못했다.
- 영향: 현재 기반만으로 시민별 거짓 섬과 항해사 제외 규칙을 제공할 수 없다.
- 다음: 지도 표시 정보·입력과 개인 정보 제공 계약을 정하고 구현한다. 서버 진위 플래그를 그대로 보내 환영을 구분하게 만들지 않도록 검토한다.

### 4. 정비공 액티브의 변경 기록과 부식 후속
- 분류: 문서 불일치 및 별도 미구현. R17·W02~W03.
- 공유 직군 문서는 부식 확인을 규정하지만 현재 Tech 연결/코드는 EmergencyRepairAbility·EmergencyRepairRequest의 대상 선택 긴급 수리다.
- 10/26 직군 구현 원문에 사용자 직접 작성 코드와 UI 연결 요청이 있다. 긴급 수리를 잘못 구현했다고 단정하지 않는다. 해당 원문은 부식 전체 삭제로 확대하지 않는다고 명시한다.
- 자체 코드에서 부식 판정·부식 확인 요청 구현은 미발견. 다음은 현재 액티브 결정의 공유 문서 반영과 부식의 유지/보류 범위 확인이다.

### 5. MainGame의 최신 승리 화면·상시 HUD 이식
- 분류: 정적 참조 범위에서 미연결/통합 확인 필요.
- 코드에 VictoryScreen과 InGameHud가 존재하지만 MainGame+참조 프리팹 추적에서는 미발견. VotingScreen·FinalBattleHud·개인 인벤토리는 발견했으므로 UI 전체가 없다는 뜻은 아니다.
- VictoryScreen 확인은 매니저 RequestReturnToLobby로 연결되고 매니저에 FinishMatch/복귀 처리가 있다. 화면이 실제 표시되는지는 별개다.
- 다음: MainGame에서 승리→확인→전원 대기실→준비 초기화→두 번째 판을 확인한다. 상시 HUD 추가 시 기존 InventoryChestScreen의 운반 카드와 중복 여부를 확인한다.

### 6. 난파 후 해안 드롭 겹침·수명
- 분류: 타 담당 최신 기록상 발견/후속 필요. W12~W14.
- 강민서 10/30 P7 기록에 모듈·자원 해안 드롭 슬롯 카운터가 별개여서 같은 점에 겹칠 수 있다는 발견이 있다. 이번 조사에서는 재현하지 않았다.
- 같은 기록에서 자원 만료 타이머 없음, 모듈 운반 종단의 원격·클라이언트 요청·만료 검증이 남아 있다.
- 다음: Player/Lighthouse의 위치 예약 공유 여부와 잔해 수명 기준을 확인하고 실제 난파·구조·미구조·재시도에서 검증한다.

### 7. 마피아의 나머지 방해와 유령선 조사
- 분류: 미발견/미연결, 기획 잔여. R19~R21·W19~W20·N06.
- 날씨 스케줄·예보·변조 데이터는 있지만 Mafia 영역에서 날씨 조작 플레이 요청 경로는 미발견. 환영·부식도 인터페이스/언급과 실제 기능을 구분해야 한다.
- 유령선 출현·항해·침몰 코드는 있으나 김지훈 최신 기록상 JH06 조사 대상은 미연결이다. 데모 장부 제안을 본편 단서 기능 완료로 세지 않는다.
- 토론 수단 R21은 결정 대기다. 삭제된 인게임 보이스를 재추가 작업으로 세지 않는다.

## 이미 존재하므로 새로 만들 필요가 없는 것
- MainIslandPlayerSpawns는 네 프리팹과 위치를 중복 없이 예약한다. 매니저가 IGamePlayerSpawnSource를 사용하며 MainGame에도 네 프리팹 참조가 있다. 과거 단일 playerPrefab 설명은 현 MainGame 상태 전체를 설명하지 못한다. 실제 4인 배정 검증은 별도다.
- Captain/Tech/Tanker/Farm 프리팹의 `_wreckBuoyancy`가 BuoyancyObject를 참조한다. 현재 CanUseWreckBuoyancy는 Downed만 요구하지 않고 비탑승 로컬 물리를 허용한다. 강민서 BC3 후속에 일반 낙수·수중 모션·1인 Play 결과가 있다. 부력 미구현으로 다시 작업하지 않는다.
- 쉴드·피버·항해사 항로·긴급 수리 요청, 배 4모듈, 개인 인벤 3탭, 난파 분리·구조, 등대 보상 동결, 소환 마피아 능력/인벤 제한 코드가 있다. 존재 확인과 실제 판 완료 판정은 구분한다.

## 검증과 한계
- 이번 실행: 파일 열거·전체 텍스트 검색·핵심 본문/호출자 읽기·MainGame/프리팹 정적 참조 추적·브랜치/미커밋 상태 확인.
- Unity 프로세스는 존재하지만 현재 프로젝트 에디터 연결/콘솔 상태·컴파일·Play·M2/M3는 실행하지 않았다. 에디터 사용 불가로 단정하지 않는다.
- World 최신 기록에는 4인 맵/경계/자원 드롭 일부 검증이 있으므로 프로젝트 전체가 4인 미검증인 것은 아니다. 최명기 최신 기능 및 MainGame 한 판 종단 완료와도 구분한다.
- 외부 플러그인·구매 에셋의 내부 코드 감사는 제외했다. 외부 스크립트와 Editor 도구까지 모두 의미 검증했다고 주장하지 않는다.
- 기존 변경 4개(meta 3개·Build Profile)를 보존했다. 이 조사에서 코드·씬·프리팹을 수정하지 않았다.

## 다음 행동
1. MainGame에서 현재 승패 규칙을 기준 문서와 맞추고 실제 촉수·승리 화면 연결을 확인한다.
2. 4인으로 직군 배정→채집→제작→운반→장착→의식/소환→승패→로비→두 번째 판을 확인한다.
3. 같은 환경에서 난파·구조·미구조 해안 드롭과 중복/만료를 확인한다.
4. 지도·환영·부식·날씨 조작·유령선 조사 등 남은 기능의 출시 범위와 선행 결정을 정한다. 현황 요청이므로 구현을 시작하지 않았다.

- 본문의 지도/날씨 요청 미구현 등은 10/30 조사 시점 설명이다. 이후 공유지도·날씨 예약·조명탄·재장전·등대 보상·소환 마피아 제한 구현을 반영한 현재 상태와 검증 순서는 [최신 재점검](전체스크립트-작업현황-누락점검.md#2026-10-31-재점검--현재-상태와-다음-작업)을 따른다.
