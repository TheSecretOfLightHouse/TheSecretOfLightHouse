## 요청과 목표
- 사용자가 SeaSummoning 경로의 수정을 직접 요청했다. 기존 원형 UI를 재사용해 F → 몬스터 소환·날씨 조정·환영섬 생성의 3칸 메뉴를 만든다.
- 몬스터는 기존 위치 선택·7종 소환을 유지한다. 날씨는 2칸으로 안개·폭풍우를 골라 다음 날 적용하며, 사용자가 안개를 현재 Overcast에 연결하도록 확정했다.
- 환영섬 실제 생성은 민서 담당으로 남긴다. 사용자가 기록 작성자를 최명기로 확인했다.

## 진행 과정과 결정 이유
- 작업 pointer, 관련 박태욱 원문, 최명기 pointer와 기존 커서 기록, 기획·기술설계·문제 대장·소유권·코딩 규칙을 확인했다. 기존 소환의 본편 승선 연결과 실제 원격 검증은 남아 있는 상태였다.
- review-design-code-gaps, check-code-ownership, ui/ui-ugui, unity-cli 스킬을 적용했다. 기존 기능 내부 UI·네트워크 4개 파일만 수정하고 World·공용 Network·Player·씬·프리팹은 수정하지 않았다. 기존 에셋·설정의 미커밋 변경은 보존했다.
- 기존 7칸 메뉴를 3/2/7칸 페이지로 확장했다. F 진입 때 입력과 커서 상태를 저장하고, 몬스터 선택 때만 카메라를 탑뷰로 이동한다. 날씨에서 우클릭/닫기 버튼은 능력 메뉴로 돌아가고, F는 메뉴를 닫는다.
- 월드에 별도 Fog 타입이 없는 사실을 확인하고 사용자 결정을 받아 Overcast에 연결했다. 기존 서버 전용 예보 서비스를 소비하며, 현재 날씨 변경 코드는 호출하지 않는다.
- 환영섬은 준비 중 안내만 표시한다. 생성 완료·성공을 표시하지 않는다.
- 독립 정적 검수에서 지연된 소환 응답이 새 능력 메뉴를 닫는 경로와 판 종료 중 예약 가능성을 발견해 보완했다. 재검수에서 두 항목은 정적으로 보완됐고 추가 차단 결함은 발견하지 못했다(CONDITIONAL, M0).
- CLI 업데이트는 사용자 요청으로 보류하고 기존 설치 버전으로 검증했다.

## 검증
- Unity 6000.0.83f1 본편 에디터 연결 확인. 에디터는 Play 중이 아니었으며 임의로 Play를 시작하거나 씬을 저장하지 않았다.
- 컴파일: 보완 전·중간 recompile completed, failed=false, compilationFailed=false, errors=[] 확인. 최종 확인 결과는 아래 후속 검증에 기록한다.
- 격리 UI 검사: PreviewScene에서 실제 기존 프리팹·소환 설정을 사용해 24조건 통과. 3/2/7칸·텍스트/아이콘·위치 선택 차단·복원·뒤로 가기·선택 영역 확인. 페이지별 1280×720 렌더를 생성해 3칸/2칸 화면을 직접 확인했다. 제목도 페이지에 맞게 바꿨다.
- 월드 예보 소비 계약 10조건 통과: 현재 날씨 유지, 다음 날 폭풍우·Overcast 적용, 원래 예보 보존, 당일·과거·마지막 다음 날 거절. 실제 Command/TargetRpc 검증은 아니다.
- 초기 임시 평가 스크립트는 평가기의 using 미지원과 PowerShell 타입 치환 대소문자 문제로 컴파일 실패했다. 검사 스크립트를 보완 후 재실행해 통과했다. 런타임 코드의 Unity 컴파일 실패로 해석하지 않는다.
- 격리 검사의 active scene dirty 표시는 기존 상태와 전후 비교하지 않았으므로 씬 무변경의 증거로 사용하지 않는다. 씬 저장·프리팹 직렬화 작업은 수행하지 않았다.
- 실제 F 입력·카메라 전환·배 입력 복원·승선·소환·원격 날씨 예약과 다음 날 시각 전환은 미실행(M0).

### 최종 보완 후 확인
- 최종 Unity recompile: `completed`, `failed=false`, `compilationFailed=false`, `errors=[]`.
- 격리 UI 최종 28조건 전부 통과. 능력/날씨 페이지 제목과 과거 소환 성공·실패 응답이 새 능력/날씨 메뉴를 닫지 않는 회귀 4조건을 추가했다.
- 콘솔 현재 오류 0, 경고 5. 경고 위치는 이번에 수정하지 않은 Player의 EmergencyRepairRequest·NavigatorRouteRequest·GatheringFeverRequest·GuardShieldRequest(CS0252), BoatController(CS0414)이며 SeaSummoning의 새 경고는 확인되지 않았다. 캡처 도구의 누적 오류 수와 현재 콘솔 오류 수를 구분했다.
- 독립 정적 재검수: 앞선 두 문제 보완 확인, 추가 차단 결함 미발견. 실제 Play/M2 미검증으로 최종 `CONDITIONAL`, `M0`.
- `git diff --check` 통과. 결정·기술설계·문제 대장·원문·pointer의 관련 링크와 변경 범위를 확인했다.

## 남은 일과 차단 조건
- 실제 호스트/원격에서 승선 → 마피아 F 메뉴 → 몬스터 위치 선택·소환 → 복귀, 날씨 예약 → 다음 날 적용을 검증한다. 서버 권한 거절과 마지막 날·판 종료 거절도 실제 접속 상태에서 확인한다.
- 기존 승선/DockZone 구성에 관한 미검증 상태는 [기존 기록](../../박태욱/2026-10-29/본편-바다소환-연결-검증.md)을 참고한다. 이번 작업으로 해결했다고 판단하지 않는다.
- 환영섬의 대상·위치 선택·생성 API는 민서와 연결할 후속 범위다. W19 예측소 공개 계약과 N06 개인 환영 계약도 별도로 남는다.
