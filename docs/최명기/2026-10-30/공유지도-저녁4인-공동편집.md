## 요청과 목표
- 등대섬만 있는 공유지도에 직접 그리기, 저녁 지도 앞 E 누적 4인 준비 후 전원 편집, 제한시간 강제 종료, M 읽기 전용 열람을 구현한다.
- 작성 담당자는 사용자에게 최명기로 확인받았다. 임의 커밋·푸시 없음.

## 진행 과정과 결정 이유
- WORK_POINTER·최명기 pointer·관련 작업 현황, 민서 S6 인계 문서와 현재 코드, UI 스킬·컨벤션·소유권·네트워크/씬 안전 규칙을 읽었다.
- S6 데이터는 실제 섬을 모두 표시하는 데 쓰지 않고 bounds/등대섬 위치만 읽는다. 기존 v4 개인 지도와 이번 결정 차이는 [결정 문서](../../design/shared-map-decisions.md)에 기록했다.
- World·공용 Interaction enum·NetworkManager·플레이어 프리팹·기존 씬을 변경하지 않았다. UI 도메인의 RuntimeInitialize 부트스트랩과 Mirror 인증 메시지로 기능의 준비/편집/복원 통신을 소유한다.
- PlayerInteractionInput에서 지도 근처 E를 우선 소비하여 작업대/승하선과 중복 실행하지 않게 했다. 기존 멀리 있는 대상 선택·동작은 유지한다.
- 서버가 송신자의 실제 PlayerController·거리·난파/승선·저녁·판 식별·타이머·요청 속도·좌표 범위를 확인한다. 준비는 연결별 HashSet으로 중복을 막는다.
- 그림은 이미지가 아닌 정규화 선 작업 기록으로 보관한다. 신뢰 채널로 전송하고 오프셋 청크로 누락/재수신을 복원한다. 중복 청크를 재적용하지 않는다. 새 판은 별도 epoch로 이전 입력을 거부한다.
- UI는 기존 uGUI/OS 한글 폰트 패턴을 사용한다. SessionScreen의 overlay 계약과 입력 비활성화를 사용하고 커서를 복원한다.
- 화면 검사에서 CanvasRenderer 누락과 SessionScreen보다 낮은 sortingOrder를 발견해 수정했다. 실제 격자·등대·그림 렌더를 다시 확인했다.
- 가만히 누르고 있는 펜의 불필요한 반복 기록을 억제했다. 기록 상한 12,000개는 단일 Graphic의 65k 정점 한계 아래다. 청크 96개는 직렬화 4KB 미만 검사로 확인한다.

## 검증
- 실제 Unity 에디터 재컴파일 오류 0.
- `SharedMapChecks.Run`: 80조건 PASS. 0~5인/준비 조합, 낮/같은 날 재시작 거부, 만료 경계, NaN/Infinity/범위 밖 좌표, 지우개 거리, Mirror 청크 직렬화 왕복.
- `SharedMapReplayChecks.Run`: 14조건 PASS. 렌더러 존재, 부분/중복/누락 복원, 다른 작성자 선 유지, 새 판 초기화, 세션 열기·만료 닫기·늦은 만료 상태 재열기 방지, 커서 복구 검사.
- 최종 Play 검사 이후 신규 에러 로그 0, 에디터 콘솔 오류/경고 0. 검사 후 Play를 종료했다. 보존된 과거 콘솔 오류를 이번 작업의 신규 오류로 계산하지 않았다.
- Play 프레임 진행 확인. 격리 UI에 샘플 선을 주입해 실제 렌더 200정점과 화면을 확인했다. **샘플 선은 실제 섬 위치가 아니며, 이 화면은 네트워크 4인 플레이 증거가 아니다.**
- [화면](공유지도-공동편집-화면.png).
- 에디터 도구의 Play 진입 직후 일시적 요청 실패는 재시도했다. 컴파일/테스트 실패로 숨기지 않고 실제 성공 반환을 근거로 기록한다.
- 실행하지 못함: 실제 4인 E 준비·동시 그리기·마우스/버튼 종단·원격 지연·실제 섬의 테이블 보행/접근·씬 왕복. 별도 클라이언트/인원 없이 통합 통과로 보고하지 않는다.

## 남은 일과 차단 조건
- 테이블은 기본적으로 실제 등대섬 중심+(3,3), 지면 레이캐스트 높이에 임시 생성한다. 최종 등대섬의 회의 테이블 위치는 현재 체크아웃에서 확인되지 않아 연결하지 않았다. 정확한 장소에는 빈 앵커에 `SharedMapTable`을 붙이면 우선 사용한다(World 담당 에셋 변경 전 합의 필요).
- Dusk 안에서만 편집하므로 늦게 준비하면 60초보다 짧아진다. 현재 구현 규칙과 가안 수치는 결정 문서 참고.
- 항해사/환영 계약, 본편 재접속 정책, 그림 보존의 디스크 저장은 이번 구현 완료로 간주하지 않는다.
- 실제 4인 통합 검증 전까지 완료(검증됨)로 올리지 않는다.

## 2026-10-30 후속 — 기존 UI 스타일과 그림판 붓

### 요청과 변경
- 사용자가 기존 UI 색감에 맞추고 선 연결처럼 보이지 않게 그림판의 자유 그리기로 바꿔 달라고 요청했다.
- 기존 `WorkbenchUiSketch/ws_panel_craft`, 버튼의 크림/금색 테두리, `InGameHud/hud_icon_lighthouse`를 설정 에셋의 Sprite 참조로 재사용했다. 원본 이미지·임포터·GUID는 수정하지 않았다.
- 갈색 패널/크림 프레임, 양피지색 캔버스, 오른쪽 4색 도구/3단계 굵기/획 지우개, 선택 강조와 Bold 한글 폰트를 적용했다. 제목과 지도 영역 겹침을 검사하고 수정했다.
- `SharedMapBrush`의 1024² 투명 텍스처에 둥근 붓 자국을 겹쳐 칠한다. 점/끝/이어지는 부분의 모서리를 둥글게 하고 가장자리를 부드럽게 처리한다. 실제 섬 윤곽 생성이나 도형 보정/섬 자동 인식은 하지 않는다.
- 마우스 점은 매 프레임 수집하며 자기 입력은 즉시 미리 표시한다. 50ms 간격 최대16개 묶음으로 서버 전송한다. 서버는 묶음 길이·모든 좌표·붓/색 범위·송신자·거리·시간을 확인한 후 전체를 적용한다. 같은 묶음에서 먼저 그린 획을 뒤에서 지우는 것도 허용한다.
- `Sample`/`Writer`를 추가해 응답 수신 시 임시 그림을 중복 칠하지 않는다. 다른 사람의 그리기와 섞일 때는 확정 기록 아래/임시 입력 위 순서로 재구성한다. 만료·판 변경 때 미확정 그림을 정리한다.
- 캔버스 메시가 4정점으로 고정돼 초기 구현의 65k 정점 제한이 사라졌다. 작업 기록 상한은 48,000으로 변경했다. 초기 12,000개/200정점 설명은 첫 구현 당시 이력이다.
