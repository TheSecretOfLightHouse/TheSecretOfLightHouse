## 요청과 목표
플레이어가 걷는 동안 발과 지형이 따로 움직이는 느낌 개선. 사용자는 측정 후 선택지에서 “자연스러운 걸음 우선: 보폭·박자와 함께 걷기 속도도 조정”을 선택했다. 이 결정에 따라 기존 목표 걷기3/달리기4.5를 변경한다.

## 진행 과정과 결정 이유
- 이전 접지 조사는 관통/몸체 지면 추종 문제이고 이번 요청은 발 모션과 이동 거리 불일치로 범위를 구분했다. N07 소유자 위치 권위와 원격 NetworkAnimator 소비는 유지.
- PlayerAnimationDriver는 이미 실제 Rigidbody 수평속도에 연동됐다. 고정 클립 기준2/3이 짧은 체형의 실제 발 속도와 맞지 않았다.
- 네 직군 실 프리팹을 PrefabUtility.LoadPrefabContents로 격리하고 PlayableGraph의 AnimationClipPlayable을 수동 평가했다. FootIK/PlayableIK는 꺼둔 상태다. 각 클립120구간에서 루트 상대 발 좌표를 읽고 발 높이 하위35%이면서 뒤로 이동하는 표본의 속도 중앙값을 사용했다. 발바닥 접촉 센서 대신 발 본의 낮은 구간을 쓰는 근사치다.
- 현재 Walk_ShortLeg 후보 지지속도0.249~0.340m/s, Run0.625~0.725m/s였다. 원본 Walk0.149~0.183·Run0.503~0.597로 더 작았다. 원본 복귀 대신 기존 후보를 유지했다. 몸체 약2.9m/s에 맞춰8~11배로 올리는 것은 이전 과배속 문제를 되풀이하므로 선택하지 않았다.
- 사용자 허용에 따라 네 직군 목표 걷기0.5/달리기1.0(배율2), 직군별 측정 클립 기준을 적용했다. 바닥 마찰이 있는 실제 검사속도는0.38228/0.88228로, 블렌드 경계를0.38/0.88로 정했다. 정지 기준0.08은 유지하고 Idle→Walk 구간0.12·재생범위0.1~1.6으로 변경했다. 모션·Animator 전환/클립·점프·배 물리·IK는 변경하지 않았다.
- 프리팹은 Editor API로 필요한 float 필드만 저장했다. Mirror prefab isolation 저장 과정에서 assetId가 디스크0이 되는 것을 발견해 실제 에셋의 정상 계산값으로 SavePrefabAsset했다. 네 직군의 기존 GUID/assetId·배 참조 유지 확인. 씬 저장 없음.

## 실제 검증
- Unity 6000.0.83f1, 사용자 Play를 종료하고 검사. 최종 컴파일 failed=false/errors=[]/compilationFailed=false. 이전 도구 timeout 오류는 콘솔 이력에 남아 있으며 오류0이라고 보고하지 않음. 기존 경고5.
- 네 실제 프리팹 × 걷기/달리기, 각150틱 독립 PhysicsScene.Simulate(.02): 실제 속도 모두0.38228/0.88228, grounded=true, y=0, 추가5틱 입력잠금 후 stopped=true. 본편 씬 물리 진행 없음. 콜백 검증으로 확대하지 않음.
- 실제 공통 AnimatorControllerPlayable로 각 직군/걷기/달리기/전후16조건, 각360표본(120Hz) 평가. 모든 조건 Movement 상태 유지. Walk 평균 지지발 월드 전후방 미끄러짐(속도+발 루트상대속도 절댓값)이 기존2.44~2.53m/s→0.108~0.129m/s, Run3.29~3.46→0.232~0.253m/s로 감소했다. 목표속도 감소 효과도 포함되며 순수 애니메이션 보정만의 개선율로 해석하지 않는다. 실제 접촉·방향전환·네트워크 검증이 아니다.
- Tanker 현재 Animator의 수정 전/후2초·18fps·72장 미리보기 렌더, 접촉시트 시각 확인. 같은 캐릭터를 카메라 중심에 두고 바닥선을 실제 검사속도로 이동시키는 비교이며 실제 게임 녹화가 아니다. GIF는 로컬 시각 산출물로 보존.
- 변경 C#/프리팹 diff --check 통과. 코드 계산 경로·권위·행동 전환 변경 없음.

## 남은 일과 차단 조건
실제 섬 걷기/달리기 체감, 이동 시간이 늘어난 게임성, 경사/회전/정지, 원격 소유자/관찰자 M2는 미검증. 완전한 발 고정은 아니며 클립의 좌우/구간별 속도 차이로 잔여 미끄러짐이 있다. 이번 결정은 자연스러움 우선으로 속도 감소를 허용한 것이며 최종 밸런스 확정으로 확대하지 않는다.

## 2026-10-27 이동 방향 회전 대안 검토(미구현)
- 사용자가 WASD 방향으로 캐릭터가 회전하면 어색함이 줄지 질문했다. PlayerController Update는 입력을 마우스 heading 기준 월드방향으로 계산하지만 FixedUpdate Face는 이동 방향이 아닌 동일 heading만 사용한다. 따라서 A/D/S에서도 같은 전진 걷기 클립이 측면/후방 이동에 사용된다.
- 이동 방향으로 시선을 맞추면 이 방향 불일치의 개선이 예상되나, 발 높이/보폭 불일치의 해결을 보장하지 않는다. 현재 카메라는 캐릭터의 자식 앵커를 따르므로 몸 회전만 바꾸면 카메라도 회전한다. 보행 카메라 yaw와 몸 방향을 분리하고 카메라 기준 입력을 유지하는 변경이 필요하다.
- v4는3인칭을 규정하지만 이 회전 방식은 구체적으로 확정하지 않았다. 대장N07의 소유자 이동 권위는 유지 가능한 범위다. 이번 대화는 대안 검토이며 새 사용자 결정이나 구현 완료로 기록하지 않는다. 코드/프리팹/카메라 수정 없음.
