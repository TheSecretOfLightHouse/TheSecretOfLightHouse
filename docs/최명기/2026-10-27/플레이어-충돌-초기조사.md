## 요청과 목표
벽·바닥·배·다른 플레이어 및 호스트/원격 전반의 충돌 이상 조사. 사용자는 증상 구분 질문에 “전부다”라고 답함. 개별 재현 상황은 아직 미확보.

## 진행 과정과 결정 이유
- PlayerMotor의 지면 중심 하향 단일 Raycast와 접지 시 속도 재설정 확인. 접촉 반응과 이동 입력의 간섭 후보이며 실제 원인으로 확정하지 않음.
- PlayerController의 원격 Kinematic 처리 및 탑승 시 detectCollisions=false, 하선 복원 경로 확인. 탑승 충돌 비활성 자체를 결함으로 판단하지 않음.
- Physics Layer Collision Matrix는 저장 설정상 전체 허용. N07은 소유 클라이언트 위치 권위 부분 결정, 충돌 경계/오차는 후속 합의 상태.
- 기존 PlayerController·프리팹·씬 등 다수 미커밋 변경이 있어 보존. 원인 미확정 상태의 일괄 물리 설정 변경은 하지 않음.

### 요청·범위
사용자는 관통보다 플레이어와 지형이 따로 노는 느낌이라고 정정했고, 접지·경사 이동 개선의 직접 구현을 요청했다. 최명기 Player 소유 범위이며 타 담당 지형·공용 설정 변경 없음. N07 위치 권위 부분 결정은 유지하고 미합의 물리 계약을 확정하지 않음.

### 구현과 결정 이유
- PlayerMotor의 중심 단일 Raycast를 하단 캡슐 반경 기반 비할당 SphereCast로 교체. contactOffset만큼 반경을 줄이고 시작점을 올려 최초 겹침을 피하며 동일 허용 접지 거리와 경사 임계값을 사용.
- Awake에서 자기 씬 PhysicsScene 캐시. 본편 기본 물리 씬과 격리된 PreviewScene 모두 자기 물리 공간을 조회.
- 자기 충돌체·자식·트리거·충돌 제외 레이어/개별 쌍을 지면 판정에서 제외.
- 지면 접선 이동 속도와 법선 방향 속도를 분리. 하강 속도 보존, 점프 중 밀착 비적용. contactOffset보다 큰 틈에서만 최대1.5m/s 제한 밀착, 기존 접촉 중 추가 누르기 없음.
- 최초 연속 누르기안은 격리 시험에서 마찰로 이동이 거의 막혀 폐기했다. 최종안은 기존 평지·일정경사 속도를 유지하는 것을 다시 확인.
- 최초 접촉 조회 API안은 컴파일 오류로 제거했고 최종 SphereCast 구현은 컴파일 성공. 오류를 숨기기 위해 콘솔을 지우지 않음.
- 보행3/달리기4.5·점프5·공중 이동·애니메이션/IK·NetworkTransform 권위·씬/프리팹·외부 에셋은 변경하지 않음.

- 이동 중 클립 확인 성공: 사용자 보행20초 관찰, 이동표본41개·앞20개 상세 반환. 상세표본 전부 Walk_ShortLeg_Candidate 가중치1, Speed0.5, Jump/Falling=false. 속도 약2.04~2.91m/s, 재생배율 약1.02~1.45(정속 약2.88m/s·1.44배). 앞선 정지20표본 Idle1은 정상정지이며 이동 중 Idle 결함으로 해석하지 않는다. 실제 이동 중 걷기 재생 연결은 확인했고, 현재 체형/클립 보폭·지면 높이 일치는 별개 문제다. 설정/모션 변경 없음, 사용자 직접 입력만 관찰.

## 사용자 승인 직접 이동 관찰
- 사용자가 현재 Play에서 AI가 직접 움직여 보라고 명시적으로 요청하여 짧은 이동 입력만 수행. 앞선 사용자 직접 테스트 지시는 이 관찰 범위에서 최신 요청으로 변경됨.
- Game View 포커스 후 Input System KeyboardState W 입력을 약1.2초 주고 해제, 2.2초 동안 관찰. 시작(2.915,1.657,-5.115)→종료(-0.360,1.660,-4.261), 이동거리3.384m. 실제속도 약2.77~2.89m/s, Walk_ShortLeg_Candidate 가중치1·재생약1.38~1.45배. 이후 속도0.00003m/s 수준 정지 확인.
- 실제 화면 캡처5장 확보·이동 중 2장 확인. 발의 작은 동작에 비해 바닥/몸의 이동량이 커 접지감이 약한 표현 확인. 화면만으로 모든 부양감 원인을 확정하지 않는다. 발 모션/이동량 불일치와 발 높이/그림자 표현을 구분할 필요.
- 임시 제어 코드의 최초 컴파일/입력 API 오류는 실행 전 또는 키 입력 전에 발생, 수정 후 실제 이동 성공. 이후 W up 추가 요청 및 입력 장치 hard reset으로 해제 확인을 수행. 입력/포커스 이외 설정·게임코드·속도·모션·씬·Play 상태 변경 없음. 임시 Editor 업데이트 관찰 콜백은 제거됨.
- 최종 입력 해제: W up/장치 reset 뒤 Editor 입력 상태의 pressed 캐시가 남아 있어, KeyboardState 전체를 Dynamic/Editor 상태에 모두 해제했다. 최종 wValue=0·wPressed=false 확인. 최초 단일 bitfield Change는 실행 오류로 미적용, 최종 전체 장치 상태 갱신 성공. Play 유지.
