# 배 3종 Boat 기준 프리팹 설정
작성자: 최명기
작성일: 2026-10-27
갱신일: 2026-10-27
상태: 구현됨(미검증)
브랜치·기준 커밋: feature/myeongki / 54efe84

## 요청과 목표
- 사용자가 추가한 TankerBoat, captainBoat, gardenBoat 프리팹을 기존 Boat와 같은 기능 설정으로 구성한다. 각 배의 메시와 머티리얼은 유지한다.
- 요청자가 최명기임을 대화에서 확인했다.

## 진행 과정과 결정 이유
- 2026-10-27: Unity MCP로 실제 프로젝트 연결 및 Edit Mode 확인. 기존 Boat는 루트 컴포넌트 24개와 Transform 10개로 구성되어 있으나 새 배 3종은 루트 메시·렌더러만 있었다.
- Boat의 탑승·조작·내구도·부력·충돌·대포·수리·상호작용·모듈·발사 피드백과 참조를 함께 옮기기 위해 PrefabUtility.LoadPrefabContents/SaveAsPrefabAsset를 사용했다. YAML 직접 수정은 하지 않았다.
- 원본 Boat를 격리 로드하고 Model의 sharedMesh/sharedMaterials만 대상 배의 것으로 바꾼 뒤 각 기존 대상 경로에 저장했다. 루트는 Boat와 같은 위치0·회전0·스케일3, Model은 기존 Boat의 회전과 스케일을 따른다.
- 세 대상의 기존 GUID를 보존했고 Mirror의 assetId는 각 프리팹에 맞게 생성됨을 확인했다. 원본 Boat 및 다른 사용자 변경을 수정하지 않았다. 씬을 저장하거나 자동 스폰 목록을 변경하지 않았다.
- 요청 전 머티리얼 조사에서는 화면의 기존 tripo 메시와 새 tanker 텍스처가 짝이 아니었음을 확인했다. 원본 tanker 메시로 교체한 화면에서 무늬가 정상임을 확인했으며 그때 씬은 저장하지 않았다. 파일명만으로 대포용 텍스처라고 했던 초기 추정은 사용자 설명과 실제 비교로 철회했다.

## 기획·코드 대조
- 시스템 디자인의 개인 배 역할, 배 모듈 기획의 공통 4종 구조와 기존 Boat 구현을 기준으로 기능 구성을 맞췄다. 직군별 수치나 규칙은 추가하지 않았다.
- 문제 대장 N07은 이동이 소유 클라이언트 권위로 부분 결정된 상태다. Boat의 NetworkTransform 설정을 그대로 복제하며 물리 권위 계약은 바꾸지 않았다.
- PlayerBoatSpawner는 `_boatPrefab` 하나를 초기·복구 스폰에 사용한다. 프리팹 구성만으로 직군별 배 자동 선택이나 NetworkManager spawnPrefabs 등록이 완료되는 것은 아니다.

## 검증
- 실행한 확인: Unity 6000.0.83f1 MCP ready, Play stopped, compiling false.
- 프리팹 저장 성공 3/3, GUID 보존 3/3.
- 각 프리팹을 AssetDatabase에서 다시 읽어 기준 Boat의 노드와 컴포넌트를 비교했다. Transform 10개·루트 컴포넌트 24개가 일치했다.
- 모델 메시·재질 및 고유 assetId, Unity 내부 프리팹 식별 정보를 제외하고 각 10,552개 직렬화 속성을 비교했다. 내부 참조는 해당 프리팹 내 상대 경로와 타입으로 대조해 차이 0개였다. 초기 비교에서 내부 fileID 차이도 출력됐으나, 참조 자체의 상대 대상 비교로 보정해 재실행했다.
- assetId: Boat=2808386830, TankerBoat=1018287347, captainBoat=2022844835, gardenBoat=3223967714. 세 신규 배 sceneId=0.
- PreviewRenderUtility 격리 렌더로 원본 포함 네 모델의 재질·방향·상대 크기를 확인했다. 활성 씬에 테스트 오브젝트를 추가하지 않았다.
- `git diff --check`는 기존 사용자 변경 RepairPassive.cs:59의 후행 공백을 보고했다. 이번 작업의 C# 수정은 없으며 해당 변경은 보존했다.
- 실행하지 못한 확인: 실제 탑승·항해·발사·수리·난파와 M2 이상 네트워크 플레이. 프리팹/격리 렌더 검증을 플레이 통과로 보고하지 않는다.

## 남은 일과 차단 조건

- 직군별 자동 스폰/등록은 이번 요청의 프리팹 설정 범위에 포함하지 않았다.
- `_wreckEffectPrefab`은 Boat와 같은 BoatWreckEffect다. 새 외형별 분리 메시를 새로 제작한 것은 아니므로 난파 시 공통 원본 배 외형의 효과를 사용한다.
- 담당자 pointer의 이전 난파 작업 링크 `2026-10-27/난파-배-분리모델.md`는 현재 체크아웃에 없어 원문을 읽지 못했다. 기록 내용을 현재 플레이 검증 근거로 삼지 않았다.

## 2026-10-27 후속: 직군별 배 최초 생성·복구 연결
- 사용자 요청: Boat spawner를 확인해 네 직군이 각자 맞는 배를 사용하게 연결.
- 현재 구현에는 별도 직군 enum/배정 상태가 없고 네 플레이어 프리팹의 능력 구성이 직군을 구분한다. 패시브의 활성 여부나 오브젝트 이름으로 직군을 추측하지 않고 플레이어 프리팹에 배 참조를 명시했다.
- PlayerController에 직렬화 `_boatPrefab`과 읽기 전용 `BoatPrefab`을 추가했다. Captain 1→captainBoat, Tech 1→Boat, Tanker 1→TankerBoat, Farm 1→gardenBoat 연결을 에디터 API로 저장했다.
- PlayerBoatSpawner의 초기 ActorJoined 생성과 TryCreateRecoveryBoat가 같은 TryGetBoatPrefab을 사용한다. 플레이어에 지정된 배가 우선이며, 지정하지 않은 기존 플레이어는 스포너의 `_boatPrefab`을 사용한다. 지정된 배의 Mirror 등록이 없으면 오류를 남기고 생성을 거절한다.
- MK_MainOffline의 NetworkManager.spawnPrefabs에 새 배 3종을 중복 없이 추가했다. 기존 24개 항목을 보존해 총27개가 됐다. 해당 최명기 개발 씬만 에디터 API로 저장했으며 최종 diff는 등록 3행 추가뿐이다. 저장 전 dirty였던 씬의 다른 사용자 상태를 되돌리지 않았다.
- 변경 파일: PlayerController.cs, PlayerBoatSpawner.cs, Captain 1/Tech 1/Tanker 1/Farm 1.prefab, MK_MainOffline.unity, 직군 능력 결정의 배 연결 안내, 이 기록과 pointer.
- 프리팹 로드·저장 뒤 Mirror assetId가 디스크에 0으로 남는 것을 발견해 Mirror의 assetId getter로 ID를 결정하고 SaveAssetIfDirty로 각 에셋을 저장했다. 네 플레이어의 기존 assetId를 보존했고, 새 배 3종도 고유 ID의 디스크 저장을 재확인했다.
- 검증: Unity recompile completed/failed=false/errors=[]/compilationFailed=false. 새 코드 컴파일 성공.
- 검증: 격리 PreviewScene의 스포너에서 실제 TryGetBoatPrefab을 호출해 네 플레이어→지정 배 및 스폰 등록 4/4, 배 미지정 기존 플레이어의 Boat 대체1/1, 양쪽 미설정 거절1/1 통과. 임시 설정·오브젝트는 저장 없이 해제했다. 최초·복구 실제 NetworkServer.Spawn을 실행한 시험은 아니다.
- 검증: 플레이어 프리팹 diff는 각 `_boatPrefab` 추가1행뿐이고, 네트워크 ID는 기존 값 유지. 범위 파일 git diff --check 통과.
- 도구 제약: 최초 일괄 에셋 연결 및 다음 조회가 MCP main-thread timeout으로 실패했다. 단일 프리팹별로 다시 연결하고 저장 및 파일 diff를 확인했다. 콘솔에는 이 타임아웃 오류가 남아 있으며 콘솔 오류0이라고 보고하지 않는다. 최종 compilationFailed=false, 콘솔 오류1/경고5; 과거 동적 폰트 오류도 캡처 버퍼에 있다. 콘솔을 지우지 않았다.
- 남은 일: 실제 최초 생성·구조 후 같은 직군 배 복구·원격 동기화 M2 검증. 통합 Main 또는 다른 담당 테스트 씬의 NetworkManager에 새 배 등록은 하지 않았다.
- 범위 한계: LighthouseNetworkManager.SpawnGamePlayer는 현재 playerPrefab(Tech 1) 하나만 생성한다. 이 변경은 생성된 직군 플레이어와 배를 연결하며 네 직군을 중복 없이 배정하거나 랜덤 선택하는 공용 코드 기능을 추가하지 않는다. 사용자에게 그 차이를 설명했다. 따라서 현재 MK 세션을 그대로 실행하면 전원 Tech 1/Boat인 현상은 남는다. 위 원문에서 자동 스폰/등록을 제외했다는 설명은 최초 프리팹 구성 시점의 기록이며, 이번 후속에서 배 선택과 MK 등록까지 확장했다.
