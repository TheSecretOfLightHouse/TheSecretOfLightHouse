# 이동 중 대포 발사 속도 보정

## 요청과 목표
- 사용자 보고: 달리면서 대포를 쏘면 포탄이 뒤로 날아온다.
- 배 속도를 상속하지 않는 초기 속도를 수정해 발사 순간 배를 기준으로 포탄이 전방으로 나가도록 한다.

## 진행 과정과 결정 이유
- BoatCannon은 `_muzzle.forward * _launchSpeed`만 Cannonball.Initialize에 전달한다. Boat 기본 속도8, 발사속도20, 항해사 패시브2배 및 대쉬1.8배 등의 기존 설정에서 배가 발사체의 월드 전방 속도를 추월할 수 있다. 실제 보고 순간의 배 속도를 포착한 것은 아니며 코드상 재현 조건이다.
- v4의 배 대포 전투와 기술설계의 서버 발사 계약을 확인했다. 문제 대장 N07은 배 이동이 소유 클라이언트 권위로 부분 결정된 상태이므로 이동 권위를 변경하거나 클라이언트가 임의 발사 속도를 보내게 하지 않았다.
- 서버 발사 시 `포구 전방 * 기존 발사속도 + 포구 이동속도`를 사용한다. 서버에서 Dynamic인 배는 Rigidbody.GetPointVelocity로 선형·회전 이동을 포함한다.
- 원격 배의 서버 Rigidbody는 Kinematic이라 물리 속도를 그대로 사용할 수 없다. 서버 LateUpdate에서 포구 위치와 Time.timeAsDouble의 차이를 기록하고, 발사 직전 최신 위치를 한 번 더 표본으로 삼아 이동속도를 얻는다. 같은 시간의 재표본은 기존 값을 유지하며 OnStartServer에서 표본을 초기화한다.
- 발사 권한·소유자·탑승·난파·쿨타임 검증, 피해량·중력·수명·Cannonball 서버 충돌 판정은 유지했다.
- 에디터는 처음 조회 때 Play 중이었으나 로드된 BoatCannon은 없었다. 수정 검증을 위해 Play를 종료했다. 다른 사용자 미커밋 변경은 보존했다.

## 변경 파일과 결과
- `Assets/01.Scripts/05.Player/Boat/BoatCannon.cs`: Rigidbody 캐시, 서버 포구 이동 표본, 발사 속도 합산.
- `docs/03-technical-design.md`: 현재 발사 속도 계약과 검증 범위 연결.
- 이 원문 및 담당자 pointer.
- 프리팹·씬·Mirror 외부 코드 수정 없음. BoatCannon을 사용하는 네 배 모두 같은 코드 적용.

## 검증
- Unity recompile completed, failed=false, errors=[], compilationFailed=false.
- 실제 GetLaunchVelocity를 격리 PreviewScene에서 호출했다. Kinematic 배의 관측 포구 위치차를 입력하고, 반환된 속도를 실제 Rigidbody에 적용해 별도 PhysicsScene에서0.1초 시뮬레이션했다. 활성 씬의 물리를 진행한 검사가 아니다.
- 전방 배 속도0/8/24/43.2/-8에서 포탄 월드 속도20/28/44/63.2/12를 확인했다. 각 조건의 배 이동을 제외한 전방 변위는 모두2m로5/5 통과했다. 이는 배 대비 초기 전방속도20m/s 확인이며 전체 비행·충돌 시험이 아니다.
- Dynamic 배의 병진 및 회전 속도 합산은 실제 GetPointVelocity 결과와 일치해1/1 통과했다.
- 앞선 MCP 타임아웃과 Edit Mode에서 SceneManager.CreateScene 사용 실패는 통과로 세지 않았다. 별도 물리 씬을 가진 EditorSceneManager.NewPreviewScene으로 바꿔 위 검사를 완료하고 임시 오브젝트·씬을 해제했다. 콘솔 기록을 지우지 않았다.
- 실행하지 못한 확인: 사용자의 실제 달리기 발사 재현 및 원격 클라이언트 M2 발사·충돌·네트워크 지연 조건. 실제 보고 순간의 원인 확정 및 네트워크 통합 통과는 주장하지 않는다.

## 남은 일과 차단 조건
- 실제 탑승 상태에서 정지·전진·항해사 고속·대쉬·후진 중 발사 체감 확인.
- 원격 소유 배의 서버 관측 위치 표본과 포탄 동기화가 지연 환경에서도 적절한지 M2 확인. 새 지연 보상·클라이언트 발사 예측은 추가하지 않았다.
