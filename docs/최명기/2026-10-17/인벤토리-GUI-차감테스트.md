# 인벤토리 GUI 차감 테스트
작성자: 최명기
작성일: 2026-10-17
갱신일: 2026-10-17
상태: 구현됨(미검증)

## 요청과 결과
- 사용자 요청으로 기존 InventoryDebugPanel에 자원 ID·요청량 입력과 차감 버튼, 서버 처리 결과를 추가했다.
- 기존 사용자가 작성한 InventoryData/PlayerInventory.TryRemoveTo를 호출하며 해당 구현은 변경하지 않았다.
- 호스트·원격 모두 자기 소유 패널에서 Command를 요청하고 서버가 차감한다. 결과는 요청자 TargetRpc로, 수량은 기존 Owner SyncDictionary로 전달한다.
- 수량 패널은 로컬 플레이어이며 _showPanel=true일 때 표시한다. 차감 시험 조작과 서버 시험 실행은 Debug.isDebugBuild로 제한하며 양수 입력과 서버 요청 간격을 검사한다. 실제 작업대 투입·거래 복구 기능은 포함하지 않는다.

## 검증
- git diff --check 통과. 기존 사용자 변경 보존.
- Unity 컴파일·Weaver·Play·M2는 미실행. 화면 배치와 클릭 입력도 실제 확인 필요.
- 시험: 보유 3/요청4→차감3/잔량0, 보유5/요청2→차감2/잔량3, 빈 자원→차감0, 원격 본인 수량 갱신과 타인 수량 불변.

## 다음 행동
- Editor 또는 Development Build에서 기존 인벤토리 패널의 ID·요청량을 입력해 차감하고 결과 문구와 수량을 비교한다.

## 반복 차감 수정
- 사용자 실행 결과: 완료 후 다시 클릭해도 새 요청량만큼 계속 차감되는 문제 확인. 기존 버튼은 단순 차감 시험이어서 누적 필요량을 관리하지 못했다.
- 총 필요량을 설정하는 '새 투입 테스트 시작'과 '남은 필요량만큼 투입'을 분리했다. 서버가 대상 자원과 남은 필요량을 보관하고 실제 차감량만큼 필요량도 줄인다. 필요량 0에서는 추가 차감하지 않는다.
- 입력 숫자 변경만으로 진행 중 목표가 바뀌지 않는다. 새 테스트 시작은 새 목표를 명시적으로 만들며 이전 투입 자원을 반환하지 않는다. 본편 작업대 상태가 아닌 개인 디버그 목표다.
- git diff --check 통과. Unity 컴파일·Play·M2 재시험 미실행. 보유3/필요4→투입3/필요1→추가획득 후 투입1/필요0→재클릭 무차감을 확인해야 한다.
