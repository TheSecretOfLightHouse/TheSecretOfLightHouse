# 전체 폴더 현황과 최명기 작업 우선순위
작성자: 최명기
작성일: 2026-10-17
갱신일: 2026-10-17
상태: 조사 완료(정적 확인), 게임 실행 미검증
브랜치·기준 커밋: feature/myeongki / c641fa7

## 요청과 목표
- 전체 폴더를 살펴 최명기(Player·시스템·UI)의 할 일과 알아야 할 사항을 정리한다.
- 폴더 구조·자체 코드·기획·작업 기록을 대조했다. 모든 외부 에셋의 내부 내용까지 전수 검수한 것은 아니다.

## 진행 과정과 결정 이유
- 전체 pointer → 사용자에게 담당 확인 → 최명기 pointer → 연결된 채집 원문·인수인계를 읽었다. 전체 pointer에는 최명기 링크가 없지만 개인 pointer와 기록은 존재한다.
- 시스템·기술·v4·승패/투표·채집 결정·문제 대장·로드맵·담당표와 실제 코드를 대조했다. 과거 문서의 완료/미구현 표기를 그대로 사용하지 않았다.
- Assets 하위 구조, 자체 스크립트 도메인, 씬·프리팹 목록, 빌드 씬 설정, Packages/ProjectSettings 위치, 문서·도구·Git 상태를 확인했다. Library/Temp/Logs/UserSettings와 외부 플러그인 내부는 조사 대상에서 제외했다.
- 코드·씬·에셋은 수정하지 않았다. 제시한 순서는 권장안이며 새로운 게임 규칙 확정이나 팀원 합의가 아니다.

## 현재 상태
| 범위 | 확인한 사실 | 해석 |
|---|---|---|
| Network | 접속·로비·판 시작/종료와 IMatchStartGate 등록 API 존재 | 기반을 재작성할 일이 아니라 본편 상태·월드와 연결할 일 |
| World | 맵·시간·날씨·부력·자원 지점/잔량/회복 코드 존재 | 실제 씬 구성과 다인 검증은 별도 |
| Interaction | Relay·Router·거리/주체/판 상태 검사·세션 존재 | 기능별 파괴·소비·구조 계약까지 대신하지 않음 |
| Player | 이동·승하선·내구도·HFSM·입력·채집 시험·픽업·개인 수량 기반 존재 | 완성된 전체 플레이 흐름은 아님 |
| Monsters/Mafia | AI·돌진/애니메이션·투표·확인·심해 계산 코드 존재 | 본편 상태 전환과 Player 연결·원격 검증 필요 |
| Lighthouse | 04.Lighthouse 아래 C# 0개 | 조사한 자체 스크립트 범위에서 작업대→등대 본편 구현 미확인 |
| Systems/UI | 08.Systems·09.UI 아래 C# 각각 0개 | 본편 게임 단계·최종 승패·HUD 통합이 가장 큰 잔여 범위. Network 로비 UI와 Player 디버그 패널은 다른 폴더에 존재 |

## 최명기 권장 작업 순서
| 순서 | 작업 | 현재 공백·위험 | 완료 확인 |
|---|---|---|---|
| 1 | 재현 가능한 2인 시험 경로 확보(MK01/03) | Myeongki Offline은 Lobby와 MKTestScene을 참조하지만 EditorBuildSettings 활성 목록에는 Myeongki 씬이 없음 | Editor에서 대상 빌드 프로필과 씬 목록 확인 후 로비→게임 전환·각자 입력·종료 확인. 공유 설정은 김지훈과 조율 |
| 2 | 현재 픽업 2인 회귀(MK03) | 서버 지급/제거·Owner 수량 동기화 코드는 있으나 최신 코드 실행 증거 없음 | 원격 드롭 표시, E키 1회 지급, 두 명 동시 획득 시 한 명만 지급, 양 화면 제거, 타인 수량 비노출, 잘못된 ID 실패 시 드롭 유지 |
| 3 | 본편 파괴형 채집(MK03, W05/N09/N10) | Probe/Handler는 LocalHarvestTestSpot 배열 경로. Handle은 드롭 생성만 하고 원본 HP·파괴·World.TryConsume을 처리하지 않음 | 실제 World SpotId→서버 파괴/승인량→드롭→E키→개인 수량. 마지막 잔량 동시 요청과 생성 실패에서도 자원 합계 보존 |
| 4 | 게임 상태·최종 승패 뼈대(MK06) | Systems 코드 미확인. 접속 MatchPhase와 숨은 단계/의식/최후 전투는 다른 의미 | 판 시작/중단, 의식 기한 정지·표 잠금, 소환 시 기존 타이머 제거, 새 수리100%/HP0 조건 보고→최종 결과 1회. 미정 경합은 결정 필요 |
| 5 | 배 피해→난파→구조(MK02/04) | 서버 Wrecked→Owner.SetDowned 호출은 존재. Mafia SetMafiaDowned 본편 호출은 자체 코드 검색에서 미발견. 난파 배는 RestoreDurability가 거부하므로 복귀/배 복구 별도 필요 | 원격 피해·난파·행동 제한·시민 투표 허용·마피아 확인/소환 거부, 직접/자동 구조 경합 시 복귀 1회 |
| 6 | 대포와 자원 소비(MK02/03) | TryFire는 재장전 검사와 CannonFired 발행까지. 자체 코드에서 소비자 미발견. 개인 인벤토리 TryRemoveTo 부분 차감은 존재하며 작업대 거래·실패 복구·용량 제한은 후속 | 서버 발사/명중/피해·재장전, [API](../../unity/PLAYER_INVENTORY_API.md)로 작업대/수리 연결·수지 검증, 용량 결정 후 적용 |
| 7 | 직군·보상·실제 HUD/지도(MK05/06) | PlayerAbility/Runner는 있으나 구체 능력 파생 타입 미발견. 직군·배정·UI 세부 미정 | 확정 직군부터 서버 판정·일차 제한·소환 후 제한. 기존 보상은 최후 전투 유지, 새 전투 수리 보상 중복 지급 금지 |

순서 4의 계약 준비는 채집과 함께 진행할 필요가 있다. 모든 Player 기능과 화면을 완성한 뒤 승패 통합을 시작하면 10/24 전 전체 판 검증 목표에 부담이 된다는 판단이다. 일정의 실제 달성 여부는 확인하지 않았다.

## 먼저 합의할 것
- 강민서·김지훈: 실제 HarvestSpot 식별, Adapter 하나의 소유 구성, World 잔량 승인량과 드롭 생성 실패 복구, 원본 파괴/재생 표시. 시험 Handler와 HarvestHost는 같은 HarvestSpot Adapter를 등록하므로 함께 켜면 등록 실패 위험이 있다.
- 채집 기획 §5: 원본 HP/타격 수·채집 시간·도구, 드롭 수/단위, 파괴/복구 시점, 인벤토리 용량·소비. 시험값을 확정 규칙으로 바꾸지 않는다.
- 김지훈·박태욱: 단계 입력/조건 보고 API와 최명기의 최종 종료 확정, 개인/공개 응답 범위. K01 동일 시점 승패·소환 경합, K02 마지막 밤 정확한 기한, K03 월드 시간·일일 효과는 미정이다.
- 난파 W10~W13: 구조 시간/거리·비용·잔액 부족·전원 난파·복귀 배 상태·화물 손실. 검토 원문의 해결 제안은 승인된 규칙이 아니다.
- 직군 상세·4인 배정 시점/중복 여부, 밤 토론 수단, HUD/지도 정보 범위.

## 알아야 할 규칙과 협업
- 이동·배 물리는 소유 클라이언트가 계산하고 게임 결과는 서버가 판정한다(N07 부분 결정). 모든 PC에서 배 물리를 중복 실행하는 방식으로 반동 문제를 해결하지 않는다.
- 자원 원본은 좌클릭 파괴 대상, 드롭은 E키 획득 대상이다. SpotId·netId·ResourceId는 서로 다른 식별자다.
- 개인 수량·개인 표는 본인만, 확인 성공/소진은 마피아만 받는다. 심해·봉인은 전원 비공개다.
- 판 진행 중 한 명이라도 이탈하면 승패 없이 판을 종료한다. 재접속은 10/25 이후 선택, 인게임 보이스/무전은 삭제된 범위다.
- 로비·로딩·종료 사유 화면은 김지훈, 본편 시스템·승패·HUD·지도는 최명기다. 자기 기능의 서버/클라이언트 동기화도 직접 맡는다.
- 월드 준비 게이트 API는 Network에 이미 있다. 자체 코드에서 World의 RegisterStartGate 호출은 미발견이므로 강민서의 실제 등록·통합 결과를 확인한다.
- 정지 배 충돌 반동은 이전 해결안 철회 상태다. 실제 몬스터/원격 배로 충돌 콜백·소유권·피해·반동을 각각 재현해야 한다. Sleep이 원인이라고 확정하지 않는다.

## 문서와 현재 코드의 차이
- 기술설계/아키텍처/로드맵 일부의 VoteService int ID, 마피아/자기표/잠금 미검사 설명은 낡았다. 실제 VoteService는 uint와 해당 제한을 제공한다.
- 본편 PlayerInteractionInput은 공용 Selector를 사용한다. 과거 PlayerPickupInput 안내를 적용하지 않는다. 이름이 같은 Interaction 영역 입력 어댑터와 중복 부착하지 않는다.
- 매니저 시작 게이트는 이미 구현됐다. 과거의 “매니저는 로딩만 검사” 설명을 현재 미구현 근거로 사용하지 않는다. World 등록은 별도다.
- 최초 조사 때 전체 WORK_POINTER의 최명기 링크가 누락돼 있었다. 2026-10-17 문서 감사에서 복구했다. 최초 조사 당시 미수정이라는 기록과 현재 진입점 상태를 구분한다.

## 변경 파일과 검증
- 이번 변경: 이 조사 기록 추가, 최명기 POINTER의 이번 조사 행 추가.
- 기존 미추적 Player 모델/텍스처/재질·Tech 1 프리팹을 보존했다. 코드 작성자나 에셋 사용 여부를 추측하지 않았다.
- 실행: Git 브랜치/로그/status, 자체 코드와 호출자 검색, 폴더/씬/프리팹/빌드 설정 및 문서 대조.
- 미실행: Unity Editor 상태/Console 확인, 컴파일·Play·빌드·M2/M3. 따라서 동작 통과나 실제 플레이 완성률을 주장하지 않는다.
- 원격 GitHub/SVN 상태와 다른 브랜치/PC는 조회하지 않았다.
