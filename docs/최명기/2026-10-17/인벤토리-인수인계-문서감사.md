## 김지훈 검토에서 확인할 API 질문
1. **어디서 누구에게 호출하나?** 서버 처리기에서 검증된 context.Sender.identity의 PlayerInventory를 사용한다. [Server]는 요청 전송 기능이 아니다. 카탈로그를 인벤토리와 패널에 각각 확인한다.
2. **부족하면 실패인가?** 아니다. 보유3/요청4는 3 차감·반환이다. 작업대는 현재 남은 필요량 이하로 요청하고 실제 반환값만 반영한다.
3. **완료 후 또 누르면?** 개인 API는 필요량을 모른다. 작업대의 필요량0 검사·완료 잠금이 필요하다. 디버그 목표의 차감 제한은 본편 작업대 구현이 아니다.
4. **중복·부분 실패를 보장하나?** 개인 API는 거래 ID·예약·복구 이력이 없다. 기존 Router 중복 검사와 별개로 거래 단위를 정하고 실패 복구/복구 실패 및 새 번호 반복을 처리해야 한다.
5. **인출·로그는 있나?** 개인 TryAdd만 있다. 공용 잔량 차감·역할 검사·제작 경합·v4의 서버 투입/인출 기록은 처리기 연결 후속이다. 마피아 전용 인출과 시민 실패 복구를 구분한다.
6. **개인 정보와 새 판은?** Owner 동기화지만 호스트는 서버다. UI 이벤트는 초기 스냅샷을 대체하지 않는다. InventoryReset은 서버 수량 초기화가 아니다. 새 판 객체 수명을 검증해야 한다.
7. **다 구현하고 검증했나?** 아니다. 본편 처리기는 조사한 04.Lighthouse에서 미확인이다. Unity 컴파일·Weaver·원격 실행 증거는 이번 감사에서 확보하지 않았다.

위 질문에 대한 현재 사실과 한계를 [API §6](../../unity/PLAYER_INVENTORY_API.md#6-연결-전-확인표와-수지-검증)에 모았다. 김지훈과 API 확장·실패 정책을 합의한 기록으로 해석하지 않는다.

## 기획·코드 대조와 남은 결정
- **W08 부분 결정:** 공용 인출은 마피아만, 시민 본인 투입분도 인출 불가. 한도·속도·시점·제작 경합·취소는 미정이다. 이번 문서 보완은 역할 검사 구현 완료가 아니다.
- **N09 계약 확인 필요:** 개인 부분 차감은 존재하지만 작업대/개인 상태의 단일 성공·실패 복구·중복 처리는 미연결이다. 부분 투입 허용과 거래 중간 유실 허용은 다른 의미다. 검토 원문의 전체 성공/실패 제안을 부분 투입 금지로 적용하지 않는다.
- **N10 부분 구현:** 공용 송신자·거리·판 단계·번호 검사는 기반에 있고 자원·권한·필요량은 기능별 검사다. API 직접 호출 시 이 공통 검사가 자동 실행되지 않는다.
- **R22 계약 확인 필요:** 소환 이후 마피아 개인 화물·모듈 처리 정책은 미결이다. 개인 API가 인벤토리 비활성화/화물 해제를 보장하지 않는다.
- v4 §7.2 투입·인출 서버 기록과 최신 공용 인출 결정, 승패·투표 결정의 최후 전투 수리/HP 분리를 대조했다. 새 수치·규칙은 확정하지 않았다.

- 외부 링크 접속·원격 GitHub/SVN·비밀값 전수 탐지·스킬 사본 비교는 이번 범위에서 미실행이다. 상대 링크의 파일 존재 검사와 제목 앵커의 의미 검수는 구분한다.
- 코드 리뷰의 정적 추론은 실행 결함 재현이 아니다. Inventory/본편 기능의 품질점수·SQALE 또는 보안 인증은 이번 평가 대상이 아니다.
