## 2026-10-17 풀 반환 연결 준비
- 사용자 후속 요청으로 ResourcePickup에 서버 회수 성공 시 RecycleRequested 이벤트를 추가했다. 구독자가 없으면 기존 Destroy 경로를 유지한다.
- TryResetForReuse는 netId가 0일 때만 내용물과 초기화·회수 플래그를 초기화한다. 스폰 중 초기화로 중복 회수되는 것을 방지한다.
- World·Player 검색에서 기존 잔해 풀을 찾지 못했다. World 코드는 변경하지 않았다. 풀 관리자는 객체 생성 시 이벤트를 한 번 구독하고, 반환 시 UnSpawn → 비활성화 → 풀 보관, 대여 시 활성화 → TryResetForReuse 성공 확인 → TryInitialize 성공 확인 → Spawn 순서로 연결해야 한다. 풀 소유 해제 시 구독도 해제한다.
- Mirror 로컬 소스의 UnSpawn과 Server 속성 Weaver guard(NetworkServer.active)를 확인했다. 클라이언트도 풀링하려면 별도 커스텀 spawn/unspawn 핸들러가 필요하다. 호스트 unspawn 콜백과 서버 이벤트에서 같은 풀에 이중 반환하지 않도록 분리해야 한다.
- 변경 코드 git diff --check 통과. Unity 컴파일·회수/재사용·원격 시험 미실행. 전체 풀링 완료가 아닌 Player 반환 API 구현 상태다.
