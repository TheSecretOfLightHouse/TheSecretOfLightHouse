## 요청과 목표
- 배 프리팹에 탐조등과 공중 빛줄기를 추가하고 시험 환경을 구성한다.
- 진행 중 사용자가 실제 테스트는 직접 하겠다고 했다. Play 시험을 수행하지 않고 연결·정적 검증을 진행했다.

## 진행 과정과 결정 이유
- unity-cli와 기존 디버그 UI 패턴을 검토했다. 최초 테스트 패널안은 컴파일 대기 중 더 단순한 컴포넌트 ContextMenu로 바꿨고 임시 패널 소스·meta는 정리했다.
- 기존 전역 BoatModule·SearchlightModule 타입을 보존했다. SearchlightModule에 빛줄기 Renderer를 추가해 조명과 같이 켜고 끄도록 했다. 참조 누락 시 전용 Light 자식 MeshRenderer를 Awake에서 캐싱한다.
- 실제 안개 산란 대신 가벼운 additive 원뿔 Mesh·URP 셰이더로 빛줄기를 표현한다. 물체를 비추는 Spot Light와 별개이며 물체 뒤의 원뿔이 완벽하게 차단되는 볼륨 조명은 아니다.
- 에디터 API로 Boat.prefab에 Equipment·SearchlightModule과 SearchlightAnchor/Beam을 추가하고 참조를 저장했다. 기존 컴포넌트·사용자 변경 보존.
- MKTestScene에 충돌체 없는 밝은 시험 표적 3개를 SearchlightTestTargets 그룹으로 추가했다. 기존 낮 조명·환경 설정은 유지한다.
- Equipment의 시험 메뉴는 UNITY_EDITOR 범위로 제한했다. 서버에서 기존 TryInstall/ApplyDamage를 호출하며 실제 인벤토리를 소비하지 않는다.

## 시험 절차
1. Offline에서 Host로 시작하고 자기 배에 탑승한다.
2. 실행 중인 자기 배의 BoatModuleEquipment 컴포넌트 메뉴에서 Test/Install Searchlight (No Inventory)를 선택한다.
3. SearchlightAnchor의 Light와 Beam Renderer가 함께 켜지는지 확인한다.
4. 밝아서 구분하기 어렵다면 Play 중 MKTestScene의 Directional Light를 잠시 끄고 표적을 비춘다. 환경 전체를 바꾸는 영구 야간 설정은 하지 않았다.
5. 다른 클라이언트에서 같은 배의 조명·빛줄기 표시를 확인한다.
6. 호스트에서 배 컴포넌트의 Test/Wreck Boat를 선택하면 장착 목록·조명·빛줄기가 제거돼야 한다. 다음 시험은 판을 다시 시작한다.

## 검증과 제한
- Unity 에디터에서 prefab 조명·beam 참조 저장 재조회 확인. 테스트 씬 표적 3개 확인.
- beam shader의 ShaderUtil 메시지 목록 비어 있음 확인.
- 컴파일 요청이 오래 대기·시간 초과됐다가 풀렸다. 최종 소스 import·컴파일 후 compilationFailed=false·isCompiling=false, TestInstallSearchlight/TestWreckBoat 메서드 로드 확인. SearchlightModule의 beam 필드·저장 참조도 확인했다.
- 실제 화면·Play·원격 결과는 사용자 시험 전이며 통과로 보고하지 않는다.
- 임시 수치: Light 거리18·각도50도·강도8, 빛줄기 길이18. 최종 기획 수치가 아니다.

- 실제 Play·야간 화면·원격 화면은 미검증. 기존 사용자 직접 시험 방침을 유지했다. 새로 시작한 판에서 장착 후 밝기와 경계를 확인해야 한다.

## 2026-10-20 실행 화면 확인 후 조명 종류 정정
- 사용자 지적으로 현재 메인 에디터의 MKTestScene Play 및 Game/Scene 캡처를 확인했다. Game 화면에서 배와 캐릭터가 과하게 밝았다.
- 앞선 조정에서 LightType 숫자 2를 잘못 해석했다. 실제 조명은 Spot이 아닌 Point였고 조사각 수정이 전방 조사에 적용되지 않았다.
- Boat.prefab을 에디터 API로 수정: LightType.Spot 명시, 광원을 배 로컬 (0,0.4,0.65)로 옮겨 전방 배치, 아래로8도. 거리35·강도40·전체각80·내부각50 유지.
- 현재 Play 중 SearchlightAnchor 2개에도 같은 종류·위치·각도를 적용해 즉시 확인 가능하게 했다. enabled와 장착 상태는 보존. Play 종료·씬 저장은 하지 않았다.
- 에디터 응답에서 실행 조명 Spot 확인 및 Game 캡처 실행. 현재 배가 상승 중이고 화면 앞에 시험 표적이 없어 전방 물체 식별 효과는 아직 미검증이다.

## 2026-10-20 손전등처럼 전방 표면이 밝아지는 효과 재조정
- 사용자 확인: 공중 빛줄기 대신 배 앞 수면·바위가 손전등처럼 환하게 드러나는 효과를 원함.
- 현재 에디터는 Play 종료된 Offline, 탐조등 인스턴스 없음. 기존 사용자 씬을 바꾸지 않고 NewPreviewScene에 임시 Lit 표면·거리12/22/28 표적·동일 위치/방향 Spot을 만들어 Camera.Render로 밝기0/40/2000 비교 PNG를 생성했다. 임시 scene·객체·재질·RenderTexture는 finally에서 정리했다.
- 시각 확인: 강도40에서는 가까운 표면만 약하게 밝고 표적이 어두웠다. 강도2000에서 전방 표적3개와 조사 표면이 명확하게 밝아짐을 확인했다. 물리 거리 감쇠를 고려하지 않고 낮은 강도를 적용한 앞선 조정의 한계를 확인했다.
- Boat.prefab Light를 강도2000·거리45·전체각65·내부각45로 조정하고 저장 재조회 확인. Spot·전방위치·하향8도·Beam 비활성 유지. 초기 시각 조정값이며 최종 게임 밸런스 확정 아님.
- 검증 범위: 격리된 URP Lit 표면 렌더 비교. 실제 게임 수면 셰이더의 추가 광원 반응·파도·주야간·M2는 미검증. 수면이 추가 광원을 받지 않으면 World 셰이더 협의가 별도로 필요하다. World/공용 렌더 설정은 변경하지 않았다.
- 실제 변경: Boat.prefab과 본 작업 기록/pointer. Offline 씬 변경 없음, 새 코드/에셋 없음.

## 2026-10-20 Point Light 장착 효과 연결
- 사용자 추가 Point Light를 프리팹에서 확인: 로컬(0,0.46,-0.29), 흰색·강도2·거리3.5·항상 켜짐. 사용자가 변경한 Spot 강도1000·거리20은 유지했다.
- SearchlightModule에 직렬화 _fillLight 추가. Awake/ApplyEffect/RemoveEffect에서 기존 Spot과 함께 꺼짐/켜짐/꺼짐 처리. 기존 Test 장착과 난파 동기화 경로를 재사용하며 네트워크 계약은 변경하지 않았다.
- 에디터 API로 Boat.prefab의 Point Light를 _fillLight에 연결·기본 enabled=false 저장. Spot과 같은 색으로 맞추고 기존 낮은 강도2·거리3.5를 근거리 보조광으로 유지해 전방 Spot을 보완한다. 실제 시각 조화는 사용자 확인 필요.
- Beam 확인: 물체 조명과 독립된 MeshRenderer이며 모든 코드 접근에 null 검사 존재. 오브젝트 삭제 시 실제 조명은 유지된다. 사용자는 삭제 가능 여부를 물었으므로 이번에는 삭제하지 않고 비활성 보존. 공유 mesh/material/shader 파일의 삭제 가능성까지 검증한 것은 아니다.
- 검증: Unity 컴파일 완료·failed=false·errors=[]·compilationFailed=false. 격리 프리팹에서 초기 두 조명 off, ApplyEffect 후 두 조명 on/Beam 비활성, RemoveEffect 후 두 조명 off 확인. Missing Script 0. 이 시험은 효과 메서드 직접 호출이며 실제 Test 메뉴·네트워크·야간 화면 시험을 대신하지 않는다.
- 변경: SearchlightModule.cs·Boat.prefab·작업 원문/pointer. 씬·외부 에셋 수정 없음.
