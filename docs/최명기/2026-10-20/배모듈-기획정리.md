## 요청과 목표

사용자가 배 모듈의 자세한 기획 문서 작성을 요청했다. 첫 모듈 탐조등, 배당 1개, 향후 종류 확장, 난파 시 소실 결정을 기준으로 정리했다.

## 진행 과정과 결정 이유

- 후속 확정: 탐조등·수심 경보기·선체 안정기 3종과 효과 방향을 기준 기획에 반영했다. 기존 미채택 후보 표기를 정정하고 수치·감지·부력 연결은 미정으로 유지했다. 앞선 탐조등의 타 플레이어 빛 공개 요구도 확정/미정 표기에 반영했다. 재료비·교체·반출 API·World 연결은 임의 확정하지 않았다. 문서 수정만 수행했다.

- 후속 사용자 결정: 배 모듈은 하선이 아닌 자기 배 탑승 중 장착한다. 기준 기획의 확정 규칙·서버 검사·시험 항목과 v4 안내를 갱신했다. 작업대 사용 조건 변경으로 확대하지 않았다. 문서 검색으로 기존 하선 장착 조건의 잔존 여부를 확인했으며 게임 코드·실행 검증은 변경하지 않았다.

- v4 3.1·7장, 작업대 모듈 결정, W03·W05·W07과 WorkbenchNet·ModuleLedger·ModuleRecipe·ModuleState를 대조했다.
- 확정 규칙·탐조등 표현 제안·미정 수치와 연결 계약을 분리했다. 이전 추천 모듈이나 슬롯 거절·자동 점등·운반 방식은 사용자 확정으로 기록하지 않았다.
- 공유 기획은 design/boat-module-decisions.md에 두고 읽기 안내·문제 대장·v4 안내에서 연결했다. 직군 설명은 중복 검토 맥락으로만 인용했다.

## 변경 파일과 결과

- 배 모듈 기획 신규 작성, 기준 문서 진입 링크와 W03 현황·담당자 pointer 갱신.
- 게임 코드·씬·프리팹 수정 없음. 기존 미커밋 변경 보존.

## 검증

- 문서·기존 코드 정적 읽기, 새 상대 링크 대상 존재 및 문서 diff 확인.
- Unity 컴파일·Play·멀티플레이 미실행. 문서의 시험 목록은 계획이다.

## 남은 일과 다음 행동

- 빛 설정·켜짐·공개 범위, 제작품 소유·운반·거리·교체 정책 결정 후 장착 본체와 첫 효과 구현.
- 작업대 완성품 이전·개체 상태·존재 제한 연결은 후속 계약.

## 2026-10-20 대체 모듈 논의
- 사용자: 탐조등은 유지할 만하지만 수심 경보기·선체 안정기의 매력이 애매해 대안 요청.
- 기준 기획·v4·시스템/기술 설계·승패 결정·W03과 Player/Boat 코드를 정적으로 대조. 현재 종류별 전용 슬롯·다종 동시 장착이 최신 규칙이며 대장 W03의 배당1개 요약은 낡은 상태다.
- 수심 경보기는 위험 지형의 빈도·가시성, 안정기는 흔들림 완화의 실제 체감에 가치가 의존한다는 설계 가설. Player/Boat 검색에서 두 효과 구현은 발견하지 못했고 enum·장착 허용은 존재한다.
- 대화 제안: 선회 보조 장치(급선회·감속), 신호 부표 투하기(위치 표식), 연막 발생기(시야 차폐). 직군 중복·표식 정보 범위·연막의 아군 방해 및 렌더링 검증 필요를 함께 제시. 미채택 제안이며 기존 확정 기획 변경 없음.
- 게임 코드·에셋 수정 및 Unity/다인 실행 검증 없음. 기존 미커밋 변경 보존. 다음은 사용자 선호 확인 후 후보의 효과·입력·제한 구체화.

## 2026-10-20 4종 상세 기획 작성
- 사용자 확정: 탐조등·대쉬·장애물 경보·선체 안정기 4종으로 상세 기획 요청. 수심 경보기 목록을 교체하고 대쉬 추가. 기존 종류별 전용 슬롯·동시 장착·탑승 장착·난파 소실 유지.
- 기준 기획을 4종 상세안으로 재작성. 효과·입력·취소·공개 범위·상호작용·제작 이전·수명·네트워크 권위·현재 코드 차이·검증 계획을 포함했다. 세부 동작과 초기 시험값은 사용자 채택 전 제안으로 명시했다.
- 대쉬는 가속안, 경보는 고정 충돌 지형 경고안, 안정기는 롤/피치 완화안으로 제안. 대쉬 시 경보 거리 확장, 환영 섬 진위 유출, 기본 속도 갱신과 대쉬 충돌, 안정화의 간접 피해 변화 검증을 명시했다.
- 코드 조사: 공통 장착/탐조등 존재. enum은 기존3종, 나머지 전용 효과는 Player/Boat 검색에서 미발견. 기본 World 안정화는 모듈 구현으로 세지 않았다.
- 변경: 기준 기획, W03 요약, v4 상단 후속 결정 안내, 본 원문과 pointer. v4 본문·게임 코드·씬·에셋 변경 없음. 기존 미커밋 변경 보존.
- 검증: 문서 참조 파일 존재·주요 문구 검색·diff 공백 검사 수행. Unity 컴파일/Play/M2/4인 시험은 문서 변경 범위여서 미실행. 실제 재미·밸런스 미검증.
- 남은 일: 상세 제안 채택·수치/입력/제작 계약 결정 후 구현. 이번 요청은 상세 기획 작성으로 완료하며 코드 구현은 수행하지 않음.
- 검증 보충: 수정 문서 범위 git diff --check 통과, 기준 기획의 Markdown 문서 링크 대상 모두 존재. 전체 diff 검사에서는 기존 MKTestScene.unity 공백 경고 2건이 남았으며 해당 씬은 수정하지 않았다.

## 2026-10-20 배 모듈 레시피·김지훈 전달 계약
- 사용자 위임: 등대 제작 방식 참고 후 배 모듈 레시피·연결 내용을 알아서 정리 요청.
- 등대 기준 기획과 실제 레시피4개·TryCraft/Complete·ModuleInteractionHandler를 읽어 대조. 별도 제작 시간이 없고 공유 보관하며 탑승 중 Deposit/Craft를 거절하는 현재 구조 확인.
- 기존6종 자원 안에서 초기 배 레시피4개 설정. 공유 보관·즉시제작·상한0·근거리 자기배 탑승장착·성공시1개소비 기준을 배 기획9절에 정리. 개인 인벤토리 운반 제안은 대체. 비용·거리10은 시험값이며 타 담당 API는 합의/구현 미완료로 구별.
- 김지훈 전달용 인수인계 신규 작성. 외부 메시지/전송·게임 코드·레시피 에셋 변경 없음. 기준 기획·W03·본 원문·pointer 갱신. 기존 미커밋 변경 보존.
- 검증: 문서 링크 대상·충돌 문구·변경 문서 공백 확인. Unity/Play/M2는 문서 작업이므로 미실행, 수급 밸런스·접안거리 미검증.
- 다음: 사용자가 인수인계 전달 후 김지훈과 ID·원자적 소비/상태 이전 API를 맞추고 담당별 구현/시험. 레시피 시험값은 실제 자원 수급 후 조정.
- 검증 결과 보충: 기준 기획·새 인수인계의 문서 링크 대상 존재, 변경 문서 diff 공백 검사 통과. 기존 pointer의 10/18·10/19 과거 링크 일부는 대상 미존재로 확인했으며 이번 범위 밖이라 수정하지 않았다.

## 2026-10-20 사용자 정정 — 완성품 보관 미정
