# 배 모듈 공통 효과 구현
작성자: 최명기
작성일·갱신일: 2026-10-20
상태: 구현됨, Unity 컴파일·격리 효과 검사 확인. 실제 장착·멀티플레이 미검증
브랜치·기준 커밋: feature/myeongki / ea6b0a2(세션 확인값)

## 요청과 목표
- 기존 BoatModuleEquipment를 살리고 공통 부모가 생명주기·이벤트 연결을 맡으며 자식이 효과를 구현하도록 요청받았다.
- 최신 슬롯 규칙은 종류별 전용 1개, 서로 다른 종류 동시 장착, 새 종류 추가 시 전용 슬롯 추가다.

## 진행 과정과 결정 이유
- 실제 기존 전역 BoatModuleEquipment·BoatModuleType을 읽고 이름·SyncList·서버 검사·기존 이벤트를 그대로 보존했다.
- 신규 BoatModule은 공통 구독·해제·현재 상태 복원·중복 적용 방지·클라이언트 실행 조건을 처리한다. 자식은 ApplyEffect/RemoveEffect 및 필요 시 CanApplyEffect를 구현한다.
- SearchlightModule은 Light 참조로 조명만 적용·해제한다. 자동 점등은 시험안이며 별도 조작·수치는 미정이다.
- 초기 네트워크 identity가 아직 연결되지 않은 경우 접근하지 않도록 guard를 추가했다.
- 안정기·경보기의 미정 World 계약은 구현하지 않았다. 부모는 클라이언트 효과 경로이며 서버 판정 효과는 별도 설계가 필요하다. 소유권이 변경되는 효과는 해당 전환 시 RefreshEffect 호출 계약도 필요하다.

## 변경 파일과 결과
- Assets/01.Scripts/05.Player/Boat/Net/BoatModule.cs 및 Unity 생성 meta
- Assets/01.Scripts/05.Player/Boat/Net/SearchlightModule.cs 및 Unity 생성 meta
- 기획의 과거 총1개 표기를 최신 종류별 슬롯으로 정정, 기록·pointer 갱신.
- 기존 장착 코드·enum·씬·배 프리팹 변경 없음. 인벤토리 이전 미연결.

## 검증
- Unity recompile: failed=false, errors=[] 확인(guard 보완 후 재컴파일 포함).
- 저장하지 않는 PrefabUtility 격리 객체에서 실제 Equipment 이벤트·SyncList와 탐조등 연결 검사. 네트워크 identity/client 상태 및 SyncList writable/recording은 시험용으로 구성했다.
- 최초 꺼짐, 목록 추가 시 켜짐, 비활성화 시 꺼짐, 재활성화 복원, 반복 갱신 유지, 다른 종류 추가 영향 없음, 목록 Clear 시 꺼짐: 7항목 true.
- 초기 격리 실행은 Mirror 초기화 미구성 및 비활성 네트워크 쓰기 검사로 실패했으며 시험 구성을 보완했다. 네트워크 전송·실제 키 입력·인벤토리 소비·호스트/원격 Play 시험을 대신하지 않는다.

## 남은 일과 다음 행동
- 배 루트에 SearchlightModule 추가 및 전용 Light 참조 연결. 이번에는 기존 프리팹을 수정하지 않았다.
- 실제 서버 장착→원격 조명→난파 소실 시험, 인벤토리 이전 API 연결.
- 경보기/안정기는 기획 수치·World 연결 확인 후 자식 구현.
