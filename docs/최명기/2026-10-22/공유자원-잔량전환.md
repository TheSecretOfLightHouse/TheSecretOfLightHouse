## 요청과 목표
- 개인별 3회가 아닌 돌 원본 하나당 전원 합계 3회로 기획을 수정한다. 코드는 수정하지 않고 변경 방법을 안내한다.
- 현행 규칙은 [자원 채집 결정](../../design/resource-gathering-decisions.md)에 둔다. 소진 후 원본 유지 결정은 유지한다.

## 진행 과정과 결정 이유
- 2026-10-22: 담당자 pointer → 기존 채집 구현 참고 → 연결된 10/17~18 실제 2인 시험을 확인했다. 당시 개인 잔량 독립성 시험은 과거 규칙의 검증이며 새 공유 잔량의 검증이 아니다.
- Handler가 요청자 identity의 PlayerHarvestProgress를 조회하고 TryConsumeOne/RestoreOne을 호출한다. PlayerHarvestProgress는 플레이어마다 PersonalHarvestData를 생성한다. 따라서 동일 SpotId도 각 플레이어 원장에 따로 기록된다.
- World의 HarvestSpotRegistry → ResourceDeposit에는 지점별 TryConsume 경로가 이미 있다. 공유 잔량을 다시 플레이어마다 만들거나 단순 static 사전으로 바꾸기보다 이 원장에 연결하는 방향을 권장한다.
- N09는 공유 한도만 부분 결정됐고 실패 복구·연동·실행 검증은 남는다. N10의 서버 거리·상태·송신자 검증을 유지한다. W05의 전체 경제표·다른 자원 수치까지 확정하지 않는다. 동일 초기값으로 개인별 3회를 공유 3회로 바꾸면 4인 기준 가능한 총 채집량이 12에서 3으로 줄어드는 영향이 있으므로 공급/소비 밸런스는 별도 확인한다.

## 코드 수정 안내 (미적용 제안)
경로는 `Assets/01.Scripts/` 기준이다.

1. `05.Player/Gathering/Server/HarvestInteractionHandler.cs`: 요청자의 PlayerHarvestProgress 조회·필수 조건 및 개인 TryConsumeOne/RestoreOne 경로를 공유 지점 원장 호출로 교체한다. 송신자·난파·탑승·대상 검사와 공용 Router 검증은 유지한다.
2. `02.World/Harvest/Rules/IHarvestSpotRegistry.cs`의 TryConsume(spotId, 1, out result), 서버 HarvestSpotRegistry/ResourceDeposit를 연결 후보로 삼는다. 본편 지점 등록값을 사용하고 돌 원본 초기 잔량을 3으로 맞춘다. 현재 Handler는 LocalHarvestTestSpot 목록만 해석하므로 메서드 한 줄 교체로 본편 연결이 끝나지 않는다. 로컬 표현과 서버 등록 지점이 같은 SpotId를 가리키도록 해야 한다.
3. 드롭 생성 전 서버에서 잔량 1을 확보하고 성공 시 확정한다. 생성 실패 시 같은 공유 지점에 되돌리는 예약/확정/취소 또는 복구 API를 World 담당과 설계한다. 현재 IHarvestSpotRegistry에는 반환 API가 없으므로 존재하는 것처럼 호출하지 않는다. 단순히 드롭부터 생성하면 실패/경합 시 중복 가능성이 생긴다. 재생 이벤트와 복구의 합계도 보존해야 한다.
4. `05.Player/Gathering/Net/PlayerHarvestProgress.cs`와 `Rules/PersonalHarvestData.cs`는 이 채집 경로의 잔량 원장에서 제외한다. 모든 호출·프리팹 참조 확인 후 제거 여부를 정하며 이번에는 삭제하지 않는다. 서버의 공유 원장을 쓰는 데 원본을 반드시 네트워크 오브젝트로 바꿀 필요는 없다.
5. `HarvestTargetAdapter`와 Handler는 모두 HarvestSpot 변환기를 제공한다. 같은 종류의 변환기 중복 등록을 피하고 실제 지점 위치를 서버가 해석하도록 단일 경로를 정한다. World 잔량은 강민서, 행동·드롭은 최명기, 공용 라우팅은 김지훈 경계이며 타 담당 코드 수정 전 연동 계약을 확인한다.
6. Probe 입력·공유 드롭 생성/획득·소유자 전용 인벤토리 표시는 유지한다. 소진 후 원본도 유지한다. 잔량 UI가 필요해질 경우 서버 상태를 전달하고 클라이언트 카운터를 판정 근거로 쓰지 않는다.
