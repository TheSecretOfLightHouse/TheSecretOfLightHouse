# 줍기 중 이동 애니메이션 전환

## 요청·원인
- 사용자 결정: 줍기 애니메이션 중 이동하면 즉시 걷는 애니메이션으로 전환해야 한다.
- PlayerAnimationSource는 이동 상태를 Walk/Run으로 제공하고 PlayerAnimationDriver는 Speed를0.5/1로 설정하지만, PlayerAnimator의 기존 Pickup→Movement 전환은 Has Exit Time=true, exitTime=0.9738676이어서 줍기 종료 근처까지 기다렸다.
- 같은 세션 review-design-code-gaps 검토 재사용. N09의 획득 거래·중복 계약은 이번 표현 변경으로 해결하지 않으며 아이템 지급·상호작용 판정은 수정하지 않는다. 최신 사용자 결정은 이동에 의한 줍기 표현 중단이다.

## 변경
- `Assets/05.Animations/Player/PlayerAnimator.controller`만 Unity AnimatorController API로 수정·저장. C#·씬·프리팹 수정 없음.
- Pickup의 최우선 전환 `Pickup movement interrupt` 추가: 목적지 Movement, Has Exit Time=false, Fixed Duration=true, duration=0.05초, Speed>0.01, IsDowned=false, IsOnBoat=false.
- 기존 시간 기반 복귀는 유지해 정지한 채 줍기는 끝까지 재생된다. Jump·Dig·아이템 지급·서버 권위는 변경하지 않는다.
- 최초 추가 때 SourceThenDestination/orderedInterruption=false 설정은 이동 중 전환이 반복 재시작되는 것을 실행 표본에서 발견해 채택하지 않았다. 최종 interruptionSource=None으로 바꾸고 재시험해 전환 완료를 확인했다.

## 실제 검증
- Unity 호스트 단독 시험, 런타임 시작 인원만 임시1로 로비 Ready→MKTestScene. 최종 기존 인원 복원, Play 종료, 씬 저장 없음.
- 실제 PlayerActionEvents.Publish(Pickup) 경로로 줍기 표현 시작 후 Input System W 입력을0.15초 뒤 공급. 최종 그래프 Rebind 후 t0.074~0.144 Pickup 상태, t0.180 입력(0,1)/Speed0.5/Movement 전환 중, t0.220 Movement 상태·전환 완료 확인. 이후 이동 유지 중 Movement 유지, 키 해제도 정상 확인. 97% 종료 대기 없이 전환되며 전환 블렌드는0.05초다.
- 정지 상태 Publish(Pickup) 회귀: Pickup 진입 확인 후2초 시점 Movement 복귀·입력0 확인.
- 대상 에셋 git diff --check 통과, diff는 새 전환32줄 추가. GUID 변경 없음.
- 한계: 표현 이벤트와 이동 입력 경로 시험이며 실제 아이템 획득 요청·인벤토리 소비·원격 NetworkAnimator 및 물리 키보드 체감은 이번 시험에 포함하지 않았다. 별도 C# 변경·컴파일은 없음.

## 남은 확인
- 사용자의 실제 줍기 중 이동 체감과 원격 관찰 회귀. 걷는 중 새로 발생한 줍기 표현 자체를 금지하는 별도 규칙은 추가하지 않았다.
