# 경사로 보행 입력 시험

## 요청과 확인 범위
- 사용자 요청: 현재 실행 중인 플레이어에 직접 이동 입력을 넣어 경사로에서 막히는 원인 확인.
- 현재 PlayerMotor에는 사용자가 적용한 지면 normal 투영 이동이 존재한다. 게임 코드와 씬·프리팹 파일은 수정하지 않았다.
- 실행 중 로컬 플레이어 주변 충돌체 조회에서 Plane (1) MeshCollider 확인. 해당 지면 경사 약 24.4도, TryGetGroundNormal=true, Ground Check Distance=0.15, Minimum Ground Normal Y=0.65. 별도 벽은 해당 주변 조회 범위에서 발견하지 못했다.
- 플레이어와 경사로의 조회 마찰은 각각 static/dynamic=0.6, Average. Rigidbody Y 위치 잠금 없음, linearDamping=0, useGravity=true.

## 실제 검증
- Unity 6000.0.83f1 Play 상태. 최초 simulate_key는 포커스가 없는 상태에서 이동 입력 유지 실패. GameView 포커스 후 W 입력 전달 확인.
- 최초 포커스 후 입력 시험에서는 플레이어가 경사로를 지나 바닥 밖으로 떨어졌다. 이후 저장한 출발 위치로 복귀시키고, Input System onBeforeUpdate에서 1초간 W 상태를 공급하고 자동 해제하는 동일 조건 비교를 수행했다. 실제 키보드 검증과 구분한다.
- 출발 좌표 약 (-3.5162,-0.1157,4.6901), 시험 방향 +Z.
- 가속도 10: 1초 후 (-3.5162,-0.0009,4.9432), 속도 (0,0.237,0.523), 입력 (0,1). 전진 약 0.25m로 완전 정지는 아니며 매우 느린 상승.
- 가속도 30: 같은 출발점에서 1초 후 (-3.5162,1.2234,8.6742), 최고 Y 약 1.2543, 입력 (0,1). 경사로 위쪽을 통과했으며 종료 시 Y 속도는 하강 중이었다. 경사 끝 접지 품질의 통과 근거는 아니다.
- 종료 시 W 해제, 임시 입력 콜백 자동 해제, 원래 가속도 10·출발 위치·heading 복구 확인. Play 유지. 파일 저장 없음.

## 판단과 남은 일
- 이번 위치에서 접지 감지 실패나 별도 벽보다, 중력·마찰에 비해 낮은 추진 가속도가 느린 상승의 주된 원인이라는 비교 근거를 얻었다. 마찰 단독 효과를 분리한 시험은 아니다.
- 가속도 30은 진단값이며 확정 설정이 아니다. 평지 출발·정지 감각을 포함한 값 선정 또는 접지 추진 처리 개선은 후속이다.
- 경사 끝·내리막·점프·승하선·원격 클라이언트 회귀는 이번 시험 범위 밖이다. 기존 변경은 보존했다.
