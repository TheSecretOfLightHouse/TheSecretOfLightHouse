# 평지 보행 미끄러짐 개선

## 요청·판단
- 사용자가 평지 보행을 직접 시험한 뒤 개선하도록 요청했다. 앞선 수정 금지 요청은 조사 단계였고 이번 요청에서 PlayerMotor 변경을 허용했다.
- 기존 PlayerMotor는 접지·공중 모두 기존 가속도10으로 출발·제동·방향 전환했다. IdleState는 입력 해제 즉시 속도 배율0을 제공하지만 실제 속도는 점진 감소해 Idle 중에도 몸이 이동했다.
- review-design-code-gaps의 같은 세션 기준 검토를 재사용. N07의 소유 클라이언트 이동 권위는 변경하지 않는다. 평지 가감속의 확정 수치는 확인되지 않아 이번 값은 사용자 조작 확인을 위한 초기 조정값이다. Player 영역은 최명기 담당이며 이번 수정은 해당 영역 안이다.

## 변경
- `Assets/01.Scripts/05.Player/Movement/PlayerMotor.cs`만 게임 코드 수정.
- 접지 중 `_groundAcceleration=30`, `_stopDeceleration=60`, `_turnAcceleration=60`, `_turnAngle=15` 추가. 목표 속도0이면 제동, 현재 속도와 목표 속도 사이 각도가15도보다 크면 전환 가속, 나머지는 출발 가속 사용.
- 기존 `_originAcceleration=10`은 공중 이동에 유지. 이미 직렬화된 기존 값을 바꾸어 공중 반응까지 바뀌는 것을 피하려고 지상 가속도를 별도 필드로 추가했다. AccelerationMultiplier는 세 가지 지상 처리에 모두 적용한다.
- 사용자가 적용한 지면 normal 투영·접지·점프 처리는 보존. 신규 속도 스냅·물리 재질 변경 없음. 기존 씬·프리팹·다른 미커밋 변경 보존.

## 실제 검증
- Unity 6000.0.83f1 컴파일 후 scriptCompilationFailed=false, 새 필드 반영 확인. 대상 코드 git diff --check 통과.
- 호스트 단독 시험을 위해 실행 중 시작 인원만1로 임시 설정, Offline 로비 Ready→MKTestScene. 종료 전 기존 인원 복원, 씬 저장 없음.
- Input System onBeforeUpdate로 W1초→해제0.7초→A0.4초→D0.5초→해제0.7초 공급 후 자동 해제. 기준 위치 (0.43,-1,-3.2), heading0, 평지 Plane에서 시험. 최초 새 판의 다른 스폰 위치에서 시작한 시험은 비교에서 제외하고 기준 위치로 다시 시험했다.
- 수정 전(같은 세션): W 약0.508초에 z속도2.057, 약0.941초에3.867. 입력0/Idle 표본 t1.025 위치z=-1.0259에서 정지z=-0.6101까지 최소0.4158m 이동, 약0.25초 뒤 정지.
- 수정 후: t0.172에 z속도4.8823, t1.000 위치z=1.3444/속도4.8823에서 해제 후 t1.086 위치z=1.4792/속도0. 추가 이동 약0.135m, 정지 약0.09초 이내(벽시계 표본 기준, 정확한 프레임 지연값 아님).
- 방향 전환: 수정 후 A로 x속도-4.8823 도달, D 구간 t2.129 입력(1,0)/속도-3.5646에서 t2.174 속도+0.1532로 전환. 수정 전에는 D 입력 확인 뒤에도 약0.1초 이상 음의 속도 유지. 전환 전 속도가 달라 엄밀한 동일 속도 비교는 아니지만 더 빠른 이전 속도에서도 빠른 반전 확인.
- 정지 점프: Space 입력으로 IsJumping=true, 최대Y=0.2247(시작Y=-1), 착지Y=-1, IsJumping=false 및 속도0 확인.
- 종료: 임시 키 입력 자동 해제, Play 종료, 시험 위치·시작 인원 설정 저장 없음.

## 한계·남은 확인
- 호스트 Input System 시뮬레이션 결과이며 물리 키보드 체감·원격 클라이언트·승하선·수정 후 경사로 회귀는 미검증.
- 체감값은 사용자의 실제 조작으로 최종 조정한다. 네트워크·물리 재질·공용 이동 계약은 변경하지 않았다. 커밋·푸시 없음.
