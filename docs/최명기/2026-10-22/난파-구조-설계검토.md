## 2026-10-23 모듈 물 드롭 목표 확인과 인계 API 요청서
- 사용자가 실제 전송했던 별도 첨부 요청서를 추가 제공해 전문을 확인했다. 해당 문서의 예약/확정/취소 제안·실패 대응 대안·회신 양식을 구현 지시나 확정 설계로 취급하지 않고, 전달용 요청서를 짧은 게임 흐름·구체 예시·담당별 부탁으로 다시 정리했다. 첨부 원본은 보존하고 저장소의 기존 전달 요청서만 갱신했다.
- 전달 대상의 요청에 따라 요청서를 비개발자도 읽을 수 있는 표현으로 다시 작성했다. 함수·변수·자료형 설명을 빼고 게임 동작, 기존 해안 방식과의 차이, 보유 정보 인계·실패 방지·재획득 요청과 담당 범위를 중심으로 정리했다. 문서만 수정했으며 외부 전송 없음.
- 현재 feature/myeongki / f4a4611, b7d1134 포함. 코드가 과거 기록보다 진행돼 자원 전용 계획→생성·차감→복귀와 TimedOut 처리가 연결돼 있다. 90초 자원 전량 드롭·모듈 유지·메인 섬 복귀·새 배 탑승은 사용자 실행 보고이며 AI 직접 검증이 아니다.
- 사용자 최신 정정: 구조 시 자원 종류별 칸+운반 모듈 중 무작위 한 칸 전체를 물에 드롭, 90초 미구조 시 둘 다 전부 물에 드롭. 이후 해안 이동은 민서 담당. 앞선 이번 단계의 모듈 유지 범위는 대체됐다. 지훈 첨부 문서와 공유 모듈 결정의 해안 직접 생성·구조 시 모듈 삭제와 차이가 있어 인계 계약 조정을 요청한다. 팀 합의 완료로 기록하지 않는다.
- 사용자가 TryBuildWreckDropPlan을 혼합 후보로 수정하고 모듈 조회 시험 함수를 추가했다. 사용자 실행 로그 ActorId=1/HasModule=True/Found=True/RecipeId=101/ModuleId=1 확인. AI 게임 코드 수정 성과가 아니다.
- 조회 API는 기존에 존재한다. 부족한 것은 WorkbenchNet 보유 정보와 ModuleInteractionHandler._carrySources·장부를 안전하게 드롭으로 이관하는 공개 계약이다. TryReleaseCarried만으로는 처리기 보유 기록이 남으며, DiscardCarried는 장부 삭제, TryDropCarriedToShore는 해안 생성이라 목표와 다르다.
- 사용자 파일 작성 요청에 따라 [지훈 전달 요청서](../../handover/최명기/2026-10-23/김지훈-난파모듈-물드롭-인계API-요청.md)를 작성하고 pointer를 갱신했다. API 이름/반환형·생성/확정/취소·재획득·제작 상한·수거 잠금·만료 시작은 합의 대상으로 구분했다. 실제 API를 지어내거나 다른 담당 코드를 수정하지 않았다.
- 이번 AI 검증은 코드·Git 상태·상대 링크·문서 diff 확인이다. Unity/MCP 조작·컴파일·Play·외부 전송·커밋·푸시는 하지 않았다. 기존 사용자 PlayerInventory.cs 변경과 별도 BoatShipBody.cs 변경을 보존한다.
- 다음: 사용자가 요청서를 전달하고 지훈 API 계약을 받으면 명기 드롭 생성·정산·목록 제공을 단계별 연결한다. 현재 모듈 실행 미연결, Recovery 실패 재개 및 민서 목록 제공도 남음.

## 진행 과정과 결정 이유
- 최신 모듈 결정 2026-10-20~21을 v4보다 우선했다. 난파 순간 인벤토리 보존, 구조 시 무작위 한 칸 전체 소실, 미구조 재스폰 순간 전량 표류, 두 경우 메인 섬 복귀, 공동 자원 비용 폐기를 확인했다.
- BoatDurability의 서버 난파 판정·동기화와 BoatController의 표시 제거·Downed 연결은 존재한다. BoatController.HandleWrecked는 TryDropAll을 즉시 시도하므로 최신 규칙과 불일치한다.
- InteractionAction.Rescue와 공용 InteractionSessions는 존재한다. 이번 Interaction 검색에서는 구조 전용 처리기를 찾지 못했다. 열거값 존재만으로 구조 구현 완료로 보지 않는다.
- 제안: Player 기능 내부 서버 조정자가 표류 시작·직접 구조·시간 만료·재스폰 정산을 관리한다. 공용 Relay/Router/Sessions를 활용하고, 두 복귀 경로를 단일 완료 함수로 모아 중복 손실·중복 생성 방지. 제안은 확정 규칙이 아니다.
- W10 공동 비용 문제는 폐기됐으나 전원 난파 처리, W11 배 복구, W12 거리·시간·취소·경합, W13 표류 회수 계약은 남는다. W11의 가까운 섬 복귀 설명은 최신 메인 섬 결정과 차이가 있어 그대로 구현하지 않는다.

## 2026-10-22 단계별 구현과 사용자 시험 후속
- 사용자가 직접 코드를 작성하고 프리팹·씬 참조를 연결했다. AI의 게임 파일 직접 수정 성과로 기록하지 않는다.
- 사용자 확정: 난파 후 90초, 구조 시작/취소로 기한 초기화하지 않음. 플레이어는 메인 섬 복귀, 기존 배 제거 후 본인 선착장에 최대 내구도·장착 모듈 없는 새 배 생성. 직접 구조와 시간 만료의 배 복구 방식은 동일.
- PlayerWreckRecovery/WreckRecoveryResult, PlayerController의 배 소유 교체, BoatController의 난파 진입·복귀 하선/RPC, PlayerBoatSpawner의 복구 배 생성·서버 참조 주입, PlayerInventory의 서버 모듈 조회·한 칸 추첨/소실을 단계별 안내했다. 중간 제안 PlayerWreckInventory는 불필요한 래퍼로 철회했다.
- 타 담당 코드 변경 금지 의사를 확인했다. ModuleInteractionHandler에 새 조회 API를 추가하지 않고, 기존 WorkbenchNet.TryGetCarried와 ModuleInteractionHandler.DiscardCarried를 PlayerInventory에서 소비하도록 안내했다. 현재 연결은 지정 작업대 한 곳 기준이며 다중 작업대 보유 조회는 별도 확인 필요.
- 사용자는 호스트의 모듈 단독 후보 조회 성공을 확인했다. 이어 기존 Test/Wreck Boat → PlayerWreckRecovery의 Test/Complete Rescue 시험에 대해 전체 성공을 확인했다. 체크 항목은 난파 순간 보존, 구조 시 한 칸 전체 소실, 메인 섬 이동/행동 복구, 기존 배 제거와 최대 내구도 새 배 생성이다. 이는 사용자 실행 보고이며 AI가 Unity에서 직접 관찰한 결과가 아니다.
- 현재 구조 성공은 시험 호출 경로다. 직접 구조 입력·거리·유지 시간·취소는 미연결. 시간 만료 정산은 미구현으로 TimedOut 진입을 임시 거절하도록 안내했다. 90초 자동 복귀 완료로 보고하지 않는다.
- 미구조 자원/모듈 표류·섬 가장자리 이동, 실패 후 재개/복구, 새 배 생성 지점의 점유 처리, 복귀 방향 반영은 후속 확인 대상이다. 전체 완료로 판단하지 않는다.
- 다음 검증: 같은 플레이어의 두 번째 난파/구조 복귀, 원격 플레이어의 서버 시험 호출과 양쪽 위치·상태·배 소유·카메라 확인. 임시 시험 메뉴는 통합 후 정리한다.

## 2026-10-22 임시 구조 UI의 MCP 생성
- 이후 사용자 확인: 같은 플레이어 반복 복귀, 원격 복귀 화면·이동·카메라·새 배 탑승/조종까지 성공. AI 직접 다인 실행 검증은 아니다.
- 사용자 확정: 접근한 동료에게 UI 표시, 구한다 클릭 시 즉시 구조 요청, 안 구한다 클릭 시 본인 UI만 닫기. 거절은 사망/탈락이 아니며 기존 미구조 90초 기한 유지. 범위 밖 이탈 후 재접근하면 재표시. E키 유지·3초 구조 제안은 채택되지 않았다.
- 사용자가 PlayerRescueInteractionHandler, PlayerRescuePrompt와 구조 전용 InteractionTarget을 단계별 작성/연결했다. 임시 접근 거리는 3m. 실 클릭 구조는 아직 연결·검증 전.
- 사용자가 UI 생성을 MCP로 요청하여 직접 에디터에서 수행했다. 현재 에디터는 Unity 6000.0.83f1, MKTestScene, Play 종료, 생성 전 씬 dirty=false·Canvas/EventSystem 없음 확인. CLI 업데이트 대신 MCP 사용을 요청해 beta.13 상태에서 MCP 사용.

- AI 실제 검증: MCP Game View 캡처에서 한글 문구/버튼과 배치 확인, 저장 후 hierarchy 속성/입력 모듈/초기 비활성 재조회. compilationFailed=false 확인. 콘솔 오류 1개는 최초 MCP 조회의 main-thread timeout이며 이후 조회/생성/저장은 성공. 콘솔을 초기화하지 않음. git diff --check는 기존 변경과 Unity 직렬화 YAML 공백 때문에 실패, YAML 수동 정리하지 않음.
- AI 변경: MKTestScene의 임시 UI/EventSystem, Assets/02.Prefabs/UI/TemporaryRescue/의 폰트와 Unity 생성 meta, 이 기록과 pointer. 앞선 사용자 코드·프리팹·다른 미커밋 변경은 보존.
