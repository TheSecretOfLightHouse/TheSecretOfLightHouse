## 요청과 목표
실행 중인 클라이언트에서 다른 캐릭터가 떠 보이는 현상을 조사한다.

## 진행 과정과 결정 이유
- Unity CLI와 Pipeline eval로 원본 호스트와 MPPM Player 2를 읽었다. 둘 다 Play 중이며 클라이언트 frameCount 51792→57845로 진행, 일시정지 아님을 확인했다.
- 호스트 플레이어 netId=6: 호스트 실제 위치 (3.05,-1.00,1.28), 클라이언트 복제 위치 (2.82,-0.10,3.05). 바닥 Plane은 양쪽 Y=-1.00이다. 클라이언트에서 원격 호스트 루트가 0.90 높게 표시되며 X/Z도 다르다.
- 원격 플레이어 netId=8은 후속 비교에서 양쪽 (1.18,-1.00,2.77)로 일치했다. 자기 캐릭터 Rigidbody는 dynamic, 타인 캐릭터는 kinematic이고 Animator.applyRootMotion=false였다. 타인 kinematic은 소유 클라이언트 이동 권위의 정상 구조이므로 중력을 켜서 떨어뜨리는 방식으로 해결하지 않는다.
- netId=6의 NetworkTransformReliable은 양쪽 enabled=true, ClientToServer, Observers, syncPosition=true, onlySyncOnChange=true다. 서버 lastSerializedPosition=(305,-100,128), 클라이언트 lastDeserializedPosition=(282,-10,305) 및 마지막 수신 snapshot 위치가 클라이언트의 잘못된 위치와 일치했다. 모델 자식만의 오프셋이 아니라 네트워크 위치 데이터 불일치다.
- 원인 후보: NetworkTransformReliable 초기 상태/델타 압축 기준 불일치. 발생 최초 프레임·패킷은 확보하지 않았으므로 확정 원인으로 단정하지 않는다. 재접속/스폰 직후부터 절대 위치와 송수신 기준을 추적할 필요가 있다. 현재 샘플만으로 패킷 누락과 초기화 순서 중 하나를 확정하지 않는다.
- 현재 사용자가 적용한 채집 변경 diff는 개인/공유 잔량 참조 변경이며 이동·Rigidbody·Animator를 바꾸는 코드는 없었다. 시간적 연속만으로 인과를 확정하지 않는다.
- 별도 기존 오류: 양쪽에 BuoyancyBody WaterSamplerHost missing/no free sample slots 로그가 있다. 캐릭터 위치 불일치의 직접 원인이라는 증거는 없다.

## 변경 파일과 결과
- 이 조사 원문과 pointer만 추가·갱신했다. 실행 위치·설정·Play 상태·코드·씬·프리팹은 변경하지 않았다. 기존 미커밋 변경은 보존했다.

## 검증
- 실제 수행: 두 에디터 런타임 위치·물리·Animator·NetworkTransform 데이터와 콘솔 조회, 관련 Mirror 구현 정적 확인. 같은 PC MPPM 2인에서 증상 확인이며 수정 통과 시험은 아니다.

## 2026-10-22 원인 추가 추적
- 사용자가 증상 직전 호스트 승하선을 확인했다. 런타임의 두 PlayerController에서 _savedNetworkTransformEnabled=true도 확인했다.
- PlayerController.ApplyBoarding 415~418행은 NetworkTransform을 비활성화하고 LeaveBoat 546~548행은 복구한다. NetworkTransformBase.OnDisable/OnEnable은 가상 ResetState를 호출하며 NetworkTransformReliable.ResetState는 lastSerializedPosition/lastDeserializedPosition과 last를 모두 0으로 초기화한다. 코드 주석도 세션 중 이 초기화가 델타 압축을 깨뜨린다고 명시한다.
- 승하선은 BoatController의 서버 처리와 원격 SyncVar hook에서 서로 다른 시점에 적용된다. 토글로 서로 다른 시점의 기준을 초기화하고 잔여/새 델타를 이어 받으면 절대 위치가 어긋날 수 있다. 이번 세션 최초 패킷 순서를 기록한 것은 아니지만, 실제 토글 경로와 델타 초기화 결함을 확인했다.
- 실제 플레이어와 분리한 HideAndDontSave 임시 송신/수신 객체 2개로 현재 Mirror 구현을 시험했다. 최초 위치 (2,-1,3)를 초기 직렬화·역직렬화하면 수신 정수 기준 (200,-100,300). 수신 NetworkTransformReliable.enabled를 false→true로 바꾼 후 송신 위치 (2.5,-1,3)의 델타를 처리하자 기대 (250,-100,300) 대신 (50,0,0)이 나왔다. 즉 절대 위치 대신 변경량만 남는 현상을 재현했다. 임시 객체는 finally에서 즉시 제거했다.
- 첫 격리 시도는 비활성 객체의 NetworkBehaviour 초기화가 안 되어 NullReferenceException으로 실패했다. 활성화 후 재시험은 위 결과로 완료했다. 실제 캐릭터와 그 송수신 기준에는 값을 쓰지 않았다.
- 수정 방향: 프로젝트 측 승하선 처리에서 Reliable의 델타 기준을 보존하면서 보간/좌석 추종을 제어해야 한다. 단순 토글을 없애는 경우에도 탑승 중 좌석 추종과 원격 보간 충돌을 검증한다. 외부 Mirror 소스는 수정하지 않는다. 이번 요청은 원인 조사이므로 수정·Play 재시작·재접속은 하지 않았다.

## 2026-10-22 수정 요청과 검증 결과
- 사용자 후속 수정 요청에 따라 PlayerController의 승하선 NetworkTransform.enabled 토글을 제거했다. 동기화는 유지하고 캐싱한 serverSnapshots/clientSnapshots의 보간 기록만 전환 시 비운다. Reliable.ResetState는 호출하지 않아 델타 기준을 보존한다. Mirror 원본·asmdef·씬·프리팹은 수정하지 않았다.
- 기존 Runtime 어셈블리에서 NetworkTransformBase 직접 참조가 불가능해 첫 컴파일은 CS0246으로 실패했다. 기존 타입 탐색 방식을 유지하며 Awake 캐시 때 공개 버퍼를 IDictionary로 확보하는 방식으로 보완했다. 후속 컴파일 완료, 실제 scriptCompilationFailed=false/compiling=false/consoleErrors=0 확인. 프레임마다 리플렉션을 호출하지 않는다.
- 기존 판을 종료하고 원본 호스트+MPPM Player 2로 새 판을 시작했다. 양쪽 실제 탑승 상태에서 좌석 위치 일치와 동기화 enabled=true 확인. 정상 RequestDisembark는 시험 씬 접안 조건으로 거절됐다.
- 접안 검사를 우회해 서버의 실제 승선/하선 SyncVar와 상태 적용 경로로 전환하고 원격 hook·NetworkTransform 전송을 확인했다. 실제 키 입력·거리/접안 승인 시험은 아니다. 하선 위치를 매 회 X 방향 0.15씩 바꾼 5회에서 두 플레이어 모두 양쪽 Y=-1, 위치 오차 0.000001 미만, 동기화 enabled=true였다.
- 반복 시험은 5회까지 결과를 확보했고 이후 도구 호출 거절로 중단됐다. 이어 사용자가 나머지 시험을 직접 하겠다고 요청해 추가 시험하지 않았다. 실행 중 새 시험 판은 유지했다. 런타임 시험 위치 변경은 씬에 저장하지 않았다.
- 남은 검증: 실제 승하선 입력·접안, 이동/점프·탑승 중 움직이는 배의 좌석 추종, 추가 반복·다른 PC. 기존 부력 설정 오류는 별도이며 이번 수정으로 해결했다고 주장하지 않는다.
