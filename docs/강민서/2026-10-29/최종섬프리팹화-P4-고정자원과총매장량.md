# 최종 섬 프리팹화 P4 고정 자원·섬별 픽업·월드 총 매장량 (2026-10-29)

[P0 명세](최종섬프리팹화-P0-조사와명세.md) 7장의 코드 공백 1·2와 [P2 기록](최종섬프리팹화-P2-파밍픽업.md) 남은 일 1·2의 Rules 코드 부분이다. 상태: 4-1·4-2 코드와 총 매장량 에셋 적용, 컴파일 오류 0, 에디터 호출 검증. 4-3(52개 지점 고정 자원 입력, 픽업 정의 연결)과 4-4(스폰 등록, Play·4인)는 남았다.

## 4-1 지점별 고정 자원과 섬별 픽업

- `HarvestSpot._fixedResource`: 지정하면 확률 배정 대신 그 자원을 받는다. 고정 지점도 가중 랜덤을 똑같이 한 번 소비해서 다른 지점의 배정은 변하지 않는다.
- `IslandResourceEntry._pickupPrefab`: 아키타입이 자원별 픽업을 정한다. 비면 `ResourceDefinition.PickupPrefab`을 쓴다. 아키타입 `_resources`에 해당 자원을 `Weight > 0`·유효 `Deposit`으로 넣어야 적용된다.
- `HarvestSpotAssigner`에서 후보 수집을 `HarvestCandidateCollector`로 분리했다.
- `MapContentHasher`: 지점 고정 자원 ID와 픽업 오버라이드 유무를 포함한다. 픽업 프리팹 식별자는 해시에 못 넣는다(런타임 안정 식별자 없음).
- 검증: 배정 검증 7건(기존 3 + 신규 4) 5개 아키타입 PASS.

## 4-2 월드 총 매장량

- `WorldDepositBudget`(SO)이 자원 ID별 총량을 가진다. `MapGenerationConfig._depositBudget`에 연결하며 비어 있으면 기존 경로(아키타입 `DepositSpec`)다.
- `WorldDepositPlanner`가 맵 생성 시작 때 모든 섬의 프리팹 지점으로 배정을 미리 계산하고 `DepositDistributor`가 자원별로 균등 분배한다. 나머지는 앞 지점부터 +1(50/3 → 17/17/16). 초기량과 최대량을 같은 값으로 둔다. 회복률과 픽업은 유지한다.
- 순서는 섬 번호 순, 그 안은 지점 순이라 모든 기기가 같은 결과를 계산한다. 서버는 `IslandHarvestSession.Register(plan, assignments, spots)`, 클라이언트는 `HarvestSpotBinder.TryBind`를 쓴다.
- 검증: 분배 3건(50/3, 총량 < 지점 수, 다른 자원 불변)과 실제 설정 3건(시드 1000 섬 18개, 총량 보존·편차 1 이하·결정론) PASS.

## 인벤토리 규칙 반영 (2026-10-29, 사용자 안내)

인벤토리 규칙(사용자 안내, 코드 `PlayerInventory`/`InventoryData.GetStackCount` 확인은 미실시): 자원 8칸 + 모듈 1칸, 칸당 스택 10(채집가 패시브 20). 같은 종류는 스택이 차야 다음 칸을 쓰고, 다른 종류는 스택이 덜 차도 새 칸을 쓴다. 칸이 비지 않으면 다른 종류를 더 얻을 수 없다.
