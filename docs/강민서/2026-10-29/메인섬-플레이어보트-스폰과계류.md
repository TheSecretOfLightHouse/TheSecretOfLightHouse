# 메인 섬 플레이어·보트 랜덤 스폰과 계류
날짜: 2026-10-29 / 담당: 강민서 / 사용자 요청: 등대섬의 네 플레이어 자리·부두 네 보트 자리에서 서버가 중복 없이 무작위 생성, 실제4인 검증, 탑승 누락·미탑승 표류 수정.

## 결정
- 플레이어 위치는 LagoonReference/LighthouseIsland_Reference의 OriginalPlayer_captain/farm/tanker/tech 배치가 기준이다. MainGame의 StartPosition1~4를 잘못 사용한 최초 연결은 폐기했다.
- PlayerSpawn_01=(-1.21,0.77,-1.50), 02=(-1.07,0.82,0.33), 03=(1.19,1.12,-0.29), 04=(0.93,0.76,-2.02). 방향도 배치 원본에서 복사.
- 서버가 네 직군·네 플레이어 자리·네 보트 자리를 각 중복 없이 배정한다. 직군별 배 참조와 접속 소유권은 기존 코드 사용.
- 맵 시드에서 플레이어/배용 난수 시드를 분리한다. debugSeed=0이면 Guid로 새 맵 시드가 생성된다. 고정 디버그 시드를 지정하면 같은 순서의 접속은 동일 배정이 재현된다.
- 미탑승 배는 현재 가로 위치 고정, 세로 부력·회전 유지. 탑승 시 해제, 하선 시 현재 위치가 다음 계류 기준. 난파 배 제외.

## 구현
- IGamePlayerSpawnSource: 서버의 준비 여부·actor별 프리팹/자리 예약·실패 예약 해제 계약.
- MainIslandPlayerSpawns: 실제 직군 프리팹4개 등록, 중복 없는 직군/자리 선택, actor 재요청은 같은 예약, 5번째 예약 거절.
- MainIslandPresentation: PlayerSpawnPoints4, BoatSpawnPoints4를 명시 참조. 외형 교체 시 유지.
- MainIslandFacilitiesBuilder: 시설 바인딩 후 플레이어/보트 스폰 설정을 준비하고 WorldReady 진행.
- LighthouseNetworkManager: 섬 준비 전 들어온 AddPlayer 요청을 대기시키고 완료 후 생성. 기존 접속/ActorId/로비 준비/시작 게이트 유지. 원래 단일 playerPrefab 생성 경로는 이 소스가 없는 다른 씬의 fallback으로 유지.
- PlayerBoatSpawner.BindMainIsland: 네 부두 기준점을 복사해 Fisher–Yates로 섞고 새 작업대/공용 모듈 처리기 연결. 기존 ActorJoined·직군별 BoatPrefab·소유권·복구 경로 유지.
- MainGame LocalMapBuilders에 MainIslandPlayerSpawns 및 facilities builder 참조 저장. MainIslandAppearance에 실제 플레이어 위치/방향에서 만든 PlayerSpawnPoints 저장. 참고 씬 원본 플레이어 위치는 보존.
- DockZone_Left/Right: 최근 BoatController/BoatContactBoarding은 플레이어와 배가 같은 DockZone에 있어야 탑승 가능하나 새 섬에는 0개였음. 두 Zone과 LandingSurfaces(왼쪽 두 발판/오른쪽 한 발판)를 외형 프리팹에 추가했다. Dock 레이어 지정만으로는 충분하지 않았다.
- BoatMooring 컴포넌트를 Boat/captainBoat/gardenBoat/TankerBoat에 추가. 실제 소유 클라이언트에서 Rigidbody의 기존 constraints를 보존하며 FreezePositionX/Z만 추가, 탑승/난파/권위 상실/컴포넌트 종료 때 복원. 매 프레임 컬렉션 할당 없음.
- Assets/Editor/MainIslandSpawnChecks: 시험 연결 대역을 사용한 서버 경로 검사. 원격 네트워크 검증과 구분.
- 이전 CoastHeight 5인자 호출(SurfCrest)과 6인자 함수의 호환 overload도 보완했다.

## 실제 검증
1. 1인 direct MainGame 실제 호스트에서 섬 준비→직군 플레이어→해당 배 생성 확인.
2. 서버 시험 연결3개 추가: 4직군/플레이어4자리/배4자리 중복없음, Owner와 connectionToClient 일치, 각 Player.BoatPrefab과 생성 배 일치, 5번째 예약 거절.
3. 1인 로비 전환 시험은 플레이어 생성·시작 진입까지 확인했으나 기존 IdentityCheckConfig가 시민0명에서 예외를 내 연결 종료. 이 시험을 게임 전체 통과로 보고하지 않음. 설정/신원확인 규칙은 변경 안 함.
4. 사용자 제공 MPP 에디터4개를 CLI에서 project-path로 지정, 실제 KCP 호스트1+원격3 접속. 로비 준비→MainGame→InProgress 확인. 호스트 MapState.ReadyCount=4, 모든 클라이언트 IsLayoutReady=true. 같은 플레이어 netId 27/29/33/31, 배 netId28/30/34/32가 네 창에서 동일하며 모든 Owner 일치. 각 창에 로컬 플레이어1명.
5. 처음 실검증은 에디터 재컴파일 및 원격 에디터 일시정지로 중단/로딩시간초과. 초기화·재접속·일시정지 해제 후 위4인 결과를 얻었다. 중단된 시도는 통과로 계산 안 함.
6. 잘못된 MainGame 시작점 대신 실제 등대섬 기준점 위치로 네 플레이어가 생성되는 것을 서버와 원격에서 확인.
7. DockZone 누락을 실제4인에서 발견(Zone0, 배 Owner정상). Zone 두개를 네 실행 인스턴스와 프리팹에 연결. 이후 재시작한 4인에서 사용자가 전원 탑승 성공 확인. 각 소유 클라이언트의 IsOnBoat/IsOccupied=true, CanSimulateLocalPhysics=true, isOwned=true, Owner일치4/4 확인.
8. 계류가 추가된 현재 판의 네 배 Anchor가 각 초기 스폰 위치에 설정됐음을 확인. 사용자가 탑승·이동한 뒤 IsMoored=false/기존 constraints복원인 것을 확인. 사용 중인 세션을 임의 이동/하선시키지 않았으므로 장시간 미탑승 표류량·하선 후 재계류는 추가 실행 측정 필요.
9. 무작위 여부 질문에 현재 서버 debugSeed=0, mapSeed=-1585742530 확인. 직전 판 Actor1은 Tanker/PlayerSpawn02였고 현재 판은 Tech/PlayerSpawn04로 바뀌었다. 적용되고 있음을 코드·실제 예약표로 확인.

## 남은 검증
계류 상태 장시간 수평 변위·하선 후 새 계류 위치·난파/복구 재검증, 원격 UI 제작/등대 장착·의식/소환. 실제 사용자의 플레이 중인4인 세션은 종료하지 않음. 커밋/푸시 없음. 기존 다른 작업 변경 보존.

## 2026-10-29 기능별 커밋 정리
런타임 코드·외형 에셋·연결을 기능별로 분리해 로컬 커밋했다. 참고 원본 씬과 백업은 이전 작업이 섞여 있어 이번 커밋에서 제외했다. 기존 본문의 미커밋·미연결 표기는 해당 작업 시점의 기록이며, 최신 커밋 범위와 후속 검증은 [커밋 정리](야간작업-기능별-커밋정리.md)를 따른다. push와 추가 Play 시험은 하지 않았다.
