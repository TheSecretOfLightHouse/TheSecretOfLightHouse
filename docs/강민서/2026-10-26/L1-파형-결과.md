# L1 파형 형태 – 데이터 변경과 검증 (2026-10-26)

브랜치 feature/minseo, 기준 HEAD b639a9c7. 이 세션에 한해 사용자 허용으로 AI가 에셋 입력과 검증을 직접 수행했다. 코드·씬 변경 없음, 커밋 없음.

## 사용자 결정

- 모아나 레퍼런스는 AI가 웹 검색으로 정해 적용한다. "아름답고 신비로운 바다 ↔ 괴물 같은 바다"를 둘 다 구현하고, 해역·날씨·최후 전투에 따라 확연히 달라지는 것이 핵심이다.
- 웹 검색 결과: 모아나 바다는 얕은 곳·열린 바다·폭풍을 같은 도구로 조절하는 연출 중심 물이고, 열린 바다는 잔잔함에서 7등급 강풍까지 폭이 있다. 파형 수치를 직접 알려 주는 공개 자료는 찾지 못해 수치는 미술 판단(가안)이다. 출처: Science Friday 인터뷰 요약, Disney Animation Moana 2 소개.

## 게임 씬 Play 검증 (2차, 실행 검증)

- 첫 시도는 `WorldSessionOffline`에서 Play해 전환되지 않았다. 퀵스타트는 **`WorldSessionGame`을 열어 둔 채 Play**하는 방식이다(사용자 안내). 그렇게 하자 `WorldSessionGame`에서 날씨 서비스 snapshot의 파도 6개(λ0=72, A0=0.45, Calm)·셰이더 `_OceanWaveCount`=6 확인.
- 캡처: Calm은 거의 거울 같은 수면, `WeatherWaveBridge.HandleWeatherChanged`에 Maelstrom snapshot을 직접 넣으면 7m급 큰 너울과 가파른 면이 겹쳐 보인다. 현재 수면 색은 채도 높은 코발트 파랑으로 불투명해 모아나 레퍼런스(맑은 터콰이즈, 투명)와 크게 다르다 → L2 과제.
- BD1 표류 경사 항 재계산(`WaveDriftModel.ComputeTarget`, 질량 500·바람 힘 0·해안 멀리, 고정점 300초, 기존 4슬롯 대비):

| 날씨 | 기존 rms/최대 | 신규 rms/최대 | 평균 |
|---|---|---|---|
| Calm | 0.286 / 0.63 | 0.142 / 0.31 | ≈0 |
| Overcast | 0.561 / 1.32 | 0.268 / 0.57 | ≈0 |
| Rain | 0.885 / 2.22 | 0.433 / 0.98 | ≈0 |
| Storm | 1.335 / 3.37 | 1.101 / 2.42 | 0.008 |
| Maelstrom | 2.198 / 4.00 | 1.928 / 4.00 | 0.010 |

  평온한 날씨의 배 흔들림은 절반으로 줄고 폭풍은 약 20% 줄었다. 순 표류(평균)는 변하지 않아 `DriftDamping`·`SlopeResponse`는 그대로 둔다. 바람 힘 항은 L1과 무관하다.

## 매끄러움 개선 (사용자 요청, 실행 검증)

원인(코드·설정 대조): ① URP `PC_RPAsset` MSAA 꺼짐(`m_MSAA: 1`)이고 카메라 AA도 없음 → 윤곽선 계단. ② 수면 타일은 200m 정사각에 정점 101×101 = 정점 간격 2m인데 슬롯 5·9m 파장은 2m 간격에 비해 짧아, 정점에서 계산해 보간한 법선이 각져 보임.

변경:
- `PC_RPAsset` MSAA 1 → 4 (프로젝트 공용 렌더 설정이라 팀에 알릴 사항).
- `OceanGerstner.hlsl`에 `OceanGerstnerBaseNormal` 함수 추가(기존 함수 변경 없음). `ClearOcean.shader`는 정점에서 (전체 법선 − 가스트너 기본 법선)을 보간하고, 픽셀에서 가스트너 법선을 직접 계산해 합친다. 해안·교란 보정은 그대로 보간.
- 컴파일 오류 없음. 같은 장면(Maelstrom 주입) 캡처에서 윤곽선 계단·각진 면이 사라진 것을 육안 확인. 거리 먼 곳의 가는 선 무늬는 남아 있어 L2에서 거리 기반 감쇠 검토. 픽셀 비용 증가(슬롯 6개 sin/cos)는 GPU 측정 안 함.
- 정점 간격 자체는 그대로라 5m 파장의 높이 변위는 여전히 성김. 필요하면 수면 타일 메시를 더 촘촘히(Synty 원본이 아닌 자체 메시) 만드는 별도 작업.

### 계단 잔존 보고 후속 (같은 날)

- 사용자 확대 화면에서 계단 지적. 측정: Game 뷰 렌더 해상도가 548×454이고 캡처 도구가 1280×720으로 늘려 계단이 크게 보인다. MSAA 4x 후 윤곽선 중간색(예: 105,133,195)이 생겨 AA 자체는 작동했으나 4단계라 확대 시 남음.
- 카메라 SMAA High를 `WorldSessionGame`의 Main Camera에 저장(MSAA 4x 유지, 8x는 비용 대비 제외). 런타임 비교 캡처에서 윤곽선이 부드러워짐을 육안 확인.
- 팀 씬 `MainGame`의 카메라(담당 외)에는 적용하지 않았다. 같은 SMAA 설정이 필요하다고 알려야 한다.
- 에디터 Game 뷰를 크게 하면 해상도 차이로 더 매끄럽게 보인다. 최종 판단은 전체 화면 또는 빌드에서.

## 미검증·후속

- 스카이박스 모아나 맞춤(사용자 요청): 분석만 [레퍼런스 문서](L0-모아나-레퍼런스-분해.md) 6번에 기록, 미착수.
- GPU↔CPU 높이 일치 실측(셰이더 루프는 개수 일반이라 구조상 6 허용), 해안 82,944표본 회귀, 4인 일치, 나란히 비교용 캡처 세트는 하지 않았다.
- 폭풍 전체 날씨 전환 실행(스케줄러 경유)은 하지 않았다. Maelstrom snapshot은 직접 주입했다.
- 해역별 파형 차이는 만들지 않았다. 파도식은 전역이라 해역 의존을 넣으려면 `WaveModel`·Burst job·셰이더 변경이 필요하다. 현재는 색·투명도 중심의 L2-Z로 해역 차이를 표현하는 가안을 유지한다. 필요하면 별도 결정.
- Quick Start 토글이 에디터 세션 상태에 남는다(현재 켜짐 추정).
