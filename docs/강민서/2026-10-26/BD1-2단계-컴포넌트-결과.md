# BD1 2단계 컴포넌트 결과

계획: [BD1 세부 계획](../2026-10-25/BD1-위치-덧씌우기-세부계획.md) / 이전: [1단계 결과](BD1-1단계-순수규칙-결과.md)
상태: **2단계 구현·컴파일·샌드박스 검증 통과. 커밋 없음.** 이 세션에 한해 사용자가 AI의 직접 파일 작성과 검증을 허용했다.

## 수행 과정과 결정

- 1단계 파일이 커밋 f3bd22e에 있고 `IForceFieldProvider`, `WaterSamplerHost`, `WaveModel.NormalAt`, `CoastWaveModel.DistanceAt` 시그니처가 계획과 같음을 확인했다.
- `Boat.prefab`은 Interpolate 없음, 회전 X·Z 고정이라 `rb.position` 가산이 보간과 충돌하지 않는다(YAML 읽기).
- 힘 계산에는 현재 표류 속도를 `velocity`로 넘겨 상대 풍속을 쓴다. 노출 면적은 프로필 `HullExposure`를 `sailArea` 인자로 쓴다.
- 프로필 필드가 비면 런타임 기본 `WaveDriftProfile` 인스턴스를 만들고 `OnDestroy`에서 지운다(3단계 자동 추가 대비).
- 3단계 전까지 `BuoyancyBody`의 힘 경로가 남아 바람이 두 경로로 민다. 그래서 바람 시험은 이동 거리가 아니라 목표 속도의 입력 재계산 일치로 판정했다. 합격 기준의 무인·탑승 ±10%는 3단계에서 본다.

## 실제 검증 (Unity MCP, 동일 PC, WorldSandbox를 MainOffline에 additive로 열고 Play)

| 항목 | 결과 |
|---|---|
| 컴파일 | 오류 0. 경고는 기존 `BoatController._dashAccelerationMultiplier` 1건(Player 영역) |
| 입력 재계산 일치(바람 8,0) | 법선·힘·해안 거리·질량으로 `ComputeTarget` 재계산 vs 컴포넌트 `TargetVelocity` 차이 8.8e-05 |
| 입력 재계산 일치(바람 15,2) | 차이 5.6e-04 (시간 정지 후 비교, 1 틱 오차) |
| 해안 거리 | 샌드박스는 해안 미등록이라 `float.MaxValue`(약화 없음). 실제 맵 해안은 미검증 |
| 충돌 | 벽을 0.3 m 앞에 두고 3 m/s 주입 → 간격 0.0053 m에서 정지, 관통 없음(`SweepTest`) |
| 권위 조건 | `isKinematic = true` → 표류·목표 속도 0으로 초기화 |
| 콘솔 | 오류 0 |

## 미검증·남은 일

- 샌드박스 바람 힘이 작아(15 m/s에서 약 4 N) 바람 표류 크기는 의미 있게 측정하지 못했다. BD0의 908 N 환경(MainGame)은 3단계 재측정에서 본다.
- 이동 거리 합격 기준, 탑승 상태, 실제 맵 해안·선착장 구간, 프로파일러 GC는 미검증이다. GC 0은 코드 검토만 했다(힘장 호출 등 기존 경로 포함).
- 시험 중 샌드박스 오디오 리스너를 런타임에 끄고 Play 후 씬을 저장 없이 닫았다. `WorldSandbox.unity`는 git 변경 없음, `MainOffline` dirty는 이전부터의 상태다.
- 시험 환경 메모: 추가 로드한 두 씬의 오디오 리스너 2개 경고가 로그 폭주로 `eval`을 막는다.
