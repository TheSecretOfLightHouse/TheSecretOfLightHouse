# 바위에 부서지는 파도: 레퍼런스 분석·리서치·설계 (2026-10-27)

브랜치 feature/minseo. 설계 제안이며 이 문서의 구현은 아직 없다. 게임 규칙·승인된 사양이 아니다.

## 사용자 지적 (최신 기준)
- 분무 점·줄기(탄산 톡톡)도, 폭발 퐁퐁도 아니다.
- 우리가 이미 만든 **하얀 거품 띠가 밀려오는 파도**(`SurfCrest`)가 그냥 밀려오는 게 아니라, **철썩 밀려오면서 부서지는** 모습이어야 한다. 레퍼런스: [1](물보라/레퍼런스/ref1-바위-물보라.png) · [2](물보라/레퍼런스/ref2-해안-물보라기둥.png) · [3](물보라/레퍼런스/ref3-절벽-파도폭발.png)

## 레퍼런스 3장에서 읽은 것
1. 물보라는 입자가 아니라 **파도 자체가 만든 하얀 물덩어리**다. 파도 앞면이 솟고, 윗부분이 앞으로 꺾여 떨어지며 바위에 맞는다.
2. 부딪힌 뒤 **하얀 물막(시트)이 바위 면을 타고 위로 올라가** 갈라지며 흩어지고, 잔 물방울은 그 가장자리에서만 보인다.
3. 올라간 물은 **줄무늬로 흘러내리고**, 바닥에는 하얀 거품 물살이 깔려 퍼졌다가 빠진다(되돌아 나가는 물).
4. 한 번의 사건에 **시작·절정·소멸이 있는 연속 동작**(약 2초)이다.

## 현재 구현이 틀린 이유 (코드·실행 근거)
- `WaterSpray`(입자)로 만들어 **작은 점의 집합**이 되었다. 거품 띠(`SurfCrest`)는 높이 0.55m 이하의 반원 단면이 해안선을 따라 평행 이동할 뿐 **앞으로 꺾이는 단면이나 충돌 반응이 없다**.
- 파도 높이장(`OceanInteraction`)은 **높이 함수라 휘어 넘어가는(curl) 모양을 만들 수 없다**. 부서지는 모양은 별도 메시로 그려야 한다(아래 리서치 3번).

## 리서치 요약 (웹 검색, 출처는 아래)
1. **부서지는 파도의 단계:** 급경사화 → 윗부분이 앞으로 던져지는 제트 → 제트가 앞면에 부딪혀 **솟는 물(splash-up)이 생기고 공기가 섞여** 하얀 난류 덩어리가 되어 전진. 흰색은 갇힌 공기 방울이 만든 거품이다.
2. **벽·바위에 부딪칠 때:** 급한 파도는 벽 면을 따라 빠르게 솟는 **평면 제트(flip-through)**, 공기가 갇히면 압축 공기가 터지며 높은 물보라가 된다. 분사된 물막은 갈라져 물방울이 되고, 이후 **흘러내림·되돌아 나감(rundown)**이 이어진다.
3. **게임 기법:** 단순 높이장은 휘어 넘어갈 수 없으므로 파도 함수에서 **립(lip)을 별도 리본 메시로** 그린다. 립 높이·립 오프셋·튜브 깊이 같은 매개변수와 시간 함수를 정점 셰이더에서 평가하면 1ms 미만으로 가능하다는 보고가 있다(절차적 breaking wave 모델, Surf's Up 분석 모델). 거품은 수명이 짧게 흩어져야 하고 **거품 텍스처의 움직임이 중요**하다.
4. **한계:** 해안에서 완전히 말려 넘어가는 물리적 파도는 일반적으로 구현하지 않는다. 검색에서 바위 충돌 전용 레시피나 GDC 발표는 찾지 못했다(위 1~3은 물리 논문·일반 기법 조합이며 바위용 완성 레시피가 아님).

## 설계안 (가안)

**원칙:** 입자로 덩어리를 만들지 않는다. 파도 한 번을 **매개변수 메시 + 거품 시트**로 그리고, 입자는 가장자리 물방울에만 쓴다.

한 사건(약 2.4초, 바위 하나당 3~6초 간격, 엇갈린 위상)의 단계:

| 구간 | 모양 | 구현 |
|---|---|---|
| 접근 0~0.9s | 앞면이 급해지며 높아짐(0.3→0.6~1.2m, 날씨 에너지 비례), 꼭대기에 흰 거품 | 단면 곡선 + 거품 텍스처 마스크 |
| 꺾임 0.9~1.2s | 립이 앞으로 던져지고 아래가 비침 | 립 리본(별도 메시), 오프셋·길이 매개변수 |
| 충돌 1.2~1.5s | 단면이 붕괴, **하얀 난류 시트가 퍼지며** 바위 면으로 **물막이 솟음**(바위 높이의 1.5~3배) | 평평한 거품 시트 + 수직 시트, 깊이 소프트 페이드 |
| 흘러내림 1.5~2.6s | 물막이 줄무늬로 내려오고 바닥 거품이 되돌아 나가며 사라짐 | 세로 줄무늬 노이즈, 역방향 UV 스크롤, 페이드 |

- **방향:** 바위 위쪽(너울 진행 방향)의 면으로 파도가 들어온다. 너울 방향은 `WaterSamplerHost.Inputs.Waves`의 주 파도 방향을 쓴다.
- **스케줄:** CPU가 `SurfaceInteractionGrid.Rasterize`가 이미 모으는 바위 콜라이더 정보로 바위별 사건을 만들고, 사건 배열(위치·방향·폭·시작 시각·세기)을 셰이더 상수로 넘긴다. 로컬 시각 연출이라 네트워크 동기화는 하지 않는다.
- **파일(안):** `View/BreakerWaveRenderer.cs`(스케줄·드로우 ~100줄), `Shaders/BreakerWave.shader` + `Include/BreakerWaveProfile.hlsl`(단면 곡선·거품), 기존 `WaterSpray`는 물방울만 남기고 안개·시트 제거.
- **확장 지점:** 세기와 주기는 인스펙터 값, 단면 매개변수는 SO 분리 가능.

## 위험·미확인
- 정지 캡처로는 **동작의 자연스러움을 판정하지 못한다.** 연속 프레임 캡처로 단계별 모양만 확인할 수 있고, 최종은 사용자 눈이 기준이다.
- 바위 표면 형상과 맞추지 않아 물막이 일부 떠 보일 수 있다(깊이 페이드로 완화).
- 모델 교체 시 콜라이더 기반이라 영향이 적지만, 바위가 없는 섬(모래 해안)은 기존 `SurfCrest`와 해안 거품이 담당한다.
- GPU 비용·4인·폭풍 날씨 미검증.
