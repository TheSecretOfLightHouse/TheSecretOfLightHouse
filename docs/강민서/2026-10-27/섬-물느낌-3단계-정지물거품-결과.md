# 섬 가안 물 느낌 3단계: 정지물 거품 결과 (2026-10-27)

브랜치 feature/minseo. 사용자가 AI의 작성·검증을 허용했다. 커밋 없음.

## 재확인 결과 (현재 코드)

- 권장안 B(정지 물체 등록)는 이미 구현돼 있었다. `SurfaceInteractionGrid.Rasterize`가 정지·이동 구분 없이 수면(±0.03m)에 걸친 비트리거 콜라이더를 등록하고, 범위는 포커스(메인 카메라) 주변 32m(128칸×0.25m)다. 오목 `MeshCollider`는 미지원이고 해안 윤곽 데이터가 대신한다.
- 문제는 강도였다. 같은 해안에서 정지 바위 12개가 등록됐는데 거품이 0.1을 넘는 칸은 49칸(총 16384), 최댓값 0.42로 Calm에서는 바위 밑이 가는 선뿐이었다(`impact`가 파도 궤도 속도에 의존해 잔잔하면 임계값 0.035 미달).

## 변경 (B′: 정지 접촉 거품 항)

| 파일 | 내용 |
|---|---|
| `Shaders/SurfaceInteraction.compute` | `StaticWall`·`StaticContactFoam` 추가, `Integrate`의 거품 증가에 `StaticContactFoam(p)*3` 합산. 벽에서 1~2칸 이내(2칸은 0.5 가중), 벽 속도 0.05 미만만, 파도 높이로 맥동(`lap`), 파도 에너지(`_WaveEnergy`)로 0.4~1배 |
| `View/SurfaceInteractionGrid.cs` | `StaticContactFoam` 프로퍼티, `_WaveEnergy`(파도 진폭 합)·`_StaticContactFoam`을 컴퓨트로 전달 |
| `View/WaterContactEffectsView.cs` | `[SerializeField, Range(0,2)] _staticContactFoam = 1.2f`(가안), 매 LateUpdate에 그리드로 전달 |

창 크기(128칸)는 그대로 뒀다. 움직이지 않는 배도 같은 경로로 포함된다(속도 0이면 적용).

## 실행 검증 (WorldSessionGame 퀵스타트 1인, 낮 고정, 포커스=메인 카메라를 섬 해안으로 이동)

| 가중 | 거품>0.1 칸 | >0.5 칸 | 최댓값 | 육안 |
|---|---|---|---|---|
| 0 (기존) | 49 | 0 | 0.42 | 바위 밑 거의 없음 ([G_off](정지물거품/G_off.png)) |
| 0.6 | 273 | 0 | 0.47 | 거의 변화 없음 |

- 컴파일·컴퓨트 오류 0. 가장자리 확인: [G_edge_wide](정지물거품/G_edge_wide.png)에서 격자 경계 팝인은 눈에 띄지 않았다.
- 기본값 1.2는 0.6(약함)과 2.0(뚜렷) 사이 가안이다.

## 한계 (미확인)

- Storm 강제 시 실제 날씨 전환이 유지됐는지 이미지로 확인하지 못했다(바다가 폭풍처럼 보이지 않음). 날씨별 비교는 미확인.
- 정박한 배의 선체 거품은 이 장면에 배가 없어 확인하지 않았다(코드상 포함).
- GPU 비용·프레임 시간 측정 안 함(`Integrate`에 이웃 8회 읽기 추가). 4인 일치는 로컬 시뮬이라 클라이언트마다 보이는 모양이 다를 수 있다.
- 씬에 기존 직렬화가 없는 필드라 기본값 1.2가 적용되는지는 Play에서 가중 값을 직접 바꿔 보기만 했다. 에디터 상태 값 재확인은 에디터 응답 지연으로 못 했다.
- 사용자 지적: 바위 위에 떠 보이는 둥근 흰 점(분무 파티클)이 마음에 들지 않는다. 별도 작업으로 다시 만든다(이 문서 범위 밖).
