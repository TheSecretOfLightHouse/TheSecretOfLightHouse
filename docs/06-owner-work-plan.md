# 담당자별 구현 작업

> 기획 기준: [게임 기획서 v4](design/references/game-design-v4.md). 2026-10-10 작업 항목을 v4 기준으로 갱신했다. 관련 작업 전 [설계 문제 대장](07-design-issue-register.md)의 관련 ID를 확인한다. 원문의 가안·미정은 임의 확정하지 않는다.

기준일: 2026-10-09(코드 조사), 2026-10-10(v4 반영). [구현 로드맵](05-implementation-roadmap.md)의 작업 ID를 담당자별로 풀어 쓴 문서다. 업무 소유권은 [CODE_OWNERSHIP](CODE_OWNERSHIP.md), 게임 규칙은 [게임 기획서](design/references/game-design-v4.md)가 기준이다. 각 담당자는 자신의 기능의 서버 판정·동기화·클라이언트 표현을 함께 맡는다. 작업별 날짜·공수는 이 문서에서 정하지 않는다. 전체 일정은 v4 12장(정기 4인 테스트, 기능 동결 10/25, 최종 마감 11/1)을 따른다.

아래 항목은 **앞으로 할 작업**이다. 기존 코드가 있는 항목도 완료로 표시하지 않는다. D01~D12는 로드맵의 결정 대기 ID이며, 의존 계약이 미정이면 독립 작업만 진행한다. 표의 세부 산출물은 권장 분해이고 신규 기능이나 확정되지 않은 수치를 승인하는 문서가 아니다.

표의 **계약 상대는 그 작업 전체가 먼저 완료되어야 한다는 뜻이 아니다.** 서로 연결되는 작업은 최소 계약을 합의해 병행한다. 차단 선행은 각 행의 D 결정 중 해당 동작에 필요한 것과 로드맵 단계의 검증 범위다. A의 입력은 콜백 수신까지만, B의 등대는 수리까지만, C의 몬스터는 자연 스폰까지만 검증한다. 투표·소환·최후 전투 관련 최종 완료 기준은 D 이후 확인한다.

## 2. 최명기 — 플레이어·시스템·UI

계정 `cmg6991`, 코드 `05.Player/`, `08.Systems/`, `09.UI/`(모두 `Assets/01.Scripts/` 아래). 기획은 v4 2~4·6~7·9장과 연결한다(보이스 삭제는 MK07 참조). v4 12.1 시스템&UI 전체 소유는 확정됐다. D09는 토론 수단, D10은 기능 입력 API·종료 판정 계약이며 담당 배정 대기가 아니다.

- `05.Player/Control/PlayerController.cs`: 로컬 이동·승하선, SetDowned, InteractionRequested. 난파 중 heading 입력 중단과 기획의 카메라 허용을 대조한다.
