# 담당자별 구현 작업

> 기획 기준: [승패·투표 결정](design/win-vote-decisions.md)이 충돌 범위에서 [게임 기획서 v4](design/references/game-design-v4.md)보다 우선한다. 2026-10-11 작업·완료 기준을 갱신했다. 관련 작업 전 [설계 문제 대장](07-design-issue-register.md)의 관련 ID를 확인한다. 미변경 규칙은 v4를 따르며 가안·미정은 임의 확정하지 않는다.

기준일: 2026-10-09(기존 코드 조사), 2026-10-10(v4 반영), 2026-10-11(승패·투표 결정 반영, 네트워크·투표 재확인). [구현 로드맵](05-implementation-roadmap.md)의 작업 ID를 담당자별로 풀어 쓴 문서다. 업무 소유권은 [CODE_OWNERSHIP](CODE_OWNERSHIP.md)을 유지한다. 각 담당자는 자신의 기능의 서버 판정·동기화·클라이언트 표현을 함께 맡는다. 작업별 날짜·공수는 이 문서에서 정하지 않는다. 전체 일정은 v4 12장(정기 4인 테스트, 기능 동결 10/25, 최종 마감 11/1)을 따른다.

아래 항목은 **작업 범위와 완료 기준**이며 실제 진행 증거는 6절에서 구분한다. D01~D12는 로드맵의 결정·계약 ID다. 새 결정으로 확정된 동작은 구현·검증 대상으로 바꾸고, 남은 미정 계약에 의존하는 부분은 독립 작업과 구분한다. 표의 세부 산출물은 권장 분해이고 신규 기능이나 확정되지 않은 수치를 승인하는 문서가 아니다.

표의 **계약 상대는 그 작업 전체가 먼저 완료되어야 한다는 뜻이 아니다.** 서로 연결되는 작업은 최소 계약을 합의해 병행한다. 차단 선행은 각 행의 D 결정 중 해당 동작에 필요한 것과 로드맵 단계의 검증 범위다. A의 입력은 콜백 수신까지만, B의 등대는 수리까지만, C의 몬스터는 자연 스폰까지만 검증한다. 투표·소환·최후 전투 관련 최종 완료 기준은 D 이후 확인한다.
