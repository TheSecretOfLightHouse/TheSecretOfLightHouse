# 기능별 담당과 코드 경계

2026-10-09 사용자 지정 기준. 폴더는 사람 이름 대신 기능으로 나누고 각 기능 담당자가 규칙·서버 판정·동기화·클라이언트 표현을 함께 맡는다. 리슨 서버(호스트 1명 + 원격 클라이언트 3명)를 유지한다.

2026-10-11 문서 갱신에서도 담당자는 유지한다. [승패·투표 결정](design/win-vote-decisions.md)이 충돌하는 [v4](design/references/game-design-v4.md) 규칙보다 우선하며, 아래에는 해당 결정의 기능 간 소비 경계를 반영한다. 의미 계약을 기록한 것이며 팀원 간 API 합의나 코드 구현 완료로 간주하지 않는다.

공용 NetworkManager 담당이라는 이유로 모든 기능의 `Net/`·`Server/`를 김지훈에게 넘기지 않는다. 기능 폴더의 소유자가 하위 서버·클라이언트 코드도 소유한다.

게임 기한과 월드 시간은 별개로 인수한다. 의식 중 월드 시간 진행·최후 전투 일일 효과·억제한 낙하의 후속 처리, 동일 판정 시점의 의식 완료/소환·수리 100%/HP 0, [설계 문제 대장](07-design-issue-register.md)의 남은 결정이다. 판 진행 중 이탈(호스트 포함)은 2026-10-13 판 종료로 결정됐다. 현재 접속 구현과 새 보존 요구의 차이는 [기술설계 §5·§7](03-technical-design.md#5-현재-요청데이터-계약)에서 확인한다.

## 3. 기능 내부 구조

```text
{도메인}/{기능}/
  Rules/   계산·정의·계약과 상태 전이
  Net/     NetworkBehaviour, 동기화 상태, Command/Rpc 경계와 전송 계약 데이터
  Server/  호스트의 서버 측 검증·상태 변경·판정
  View/    로컬 입력·UI 연결·카메라·표현
```

실제로 필요한 층만 만든다. 위 폴더는 책임 구분이며 별도 담당자나 빌드 제외를 뜻하지 않는다. 서버 코드도 일반 리슨 호스트 빌드에 포함한다. `UNITY_SERVER`나 전용 서버 빌드에만 넣지 않는다. 기존 혼합 책임 코드는 기능 루트에 두고 후속 작업에서 실제 로직을 나눌 때 층으로 옮긴다. 폴더 이동만으로 서버 권위가 구현됐다고 보고하지 않는다.

## 4. 다른 영역을 수정해야 할 때

1. 수정할 실제 파일과 [.github/CODEOWNERS](../.github/CODEOWNERS)를 확인한다. 작업자의 담당은 명시된 정보로 확인하고 로그인만으로 추측하지 않는다.
2. 자기 영역 밖 수정이 필요하면 **담당자, 대상 파일, 변경 이유, 영향받는 계약, 검증 방법**을 수정 전에 사용자에게 알린다.
3. 이미 이번 요청에서 해당 수정이 허용됐는지 확인한다. 필요한 담당자 합의가 없다면 그 파일의 수정만 대기하고 자기 영역의 독립 작업은 계속한다.
4. 담당자가 미정인 새 기능은 임의로 다른 사람을 등록하거나 자기 영역으로 취급하지 않는다. 게임 진행·승패·직군 배정 등 v4 12.1의 시스템은 최명기 담당으로 확정됐다. UI는 2026-10-30 사용자 결정으로 김지훈이 맡고, 인벤토리 화면과 배 모듈 장착 UI만 최명기 담당으로 남는다. 단, 판 시작 때 마피아 1명을 정하는 배정은 2026-10-22 합의로 김지훈(`01.Network/Session`)이 맡는다. 직군 배정은 최명기 담당 그대로다. 인게임 보이스·무전은 v4에서 삭제됐다. 해당 범위를 미배정으로 다시 질문하지 않는다.
5. 담당자에게 메시지·리뷰 요청을 대신 보내는 것은 별도 사용자 지시가 있을 때만 한다. 코드 경계 확인은 외부 연락 권한이 아니다.

```text
영역 변경 안내
- 대상: {실제 파일 또는 폴더}
- 담당: {이름 / GitHub}
- 이유: {현재 작업에 필요한 변경}
- 영향: {공용 계약 / 서버 판정 / 클라이언트 / 데이터}
- 확인할 합의: {이미 받은 승인 또는 필요한 결정}
- 검증: {실제 수행할 확인}
```

## 5. CODEOWNERS와 운영

CODEOWNERS는 경로별 리뷰 담당을 지정한다. 파일 자체가 편집을 차단하거나 여러 담당자 모두의 승인을 보장하지 않는다. 자동 리뷰 요청에는 기본 대상 브랜치의 파일 반영과 해당 계정의 저장소 쓰기 권한이 필요하며, 필수 리뷰는 저장소 보호 설정에서 별도로 관리한다. 이번 작업은 로컬 파일 등록이며 원격 권한·브랜치 보호를 변경하지 않는다. [GitHub CODEOWNERS 문서](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-code-owners).

공유 씬은 한 명이 저장하고 관련 담당자가 검증한다. 기존 개발 씬 `Minseo/`, `Jihun/`, `Myeongki/`, `TaeWook/`은 지정된 담당자에게 연결한다. 시스템은 최명기, UI는 김지훈(인벤토리 화면·배 모듈 장착 UI는 최명기)이 담당하며 AX 담당자로 덮어씌우지 않는다.
