# 인수인계 작성

사용자가 인수인계를 요청하거나 작업 중단·종료를 명시했는데 남은 작업이 있을 때 적용한다. 커밋하지 않은 파일이 있다는 이유만으로 사용자가 계속 진행하는 작업을 종료하지 않는다.

## 저장 위치와 기존 기록

1. [AGENTS.md](../../../AGENTS.md), 적용 중인 전역 지침과 [문서 안내](../../../docs/README.md)를 확인한다. 팀 공유 계약은 `docs/`, 개인 실행·재개 기록은 지정된 개인 기록 영역에 둔다.
2. 전역 지침이 기록 도구를 지정하면 그 도구에서 이 프로젝트의 저장 범위와 기존 기록을 먼저 확인하고 전역 지침을 따른다. 파일 산출물을 명시적으로 요청받았으면 그 요청도 이행한다.
3. 세션 인수인계는 `.claude/docs/{날짜}/{내용}.md`, 다른 담당자에게 전달할 문서는 `.claude/handover/{날짜}/{내용}.md`에 쓴다. `{날짜}`는 처음 쓴 날(`YYYY-MM-DD`)이다. 쓰기 전에 `git check-ignore -v <경로>`로 Git 제외를 확인한다. `.agents/`와 `.claude/skills/`는 개인 기록 보관함으로 사용하지 않는다.
4. 기존 항목이 있으면 원본을 갱신하고 같은 결과를 날짜별로 복제하지 않는다. 파일로 남기지 않겠다는 요청이면 같은 양식을 채팅에 제공한다.

## 사실 수집과 작성

- `git status`, `git log --oneline -5`, `git branch --show-current`와 이번 변경 파일을 확인한다. 다른 작업자의 변경을 이번 세션 성과로 표시하지 않는다.
- 수정 씬·ScriptableObject·프리팹·실제 검증·임시 설정·기다리는 담당자 결정을 확인한다. 확인할 수 없는 설정은 값 대신 재확인 방법을 적는다.
- [세션 인수인계](../../../docs/ai/05_SESSION_HANDOFF.md)의 머리 필드와 8개 절을 사용한다. 목표, 완료, 미완료, 저장소 상태, 검증, 차단 조건, 다음 첫 행동, 주의를 채운다.
- 상태 어휘와 L1~L3는 [검증 플레이북](../../../docs/ai/03_VERIFICATION_PLAYBOOK.md), M0~M3는 [멀티플레이 테스트](../../../docs/ai/04_MULTIPLAYER_TEST_PROTOCOL.md)를 따른다. 실행하지 않은 테스트를 완료로 표시하지 않는다.
- 다음 행동은 실행 순서와 명령형으로 적는다. 차단 조건은 누가 무엇을 해야 풀리는지 밝힌다. 미확정 파트·인원은 추측하지 않는다.

## 링크·색인·보고

- 파일 링크는 실제 문서 위치에서 계산한다. 저장소 밖 기록은 확인한 절대 경로나 저장소 루트 기준 경로를 사용한다.
- 현재 작업 색인이 정해져 있으면 위치·상태만 갱신한다. 본문을 복제하지 않는다. 색인이 없으면 만들기로 합의한 것처럼 가정하지 않는다.
- 팀 공유 문서는 개인 기록을 읽어야 이해되는 구조로 만들지 않고, 개인 계정·모델 선호·원시 로그 경로를 넣지 않는다.
- 저장한 경로 또는 기록 식별자, 갱신한 색인, 미확인 입력을 보고한다. 기록을 만드는 김에 코드·설정·브랜치를 수정하지 않는다.
