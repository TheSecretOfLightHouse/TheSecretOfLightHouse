# 주석 작성

주석 추가·정리 요청에 적용한다. [코딩 컨벤션](../../../docs/coding-convention.md)의 주석 기준을 먼저 읽는다. 다른 담당 영역의 수정은 [소유권 확인](../check-code-ownership/SKILL.md)을 적용하고 이미 허용된 범위는 다시 승인받지 않는다.

## 작성 기준

- 주석 언어, "왜"를 쓰는 원칙, `///` 요약 대상 범위는 [코딩 컨벤션 서식](../../../docs/coding-convention.md#서식)을 따른다. 코드로 보이는 동작 대신 숨은 계약·제약·판단 이유를 설명하고, `///` 대상이 아닌 내부 판단은 `//`로 설명한다.
- 도메인의 서버 판정, 동기화, 클라이언트 표현 경계는 실제 코드에 근거해 설명한다. 폴더 이름만으로 실행 환경이나 권한을 단정하지 않는다.
- 후속 작업은 확인된 사실만 남긴다. 담당자·수치·검증 결과를 추측해서 적지 않는다.
- 주석만 요청받았다면 리팩터링, 명명 변경, 로직 수정으로 범위를 넓히지 않는다.

## 수정 범위와 검증

1. 대상 코드의 계약·수명·재시도·중복 방지·권위 조건을 읽고 설명이 필요한 부분을 좁힌다.
2. 외부 코드·생성 코드와 저작권·라이선스 고지, 컴파일러·생성기 지시문을 보존한다.
3. 주석만 바꾸는 작업에서는 실행 토큰, 전처리 지시문, 직렬화 필드와 문자열을 변경하지 않는다.
4. diff로 주석 밖 변경과 사실에 맞지 않는 설명을 확인한다. 주석 검토를 게임 실행 검증으로 보고하지 않는다.
