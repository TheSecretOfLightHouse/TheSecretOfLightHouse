# 모호한 요청 명확화

여러 해석이 실제로 다른 결과물을 만드는 요청에 적용한다. 규칙이나 코드 검색으로 답이 정해지는 질문, 사소하고 되돌릴 수 있는 구현 선택에는 적용하지 않는다.

## 절차

1. 대상·현재 상태·기존 결정을 [AGENTS.md](../../../AGENTS.md), 관련 코드와 설정에서 확인한다. [실행 정책](../../../docs/ai/01_AGENT_EXECUTION_POLICY.md)과 [응답 스타일](../../../docs/ai/10_RESPONSE_STYLE_GUIDE.md)의 사실·추정·미검증 구분을 따른다.
2. 대상 파일, 씬, 시스템과 요청 범위를 먼저 좁힌다. 확인 가능한 것은 조사로 해결한다. 미정인 게임 디자인·서버 빌드 설정·최대 인원·담당 파트를 사실로 채우지 않는다.
3. 결과를 실질적으로 바꾸는 미확정 입력만 질문으로 남긴다. 기술적 선택은 [대안 제시](../present-alternatives/SKILL.md)로 실제 비용과 영향을 비교한다.
4. 현재 환경에서 사용 가능한 사용자 질문 도구를 사용한다. 비동기 질문이 지원되면 답변을 기다리는 동안 독립적인 작업을 진행한다. 도구가 없으면 짧은 채팅 질문을 남긴다.
5. 조사에서 나온 선택지 2~3개와 각각의 영향을 간단히 제시한다. 추천안은 이유와 함께 표시한다. 답이 앞 질문에 의존하면 순서대로 묻고, 독립적인 결정은 묶는다.
6. 필수 답변을 기다리는 동안 그 결정에 의존하지 않는 조사·검증을 계속한다. 시간이 지났다고 승인이나 필수 답변으로 간주하지 않는다. 선택적 선호는 합리적인 가정을 밝히고 진행할 수 있다.
7. 받은 결정을 반영해 작업을 완료하고 같은 사안을 다시 질문하지 않는다.

예를 들어 이동 기능 요청에서 폴더·네임스페이스·명명은 코딩 컨벤션으로 결정한다. 이동 방식이나 네트워크 동기화 범위가 실제로 미정이고 동작을 바꾸는 경우에만 그 차이를 질문한다.
