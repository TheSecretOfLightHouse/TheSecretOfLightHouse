# 가이드 이슈 등록

GitHub 이슈 등록·초안 요청에 적용한다. 실제 게시 요청과 본문 작성 요청을 구분하며, [실행 정책](../../../docs/ai/01_AGENT_EXECUTION_POLICY.md)의 허용 범위를 따른다. 이미 확정한 내용의 게시를 재요청받으면 같은 승인을 반복하지 않는다.

## 템플릿과 중복 확인

1. `.github/ISSUE_TEMPLATE/`에 실제 파일이 있는지 확인하고 작업·버그·밸런스 중 맞는 양식을 읽는다. 제목 접두어와 라벨은 파일의 현재 값을 따른다. 이름과 라벨을 기억으로 복원하지 않는다.
2. YAML 폼은 각 필드의 `label`을 Markdown 제목으로 옮기고 순서·필수 항목을 유지한다. dropdown은 선택값, checkboxes는 체크 목록으로 변환한다. 템플릿이 없으면 없음을 밝히고 목적·현상·재현·검증·남은 결정 중심으로 초안을 준비한다.
3. 먼저 `gh --version`과 `gh auth status`로 gh 설치·로그인을 확인한다. 없으면 [gh 설치와 로그인](../../../docs/unity/UNITY_START_HERE.md#github-cli-설치와-로그인)을 사용자에게 안내하고 완료 뒤 이어 간다. `gh issue list --state all --search "핵심 키워드"`로 중복을 확인한다. 같은 열린 이슈가 있으면 번호를 제시하고 새 생성 대신 가능한 후속 작업을 알린다. 댓글·재오픈은 별도로 허용된 경우에만 수행한다. 재발이면 확인한 이전 번호를 참조한다.

## 사실과 로그 수집

- 재현은 실제 관찰 또는 사용자 보고를 구분해 적는다. 씬·실행 환경·인원·서버/클라이언트·입력 순서를 지어내지 않는다.
- 원인·심각도·담당 파트가 미확인이면 그렇게 적는다. 의심은 의심이라고 표시하고 파일·메서드 근거를 연결한다.
- 버그는 실제 로그 경로를 확인한 뒤 관련 구간만 인용한다. 확인한 경로와 없었던 결과도 남긴다. 비밀값은 제외한다.

| 로그 | 확인 방법 |
|---|---|
| Player 로그 | `ProjectSettings/ProjectSettings.asset`의 실제 `companyName`·`productName` 또는 `Application.persistentDataPath`로 위치를 확인한다. Windows는 `%USERPROFILE%\AppData\LocalLow\<companyName>\<productName>\Player.log`를 기준으로 확인한다 |
| Editor 로그 | `%LOCALAPPDATA%\Unity\Editor\Editor.log`에서 해당 재현 시각을 찾는다 |
| 빌드·크래시 로그 | 실행 스크립트·로그가 알려주는 실제 출력 경로를 확인한다. 설치되지 않은 스크립트와 확인되지 않은 경로를 가정하지 않는다 |

다인 테스트는 어느 PC의 로그인지 구분하고 [멀티플레이 테스트](../../../docs/ai/04_MULTIPLAYER_TEST_PROTOCOL.md)의 실제 등급을 적는다.

## 메타데이터와 게시

1. 라벨은 실제 템플릿과 `gh label list`로 확인한다. 없는 라벨·마일스톤을 새로 만들지 않는다.
2. 담당자는 원인 파트가 확인되고 사용자 지정 또는 실제 `CODEOWNERS`로 계정이 확인된 경우에만 설정한다. `담당 파트` 필드는 작업 양식(`01-task.yml`)에만 있고 버그(`02-bug.yml`)·밸런스(`03-balance.yml`) 양식에는 없다. 필드가 없는 양식에서는 본문의 자유 입력 칸(버그는 `실제 동작`, 밸런스는 `근거`)에 담당 후보를 미확인 후보로 근거와 함께 적는다. 일정·마일스톤은 확정된 선택을 따르며 필수 결정만 질문한다.
3. 제목·본문·라벨·담당자를 검토 가능하게 준비한다. 필요한 새 승인은 이 단계에서 받고, 승인된 게시 요청은 실행한다.
4. CLI는 저장소 밖 UTF-8 임시 파일과 `--body-file`을 사용한다. 안내 뒤에도 gh를 쓸 수 없으면 초안과 미생성 사유를 제공한다. 결과가 불명확하면 먼저 조회하고 중복 생성하지 않는다.
5. 생성한 URL을 보고한다. 관련 PR·커밋은 확인된 번호만 이슈 본문에 연결하며, 다른 PR 본문 수정이나 팀원에게 보내는 메시지는 요청 범위에 포함된 경우에만 수행한다. 세션을 넘길 때는 [인수인계](../write-handoff/SKILL.md)에 번호를 남긴다.
