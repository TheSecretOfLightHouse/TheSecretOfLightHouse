# 코드 소유권 확인

요청자 소유를 벗어나는 변경에 적용한다. 기준은 [AGENTS.md](../../../AGENTS.md), [담당 경계](../../../docs/CODE_OWNERSHIP.md), [실행 정책](../../../docs/ai/01_AGENT_EXECUTION_POLICY.md), [서버·클라이언트 협업](../../../docs/unity/SERVER_CLIENT_WORKFLOW.md)이다. `CLAUDE.md`에 별도 작업 범위표가 있다고 가정하지 않는다.

## 판단 절차

1. 실제 수정할 파일과 영향받는 계약을 좁힌다. 조사와 읽기만으로 승인이 필요해지지는 않는다.
2. [.github/CODEOWNERS](../../../.github/CODEOWNERS)의 실제 경로 규칙을 읽는다. 규칙에 없는 경로는 팀이 확정한 파트와 위 기준 문서를 사용한다. 확인되지 않은 담당자 이름을 실제 계정으로 추측하지 않는다.
3. 같은 대화에서 이미 허용된 파일·작업 범위인지 먼저 확인한다. 요청자의 역할은 명시된 정보로 판단하고, GitHub 로그인만으로 팀장이나 타인의 승인 권한을 단정하지 않는다.
4. 다음 영역은 실제 소유자와 허용 범위를 확인한다.

| 영역 | 확인할 경계 |
|---|---|
| 다른 파트의 `Assets/01.Scripts/` | 담당 파트의 변경 허용 여부 |
| 도메인별 `Rules/`, `Net/`, `Server/`, `View/`, 공용 API | 각 도메인 담당자의 서버·클라이언트 구현 범위, 리슨 서버 권위와 공용 계약 영향 |
| 통합 씬·다른 사람의 개발 씬 | [씬·에셋 안전](../../../docs/unity/SCENE_AND_ASSET_SAFETY.md)의 실제 씬 소유 |
| 공용 설정·외부 에셋·대량 이동 | 기존 승인과 복구·팀 작업 영향 |

5. 다른 담당 영역을 수정하기 전 구체적인 파일·이유·담당자를 안내하고 합의 범위를 확인한다. 필요한 합의가 없다면 그 결정만 질문한다. Codex에서 사용 가능한 사용자 질문 도구를 쓰고, 없으면 짧은 채팅 질문으로 남긴다. 승인을 기다리는 동안 독립적인 조사와 검증은 진행한다.
6. 다른 사람의 개발 씬 저장, 생성물 수정, 타인의 변경 되돌리기는 [실행 정책](../../../docs/ai/01_AGENT_EXECUTION_POLICY.md)의 '절대 하지 않음' 목록을 따른다. 명시적 사용자 지시가 범위를 바꾸면 그 허용 범위와 이유를 확인하고 반영한다.

명시적으로 전체 영역 권한을 받은 요청자에게 같은 승인을 반복하지 않는다. 권한이 있어도 구조·권위·공유 계약을 바꾸면 영향을 알리고 실제 검증을 수행한다. AX 지원 역할을 코드 소유자나 필수 리뷰어로 지정하지 않는다. 이 스킬은 담당자에게 대신 연락할 권한을 주지 않는다.
